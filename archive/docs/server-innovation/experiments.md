## INV-001：最初の実験を進める

### 目的を一文にする

「復旧の意味が違う数字を一つのPASSへまとめず、必要な根拠を少ない確認作業で判断できるようにする」。

根拠は[9月8日のD-1記録](https://github.com/ns7jp/server/blob/2297fbb909d55184d9c4f46152b51d02e584a9fe/docs/evidence/2026-09-08-lab-base01-d1-practice.md)です。
記録はアプリ再起動回数0→1、HTTP復帰2秒、後続healthyを確認しています。
記録の2秒はhealthy到達や全機能のRTOではありません。

### 小さく試す順番

1. Codexが指定SHAのD-1スクリプトと日付付き記録を読み、成功条件・計測区間・未採録を一覧にする。
2. 新旧の結果を比較できるよう、`http_recovered`、`healthy_recovered`、`restart_observed`を別の項目にする案を作る。
3. 正常、HTTPだけ復帰、healthyだけ未復帰、再起動証拠不足、タイムアウトの保存ログを合成例として用意する。
4. 期待する判定を先に決め、保存ログを読む結果検査をローカルで実装する。根拠のない項目は不明のまま返す。
5. 機能テストと既存検査を通し、旧版・新版のコミットを比較計画へ登録する。
6. 同じ内容と難しさのケースで旧手順と新手順の判定時間・正答・見落としを記録する。
7. 初期比較を3組行い、順序をAB/BA/ABなど交互にする。既知の答えによる慣れを記録し、必要なら別の等価ケースを使う。
8. CLIで全試行と悪化を確認し、次の測定や採用判断へ進む。

最初のローカル実装は保存ログの読み取りで完結できます。
実機の異常終了を必要とする段階は、対象・管理経路・戻し方・時間枠を確定した別の実施です。
このシステム作成のために既存VMを自動停止しません。

### 登録前に決める内容

| 項目 | 記入すること |
| --- | --- |
| 比較対象 | 旧版SHA、新版SHA、変更する結果検査の範囲 |
| 計測区間 | 一つの結果の確認開始から、正しい判定と根拠記入の完了まで |
| 主指標 | 判定に要した秒数。平均ではなく3組の中央値と最悪値 |
| 品質条件 | 用意したケース全ての正答、未確認をPASSにしない、秘密値を出力しない |
| 環境条件 | 同じPC、表示方法、課題集合、実施者、支援量、計測方法 |
| 失敗 | 判定誤り、根拠が欠ける成功、必要な記録の消失 |
| 戻し方 | 旧結果検査を使う。新旧の記録と変更差分は保存 |
| 本人の時間 | 既存careerの技術枠に収める。採録時間も含める |

数値を入れた合成例だけで「判定時間20%減を達成」とはしません。
本人による操作・正答・時間が実測された後に、限定した条件の結果として評価します。

### 判断の例

旧100秒、新70秒なら中央値の改善率は30%です。これは説明用の合成値です。
新しい方法が一件でも未確認を成功と判定した場合は、速くてもREJECTです。
中央値が速くても一試行だけ極端に悪化した場合は、最悪値の条件でREJECTになります。
有望な場合も、別日または別のケースで確認し、人が採用を判断します。

## 他の実験へ進む前提

- INV-002：Lokiを停止したアーカイブと、起動後に書き込まれた復元先を無条件に全量一致比較しない。取得時点と照合対象を固定する。
- INV-003：再利用VMの成功を新規構築へ転記しない。初期状態・管理端末・適用コード版と全機能試験を揃える。
- INV-004：Ansible入門のファイル管理はOS全体の冪等性ではない。check mode、適用、再適用、機能を別に確かめる。
- INV-005：2GiBの部分構成から全10サービスを同時起動できると推測しない。構成、負荷、欠測、メモリを同じ窓で測る。
- INV-006：パスワード本文をログや公開結果へ含めない。正しい認証・不正な認証・認証なしをケースIDで記録する。
- INV-007：AIが第三者の回答や独力の理解を作らない。支援が必要になれば実験を中断して助け、条件変更を残す。
- INV-008：合成した保存ログ検査は24h/72hの稼働実測ではない。実時間の経過は元の受け入れ試験で確認する。

## 本人が覚えるための振り返り

実施後は次を自分の言葉で答え、既存の学習記録に残します。

1. 何が困っていて、なぜその方法を変えたか。
2. 何を同じ条件にし、何だけを変えたか。
3. 予想と実際はどう違ったか。
4. 速くても採用してはいけないのはどんな結果か。
5. 別の日や別の人に変わっても成立するか。まだ何が分からないか。

覚え方は「困り事 → 一つ変える → 前後を測る → 悪化も見る → 次へ残す」です。
AIは質問や説明の補助をします。本人の理解の確認結果は代筆しません。
