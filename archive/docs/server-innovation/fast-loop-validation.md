## 速度の確認

同じ合成観測を使い、一時ルートで通常のオフラインrunとiterateを比較します。
比較対象のrunもネットワークを使わず、両方とも事前に一度実行して状態を用意します。
処理時間はこのローカル環境の参考値で、実機の復旧速度や一般的な高速化率を表しません。

測定日時：2026-09-10 02:36 UTC。初期化と最初のrunを済ませ、同一Node.jsプロセス内でコマンド処理を5組測定しました。
実行順は交互に変えています。プロセス起動、実ネットワーク、実サーバーの速度は計測していません。

| 回 | 通常のオフラインrun（ms） | 保存結果を使うiterate（ms） |
| --- | --- | --- |
| 1 | 535.021 | 100.134 |
| 2 | 642.184 | 118.438 |
| 3 | 401.914 | 74.823 |
| 4 | 385.666 | 69.723 |
| 5 | 809.298 | 76.405 |
| 中央値 | 535.021 | 76.405 |

この条件では中央値が0.535秒から0.076秒となり、処理時間を約86%短縮しました。初回モデル探索自体は17.579msでした。
最終入力上限検査の追加前に行った参考計測では、中央値が0.824秒から0.203秒でした。計測時の端末負荷などで差が出るため、固定の高速化率として扱いません。
5回のiterateは全てキャッシュ利用、エンジン再実行0回、ネットワーク0回です。観測や記録量、端末の負荷で所要時間は変わります。
この値は固定の性能保証ではありません。

## 試験で守る境界

全ケースと採らなかった案の結果を保持し、以前一致していたケースを悪化させる案は選びません。
探索後の別seedは方針を固定してから確認し、選択には戻しません。
時刻の逆行や非有限値、不正な上限は拒否します。時間切れの未完了ラウンドは採用せず、途中結果を残します。
取得したコードや文字列の実行、任意コマンドの起動はありません。合成ケース内のシェル風文字列もデータです。

レビューで、missingフラグに旧本文と旧ハッシュが混在する入力の拒否、
時間切れを同じ設定で再試行できること、途中履歴を失わないことの回帰試験を追加しました。
