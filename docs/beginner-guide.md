# やさしい用語・見方ガイド

このページは、サーバーを初めて学ぶ人が本ポートフォリオを読むための入口です。用語を丸暗記せず、**役割と確認方法をセット**で覚えます。

## まず覚える 1 本の流れ

サーバー構築の仕事は、次の 6 語で整理できます。

> **設計 → 構築 → 試験 → 監視 → 復旧 → 記録**

| 工程 | やること | 身近なたとえ |
| --- | --- | --- |
| 設計 | 何を、どこに、どの設定で作るか決める | 家の設計図を作る |
| 構築 | OS、ソフト、ネットワークを設定する | 設計図どおりに建てる |
| 試験 | 想定どおり動くか確かめる | 水や電気が使えるか確認する |
| 監視 | 異常の兆候を継続して見る | 火災報知器を付ける |
| 復旧 | 壊れた状態から戻す | 故障箇所を直す |
| 記録 | 誰でも再現できるように残す | 点検記録を書く |

## 技術を「役割」で覚える

| 用語 | 役割 | このポートフォリオでの使い方 |
| --- | --- | --- |
| Linux | サーバーを動かす OS | Ubuntu 24.04 を使用 |
| Nginx | 通信の入口 | リクエストを Web アプリへ渡す |
| Flask / Gunicorn | Web アプリ本体 | 監視対象の応答を返す |
| Docker | アプリを箱に分けて動かす | 同じ構成を再現しやすくする |
| Ansible | 設定を自動化する | 手作業を playbook に置き換える |
| Prometheus | 数値を集める | CPU やサービス状態を記録する |
| Grafana | 数値を見える化する | ダッシュボードに表示する |
| Loki / Alloy | ログを集めて運ぶ | 原因調査に使うログを集約する |
| Alertmanager | 異常を通知する | 条件を満たした警告を送る |
| Terraform | クラウド構成をコード化する | AWS 構成コードを管理する（適用は未実施） |

## コマンドは「目的」で覚える

すべてのオプションを暗記する必要はありません。最初は次の対応だけ覚え、必要なときに `--help` や公式文書で調べます。

| 知りたいこと | 最初に使うコマンド | 見る場所 |
| --- | --- | --- |
| サービスは動いているか | `systemctl status <名前>` | `active` / `failed` |
| なぜ失敗したか | `journalctl -u <名前>` | エラー直前のメッセージ |
| ポートを待ち受けているか | `ss -lntp` | IP、ポート、プロセス |
| 名前解決できるか | `dig <名前>` | ANSWER、参照した DNS |
| HTTP が返るか | `curl -v <URL>` | 状態コード、接続先 |
| ディスクに空きがあるか | `df -h` | 使用率 `%` |
| コンテナは動いているか | `docker compose ps` | Status、Health |
| ログを確認したい | `docker compose logs <名前>` | 最初のエラー |

## 障害対応の 4 ステップ

覚え方は **「見る・絞る・変える・確かめる」** です。

1. **見る**：エラー全文、時刻、対象、直前の変更を記録する
2. **絞る**：利用者側、ネットワーク、入口、アプリ、DB のどこかを確認する
3. **変える**：一度に 1 つだけ変更する
4. **確かめる**：同じ確認コマンドを再実行し、復旧を記録する

いきなり再起動すると原因が消えることがあります。まず状態とログを保存します。

## 安全に練習するための約束

- 本番環境ではなく、削除できる VM やコンテナで練習する
- 変更前にスナップショットまたはバックアップを取る
- コマンドの対象ホスト、ファイル、ユーザーを声に出して確認する
- 削除・Firewall・権限変更は、戻し方を決めてから実行する
- パスワード、トークン、メールアドレスなどの秘密情報を証跡に残さない
- クラウドは予算アラートを設定し、終了後にリソースを削除する

## 1 つの演習で残す 5 点

```text
目的:
実行したこと:
期待する結果:
実際の結果:
失敗時の戻し方:
```

「コマンドを打てた」ではなく、**何を見て成功と判断したか**まで説明できれば、知識が実務で使える形になります。
