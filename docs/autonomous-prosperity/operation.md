# 毎週の運用：実行する、ひとつ進める、結果を戻す

## 初回だけ

1. 既存の本人台帳が入ったリポジトリを使う。別のコピーへ空の本人記録を量産しない。
2. 未初期化の場合だけ `node tools/portfolio-loop/loop.mjs init 10` を実行する。既存ファイルは維持される。
3. 本人が今週の負荷を確認し、`node tools/portfolio-loop/loop.mjs check-in normal` を実行する。必要なら `reduced` または `paused` を選ぶ。
4. `node tools/portfolio-loop/loop.mjs run` を実行する。学習枠が未接続なら、表示された既存の接続手順を本人が確認する。

追加のアカウント、AI API、別のスケジューラは必要ありません。
Node.js が PATH にない環境では、利用する Node.js 実行ファイルの絶対パスで `node` を置き換えます。

## 普段は同じ一行

```text
node tools/portfolio-loop/loop.mjs run
```

機械が監査・計画・改善準備・成果比較を行い、最優先の行動を示します。
本人は表示された一つを進めます。人の実技・職場の承認・実験条件が必要なところで、その内容を確認します。
自動で準備できる下書きは既存ループが用意するため、複数のCLIを順に打つ必要はありません。

| 表示の例 | 次にすること |
| --- | --- |
| 変化なし | 新しい判断依頼なし。取りかかっている行動を続ける |
| REFRESH_REVIEW | 振り返り枠で負荷と成果を確認し、`check-in` を入力 |
| REVIEW_EXISTING | 同時に表示される既存の最優先行動を進める |
| REVIEW_LOAD | 既存計画を小さくする。余白を増やすために原本を見直す |
| READY | 既存計画の先頭行動と完了条件を確認して実施 |
| PAUSED | 止めたままにする。本人が再開条件を確認したら再開 |

繰り返しの通知がなくても未完了の仕事が完了になるわけではありません。
詳しい状態を見直すときは `node tools/autonomous-prosperity/prosperity.mjs status` を使います。

## 週次の15分

既存の `weekly-review` の内訳として行います。
実際の枠が15分未満ならその範囲に縮め、0分なら確認時間を追加しません。READYでも選択済み行動がなければ新規作業は追加しません。

| 分数 | 確認 | 記録 |
| --- | --- | --- |
| 0〜3分 | 今週の負荷と約束、使える時間 | 通常・減らす・止める |
| 3〜8分 | 実施した一つ、未実施、環境、観測 | 既存の本人記録。未実施はNOT RUN |
| 8〜12分 | 役立った点と困った点、比較条件 | 指標と品質条件、次の確認 |
| 12〜15分 | 次の行動と見直し日 | `run` の提案を一つ確認 |

成果比較の索引は必要なときだけ追加します。数値の記録がなくても、通常の監査・計画・改善準備は動きます。
記録は[仕様](tool-guide.md)と[記録票](practice.md)に沿って、実測の原本を先に残します。

## 月次と四半期

月次は既存の振り返り時間の中で、継続した行動について「誰に役立ったか」「同条件で再現したか」「維持が重くないか」を確認します。
改善が2日揃った候補は、同じ対象での再利用を検討します。別の環境や仕事への適用は別の比較・承認が必要です。
変化がない候補は条件を変えて試すか、既存ループの `done ... PARK` で本人が保留します。理由と再開条件を残します。

四半期は既存キャリアの目標を確認し、優先する行動を一つ入れ替えます。新しい技能称号や別の学習時間は作りません。
就職・定着・成長の区分は、本人が実際の状況を確認して既存台帳で変更します。

## 止める・再開する

```text
node tools/portfolio-loop/loop.mjs check-in paused
node tools/portfolio-loop/loop.mjs run
```

`PAUSED` になり、この入口から既存ループを呼ぶ処理も省略します。キャリア原本が停止中なら、負荷だけ戻しても停止は続きます。
再開時は本人が負荷と既存キャリア設定を確認し、`check-in normal` または `check-in reduced`、その後 `run` を実行します。

## 困ったとき

| 症状 | 確認 | 復旧 |
| --- | --- | --- |
| EEXIST、ロックあり | 別の処理が動作中か、前回が停止したか | 進行中なら待つ。残存ロックの除去は対象処理の停止を本人が確認してから |
| Evidence missing, empty or changed | 正本の存在・空でないこと・SHA256 | 原本を確認し、本人が索引を訂正。合格値へ置換しない |
| Invalid fields | 項目名・余分な項目・形式 | [仕様](tool-guide.md)と比較。原本を保持したまま修正 |
| 終了コード3 | 収集不全、古い観測、API制限 | 既存ループの監査レポートを確認して取得をやり直す |
| 再実行前に止まる | 私用入力に破損や未来日がある | 時刻と原本を確認。自動修復は行わない |
| 別の保存先に見える | カレントディレクトリと `--root` | すべてのコマンドに同じ `--root` を指定 |

結果保存の直前に失敗した場合、既存ループの一部が完了していることがあります。
既存の原本と状態を確認して同じコマンドを再実行します。既存の取り込み重複防止が働きますが、全工程を一括で巻き戻す機能はありません。
