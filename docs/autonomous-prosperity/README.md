# 自律繁栄システム

**役に立つ成果を確かめ、続けられる負荷で、次の行動を一つずつ回す仕組みです。**
作成日：2026-09-10。対象：`ns7jp/ns7jp`。既存の[ポートフォリオ改善ループ](../portfolio-loop/README.md)に組み込みました。

ここでの繁栄は、サーバー構築職への就職・定着に向けて、再現できる技能、相手に役立つ成果、伝わる証拠、無理なく続けられる余力が増えることです。
本人の現在の雇用状態、収入、技能合格を推測するものではありません。

## いつもの一行で回す

リポジトリのルートで実行します。既に初期設定済みなら、これまでと同じコマンドです。

```text
node tools/portfolio-loop/loop.mjs run
```

監査の取得、キャリア計画、学習課題、実験結果の取り込み、改善候補の準備に続いて、成果と負荷を確認します。
結果に**次の行動を一つ**表示します。判断材料が変わらない再実行は「変化なし」と表示します。
定期実行の登録は増やしていません。既にこのコマンドを呼ぶ運用があれば、そのまま接続できます。

初めて使う場合は一度だけ設定します。既存の本人台帳がある場合は、そのルートを使ってください。

```text
node tools/portfolio-loop/loop.mjs init 10
```

週の負荷は本人が確認して入力します。例は「通常どおり」です。減らす週は `reduced`、止めるときは `paused` に置き換えます。

```text
node tools/portfolio-loop/loop.mjs check-in normal
node tools/portfolio-loop/loop.mjs run
```

この入力で成果や実測値は作られません。週次確認は既存の振り返り枠のうち最大15分を使い、週10時間へ上乗せしません。

## 自動で進むこと

| 工程 | 自動処理 | 本人に返すもの |
| --- | --- | --- |
| 観測 | 既存の GitHub GET 収集、状態と鮮度の確認 | 取得不全や古い根拠の再確認 |
| 配分 | 既存キャリア計画と成長計画を実行 | 既に選ばれた行動の中の次の一手 |
| 改善準備 | 既存ループの限定下書き・探索・実測取り込み | 実験条件や採否の判断 |
| 成果確認 | 根拠ファイルのハッシュ、環境、比較条件、改善・悪化を確認 | 再測定・方法変更・再利用を検討する理由 |
| 負荷管理 | 停止・縮小・未確認を検出 | 時間枠の再確認。自動で時間を増やさない |
| 次回へ接続 | 最新の提案を私用領域に保存、意味の変化を判定 | 必要な判断だけを短く表示 |

本人の実操作、理解、応募・職場での応答、実験の採否は本人の記録へ戻します。
システムは実績を代筆せず、`LEARNINGS.md`、SE合格、PJ承認、キャリア原本を自動更新しません。

## 実装の範囲

月次・四半期の指標、価値実験の比較、原期限を残す再計画、30・60・90日の導入は[詳細運用](../prosperity-review/README.md)にまとめています。詳細な一件の観察を管理する補助評価器は任意です。日常の負荷と成果の正本、通常の `run` はこのシステムを使います。

Node.js 標準ライブラリと既存モジュールだけで動きます。AI API、追加のAPIキー、外部通知先は不要です。
`run` と `weekly` のCLIが接続点です。ライブラリの `runLoop()` と既存の `demo` は従来の4系統を実行します。
自動実行はコマンドを呼んだときに行います。常駐プロセスや別のスケジューラは作りません。
通知判定は出力の `notify` で、メールやSlackへ送信する機能ではありません。

コードの動作確認と、本人の成長・採用・定着・サーバー実測は別の確認です。後者は今回 **NOT RUN** です。
