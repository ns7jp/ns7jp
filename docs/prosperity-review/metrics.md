# 成果・証拠・負荷を測る

[入口](README.md) / [設計](design.md) / [運用](operation.md) / [実験](experiments.md) / [記録票](templates.md) / [導入計画](roadmap.md) / [CLI](../../tools/prosperity/README.md)

## 1. 数字の前に確認する

指標は、次の行動を選ぶために使います。個人の価値や将来の採用確率を一つの数値で表すものではありません。
すべての測定に、対象期間、対象者・環境、対象版、数え方、分母、情報源、確認時刻、欠測、支援量を対応させます。
その情報が揃わなければ、計算できた数値でも比較可能とは限りません。

このページは運用全体の指標設計です。すべてをCLIが自動収集・計算するわけではありません。
実装済みの入力・計算・出力は[CLI仕様](../../tools/prosperity/README.md)、今回の実行範囲は[検証記録](validation.md)で確認します。
就職・職場・受け手・本人の理解の情報は、対応する原記録を本人と関係者が残します。

## 2. 少数の指標で見る

初月は「次の一手が決まるまでの時間」「実際に一件を実施した根拠」「本人の実時間と負荷」だけでも始められます。
他の指標は必要な判断が生じたときに増やします。測るための記録が実践時間を圧迫するなら、測定項目を減らします。

| 観点と指標 | 分子・値 | 分母・比較対象 | 確認頻度と原本 |
| --- | --- | --- | --- |
| 技術条件の充足 | 既存SEが条件充足とした対象条件数 | 同じ教材版で選んだ対象条件数 | 月次。SEのreport。人の段階評価は別表示 |
| 独力の再説明 | 当該期間に実記録がある独力EXPLAINED件数 | 当該期間に予定した対象の再説明件数 | 週次。growthの記録。未実施件数も併記 |
| 主張と証拠の対応 | 対象版・環境・範囲を確認できた主張数 | 今回確認対象とした主張総数 | 月次。主張と原記録の対応票 |
| 合意した約束の完了 | 元の期限内に完了を確認した約束数 | 対象期間に期限が来た約束数 | 週次。careerまたは職場の正本 |
| 受け入れ結果 | 受領者が受け入れを記録した対象件数 | 同期間に受け入れ確認の時点を迎えた件数 | 案件の節目。PJまたは職場の正本 |
| 作業・判断時間 | 定めた開始から終了までの分・秒 | 同じ課題区分の旧方法、条件を揃えた比較 | 実験時。全試行の実記録 |
| 実時間と計画 | 本人が記録した対象範囲の実分数 | その期間に合意した上限と計画分数 | 週次。本人記録とcareer |
| 機会への接続 | 本人が確認した要求と証拠の対応 | 今回比較した公式求人・担当要求 | 週次。career。応募や採用とは別 |
| 再利用の結果 | 同じ成果を実際に使った別の機会と結果 | 記録がある利用機会。見込み件数を含めない | 月次。利用記録 |

率だけでは件数が分からないため、`2/3件、未実施1件` のように分子と分母を併記します。
「対象条件3件中2件」をSE全体32条件や実務全般の達成率へ読み替えません。
一人・一回の利用確認は、その人・その条件の結果として残します。

## 3. 証拠の種類と測定率

運用上の証拠は、次の種類を明示します。

| 種類 | 意味 | 言えること |
| --- | --- | --- |
| 計画・下書き | 条件と方法を準備した | 実施に必要な準備の範囲 |
| synthetic | 合成・テスト・説明例 | 道具の挙動や計算例 |
| measured | 本人等が実際に観測した記録 | 当該対象・期間・環境で観測したこと |
| 人の確認記録 | 誰がどの条件を確認したかの原記録 | その人が確認した範囲 |
| 公開資料の観測 | 指定URL・版で取得した内容 | 取得できた時点の公開状態 |

CLIで実測として扱うには、`measured` という値だけでなく、所定の証拠ファイルとhashの一致など実装の検査条件を満たす必要があります。
hashはファイルの同一性を確認するもので、内容が真実であることや本人が独力で実施したことを認証するものではありません。
人の確認が必要な場面では、その確認の記録を別に照合します。

測定率は、CLIが定義する対象P候補集合のうち、有効な実測証跡と測定値がある件数の割合です。対象集合・除外条件は出力の分母と[仕様](../../tools/prosperity/README.md)を確認します。
全件を測った割合であって、良い結果だった割合ではありません。実測で悪化した一件も測定済みです。
技術実験の成功率、本人の理解度、就職確率へ変換しません。

## 4. UNKNOWN・0・対象なしを分ける

| 値や状態 | 使う条件 | 例 |
| --- | --- | --- |
| 0 | 定めた期間と範囲を確認し、該当する実数が0だった | 対象3試行で判定誤り0件 |
| UNKNOWN・欠測 | 読めない、未確認、測り忘れた | タイマー記録なし、本人時間が未入力 |
| NOT RUN | その試行・観測を実施していない | 新方法の比較をまだ試していない |
| 対象なし | その期間・条件には対象がない | 今週期限を迎える約束が0件 |
| 古い観測 | 過去に確認したが現在条件に使えない | 旧版だけにあるCI結果 |

分母が0なら、率は「対象なし」等の理由付きで計算しません。100%達成とも0%失敗とも扱いません。
読み取りが失敗した場合、最後に成功した確認時刻は残し、試行した時刻と分けます。
欠測を平均から黙って除かず、予定全試行数、取得できた数、欠測数と理由を同時に示します。

## 5. 比較の計算と限界

短いほどよい指標で、基準値が正の数なら、改善率は `(旧値 − 新値) / 旧値 × 100` です。
高いほどよい指標なら `(新値 − 旧値) / 旧値 × 100` とし、単位と方向を先に決めます。
旧値が0なら相対改善率は計算せず、同じ単位での差と対象条件を示します。

説明用の合成例：旧方法の判断時間が12分、新方法が9分なら、差は3分、相対減少は25%です。
これだけで週3分の節約を確定できません。同じ判断の実際の頻度、習熟、測るための時間、保守の追加負担が必要です。
一方で、誤判定が1件増えたなら、速度だけで採用しないという品質条件を先に決めます。

繰り返し測る場合は全試行と中央値、最も悪かった値を見ます。
改善率が大きい結果だけを残さず、失敗、中断、外れた条件、やり直しを表示します。
比較順、課題の難しさ、AI支援、実施者が変われば、その影響を記録して同列比較の可否を判断します。

## 6. 負荷と再投資

本人の負荷は「余裕あり・許容内・負担が大きい・未記録」など、本人が一貫して使える簡単な尺度で記録します。
コード上の受け付け値は[CLI仕様](../../tools/prosperity/README.md)に合わせます。自己申告を医学的な評価や能力順位には使いません。
実時間は学習・作品改善・就職活動・記録・レビューなど本人が管理対象に含めた範囲を揃えます。

「計画を全部実施した」を優先して上限を超えることは成果にしません。
計画超過、長い判断待ち、同じ失敗、保守の増加は、翌週の行動数や方法を変える信号です。
再投資の根拠は、実際に減った時間から新たに必要になった維持・測定時間を差し引き、同じ条件で再現するか確認します。
見込みの削減分を予定へ先に詰め込まず、[月次運用](operation.md)で本人が配分を決めます。
