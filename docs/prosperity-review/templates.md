# 判断に必要な記録のテンプレート

[入口](README.md) / [設計](design.md) / [運用](operation.md) / [指標](metrics.md) / [実験](experiments.md) / [導入計画](roadmap.md) / [CLI](../../tools/prosperity/README.md)

## 使い方

必要な票だけ使い、既存の正本と同じ内容を重ねて管理しません。
本人の学習はSE、応募や時間はcareer、実案件は職場またはPJ、サーバー比較実験はINVへ記録します。
ここに残すのは、それらへの参照と今回の運用価値についての判断です。

Markdownの票は読みやすい補助記録です。CLIがこれらの全文を解析してledgerへ取り込む機能ではありません。
機械入力は[CLI仕様](../../tools/prosperity/README.md)の形式に合わせます。私用の参照記録は `.local/` 内の適切な既存保存先へ置きます。
未記入を埋めるために実績を作らず、実施前は `NOT RUN`、未確認は `UNKNOWN` を使います。

## 1. 最初の接続と本人確認

```text
記録日：
本人がこの運用を採用した日：未採用
当面の目的：既存careerの目的を参照
正本のパスと確認日時：
週の上限：既存profileを参照
上限に含める活動：学習 / 作品改善 / 就職活動 / 記録とレビュー
今週の既約束と期限：
負荷の本人記録：UNKNOWN
SE台帳IDと正本：未接続
職場・PJの正本：未接続 / 対象なし
既存loopのlatestと参照先run：未確認
実施中・判断待ちの一件：未確認
最初に確認する不足一つ：
次に確認する日時：
```

過去に選んだ週10時間を読み取れたことと、本人が今日計画を確認したことを分けます。
確認時刻を更新する場合は、何を本人が確認したかを残します。

## 2. 次の一手のカード

```text
対象の既存行動ID / 候補ID：
困り事と、今回終えること：
参照する正本と版：
今回の作業：一つ
開始前の予想：本人記入
期待する出力と確認方法：
実施者 / 必要な支援 / 実施できる範囲：
既存行動の時間枠 / 今回使う予定分数：
中止条件 / 戻し方：
結果の保存先：
実施日時・実時間：NOT RUN
実際の出力 / 予想との差：NOT RUN
完了 / 続行 / 保留と理由：未判断
次の一手：
```

完了条件は「読む」だけにせず、例えば「期待と実出力の違いを一つ説明できる」のように観察可能にします。
説明文をAIが用意した段階と、本人が実際に説明した結果を別に記録します。

## 3. 価値観察の記録

```text
P候補ID / 登録した比較計画への参照：
この票の状態：計画 / 実施 / 中断 / 結果確認
利用者と困り事：
比較する旧方法A / 新方法B：
対象版・環境・情報量・支援量：
主指標 / 単位 / 良い方向：
開始と終了の定義：
予定全試行数 / 比較順 / 中止条件：
事前に決めた品質条件：
旧方法の基準値 / 証拠：UNKNOWN
実施した全試行と証拠ファイル：NOT RUN
実測値 / 中断 / 欠測の理由：NOT RUN
結果の差 / 悪化 / 維持の追加負担：未確認
慣れ・課題差など、比較の限界：
別日・別課題で確かめること：
本人の判断 / 理由 / 判断日：未判断
```

技術実験に該当する場合はこの票を二重の採否台帳にせず、既存のINV計画・全試行・decisions.jsonへ戻します。
証拠の種類とhashの扱いは[指標](metrics.md)へ、機械が受け付ける値は[CLI](../../tools/prosperity/README.md)へ合わせます。

## 4. 週次の実績と未完

```text
対象週：
本人が確認した上限と負荷モード：
既存career計画への参照：
今週実施した一件と正本：NOT RUN
予定分数 / 実分数 / 測り忘れた範囲：
得られた結果と、まだ言えないこと：
未完の対象 / 残見積 / 理由：
元の期限 / 超過期間 / 現在の合意期限：
必要な判断者 / 判断内容 / いつまでか：
負荷の本人記録：UNKNOWN
翌週に残す一件 / 減らす作業：
通知する意味のある変化：なし / 具体的内容
```

「未実施がある」と「本人の能力がない」を結び付けません。
時間、環境、条件の不明、評価待ち、別の優先事項などを分け、次に変えられるものを一つ選びます。

## 5. 月次の継続と再投資

```text
対象期間 / 本人の確認日：
役立ったこと / 受け手 / 実際の利用の正本：未確認
比較した基準と条件：
効果が確認できた範囲 / 欠測と因果の限界：
実際に減った時間 / 増えた維持・採録時間：UNKNOWN
負荷と継続上の困り事：
継続する方法 / 理由：未判断
条件を変える方法 / 変える一項目：未判断
保留・終了する方法 / 理由 / 再開条件：未判断
次の配分：維持 / 休息と余白 / 再発防止 / 次の不足
既存profileで変更する行動IDと時間：変更なし
次回、配分の効果を確かめる日：
```

見込みの効果を実際に増えた余白へ置き換えません。
配分変更を採用するまでは提案として残し、採用したときに既存profileを更新します。

## 6. 停止・再開と訂正

```text
検知日時 / 対象 / 元のエラーメッセージ：
確認できた事実 / 未確認：
影響のある処理 / 影響のない処理：
停止・縮小した範囲と理由：
原本 / 正常履歴 / 保存した変更差分：
元の期限と超過期間：
修正または復元したこと / 訂正理由：
再開に必要な条件と確認者：
再確認した正本・版・時刻：未確認
再開後一回の実行記録：NOT RUN
残る制約 / 次の確認：
```

古い結果や失敗を削除して新しい成功に置き換えず、訂正理由と新しい記録を対応させます。
実際の障害対応は対象環境の手順を優先し、詳細な記入が初動を遅らせる場合は事実と時刻を先に残します。

