# 本人の採用日から始める30・60・90日計画

[入口](README.md) / [設計](design.md) / [運用](operation.md) / [指標](metrics.md) / [実験](experiments.md) / [記録票](templates.md) / [CLI](../../tools/prosperity/README.md)

## 1. 起点を決める

Day 0は、本人がこの運用を採用した日です。文書の作成日、CLIの初期化日、デモ実行日から本人の活動日数を進めません。
初期の採用日は未記入で、進捗も未実施から始めます。
30・60・90日は成果を確約する期限ではなく、方法と負荷を見直す節目です。

この導入計画と、[就職後の30・60・90日](../engineer-career/onboarding.md)は起点が異なります。
就職後の計画は実際の入社と職場の合意を起点にし、この運用の経過日数で職務権限や独力担当を決めません。
導入中に状況が変わった場合は、本人がcareerの活動段階と時間配分を見直します。

## 2. Day 0：現在地と入口を一つにする

| 準備 | 終了を確かめるもの | 未確認のとき |
| --- | --- | --- |
| 既存の目的と週の上限を読む | 本人が確認したcareerの正本と確認日 | 過去の選択として保持し、現在の確認を分ける |
| SE・PJ・実記録の場所を調べる | 既存ID、保存先、読めた範囲 | 未接続として残す。空の実績で代替しない |
| 既存ループの状態を読む | 最新観測、参照run、未完の一件 | 取得・整合性確認を最初の一件にする |
| demoで道具を試す | 合成表示、次の一手、欠測の扱い | 道具の確認を続け、本人の実測とはしない |
| 導入を採用するか決める | 本人の採用日と目的 | 候補のまま保存し、日数を進めない |

既存の `evidence-map` など目的に合う行動内で準備します。
初期導入のために本人の週10時間を上乗せしません。時間が足りなければDay 0の準備を複数回に分けます。

## 3. Day 1〜30：一巡して基準を作る

狙いは、情報を増やすことより、実施可能な一件を選び、結果と負荷を戻せることです。
最初の基準値は本人の実測から作り、何分短縮できるかを先に実績として置きません。

| 期間の目安 | 行うこと | 確認する根拠 |
| --- | --- | --- |
| 最初の週 | 接続と上流の阻害要因を解消し、今日の一件を準備 | 正本の参照、欠測一覧、次の一手のカード |
| 2週目前後 | 共通枠が空き、本人が選べるならP-001の比較を決める | A/Bの条件、全試行計画、品質条件、時間枠 |
| 3週目前後 | 本人が旧方法・新方法を試し、全結果と負荷を記録 | 実施した試行と証拠。未実施なら理由 |
| 30日の見直し | 続ける、変える、保留する、終了するを判断 | 原本、比較限界、月次の判断記録 |

既存のINVが進行中なら、その実験と成果の利用を優先し、P実験は後へ置きます。
30日までに技術実験とP実験の両方を完了することをノルマにしません。
実施機会がなければ準備済み・NOT RUNを保ち、必要な環境・時間・支援のどれを整えるか一つに絞ります。

30日の運用上の到達条件は、正本が分かること、一件の結果へ戻れること、測っていない項目を識別できること、翌期間の配分を本人が決められることです。
技能合格、応募送信、内定、収入増加は別の実際の記録で確認します。

## 4. Day 31〜60：使う場面へつなぐ

狙いは、採用した方法を別の機会でも使い、対象を限定した価値を確かめることです。
一回よかった方法を繰り返すだけでなく、別日・別課題・支援量の違いを見て、どこで役立つかを狭く正確にします。

| 本人が確認した状況 | 次に行うこと | 価値の根拠 |
| --- | --- | --- |
| 就職活動の準備段階 | 公式求人の要求と証拠を照合し、実記録で説明練習をする | 対応する要求、本人の回答、詰まった問い |
| 実際に応募・面接を行った | 本人が受けた問いと説明の差を既存careerへ戻す | 実際の活動日と記録。相手の意思を推測しない |
| 入社後の合意した小担当がある | 職場の正本で実施・相談・受領を確認する | 実担当範囲、支援、責任者の確認 |
| 活動段階が未確認 | 本人の目的と現在の条件を確認し、技術・説明の小練習を続ける | 状況確認と許可済みの個人実践 |

本人だけの練習なら本人の変化として、受け手が実際に確認したならその人の確認範囲として記録します。
一つの結果から一般的な能力・職場評価へ広げません。
うまく使われなかった成果は、対象者、必要な情報、導線、前提のどこに差があったかを確かめます。

60日の見直しでは、再利用された方法一つ、修正が必要な方法一つ、維持にかかった時間を比較します。
結果がない場合は件数を作らず、阻害要因と次の条件変更を決めます。

## 5. Day 61〜90：残す方法と配分を決める

狙いは、役立った方法だけを維持し、余白と次の選択肢へつなぐことです。
現在の成果を説明する材料と、次の不足を改善する計画を分けます。

1. これまでの採用日、本人の記録、実験結果、負荷、未完の一件を照合する。
2. 役立った方法を、対象・前提・手順・期待結果・限界が分かる短い標準へまとめる。
3. 同じ原本から本人の説明と詳細手順をつなぎ、重複更新が必要な箇所を減らす。
4. 維持・採録に要した時間を確認し、見込みと実際の差を残す。
5. 次期間の余白と、伸ばす技術または仕事上の不足一つを本人が決める。
6. 正本を残したまま、役立たない定型記録・通知・候補生成を減らす。

90日の到達条件は、何を続けるか、何を止めるか、次に何を確かめるかが根拠付きで決まることです。
新しい商品、独立、受注、収益化を自動的な次段階にしません。
それらを本人が選ぶ場合は、希望、提供価値、実績、条件、費用、契約等を確認する別の具体的な計画が必要です。

## 6. 遅延・休止から戻る

| 起きたこと | 計画の扱い |
| --- | --- |
| 30日を過ぎても比較未実施 | 元の節目と未実施理由を残し、先に前提を一つ整える |
| 期限がある活動が増えた | 既存careerで約束を優先し、運用実験を保留する |
| 本人が縮小・休止を選んだ | 開始日や履歴を変更せず、休止期間と再開条件を残す |
| 入社・生活条件が変わった | 本人の確認に基づき活動段階と業務外の上限を見直す |
| 方法が役立たなかった | 結果と条件を残し、旧方法へ戻すか次の仮説を選ぶ |
| 道具の入力・状態が壊れた | [復旧手順](operation.md)で原本を保全し、再確認後に進める |

日数に追い付くために測定を省いたり、完了日を遡って書いたりしません。
再開後は「最後に正常だった時点」「いま変わった条件」「次に実施する一件」を確認します。
四半期ごとの循環は同じ方法で続け、必要な詳細だけ[記録票](templates.md)へ残します。
