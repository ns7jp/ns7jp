# ヘルプデスクの一次対応例｜異動先の共有フォルダが開けない

AI の支援で作成した模擬チケットです。以下の会話・時刻・担当者の回答は架空です。末尾に、この題材に関連して本人が VM で確認した結果を載せています。

## 利用者への最初の返信

> **利用者（9時10分）**　今日から別の部署に異動しました。引き継ぎ資料が入っているフォルダを開けません。
>
> **一次受付**　ご連絡ありがとうございます。資料は何時ごろ、どんな作業でお使いですか。同じ部署で、ほかにそのフォルダを開ける方はいらっしゃいますか。
>
> **利用者**　10時の打ち合わせで使います。隣の席の方は同じフォルダを開けました。
>
> **一次受付**　10時の打ち合わせ用ですね。開こうとしたフォルダ名と、画面に表示されたメッセージを教えてください。
>
> **利用者**　「部内共有」です。「アクセスが拒否されました」と表示されます。

## 一次受付からアクセス権の担当者へ

| チケット項目 | 記入例 |
| --- | --- |
| 引き継ぎ時の状態・期限 | 担当者の確認待ち。10時の打ち合わせ準備に支障あり。 |
| 聞き取った事実 | 利用者によると対象は異動先の「部内共有」。表示は「アクセスが拒否されました」。現在分かっている影響は申告者1名で、同僚1名は同じフォルダを開けた。 |
| 切り分け | フォルダ全体の停止よりも、対象アカウントの利用条件を先に確認したい。異動申請の承認状況、所属グループへの反映状況は未確認。 |
| 担当者への依頼 | 対象フォルダの利用が承認済みか、現在の所属グループが申請内容と一致するかを照合してほしい。一次受付での権限変更はなし。 |
| 次の連絡 | 一次受付が9時30分までに利用者へ進捗を連絡する。担当者の確認後、ご本人が必要な資料を開けたかを確かめて記録する。 |

**引き継ぎ時に利用者へ伝える文面**

> 10時の打ち合わせで資料を使うことを担当者に伝えました。異動に伴う利用申請と、現在の設定を照合してもらいます。確認が続いている場合も、9時30分までに私から状況をご連絡します。

## 途中連絡と業務再開の確認

> **一次受付から利用者へ（9時30分）**　今、担当者が異動後の設定を確認しています。9時45分までに、もう一度こちらからご連絡します。
>
> **権限担当から一次受付へ（9時35分）**　「部内共有」の利用は承認済みで、現在の所属グループも申請どおりです。サインインし直した後で資料を開けるか確認してください。
>
> **一次受付から利用者へ（9時38分）**　担当者が設定を確認しました。編集中のファイルを保存してから、Windows をいったんサインアウトし、もう一度サインインしてください。「部内共有」から、打ち合わせで使う引き継ぎ資料を開けますか。
>
> **利用者（9時42分）**　資料を開けました。これで打ち合わせの準備を続けられます。
>
> **一次受付（9時43分）**　ご確認ありがとうございます。この件は対応完了とします。また開けなくなったら、このやり取りに返信してください。

**完了記録（9時43分）**　再サインイン後、必要な資料を開いて打ち合わせの準備を再開できたと利用者から回答があり、チケットを完了。一次受付での権限変更はなし。最初に拒否された原因は未特定。

## 関連する本人の実習

個人の仮想環境では、AI の案内を受けて部署異動を試しました。異動直後は旧部署のドライブが画面に残っていました。同じ利用者でサインインし直し、新部署のファイルを読めること、旧部署の共有先を直接指定すると拒否されることを確かめました。[部署異動の検証結果](https://github.com/ns7jp/server/blob/main/docs/evidence/2026-11-10-kvm-ad-client-access-gpo.md#部署異動の検証)

PC の動作が遅い場合やネットワークにつながらない場合についても、[問い合わせと対応ログの記入例](https://github.com/ns7jp/ns7jp.github.io/blob/main/learning-docs/support-scenarios.md)を公開しています。
