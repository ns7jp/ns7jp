# 本人が記入する成長記録

[練習の進め方](practice.md) / [既存の週次記録](../engineer-career/templates.md)

必要な節を非公開の記録先へコピーします。これは未記入の用紙で、実施・習得・合格・承認の証拠ではありません。
詳細な操作・ログ・評価は [既存のSE評価](../server-engineer/assessment.md)と [BX等の記録用紙](../server-engineer/advanced/templates.md)へ残し、ここには参照と次の改善を書きます。
分からない値は未確認、実施していない操作は `NOT RUN`、記録していない時間は欠測のままにします。

## 1. 今回の練習を決める

```text
記録ID / 記入日・タイムゾーン: 未記入
本人の識別ID: 未記入
入口（求人の要求 / 面接の問い / 試験の失敗 / その他）: 未確認
入口の原記録と、実際に分かった不足: 未記入
今回の目的を本人の言葉で一文: 未記入
対応するSE/BX条件と正本の版: 未確認
前の試行ID / 前の結果の参照: 未確認
今回終わらせる一つの確認 / 期待値: 未記入
週次計画の行動ID / 今回の予定時間: 未確認
実際に使った時間: 欠測
```

週10時間の総枠へ新しい練習時間を上乗せしません。再確認も既存の週次計画へ入れます。
条件IDが不明なら対応付けを保留し、この記録独自の合格条件を新設しません。

## 2. 実行前と実行後をつなぐ

| 項目 | 本人の記入 |
| --- | --- |
| 試行ID / 実施日時・タイムゾーン | 未採番 / 未実施 |
| 対象環境 / OS・ソフトウェア / 構成版・Git SHA | 未確認 |
| 実行前の状態 / 今回変える一つの要因 | 未確認 |
| 対象・影響・権限 / 必要な許可の原記録 | 未確認 |
| 中止条件 / 戻し方 / 必要な相談先 | 未確認 |
| 支援量の予定 / 実際の支援量 | 未選択 / 未確認 |
| 期待する出力・状態 / 失敗とする条件 | 未記入 |
| 実操作と出力の正本 / 試験別結果 | 未取得 / NOT RUN |
| 終了・復旧・利用者側の確認と残った影響 | 未実施 / 未確認 |
| この結果から言える範囲 / 言えない範囲 | 未記入 |

支援量は既存定義の `guided / ai / independent` を使います。混在した場合は支援を受けた時刻・区間・内容を追記します。
独力試行中に原因や手順の答えを得た場合、その回を独力評価にせず、別の試行へつなぎます。
AIや第三者が実行した出力を本人の操作欄へ入れません。静的検査と実機試験も区別します。

## 3. 本人の説明と原因の仮説

```text
説明した実日時 / 方法（口頭・文章等）: 未実施 / 未確認
本人の説明: 目的は【未記入】、予想は【未記入】、実際は【未記入】でした。
そう判定した出力の箇所と理由: 未記入
説明できなかった点 / まだ確かめていない条件: 未記入
原因候補の分類: 未選択（前提・環境 / 対象・手順 / 知識・判断 /
  観測・判定 / 説明 / 連絡・計画 / 原因不明。複数可）
観測した事実と証拠: 未記入
仮説A / 正しければ見える結果 / 違えば見える結果: 未記入
別の仮説B / Aと区別する確認: 未記入
次に確認・変更する一つのこと: 未決定
改善後に同じ基準で行う確認 / 影響する既存試験: 未決定
新しい試行ID / 結果 / 仮説を維持・修正する理由: 未実施 / 未確認 / 未記入
```

AIによる説明案は本人の説明と別に保管します。答えを読んだ後の修正と、先に自分で答えた内容を分けます。
原因が確かめられなければ仮説のままです。設定を変更して動いたことだけで原因確定にしません。

```text
相談を考えた理由 / 同じ結果になった試行ID: 未記入
対象と影響 / 今止めている操作: 未確認
確認できた事実 / まだ分からないこと: 未記入
試したことと各結果 / 試していないこと: 未記入
自分の仮説 / 識別に足りない情報: 未記入
相談したい一つの質問: 未記入
相談先の候補 / 判断が必要な期限: 未確認
下書きの確認 / 実際の連絡日時 / 返答: 未確認 / 未連絡 / 未回答
支援を受けた内容 / 次の試行の支援量: 未確認
```

同じ確認2回で新しい事実が増えなければ方法を見直す目安とします。対象誤りや影響拡大なら回数を待ちません。
この用紙の作成を送信や相談完了に数えず、人の実技観察が未実施なら評価待ちを残します。
