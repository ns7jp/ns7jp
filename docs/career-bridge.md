## 前職で取り組んだ改善

物流現場の在庫管理・ピッキングで作業時間を記録し、棚ラベル・動線・補充ルール・新人向けチェックリストを改善しました。上長へ数値を示して提案し、小さく試して展開することで、**自分の作業時間を 1 日約 1 時間短縮**しました。

改善後の継続計測を仕組み化できず、ミスや OJT 期間への効果を定量化できなかったことが反省点です。[業務改善レポート](./business-improvement/picking-improvement.md)では、実測した短縮時間と、原資料が残っていないため再構成した内訳・定性評価を分けています。

## インフラの仕事で活かしたい姿勢

- **計測する**：感覚だけで判断せず、作業前後の状態と結果を確認する。
- **記録・報告する**：現場の困りごとを整理し、確認した事実と判断に迷う点を分けて伝える。
- **標準化する**：手順やチェックリストを残し、継続して確認できる形にする。

これは前職の進め方を活かす方針です。サーバー監視・構築を独力で担当できるという意味ではありません。仕事の構造、5S・BCP、設計資料への詳しい対応付けは[比較資料](./career-bridge-reference.md)にまとめています。

## 志望の経緯

### 1. 就業先の研修で何をやり、何が足りなかったか

2026 年 7 月にアデコ株式会社へ入社し、7 月 21 日〜9 月 15 日に IT 企業で Windows Server / Linux サーバー構築、利用者アカウントと権限の管理を研修で学びました。10 月 7 日からは別の IT 企業でトライアル就労・社内研修中です。**勤務開始時期は相談（2026-11-05 本人確認）**で、就業先の社名は面談時に開示します。

研修は VM 演習が中心で、顧客環境での構築・運用や、引き渡し・受け入れ試験・実障害対応を一貫して担当した経験はありません。正社員として Linux サーバーの設計・構築を担えるようになることが目標です。

### 2. なぜネットワークでもクラウドでもアプリでもなく、サーバー構築か

[学習記録](../LEARNINGS.md)の次の経験から、設定や前提条件を確かめ、土台を正しく作る仕事に関心を持ちました。

- **UFW の設定競合（2026-08）**：同じポートに `allow` と `limit` を適用するロールの不具合を CI が検出し、AI が分析・修正しました。私は説明を読み、同じ操作で設定が変わり続ける原因を学びました。
- **AD ドメイン参加時の DNS 設定不備（2026-08、研修）**：クライアントの DNS の向き先と Hyper-V のネットワークを見直した事例です。**文章は AI の代筆で、本人の記憶に基づく書き直しは未完了**です。[執筆の内訳](./ai-usage.md#learningsmd-について)
- **app が healthy でも nginx 停止中はアクセスできなかった件（2026-09）**：本人が書いた記録です。コンテナ単体の状態だけでなく、利用者が通る経路の正常性を確認する必要があると学びました。

### 3. 監視・運用を「入口」として受ける位置づけ

まずは IT 事務・キッティング、監視・運用の補助を通じて、手順に沿った作業・確認・報告を経験したいと考えています。判断に迷うときは確認者へ相談し、学習では状態やログを自分の言葉で説明できる範囲を広げます。[応募分野と確認済みの範囲](./target-roles.md)
