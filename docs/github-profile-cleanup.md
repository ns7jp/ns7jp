## 3. 言語判定（Linguist）の確認方法

### 前提（対応済みの内容）

`ns7jp/ns7jp`（プロフィールリポジトリ）の GitHub 言語判定が **JavaScript** になっていました。
原因は `tools/` 配下にあった約 8,300 行の JS です。
2026-09-17 に、これらを `archive/` 配下へ移動し、`.gitattributes` に次の行を追加して対応済みです。

```text
archive/** linguist-documentation
```

（`.gitattributes` の属性名は、`=true` を書かなくても「設定された」＝有効として扱われます。
 上の 1 行は `archive/** linguist-documentation=true` と同じ意味です。）

### なぜすぐ反映されないのか

GitHub の言語判定（Linguist）は、**デフォルトブランチの内容**に対して実行され、結果はキャッシュされます。
`.gitattributes` を変更しても、GitHub 側で再解析（再インデックス）が走るまで、
リポジトリページの言語バーは古い表示のまま残ることがあります。
新しいコミットがデフォルトブランチに入ると再計算される仕組みですが、
**反映までにどれくらい時間がかかるかは確実な公式値を確認できていないため、ここでは「未確認」とします。**
数日おいて再確認することを勧めます。

### 確認手順

**手順1: ローカルで「属性が効いているか」だけ先に確かめる（すぐできる／確実）**

リポジトリのディレクトリで次を実行します。

```text
git check-attr linguist-documentation -- archive/<実在するJSファイルのパス>
```

`... : linguist-documentation: set` と表示されれば、`.gitattributes` の書き方は正しく、対象ファイルに効いています。
`unset` や `unspecified` と出た場合は、パターン（`archive/**`）とファイルの実際のパスが合っていません。
これは GitHub の再インデックスを待たずに、その場で確かめられます。

**手順2: GitHub 上で言語バーを見る（反映待ち）**

1. `github.com/ns7jp/ns7jp` を開きます。
2. 右サイドバーの **Languages** の欄を見ます。
3. 言語バー（色帯）をクリックすると、言語ごとの割合の内訳が出ます。
4. JavaScript が消えている、または大きく下がっていれば成功です。
5. 変わっていない場合は、デフォルトブランチに新しいコミットが入っているかを確認し、数日後に再確認します。

**手順3（任意）: 手元で Linguist を直接動かす**

`github-linguist` は Ruby の gem として公開されており、インストールすればローカルで集計を確認できます。
ただし環境構築の手間があり、**手元のバージョンと GitHub 側のバージョンが一致する保証はありません。**
急ぎでなければ手順1と手順2で十分です。

### `linguist-vendored` / `linguist-documentation` / `linguist-generated` の違い

まず、**3 つとも共通して「リポジトリの言語統計（言語バー）から対象ファイルを除外する」**という同じ効果を持ちます。
違いは「そのファイルが何であるか」という意味づけと、言語統計以外への影響です。

| 属性 | 意味づけ | 言語統計 | 既定で対象になるもの |
| --- | --- | --- | --- |
| `linguist-vendored` | **外部から持ち込んだ第三者のコード**（ライブラリを直接リポジトリに入れた場合など）。自分が書いたものではない、という宣言です。 | 除外される | Linguist の `vendor.yml` に載っているパス（`node_modules/`、`vendor/` など） |
| `linguist-documentation` | **説明・資料のためのファイル**。動かすためのコードではなく読ませるもの、という宣言です。 | 除外される | Linguist の `documentation.yml` に載っているパス（`docs/`、`README` など） |
| `linguist-generated` | **ツールが自動生成したファイル**。人が手で書いたものではない、という宣言です。 | 除外される | ビルド成果物やミニファイ済みファイルなど、Linguist が自動検出するもの |

確実に言えるそれ以外の差:

- `linguist-generated` が付いたファイルは、**GitHub 上の差分表示（diff）で既定で折りたたまれます**。
  自動生成物の巨大な差分でレビュー画面が埋まるのを防ぐための挙動です。
- `linguist-vendored` / `linguist-documentation` を付けたファイルが、同じように差分表示で折りたたまれるかどうかは、
  **今回確認できていないため「未確認」とします。**（言語統計から外れることは確実です。）
- これらの属性がコード検索の結果に影響するかどうかも、**未確認**です。
- 逆向きの指定として `linguist-detectable`（除外対象を統計に戻す）や
  `linguist-language=<言語名>`（判定される言語を強制指定する）も存在します。

### 今回 `linguist-documentation` を選んだことについて

`archive/` に入れた JS は「第三者のライブラリ」でも「自動生成物」でもないため、
厳密な意味づけとしては `vendored` や `generated` より `documentation`（＝もう動かす対象ではない資料的な置き場）の方が近く、
言語統計から外すという目的も達成できます。
より正確に「過去の記録であり成果物ではない」と示したいなら、`.gitattributes` の該当行の上に
`# archive/ は過去の作業記録。言語統計の対象外にする` のようなコメントを 1 行足しておくと、
第三者が読んだときに意図が伝わります（`.gitattributes` は `#` で始まる行をコメントとして扱います）。

### 進め方の提案

一度に全部やる必要はありません。効果と手間の比が良い順に並べると次のようになります。

1. **今日 10 分でやる**: ピン留め 3 個 + `git check-attr` によるローカル確認。
2. **次にまとまった時間が取れたとき（1 時間）**: 10 リポジトリの中身確認 → 説明文入力 → 非公開化。
3. **その後（30 分）**: README の点検と、ピン枠 4〜6 の追加判断。
4. **急がない**: (c) の主作品への統合。`server` 本体の品質に直接効く作業を優先してください。
