# SE00 準備と学び方 — 自分の操作を、自分の記録で説明する

[育成システムの入口](../README.md) / [評価手順](../assessment.md) / [次: Linuxを一台構築する](01-linux.md)

ここでの目的は、難しいコマンドを覚えることではありません。「どの機械の、どの場所で、誰の権限を使い、何を確認したか」を説明する習慣を作ります。サーバー構築は、同じコマンドでも対象を間違えると別の結果になる仕事です。まず対象と記録を揃えます。

**教材の状態:** 手順を設計・記述した段階です。このページの存在、静的検査、著者の過去ログは、あなたの実施証跡にはなりません。実施前は4条件すべて `NOT RUN` とします。目安は準備1〜2日と、翌日の振り返りです。所要時間は合格条件ではありません。

## 最初に決める3つの場所

| 場所 | 役割 | ここで扱うもの |
| --- | --- | --- |
| 手元のWindows PCなど | 管理端末 | 仮想化ソフト、ブラウザ、VMへ接続するSSHクライアント |
| 自分専用のUbuntu 24.04 VM | 構築・障害演習の対象 | Linux、サービス、仮想ディスク、学習用ネットワーク |
| VM内に取得したリポジトリ | 教材・コードの置き場所 | `ns7jp`は学習体系、`server`は動かす実装 |

VMは「PCの中に作る、別のOSを起動できる機械」です。コンテナはOSのカーネルを共有する実行環境です。WSLでコマンドに慣れることはできますが、通常VMのOS導入、仮想NIC、再起動試験を済ませたとは記録しません。

既存の[開始前診断](../../learning-plan/00-start-here.md)と[学習環境の作り方](../../learning-plan/01-environment.md)を開き、OS、利用可能メモリ、空き容量、管理権限、仮想化ソフト、週の学習時間を作業メモへ書きます。資源の表は計画値です。自分の端末で不足した場合は、その実測と詰まった箇所を記録します。クラウド契約はこの段階には不要です。

| 条件 | ここで示すこと | 判定材料 |
| --- | --- | --- |
| SE00-C1 | 実行場所と対象を説明して状態を採録する | 対象表、状態確認コマンドの実出力 |
| SE00-C2 | 学習用VMを用意し再作成・接続経路を記録する | VM設定、OS、接続経路、再作成手順 |
| SE00-C3 | 期待結果・実際の結果・未確認を分ける | 成功と失敗を別々に判定した記録 |
| SE00-C4 | 秘密情報を除いた質問と翌日の再説明を行う | マスク済み質問、別日の説明記録 |

## SE00-C1 実行場所と対象を説明して状態を採録する

1. 作業メモの冒頭へ「実行場所: Ubuntu VMのBash」「対象: 自分の学習VM」「変更: なし」と書きます。VM未作成なら先にC2へ進んでよく、段階全体の合格は4条件が揃ってからです。
2. 次を**Ubuntuのターミナル**で1行ずつ実行します。Windows PowerShellへそのまま貼りません。

   ```bash
   date -u --iso-8601=seconds
   whoami
   pwd
   cat /etc/os-release
   ip -brief address
   ```

3. `whoami`の利用者、`pwd`のディレクトリ、OSの`PRETTY_NAME`、`lo`以外のインターフェースを説明します。rootであれば一般ユーザーへ戻り、最初から確認します。
4. 出力を、公開リポジトリへ直接書く前の個人用作業記録へ保存します。原本を保持し、公開する写しだけで個人名・実IPなどを伏せます。どの行を伏せたかも記載します。

**期待する観測:** 日時とOSが取得でき、ユーザー名・現在位置・IPを「同じもの」と取り違えず説明できること。IPが取得できない場合は、その出力を記録してC2の接続設定を見直します。出力にUbuntuと書いてあることだけで、専用VMであると判定せず、仮想化ソフト側の対象名とも照合します。

**変更と戻し方:** この節は読み取りだけです。コマンドが見つからないときはコマンド名とエラーを残します。ここからパッケージ導入は行わず、後続の準備手順へ分けます。

## SE00-C2 学習用VMを用意し再作成・接続経路を記録する

GUI操作と設定値の正本は[Phase 1 初期構築演習の作業前確認・VM作成](../../learning-plan/05-phase1-exercise-design.md)です。OSイメージの取得先は[公式資料の一覧](../sources.md)から確認します。

1. 新規の学習VMを1台作ります。会社・共有・他用途のVMを転用しません。仮想化ソフト、VM名、vCPU、メモリ、OSディスク容量を表に記入します。まだ3台同時起動する必要はありません。
2. NAT側はパッケージ取得、ホストオンリー側は管理端末からの接続、と役割を分けて設定します。利用する方式で名称が異なる場合は、名称と実際の通信先を対応付けます。既存ネットワークと重複しない範囲を使い、教材のIPを無条件でコピーしません。
3. Ubuntuを新規導入し、一般ユーザーでログインします。OpenSSH Serverを導入する操作は**OS構築の変更作業**として記録します。状態確認だけの作業記録と混ぜません。
4. 仮想化ソフトのコンソールから入れることを確認します。SSH接続が失敗してもコンソールから調べられることが、復旧経路になります。
5. OSとNICをC1のコマンドで確認し、手元PC→SSHクライアント→学習VMの図を描きます。SSHの宛先、ポート、認証方式、実行する端末を記載します。秘密鍵・パスワードは図へ書きません。
6. 一般ユーザーで接続できた状態のスナップショットを取得します。名称、取得時刻、復元操作の場所を記録します。スナップショット未対応なら、VM新規作成からの手順を記録します。

| 記録項目 | 記入内容 |
| --- | --- |
| VMの識別 | 仮想化ソフト内の名称とOS内のホスト名の対応 |
| 接続経路 | PCからのSSH、仮想化ソフトのコンソールの2経路 |
| 再作成 | 使用ISO・OS版、VM設定、導入順、所要時間 |
| 戻せる範囲 | OSディスク、追加ディスク、外部保存先のどこまで含むか |
| 未確認 | スナップショットからの実復元をまだ試していない場合など |

**つまずいたら:** VM起動失敗は仮想化設定とVM側エラー、SSH失敗は接続先とコンソール上のSSH状態を保存します。学習VMだけを直し、手元PCのNICを一括削除したり、ファイアウォールを全面無効化したりしません。30分止まったらC4の質問にまとめます。

## SE00-C3 期待結果・実際の結果・未確認を分ける

次はOS設定を変更しない、ファイル1枚の小さな演習です。C1を済ませたUbuntuのBashで実行します。`mktemp`は他のファイルとぶつからない新規の一時フォルダを作ります。

```bash
SE00_WORK="$(mktemp -d /tmp/se00-record.XXXXXX)"
printf 'server engineer practice\n' > "$SE00_WORK/note.txt"
cat "$SE00_WORK/note.txt"
cat "$SE00_WORK/missing.txt"
printf '直前の終了コード=%s\n' "$?"
```

1. 実行前に、1回目の`cat`は本文を返し、2回目は存在しないファイルのエラーになる、と書きます。
2. 実行後に、出力をそのまま保存します。エラーメッセージの文言はOSの言語で変わるので、教材の日本語を実出力として転記しません。
3. 2回目の`cat`が非ゼロ終了し、存在しないパスを指摘したことを確認します。これは「想定した失敗を観測した」という演習上の成功です。
4. 同じ場所で実在する`note.txt`を読めることを再確認し、障害の範囲がファイルの存在であると説明します。

| 項目 | この演習での記入例 |
| --- | --- |
| 期待結果 | missing.txtは存在しないのでcatが非ゼロ終了する |
| 実際の結果 | 自分が得たエラー全文と終了コードを貼る |
| 判定根拠 | パスの不存在が示され、既存ファイルは読める |
| 未確認 | 別ユーザーの権限、別OS、ネットワークは調べていない |

終了コードは**直前のコマンド**についての値です。間に`echo`などを挟んでから`$?`を読むと、別のコマンドを判定してしまいます。`PASS`は「画面がそれらしく見える」ではなく、決めた期待値との比較で書きます。

演習フォルダは残したままで構いません。結果を個人用記録へ保存した後、`printf '%s\n' "$SE00_WORK"`で対象を確認し、その1フォルダだけをファイル管理画面から片付けます。再帰削除コマンドを覚えることはこの課題の目的ではありません。

## SE00-C4 秘密情報を除いた質問と翌日の再説明を行う

質問は、他の人が同じ現象を確認するための小さな手順書です。実際のつまずきが無ければ、C3の意図したエラーを「質問練習」と明示して使えます。実際には起きなかった事故を体験談にしません。

```text
能力ID / 対象教材 / 手順番号:
対象環境と実行場所:
教材のGit SHA:
期待した結果:
実際のコマンド・出力・終了コード:
事実から考えた仮説:
すでに試した確認と結果:
最後に正常だった状態 / 戻し方:
秘密情報を伏せた箇所:
質問したい一点:
```

公開前に、秘密鍵、パスワード、トークン、Cookie、個人情報が入っていないか見ます。IPを伏せる場合も「管理PC」「VM-A」「同一サブネット」などの関係は残します。全てを同じ伏せ字にして通信経路を失わないようにします。この練習の提出先は個人台帳と評価者であり、公開Issueへの投稿は必須ではありません。

翌日、昨日のコマンドを最初は見ずに「どこで操作し、何を期待し、何を見て判断したか」を90秒で説明します。途中で資料やAIを使ったら、その範囲を支援欄に記録します。説明後に原本と照合し、間違えた箇所を直します。

## 提出と振り返り

- [ ] C1の対象表と実出力がある。
- [ ] C2のVM設定・接続図・再作成手順がある。VM以外の練習をVM実績へ置き換えていない。
- [ ] C3は期待値・実出力・終了コード・未確認を分けている。
- [ ] C4は公開用の質問と翌日の説明日時がある。
- [ ] 実行者、UTC時刻、セッション、教材版、支援量を[台帳の使い方](../tracker-guide.md)に従って登録する。
- [ ] 自分以外の人による確認が未実施なら、段階の評価済みPASSとしない。

| 説明問題 | 解答の観点 | 補習先 |
| --- | --- | --- |
| 自分のPCとVMで`127.0.0.1`は同じ相手か | それぞれ自分自身を指す。どのOSから接続するかで宛先が変わる | 本文の「3つの場所」を図に描き直す |
| 想定したエラーが出たのに合格にできるのはなぜか | 失敗条件を正しく観測する試験だから。コマンドの失敗と試験の失敗を区別する | C3を別ファイル名で再実施 |
| スナップショットがあれば別DB復元の試験は不要か | 保存対象と復元目的が異なる。スナップショットだけではDB復元を示さない | [既存の学習環境](../../learning-plan/01-environment.md) |
| 誰かのPASSログを自分の台帳に入れてよいか | 参考例にはできるが、自分が実行した証拠にはならない | [評価手順](../assessment.md) |

4条件の証跡が揃ったら評価へ進み、次に[SE01](01-linux.md)を実施します。分からない単語は[やさしい用語ガイド](../../beginner-guide.md)で調べ、一度に全部を覚えず、自分が使った言葉から説明できるようにします。
