# 学習の運営と教材の保守

[育成システムへ戻る](README.md)

**学習者の実施、評価者の観察、教材の検査をそれぞれ記録します。** 未実施を消して見かけの進捗を良くする運用はしません。

## GitHub上での使い方

公開教材の変更はブランチとPull Requestで管理します。課題や教材の不具合にはリポジトリのIssueフォームを使えます。Issueの作成は任意で、台帳ツールが勝手に投稿することはありません。

個人の試行と生ログは `.local/server-engineer/` に保存します。GitHubへ公開する場合は、自分で匿名化した要約だけを別途確認して投稿します。トークン、SSH秘密鍵、パスワード、Cookie、接続先の機密値を含むファイルは添付しません。`.gitignore` は暗号化や漏えい検査ではないため、共有前の確認は必要です。

使うIssueフォームは「学習の提出」「評価・再提出」「教材の不具合」の3種類です。公開したIssueは個人台帳の代わりではなく、相談やレビューの入口です。

## 毎回・毎週・毎月

| 頻度 | 担当 | 実施すること | 記録 |
| --- | --- | --- | --- |
| 演習前 | 学習者 | 対象、版、期待結果、戻し方を確認 | 作業記録 |
| 演習後 | 学習者 | 結果・出力・支援量を追記 | 個人台帳 |
| 週1回 | 学習者 | 未合格条件を一つ選び補習、復習日を確認 | 週次レビュー |
| 段階の提出時 | 評価者 | 実技・説明・証跡を確認 | 評価記録 |
| 月1回・依存先変更時 | 教材保守者 | リンク、能力ID、CLIテスト、OSや依存手順の変更を確認 | 保守記録 |
| 導入時・大幅改訂時 | 教材保守者と協力者 | 初心者による通し利用と採点者間の比較 | 利用テスト記録 |

この表は運用手順です。定期ジョブや通知の登録はしていません。GitHub ActionsではPR・main更新時に教材の整合とツールのテストを実行します。

## 保守の検査コマンド

リポジトリ直下のターミナルで実行します。Node.js 22が前提です。

```text
node scripts/server-engineer.mjs check
node --test tests/server-engineer.test.mjs
node scripts/check-engineer-links.mjs
git diff --check
```

それぞれ終了コード0を確認します。Markdownの書式・Mermaid・リンクは既存の `docs-check`、台帳は追加の `server-engineer-check` が検査します。Actionsが成功しても、VMを構築・再起動・復元した証拠にはなりません。

## 更新時に残す情報

```text
変更日:
対象ページ・能力ID:
変更理由:
元の教材版:
新しい教材版:
静的検査の日時・コマンド・結果:
実機確認の日時・対象・結果: NOT RUN
初心者の通し利用: NOT RUN
評価者間の比較: NOT RUN
既存の提出への影響:
元の確認期限:
超過日数・理由:
次回確認予定:
```

実機未確認の修正には、静的検査日だけを記録します。実機確認日を更新しません。期限を変えるときは元の期限・超過期間・理由を残します。

## 版と既存台帳の扱い

能力条件を変えたら `curriculum.json` のversionを更新し、既存提出のどの条件に影響するかを書きます。台帳と教材の版が違う場合、以前の合格を新しい条件へ自動移行しません。元の台帳を保管し、新版で別の学習者ID（例: `learner-v2`）の台帳を初期化して、根拠を確認しながら再提出します。

誤った試行は履歴を削除せず、新しい試行のnoteに訂正理由を残します。更新した証跡は別の試行へ添付します。評価は最新試行に結び付いているため、再実施後は再評価します。

## バックアップと復帰

学習後に個人台帳ディレクトリ全体を、自分が管理できる非公開のバックアップ先へコピーします。保存先のアクセス権・暗号化は利用環境に合わせて管理します。バックアップ対象にはprogress.jsonとevidenceフォルダの両方が必要です。

復帰の確認は、別の一時チェックアウトへコピーして `check --learner <ID>` を実行し、証跡のハッシュと最新試行・評価が対応するかを確認します。元データを上書きする前に内容を比較してください。コピーしたことだけで復元確認済みにしません。
