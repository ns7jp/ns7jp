## 最初の30分

1. [設計の「現在地を決める」](design.md#現在地を決める)を読み、説明できる項目と、実行証拠がある項目を別々に記録する。
2. 既存の[SE00 準備と学び方](../stages/00-orientation.md)で、操作するPC・VM・シェル・フォルダを特定する。
3. [計画](action-plan.md)の「最初の2週間」から未確認の課題を一つだけ選ぶ。手元環境の準備状況は本設計では未確認。
4. 実施前の予想と、実施後の出力を[記録](templates.md)に記録する。まだ行っていない試験は `NOT RUN` のままにする。

Linuxを主軸とし、Windows・ADは既存の実測記録を使って理解と再現を確認する専門分岐にします。クラウドや新しい製品を一度に追加せず、一つの案件を最後まで説明・確認できることを優先します。

## 設計の読み方

- `SE00〜SE07`：既存の育成体系。8段階・32条件。基本課程の合否は既存台帳を使う。
- `BR0〜BR6`：今回提案した能力の見取り図。既存SEと同じ番号の段階を意味しない。
- `BX01〜BX12`：今回提案した中級以降の追加課題。既存CLIには未実装。
- `PJ00〜PJ07`：既存の案件運営体系。技能の評価と案件の承認・検収を分けて扱う。
- `Level 0〜6`：主作品serverを学ぶための既存の順序。BRやSEの合格へ自動変換しない。
