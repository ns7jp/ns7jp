# 実装と教材の共通契約

能力ID・順序・証跡要件の正本は [curriculum.json](curriculum.json) です。SE00〜SE07の8段階、各4条件を定義します。既存学習計画のG番号とは別のIDです。

- 教材は `stages/00-orientation.md` から `stages/07-capstone.md`。各能力IDを見出しまたは表に必ず記載し、目的、前提、実施手順、期待結果、失敗・戻し方、提出物、説明問題、補習先を付けます。
- 個人台帳は既定で `.local/server-engineer/<learner>/progress.json`。公開用教材と分離し、初期値は全て未実施。外部通信や実機操作は台帳ツールから行いません。
- 環境 `any` は机上・ローカル・VM等、`runtime` はコンテナ・VM・物理・クラウドでの実行、`vm` はVM・物理・クラウドOSの実行を要求。コンテナだけでVM条件を満たしたことにはしません。
- 支援量は `guided`（手順・助言あり）、`ai`（AIの操作指示あり）、`independent`（本人が判断。公式資料と自作手順書は参照可）。`independent` 必須条件には他の支援量を充当しません。
- 条件ごとの実施結果は `PASS / FAIL / BLOCKED`。未記録は `NOT RUN`。再実施は追記し、判定には最新の試行を用います。失敗・欠測を削除して合格にしません。
- 実施時刻、学習者、対象環境、教材のGit SHA、セッション、説明、証跡ファイルのSHA-256を記録します。ツールは既存の出力を添付し、その内容の真実性を証明するものではありません。
- 全条件を満たす段階は `READY FOR REVIEW`。本人以外の評価者が実際に観察した評価記録を添付して初めて `PASS`。署名認証システムではなく、入力された評価記録に基づく判定です。先行段階がPASSでなければ後続は `WAITING PREREQUISITE`。
- 評価はその時点の試行ID集合に結び付けます。再実施後は古い承認を使い回さず再評価します。SE07-C1/C2は異なるUTC日付・セッションが必要です。
- 人による評価と実機実行は本人・評価者の実施待ちです。自動テストや過去の著者証跡で初期台帳を埋めません。

詳細な操作は [台帳の使い方](tracker-guide.md)、人による判定は [評価手順](assessment.md) を参照します。
