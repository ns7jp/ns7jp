# 合格・再提出・再試験の決め方

[育成システムへ戻る](README.md)

**合格は「動いた」だけではなく、対象・出力・本人の判断・戻し方を確認した状態**です。点数の平均で重要な失敗を隠さず、各段階の4条件をすべて確認します。能力定義の正本は [curriculum.json](curriculum.json) です。

## 4種類の結果を混ぜない

| 記録 | 意味 | 証明しないこと |
| --- | --- | --- |
| 教材・コードの静的検査成功 | ファイルや台帳処理の検査に通った | 実機で動くこと、本人ができること |
| 条件ごとのPASS | 本人の申告と添付出力がその試験の合格条件を満たす | 第三者の確認、別環境の合格 |
| READY FOR REVIEW | その段階の提出物がそろった | 人の観察が終わったこと |
| 段階のPASS | 前提段階を満たし、最新提出に対する本人以外の評価記録がある | 資格認定、本番作業権限、雇用上の経験 |

ツールは氏名の真正性や添付ファイルの事実性を認証しません。評価者名の入力だけで技能を保証するものではなく、実際に観察した結果を保存する台帳です。人が内容を確かめます。

## 評価する人と役割

学習者は操作・予想・判断・分からないことを記録します。評価者はLinux構築と障害対応の確認ができる人を選び、評価する範囲と観察方法を先に合意します。講師、実務経験のある同僚、学習会の協力者などが候補です。氏名は公開しなくてよく、ローカルでは識別できるIDを使えます。

評価者が不在なら、自分でチェックし、不足箇所を直すところまで進められます。最終評価は保留します。AIによる説明補助・コードレビューは利用できますが、人の実技観察の代わりにはしません。

## 1回のレビューを進める手順

1. 学習者が4条件の最新試行ID、Git SHA、対象、出力、手順書を渡す。生ログは公開せず、合意した非公開経路を使う。
2. 評価者が本人と日時を合わせ、画面共有または対面で対象と操作を確認する。過去ログだけの確認は「書類レビュー」と記録し、実技観察済みにしない。
3. 4条件ごとに「なぜこの操作か」「何が出たら失敗か」「どこまで戻すか」を質問する。
4. 正常系だけでなく、権限拒否・接続拒否などの異常系と、戻した後の再試験を確認する。
5. 支援量を記録する。評価者が原因やコマンドを教えたら、独力条件は再提出とする。
6. [評価記録](templates/review.md)に各条件の判断と根拠を記入し、承認または再提出を決める。
7. 承認後に記録コマンドで評価を添付する。新しい試行を追加した場合は前の承認を流用せず、差分を再確認する。

## 観察可能な判定基準

| 観点 | 合格の観察例 | 再提出になる例 |
| --- | --- | --- |
| 対象 | VM名・OS・Git SHAと操作画面が一致する | 別ホストのログを混ぜた |
| 再現 | 前提から順に実施し、期待した出力を示す | 手順途中の手修正を説明できない |
| 判定 | 出力と合格条件を比較し、失敗も残す | コマンドが終わっただけでPASS |
| 説明 | 設定値を選んだ理由と代替案を話せる | 生成された説明を読むだけ |
| 安全 | 作業対象・影響・中止条件・復旧経路を確認する | 接続を失う操作を復旧経路なしで続ける |
| 引き渡し | 別の人が手順を追い結果を残す | 本人が横から全操作を指示する |

次は必ず再提出です。対象外への操作、秘密値の公開、本人以外の結果の流用、必須試験の省略、失敗を消した報告、独力課題中の答えの提供。問題があれば作業を止め、影響と復旧を先に確認します。

## 支援量と「独力」の定義

- `guided`: 手順例・講師の助言を使って実施。SE00〜基礎課題では通常の学び方。
- `ai`: AIに操作コマンドや原因の答えを出してもらった。内容を説明できても、その回は独力評価には使わない。
- `independent`: 公式資料、自分の手順書、manやhelpは参照できる。原因の答えや操作手順を他者・AIから得ず、自分で選んで実行する。

練習では何度でも支援を使い、別の試行として独力確認を行えます。「完全な暗記」は要求しません。何を調べるべきかを自分で判断できることを確かめます。

## 総合演習の採点

SE07-C1とC2は別日・別セッション・新規VMで行います。台帳はUTC日付を比較するため、日本時間だけで日付をまたいでもUTCで同日なら別日条件を満たしません。日を空け、実際の実施日時を記録してください。日時を評価条件に合わせて書き換えてはいけません。

C1では、作業前に承認した要件と試験をすべて満たすこと。C2では、接続元の制限、配置先、ホスト名などの条件を一つ変更し、影響箇所と回帰試験を説明すること。C3は評価者が本人に答えを教えずに選んだ障害を扱います。C4は受領者が本人の逐次指示なしに状態確認・計画停止・再開・異常連絡を実施します。

所要時間を記録しますが、速さだけでは採点しません。時間上限は演習前に合意し、超えたら理由と残作業を記録します。時間内でも復旧確認を省けば不合格です。

## 再提出と評価のばらつき

不合格の条件だけを補習します。ただし変更の影響が他の条件へ及ぶ場合は、その試験も再実施します。古いFAILは履歴として残し、新しい出力で再提出します。1週間後の再説明で分からなくなった場合も、復習記録を追加します。

導入初回は、初心者2名を目安にSE00〜SE01を通して利用してもらい、所要時間、止まった箇所、危険に感じた表現を記録します。さらに同じ提出物を評価者2名が独立に採点し、判断が異なった項目の基準を直します。人数は運用上の目安で、教材の統計的な有効性を証明するものではありません。現時点ではどちらも未実施です。
