## 要件・設計・試験の対応

| 要件 | 設計 | 試験 |
| --- | --- | --- |
| 自分の環境内で試す | IPv4ループバック、OS割当の空きポート | T01 |
| 正しいページを返す | 専用webフォルダーのindex.htmlを配信 | T02 |
| 存在しないページを区別する | /missingには404 | T03 |
| 変更前を保管する | 配信フォルダーの外にバックアップ | T04 |
| 変更が見えることを確認する | version 1をversion 2に更新 | T05 |
| 元の内容へ戻す | バックアップを復元、HTTP本文とSHA-256を照合 | T06、T07 |
| 作業を終えて片付ける | スレッド停止、ソケット終了、一時フォルダー削除 | T08〜T10 |

Python標準ライブラリだけを利用し、追加パッケージ、sudo、既存サービスの変更を必要としない。
HTTPの出口には環境のプロキシ設定を使わず、ループバックへ直接接続する。
ログはホスト名、利用者名、一時フォルダーの実パスを出力しない。
強制終了・OS停止時の清掃は保証しないため、異常終了時は自身の演習プロセスと一時領域を確認する。

## 再実行する

Ubuntuのリポジトリルートで実行する。Python 3.12で実測した。

```bash
python3 --version
mkdir -p .local/project-incoming/training-linux-web-01
python3 scripts/rehearse-linux-web.py \
  > .local/project-incoming/training-linux-web-01/result.json
echo $?
cat .local/project-incoming/training-linux-web-01/result.json
```

期待結果は終了コード0、総合 `PASS`、T01〜T10の10件がすべて `PASS`。
失敗時は終了コード1と `FAIL` を保持し、成功記録に書き換えない。
再試行する場合は前の結果ファイルを別名で保管してから実行する。
実行スクリプトのSHA-256も結果に含むため、記録した版と現在のファイルを照合できる。

覚える順番は **起動 → 応答 → 保管 → 変更 → 復元 → 停止**。
初心者はスクリプト内の `T02`、`T05`、`T06` を探し、期待本文がどう変わるかを読む。
HTTP 200だけでは変更や復元の成否を決めず、本文とハッシュも確認する。

## つまずいたとき

| 現象 | 確認すること | 次の行動 |
| --- | --- | --- |
| WSLにアクセスできない | 実行端末のWSL利用権限 | 許可されたUbuntu端末で再実行。VM構築成功としない |
| Pythonがない | python3 --version | 環境担当へ確認。試験はNOT RUNのまま |
| T02/T05/T06がFAIL | statusと本文のexpected/actual | 読んだファイルと更新・復元の順を確認 |
| T07がFAIL | 元データと復元後のSHA-256 | バックアップと対象を確認し、後工程を止める |
| T08〜T10がFAIL | 停止・清掃結果 | 自分の演習プロセスだけを確認。他サービスを終了しない |
