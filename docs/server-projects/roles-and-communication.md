# 役割・判断・報告を決める

[案件運用の入口](README.md)

担当者とは「手を動かす人」だけではありません。成果をまとめる主担当、技術を確認する人、対象システムの変更を認める人、受け取る人を決めます。少人数で役割を兼ねても、どの立場で何を確認したかを記録します。

## 最初に名前と代理を埋める

| 役割 | 主な責任 | 決めておく事項 |
| --- | --- | --- |
| 主担当 owner | 計画・成果物・進捗・問題をまとめる | 担当可能な範囲、代理、連絡先 |
| 案件責任者 sponsor | 範囲・優先順位・期限・終結の判断 | 予算や条件を誰が決めるか、判断期限 |
| 技術確認者 technical | 設計・試験・運用の妥当性を確認 | 対象製品の確認能力、確認範囲 |
| 変更責任者 change | 対象システムの変更窓・リスク・中止を判断 | 本番承認経路、緊急時の代理 |
| 受領者 customer | 合意した受入条件を確認して受領する | 検収の担当者、正式な記録方法 |
| 運用受領者 operations | 運用操作と対応範囲を引き受ける | 当番・保守時間帯、未解決事項の担当 |

権限がない人を役職名だけで承認者にしません。権限の確認方法と根拠を案件の許可された原本へ残します。CLIの役割名とIDは記録欄で、本人認証や代理権確認をしません。案件主担当が自分を確認者にして工程を承認する操作は拒否します。

## 各場面で誰が判断するか

| 場面 | 主担当が準備するもの | 判断する人 | 次へ渡すもの |
| --- | --- | --- | --- |
| 担当範囲外の依頼 | 不足能力、依存、対応案 | 案件責任者 | 担当・支援・調査・辞退の記録 |
| 見積と納期 | 作業分解、幅、前提、対象外 | 案件責任者と依頼側の決定者 | 合意版と未決事項 |
| 設計レビュー | 要件対応、比較、試験、戻し | 技術確認者 | 指摘と解消の記録 |
| 本番着手 | 対象版、試験、作業窓、影響、戻し | 変更責任者 | 有効な作業承認 |
| 作業中の異常 | 事実、影響、残時間、復旧案 | 決めた変更・障害責任者 | 中止・戻し・継続の判断 |
| 受入条件の不一致 | 合意条件と実結果の差 | 受領者と案件責任者 | 修正か追加変更かの整理 |
| 初期保守の終了 | 観測、実操作、残事項 | 運用受領者 | 対応範囲と残課題の受領 |

## 報告の型

報告は、読む相手が次の判断をできる順番で書きます。

1. **結論**: 予定内、遅延のおそれ、停止、判断待ちのどれか。
2. **対象と影響**: 案件、サービス、利用者、時間帯。
3. **事実**: 実施した作業、測った値、試験結果、まだ未確認のこと。
4. **差分**: 計画との差、元の期限、追加の作業量。
5. **選択肢と推奨**: それぞれの影響と戻し方。
6. **依頼**: 誰に何をいつまでに決めてほしいか。次回の更新予定。

架空の報告例: 『DEMO-Aは検証環境のDNS回答待ちのためPJ03へ進めません。申請票は作成済み、名前解決試験はNOT RUNです。9月8日10時に回答がなければ変更窓の再調整が必要です。責任者には、代替の検証方法を採るか、変更窓を移すかの判断をお願いします。』日付・申請・連絡の実績は例であり、自分の記録へ置き換えます。

## 会議を成果物につなぐ

レビュー前に、対象版、見てほしい点、未決事項、判断期限を共有します。会議では決定・保留・却下と、担当・期限を記録します。『確認した』だけでなく、何がどの範囲で確認されたかを残します。

回答がないことを承認と扱いません。会議後に合意事項の確認が必要なら、組織の方法で実際に確認します。確認者の名前を推測して入力しません。公開用の架空演習でも、相手の実在しない承認を作る代わりに `READY FOR REVIEW` を保ちます。

## エスカレーションの条件

作業対象が不明、権限不足、受入条件未合意、本番への予期しない影響、データ保護の不備、戻し期限が迫る、担当容量を超える、確認者不在の場合は、主担当の判断範囲を超えています。

報告のために調査を無制限に続けず、分かる事実と分からない点を分けて渡します。責任者が不在なら事前に決めた代理へ連絡し、代理も不明なら本番変更を始めません。

## 情報の置き場所

秘密値は秘密管理の仕組みへ、業務証跡は許可された案件原本へ、公開教材は独立した架空例へ置きます。顧客原本の匿名化だけで公開可能だとは判断しません。公開許可と公開内容の確認が必要なときは組織の手順で扱います。

この仕組みはメッセージを自動送信しません。送信前の文章や会議の議題を作成しても、送った事実には数えません。
