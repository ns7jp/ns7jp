# PJ07 終結・振り返り

[案件の入口](../README.md) / [前工程 PJ06](06-support.md) / [日々の運営](../operations.md)

終結では、完了した範囲、残る責任、事務手続、記録の保管、アクセスの終了を照合します。そのうえで、案件責任者が終結の種類と理由を確認します。作業者が忙しくなくなったことや、予定日が過ぎたことを終結の根拠にはしません。

DEMO-A「研修用監視VM1台の構築・引渡し」は架空の演習例です。実績、受領、請求、入金、アクセス終了はすべて未確認・未実施から始めます。この工程は法務・会計上の判断を提供せず、契約や組織の担当者が確認した条件と状態を記録します。

## 1. 最初に終結の種類を分ける

| 種類 | 意味 | 保存するもの |
| --- | --- | --- |
| 成功としての終結 | 合意した完了条件と必要な受領・移管が成立 | 完了範囲、証跡、責任者の確認 |
| 保留 | 再開の条件や時期を待っている | 理由、未完了、資源・責任の維持、再確認日 |
| 取消による終了 | 依頼を継続しない判断があった | 取消理由、決定者、残る義務・資源・費用確認 |
| 一部完了後の範囲変更 | 元の合意から範囲が正式に変わった | 元範囲、変更合意、除外と移管、改版後の条件 |

このPJ07を成功経路で通る前提は、有効なPJ06のPASSです。取消・保留の案件に対して、PJ00〜PJ06の未実施を埋めて成功経路を作りません。[日々の運営](../operations.md)の該当経路で理由と責任を記録し、必要な保全・移管・事務だけを実施します。

台帳の案件状態と工程の判定は別です。通常の全工程PASSによる`COMPLETED`と、取消による`CANCELLED`を区別します。実際の操作は[ツール操作](../tracker-guide.md)を正本にします。

### 保留・取消時の台帳の扱い

保留中は、条件記録・レビュー・作業項目の変更を台帳に追加できません。使えるのは再開、取消、期限の再設定です。安全確保や連絡など必要な事実は原本へ保全し、台帳へ取り込む作業は正式な再開後に行います。再開操作が本番の実行許可を発行するわけではなく、既存の承認条件と対象版を別に確認します。

`cancel`は終端操作で、取消後の台帳には追記できません。取消対応の実作業、残作業の移管、資源・アクセスの扱い、証跡の保管、未請求等の確認事項を先に原本へ記録し、必要な記録をそろえてから最終取消を登録します。既に取消した後で処置が必要になった場合は、元の原本または新IDの後処理案件で管理し、元案件IDへ関連付けます。取消案件を成功終結へ変更して後処理を記録しません。

## 2. 入力と役割

| 入力 | 照合する内容 |
| --- | --- |
| PJ01の合意と変更履歴 | 元の範囲、正式に変更した範囲、受入・費用・期日の前提 |
| PJ04の作業結果 | 最終対象版、実績、必須試験、障害と戻し |
| PJ05の検収・引き渡し | 受領者、対象、日時、条件、未回答 |
| PJ06の保守・移管 | 実観測、欠測、期間、運用受領、残課題 |
| WBSと課題台帳 | 見積、実績、依存、未完了、移管先、期限 |
| 契約・事務担当の確認 | 請求・支払・保管等の条件と実際の確認状態 |
| アクセスと資源一覧 | 一時権限、サービス権限、復旧経路、保管先、継続資源 |

案件主担当が照合票を作り、技術確認者・運用受領者・契約や事務の担当者が自分の範囲を確認します。案件責任者`sponsor`が案件全体の終結を確認します。主担当と異なる確認者の記録が必要で、本人のIDを別名にした自己承認は使いません。

[終結・振り返り票](../templates/closure.md)を案件の非公開記録先に複製します。受領や入金を証明する原記録がある場合は、許可された場所への参照と担当者の確認を残し、顧客文書を公開教材へ複製しません。

## 3. PJ07-C1 完了範囲・未完了の移管と契約上の事務を照合

**目的：** 終了した仕事と、引き続き誰かが持つ仕事を区別します。

### 完了範囲の確認

1. PJ01の元要件と正式な変更合意から最終対象範囲を作る。採否待ちの提案を採用済みと扱わない。
2. 要件ごとに、最終成果、対象hostname・VM識別・SHA、受入結果、運用移管先を結び付ける。
3. 失敗・未実施・条件付き受領・未回答を抽出する。必須の未達がある場合は成功終結へ進めない。
4. 成功した変更と、切戻した変更、取消した変更を分ける。旧版へ戻せたことを新しい要件の達成にしない。
5. 最終構成と引き渡し資料の一致を確認する。移管後に修正した場合は、必要な再受入と運用担当の再確認を行う。

### 未完了の移管

未完了項目ごとに、内容、影響、回避策、終了条件、移管先、担当者、期限、記録先、受領日時をそろえます。別案件へ回す場合は、その案件IDと窓口が実在し、受け入れられたことを確認します。「別途対応」と書くだけでは責任は移りません。

必須の未達を単に残課題へ移して、元の合意を達成したことにはできません。対象外への変更が必要なら、元の範囲と未達を保存し、権限を持つ人による変更合意と必要な再評価を行います。

CLIでは、合意した範囲縮小により不要となった未完作業を `task-withdraw` でWITHDRAWNへ変更できます。別の確認者によるsponsor判断と証跡が必要で、当該工程以降の条件は新たに確認します。取り下げた作業はDONEの実績に数えません。非WITHDRAWNの依存先が残る場合や、すでにDONEの作業の取り下げは拒否されます。必要な後処理を新しい作業・案件へ整理し、受領まで確認します。

| 移管項目 | 必要な根拠 | 不足したとき |
| --- | --- | --- |
| 継続する運用 | 受領した担当、開始日時、対応範囲 | PJ06へ戻す |
| 既知の非必須残課題 | 影響と合意、担当、期限、受領 | 未移管のまま責任者へ |
| 追加要望 | 元範囲外である根拠、採否、次案件の受付 | 元案件の完了に混ぜない |
| 保管・更新 | 保管責任者、保存場所、見直し時期 | 削除・権限終了を進めない |

### 契約上の事務の確認

1. 契約・発注・変更合意にある完了と検収の条件を、確認権限のある担当者へ照会する。
2. 請求の対象、金額、発行条件、送付先、担当、期限の確認状態を記録する。金額の初期欄は未記入にする。
3. 支払条件、支払期限、確認担当、入金の確認状態を記録する。請求書があることを入金済みと扱わない。
4. 未請求・未入金がある場合、案件の技術上の終結と事務上の未完了を別に表示する。終結が許される条件は契約・案件責任者が判断し、担当・期限と根拠を残す。
5. 保証、問い合わせ、保管、返却等、終結後も続く事項は担当へ移管する。期間や義務を教材の既定値から決めない。

**期待結果：** 完了・未完了・移管・事務の状態がそれぞれ根拠付きで説明できます。未回答や未入金を確認済みにしていません。

**中止・戻り先：** 検収の根拠なし、必須未達、未受領の移管、事務条件不明なら成功終結を止め、該当工程・担当者へ戻します。

**提出物：** 最終範囲表、受領との対応、未完了移管、契約・事務担当の確認状態、残る担当と期限。

## 4. PJ07-C2 実績工数・差異・改善と再利用物を整理

**目的：** 次の案件で見積・手順・試験の精度を上げられる記録に変えます。

### 見積と実績の比較

1. PJ01で作った元のWBSと見積幅を保存し、実施中に変更した見積も並べる。元見積を実績へ上書きしない。
2. WBSごとに実作業、レビュー、待機、手戻り、追加変更を分け、集計対象と単位を確認する。
3. 実測していない時間を抽出する。未測定を0時間にせず、合計に含めた範囲と含められない範囲を記載する。
4. 実績が元の見積幅内か、上限を越えたかを確認する。比較に使った式と対象を残す。
5. 差異の大きい項目を選び、環境差、前提の見落とし、外部待ち、追加範囲、再試験など事実に分解する。

| DEMO-Aの架空の比較欄 | 元見積 | 最新見積 | 実績 | 差異・理由 |
| --- | --- | --- | --- | --- |
| DEMO-A-WBS-001 直前確認 | NOT SET | NOT SET | NOT RUN | 未確認 |
| 構築と事後試験 | NOT SET | NOT SET | NOT RUN | 未確認 |
| 受入・教育・資料修正 | NOT SET | NOT SET | NOT RUN | 未確認 |
| 初期保守・運用移管 | NOT SET | NOT SET | NOT RUN | 未確認 |
| 障害・手戻り・追加変更 | NOT SET | NOT SET | NOT RUN | 未確認 |

例えば上限超過は「同じ範囲の実績時間－元見積上限」で比較できますが、追加範囲を混ぜたまま見積の誤りとは断定しません。金額への換算や請求可否は、合意した計算方法を担当者が確認するまで判断しません。

### 振り返りと再発防止

1. うまくいった点と問題を、根拠のある出来事として記録する。個人の性格や努力不足を推測しない。
2. 問題について「起きたこと」「影響」「直接原因」「条件・仕組みの不足」「早く気付けた場所」を分ける。
3. 再発防止を、手順変更、入力検証、事前試験、レビュー対象、監視、担当境界のいずれかへ落とす。
4. 各改善に担当、期限、適用先、確認試験、完了を確認する人を付ける。提案段階なら採否待ちとして残す。
5. 次回案件で何を変えるかを一つずつ決め、見積の前提、テンプレート、試験項目に反映する。承認前に他者の仕事や予定を変更しない。

| 架空の問題例 | 改善候補 | 確認方法 |
| --- | --- | --- |
| 対象SHA確認が手順の後半にあった | 直前照合の開始条件へ移す | 異なる版を指定した演習で開始を止められるか |
| 引き渡し資料の実行場所が不明だった | 手順行ごとに管理端末・対象を記載 | 別の人が補足なしで対象を選べるか |
| 観測器停止を正常と見ていた | 欠測条件と採録先の確認を追加 | 模擬欠測を0件の正常として記録しないか |

### 再利用物の選別

顧客資料やログをそのまま教材へ持ち出しません。契約と組織の許可範囲を担当者へ確認し、再利用できる一般化した知識だけを別に作ります。氏名やIPを伏せるだけで、構成・課題・取引情報の公開が許可されたとは扱いません。

一般化した手順、原因調査の考え方、検査項目を再利用候補として残し、採否・技術確認・公開可否を別々に記録します。構文検査に通っただけの改善を、実運用で効果確認済みとは書きません。

**期待結果：** 工数差の根拠があり、改善が担当・期限・確認方法へつながっています。顧客情報の公開を伴わずに知識を還元できます。

**提出物：** WBS比較、未測定範囲、振り返り、改善台帳、再利用候補と許可・採否の状態。

## 5. PJ07-C3 保管・アクセス終了と案件終結を責任者が確認

**目的：** 必要な記録と運用経路を維持し、案件のためだけに残った権限を適切に終了します。

1. 保存する成果、受領、承認、試験、生ログ、契約・事務参照、課題移管を分類する。
2. 保存場所、閲覧者、保管責任者、保存期間の根拠、見直し日、返却・削除の担当を確認する。期間は契約・組織の担当者が確認した値を使い、教材で一律に設定しない。
3. 正本と参照先が開けるか、権限が移管先で機能するかを確認する。必要なバックアップと更新経路が残っていることを確かめる。
4. 一時アカウント、SSH鍵、VPN、クラウド権限、CI権限、共有リンク、通知先など案件固有のアクセスを一覧にする。値や秘密は書かず識別情報と管理者を記録する。
5. 継続が必要なサービス権限、運用担当の権限、復旧経路と、一時作業権限を分ける。運用移管と必要なアクセスの実操作確認が終わる前に権限を外さない。
6. 承認された終了対象だけを、各管理者が指定した日時と方法で終了する。共有アカウントやサービス鍵を一括削除しない。変更が運用へ影響する場合は通常の変更手続へ回す。
7. 終了した一時権限の拒否と、残す運用権限の成功を確認する。ログ保存先やバックアップジョブが使う資格情報を誤って止めていないか確認する。
8. 案件責任者が完了範囲、未完了移管、事務の状態、改善、保存、アクセス終了を確認し、終結の種類・日時・根拠を記録する。

**期待結果：** 保存先が受け手に使え、不要な権限だけが終了し、継続する責任と資源が明示されています。責任者の確認が最新の証跡に結び付いています。

**中止・戻し：** 移管先がアクセスできない、権限の用途が不明、保存義務や保管期間が未確認なら削除・失効を進めません。誤ったアクセス終了が起きた場合は管理者へ連絡し、承認された復旧経路で運用を戻して記録します。

**提出物：** 保存・参照確認、アクセス終了一覧、残す権限の正常性、終結判断、終結後の窓口と責任。

## 6. 終結前の最後の確認

- [ ] 成功、保留、取消のどの経路かが明確である。
- [ ] 必須未達や未受領の移管を成功完了へ隠していない。
- [ ] 請求・支払・保管の状態は担当確認の根拠があり、未確認を保存している。
- [ ] 工数差、手戻り、待機、未測定が区別されている。
- [ ] 改善と再利用候補に担当・期限・採否・確認方法がある。
- [ ] 必要な運用アクセスを確認した後に、一時権限だけを終了している。
- [ ] 案件責任者`sponsor`が実際の証跡を確認した記録がある。

終結後に問題が見つかったら、元の終結結果を黙って上書きせず、問い合わせ・変更・再開のどの経路で扱うかを合意します。元案件IDと関連付け、担当範囲と責任を追える状態にします。
