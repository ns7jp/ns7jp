# 案件で使う様式

[案件運用の入口](../README.md)

コピー先は許可された案件原本です。演習のコピーはローカルの `.local/` 配下へ置けます。IDは案件ごとに発行し、他案件と混ざらないよう『案件ID＋書類ID』で識別します。空欄やNOT SETを成功と読み替えません。

| 様式 | 作る時点 | 使い終わる条件 |
| --- | --- | --- |
| [受付票](intake.md) | 依頼受領 | 目的・窓口・担当可否・次の期限が明確 |
| [要件と見積](scope-estimate.md) | 調査後 | 前提・範囲・受入条件・工数幅の合意 |
| [要件対応表](requirements-trace.md) | 要件を設計へ移すとき | REQ・DES・TEST・EVIDが対応 |
| [実行計画](execution-plan.md) | 設計・検証 | 対象版、作業窓、手順・中止・戻しが確定 |
| [作業結果](work-result.md) | 実行前に準備 | 時系列・実績・試験・差異を記入 |
| [検収と引き渡し](acceptance-handover.md) | 受入前に準備 | 受領者と条件・操作・残事項を確認 |
| [保守台帳](support-register.md) | 保守開始前 | 期間・欠測・問い合わせ・移管を記録 |
| [終結票](closure.md) | 終結前 | 未完了の移管、実績・保管・事務を確認 |
| [変更要求](change-request.md) | 追加・変更の提案時 | 採否、実施、再試験を別々に記録 |
| [障害記録](incident.md) | 検知時 | 復旧、原因、再発防止の担当を区別 |
| [リスク・課題・判断](risk-decisions.md) | 受付から継続 | すべてに担当・期限・処置がある |
| [週次配分](portfolio-review.md) | 毎週 | 全残作業量と翌週の割当を分ける |

更新履歴は消さずに追記します。レビュー対象版が変わったら古い承認をそのまま転記せず、変更の影響範囲から確認し直します。記入例は [架空3案件](../examples/three-projects.md)を参照してください。
