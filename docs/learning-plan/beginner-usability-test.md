# 第三者再現テスト記録

このテンプレートは、初心者向け教材の分かりやすさを感想ではなく実測で確認するために使います。個人名、IPアドレス、ユーザー名などの端末固有情報は公開しません。

## このテストの進め方

このテストで探すのは**教材の欠陥**であり、受ける人の能力を測るものではありません。詰まった箇所が多いほど、教材にとって価値のある記録になります。

1. テストを受ける人は、このファイルをコピーして別名で保存し（例: `beginner-usability-test-01.md`）、コピー側へ記入します。元のファイルは空のまま残します
2. リポジトリのトップページの README を入口に[初心者向けスタートガイド](./00-start-here.md)までたどり、「1. 開始前診断」と「2. 最初の 30 分」を、**教材に書かれていること以外のヒントなしで**最後まで実行します。別のページや Phase を対象にする場合は、その範囲を「対象ページ / Phase」へ書きます
3. 1 つの手順で 30 分以上進めなくなったら、そこでいったん手を止め、「停止箇所の詳細」の表に 1 行追加してから、ヒントをもらって先へ進みます
4. 実行が終わったら「テスト情報」「結果」「停止箇所の詳細」を記入し、教材の作成者へ渡します。「教材への反映」以降は作成者が記入します

## テスト情報

```text
テストID:
実施日:
事前経験（Linux コマンドやサーバー構築の経験。未経験なら「なし」）:
利用 OS / バージョン:
PC のメモリ:
選択ルート（標準・軽量・基礎補習）:
対象ページ / Phase:
開始・終了時刻:
ヒント提供者（詰まったときに質問した相手。誰にも聞かずに終えた場合は「なし」）:
```

## 結果

「項目」は、対象ページの完了判定にあるチェックボックスを 1 つずつ数えます。標準の対象である[初心者向けスタートガイド](./00-start-here.md)の「2. 最初の 30 分」なら、末尾の完了判定が 5 項目です。ヒントをもらって達成した項目は「ヒントなしで完了した項目」に数えません。

```text
ヒントなしで完了した項目数 / 全項目数（例: 3 / 5）:
30 分以上止まった箇所:
追加で質問した内容:
危険または曖昧だと感じた手順:
終了時に自分の言葉で説明できたこと（1〜2 文で書く）:
完了できなかった項目:
```

## 停止箇所の詳細

「手順」欄は、対象ページの章番号と手順番号を `章-手順` の形で書きます。例の `2-3` は、スタートガイドの「2. 最初の 30 分」にある「手順 3：SSH サービスの状態を確認する」を指します。

| 手順 | 期待していたこと | 実際に起きたこと | 停止時間 | 必要だったヒント |
| --- | --- | --- | --- | --- |
| 例: 2-3 | SSH の状態確認 | `Unit ssh.service could not be found` | 35 分 | OpenSSH未導入の場合の分岐 |

## 教材への反映

```text
原因分類（教材の省略・環境差・前提知識・操作ミス）:
教材へ反映した修正:
修正したコミット / PR:
再テスト日:
再テスト結果:
```

## 完了条件

- [ ] 初学者2名以上の独立した記録がある
- [ ] 質問箇所、停止箇所、完了率、所要時間が記録されている
- [ ] 同じ停止箇所が2名にあれば教材を修正した
- [ ] 修正後に同じ条件で再テストした
- [ ] 個人情報と秘密情報を公開していない
