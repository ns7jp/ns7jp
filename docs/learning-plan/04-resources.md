# 04 教材と資格の対応

> **本ドキュメントの位置付け**
>
> [学習プラン](./README.md)の各フェーズで使う教材の候補と、資格試験との対応をまとめます。
> 書名・サービス名は **2026-08 時点で入手しやすいものの例**です。改訂が頻繁な分野のため、
> 購入前に**最新版かどうかと、対象バージョンが自分の環境と合っているか**を必ず確認してください。
> 資格の時期・優先順位の判断は[資格取得ロードマップ](../certifications/roadmap.md)を一次情報とします。

最終更新: 2026-08-11

## 1. 教材の選び方

| 原則 | 内容 |
| --- | --- |
| 1 分野 1 冊に絞る | 同じ分野の本を並行して読まない。詰まったときだけ別の本で補う |
| 手を動かせる本を選ぶ | 図解だけの入門書は、全体像の把握に 1 冊だけ使う |
| 発行年とバージョンを見る | Linux・クラウドは 3 年で内容が変わる。古い版は設定手順が動かない |
| 公式ドキュメントを併読する | 書籍は入口、正解は公式。バージョン差はここでしか埋まらない |
| 読み終えることを目的にしない | 通読より、**各章の内容を VM で 1 回実行する**ほうが優先 |

### 時間配分の目安

| 用途 | 週あたりの時間 |
| --- | --- |
| 書籍・動画（インプット） | 5 時間 |
| ハンズオン | 8 時間 |
| 記録・振り返り | 2 時間 |

**インプットがハンズオンを上回った週は、進め方が崩れている合図**です。翌週で調整します。

## 3. 資格との対応

### 学習フェーズと資格の重なり

| Phase | 資格 | 重なる範囲 | 位置付け |
| --- | --- | --- | --- |
| 1 | LPIC-1 101 | コマンド、ファイル管理、権限、プロセス、パッケージ、ディスク | ハンズオンで触れなかった範囲の穴埋め |
| 2 | CCNA | OSI、IP、ルーティング、スイッチング、無線、自動化 | 用語と体系の整理 |
| 2 | 基本情報技術者（テクノロジ系） | ネットワーク、セキュリティ、データベースの基礎 | 非技術系の採用担当にも通じる汎用資格 |
| 3-4 | LPIC-1 102 | シェル、ネットワーク設定、サービス、セキュリティ | 構築作業とほぼ一致する |
| 5-6 | AWS Solutions Architect - Associate | VPC、EC2、RDS、S3、IAM、監視、コスト | クラウド設計の共通語彙 |

### 未経験からの優先順位

1. **基本情報技術者（FE）** — 書類選考で最も広く通用する。非技術系の担当者にも伝わる
2. **LPIC-1** — Linux を扱う職種での基礎証明。学習内容がそのまま実機作業に直結する
3. **CCNA** — ネットワーク寄りの案件を狙う場合に優先度が上がる
4. **AWS SAA** — クラウド案件を狙う場合。就業後でも十分間に合う

> **注意**: 資格を揃えてから応募する進め方は、応募開始を大幅に遅らせます。
> 本リポジトリでは[応募開始を成果物や資格の完成と連動させない](../../STATUS.md)ルールを設けています。
> 学習と応募は**並行**して進めます。

### 学習サービスの例

| サービス | 対象 | 補足 |
| --- | --- | --- |
| [Ping-t](https://ping-t.com/) | LPIC / CCNA など | 問題演習。一部無料 |
| [基本情報技術者試験ドットコム](https://www.fe-siken.com/) | 基本情報 | 過去問演習。無料 |
| [AWS Skill Builder](https://skillbuilder.aws/) | AWS 認定 | 無料コースあり |

試験制度は改定されます。**出題範囲・試験コード・実施方式は必ず公式で確認**してください
（本リポジトリでも [2026-07 に制度変更へ追随した記録](../certifications/roadmap.md)を残しています）。

## 5. 情報の鮮度を確認する習慣

インフラ領域では、教材の内容が古くなることが**技術的な失敗の主要因**になります。
採用を決める前に、次の 3 点を確認する習慣をつけます。

| 確認項目 | 確認方法 |
| --- | --- |
| サポート期限 | 公式のライフサイクルページで EOL を確認する |
| 後継の有無 | 開発終了して別プロダクトへ統合されていないか |
| 現行の推奨手順 | 公式ドキュメントの手順と、書籍・ブログの手順が一致しているか |

> 本リポジトリでも、設計時にサポート状況を確認していなかったために
> **EOL 済みのコンポーネントを前提に設計してしまった実例**を記録しています
> （[学習の一次記録](../../LEARNINGS.md)）。同じ失敗を避けるため、この確認は着手前のルールにします。
