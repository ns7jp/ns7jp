## 0. 事前準備

- [ ] [1 章 前提条件](../05-phase1-exercise-design.md#前提条件) を満たしている（ホストオンリー相当ネットワーク、ISO 取得）
- [ ] ISO の SHA256 を確認済み（2-2）
- [ ] Hyper-V: `hyperv/00-create-internal-switch.ps1` を実行し `lab-internal` を作成済み（[付録 A-2](../05-phase1-exercise-design.md#a-2-ホストオンリー相当のネットワーク)）

## 1. 構築（4 章 構築手順書）

- [ ] 3-1〜3-3 VM 作成・OS インストール（Hyper-V: `hyperv/01-create-vm.ps1` 実行後、GUI コンソールで Subiquity インストーラを手作業で進める。SSH 鍵はここでインポートしない）
- [ ] 3-4 ホスト名・タイムゾーン・NTP・ロケール
- [ ] 3-5 固定 IP（`netplan/60-lab-static.yaml` を配置。適用前に `ip a` で実際の NIC 名を確認）
- [ ] 3-6 ユーザー作成（`opsadmin`）
- [ ] 3-7 SSH 公開鍵登録・鍵ログイン確認 → **鍵ログイン成功を確認してから** チェックポイント `key-login-ok` 取得（`hyperv/02-checkpoint-helpers.ps1` の `New-LabCheckpoint -Name key-login-ok`）
- [ ] 3-8 パスワード認証・root ログイン禁止（`sshd/00-lab-hardening.conf` を配置。実効値確認まで必ず実施）
- [ ] 3-9 ファイアウォール（ufw）
- [ ] 3-10 OS 最新化・自動更新・ログ確認
- [ ] 3-11 再起動試験 → 全設定保持を確認 → チェックポイント `base-clean` 取得
- [ ] 4 章 作業後確認（4-1〜4-3）

## 2. 試験（5 章 試験項目書）

正常系・単体・結合・総合（T-01〜T-11、T-19〜T-21）:

- [ ] T-01 ホスト名 / T-02 タイムゾーン / T-03 NTP 同期 / T-04 固定 IP
- [ ] T-05 sudo 権限とパスワード必須 / T-06 SSH 鍵ログイン
- [ ] T-07 パスワード認証拒否 / T-08 root ログイン拒否 / T-09 ファイアウォール許可ポート（内側）
- [ ] T-10 再起動後の復帰 / T-11 スナップショット復元
- [ ] T-19 ロケール / T-20 自動更新の動作 / T-21 root アカウントのロック

異常系に入る前:

- [ ] チェックポイント `before-drill` を取得済み

異常系（T-12〜T-18、約 33% を占める。[異常系 3 割以上の理由](../03-build-process.md#異常系を必ず入れる理由)）:

- [ ] 検証用セグメント追加（Hyper-V: `hyperv/03-test-segment-setup.ps1` + `netplan/61-lab-test.yaml`）
- [ ] T-12 誤った鍵での接続 / T-13 未許可の接続元からの SSH（検証用セグメント使用）
- [ ] T-14 `/var` 容量枯渇 / T-15 SSH 誤設定からの復旧 / T-16 自動更新設定の欠落検知
- [ ] T-17 サーバー側パーミッション起因の鍵失敗 / T-18 クライアント側秘密鍵パーミッションの失敗
- [ ] 異常系の後始末（ダミーファイル削除、退避ファイルの復元、`authorized_keys` を 600 に戻す）
- [ ] 検証用セグメント撤去（Hyper-V: `hyperv/04-test-segment-teardown.ps1`）
