# Windows コマンド集（初心者向け）

このページは、未経験からサーバー構築・運用エンジニアを目指す学習者のための、Windows コマンドプロンプトと PowerShell の基本コマンド集です。実務でよく使う操作を「目的」ごとに整理し、危険な操作には注意点を添えることで、安全に・少しずつコマンドを覚えられるようにしています。すべてを一度に覚える必要はなく、困ったときに該当のセクションを引く「辞書」として使ってください。

> **注記**: このドキュメントは、コマンドの仕様や一般的な既定の挙動をもとにまとめた**参考資料**です。この AI 支援セッションには実際に Windows を操作できる環境が無いため、記載しているコマンドを実機で実行して動作を確認したものではありません。Windows のバージョンや設定によって挙動・表示・既定値が異なる場合があるため、とくに初めて実行するコマンドや、システムを変更する操作の前には、`コマンド名 /?`（コマンドプロンプト）や `Get-Help`（PowerShell）、公式ドキュメント（Microsoft Learn）で必ず確認してください。

## コマンドは「目的」で覚える

このドキュメントに載っているコマンドやオプションを、最初からすべて暗記しようとする必要はありません。まずは「困りごと → 打つコマンド → 何が表示されたら正常か」という3点セットで覚え、細かいオプションは実際に必要になったときに `/?` や `Get-Help` で調べれば十分です。各セクションは目的別（ファイル操作、システム確認、ネットワーク確認など）に分かれているので、辞書のように該当する章を引きながら、少しずつ使えるコマンドを増やしていきましょう。

## 1. 基本操作とファイル・フォルダの操作（コマンドプロンプト）

コマンドプロンプト（キーボードで文字を打ち込んでパソコンを操作する黒い画面のこと）を使うと、マウスでのクリック操作と同じように、フォルダを移動したり、ファイルを作成・コピー・削除したりできます。ここでは、サーバー構築の作業でも土台になる「フォルダの中を見る」「移動する」「ファイルを操作する」という一番基本の動きをまとめます。まずは壊れても困らない練習用のフォルダで、実際に手を動かしながら覚えていきましょう。

| やりたいこと | コマンド（書式） | 実行例 | 覚え方・注意点 |
| --- | --- | --- | --- |
| 今いるフォルダの中身（ファイルとフォルダ）を一覧表示したい | `dir` | `dir`<br>ファイル名・サイズ・更新日時などが一覧で表示されます。 | "directory（ディレクトリ、フォルダのこと）"の略。迷ったらまず `dir` を打つ癖をつけましょう。 |
| ファイル名だけを横に並べてコンパクトに見たい | `dir /w` | `dir /w`<br>ファイル名が複数列に並び、詳細情報（サイズなど）は省略されます。 | /w は "wide（横に広い）"の頭文字。ファイル数が多いフォルダで見やすくなります。 |
| 一覧が画面に収まらないとき、1画面ずつ止めて見たい | `dir /p` | `dir /p`<br>1画面表示するたびに「続行するには何かキーを押してください...」と表示され、入力を待ちます。 | /p は "pause（一時停止）"。ファイルが多いフォルダで表示が流れて見えなくなるのを防げます。 |
| 別のフォルダに移動したい | `cd フォルダパス`（change directory） | `cd Documents`<br>今いるフォルダの中の Documents フォルダへ移動します。<br>`cd C:\Users\test\Desktop`<br>Cドライブの根元から辿るパスで一気に移動します。 | "change directory（フォルダを変える）"の略。パスの書き方には相対パス・絶対パスの2種類があります（下の補足参照）。 |
| 1つ上の階層（親フォルダ）に戻りたい | `cd ..` | `cd ..`<br>今のフォルダから1つ上のフォルダへ移動します。 | `..` は「1つ上の階層」を表す特別な書き方です。`cd ..` 単体では1段階しか上がりませんが、`cd ..\..\..` のように `..` を `\` でつないで書けば、1回のコマンドで複数階層まとめて上がることもできます。 |
| 画面いっぱいの文字を消してスッキリさせたい | `cls` | `cls`<br>画面がまっさらになり、入力待ちの記号（プロンプト）だけが残ります。 | "clear screen（画面をクリアする）"の略。見た目が変わるだけで、それまでの操作結果やファイルには影響しません。 |
| コマンドプロンプトを閉じたい | `exit` | `exit`<br>コマンドプロンプトのウィンドウが閉じます。 | そのまま「終了」。ウィンドウ右上の×ボタンを押すのと同じ結果になります。 |
| 今使えるコマンドの一覧をざっと確認したい | `help` | `help`<br>コマンド名と簡単な説明が一覧で表示されます。 | 一覧に載っていないコマンドもあるため、「すべてを網羅した一覧」ではない点に注意しましょう。 |
| あるコマンドの詳しい使い方（使えるオプション）を見たい | `コマンド名 /?` | `dir /?`<br>dir コマンドで使えるオプション（/w や /p など）の説明が表示されます。 | 困ったときはまず `/?` を付けてみる、を基本の習慣にすると安心です。 |
| 新しいフォルダを作りたい | `md フォルダ名` または `mkdir フォルダ名` | `md test`<br>今いるフォルダの中に test という名前の新しいフォルダが作られます。 | md は "make directory" の略で、mkdir と完全に同じ働きをする短縮形（エイリアス）です。 |
| 中身が空のフォルダを削除したい | `rd フォルダ名` または `rmdir フォルダ名` | `rd test`<br>test フォルダが空であれば削除されます。中身が残っていればエラーになり、削除されません。 | rd は "remove directory" の略。中身が入っていると消せない、という安全装置が最初から付いています。 |
| 中身（サブフォルダやファイル）ごとフォルダを削除したい ⚠️ | `rd /s フォルダ名` | `rd /s test`<br>「test、よろしいですか (Y/N)?」のような確認が表示され、Y と答えるとフォルダと中身がすべて削除されます。<br>`rd /s /q test` のように /q を付けると、確認なしで即座に削除されます。 | ⚠️ /s は "subdirectory（サブフォルダ）も含めて"の意味。ゴミ箱を経由せず消えるため、元に戻せません。 |
| ファイルをコピーしたい | `copy コピー元 コピー先` | `copy memo.txt D:\backup\`<br>memo.txt を D:\backup フォルダにコピーします。同名ファイルがあると上書きの確認が出ることがあります。 | copy はファイル用のコマンドで、フォルダそのものはコピーできません。フォルダごとコピーしたいときは後述の xcopy / robocopy を使います。 |
| ファイルやフォルダを別の場所へ移動したい（名前変更にも使える） | `move 移動元 移動先` | `move memo.txt D:\backup\`<br>memo.txt が D:\backup フォルダへ移動します（元の場所からは無くなります）。 | copy と違い、元の場所にファイルは残りません。また copy と違って move はフォルダそのものも移動できます。移動先を新しい名前にすると、名前変更としても使えます。移動先に同じ名前のファイルがすでにある場合は、上書きしてよいか確認されることがあります。 |
| ファイルやフォルダの名前を変更したい | `ren 元の名前 新しい名前` または `rename 元の名前 新しい名前` | `ren memo.txt memo_old.txt`<br>memo.txt が memo_old.txt という名前に変わります。 | ren は rename の短縮形で働きは同じです。フォルダをまたいだ移動はできません（それは move の役目）。 |
| ファイルを削除したい | `del ファイル名` または `erase ファイル名` | `del memo.txt`<br>memo.txt が削除されます（通常、確認メッセージは出ません）。 | del は "delete" の略、erase は同じ働きの別名です。⚠️ ゴミ箱を経由しないため、基本的に元に戻せません。なお `memo.txt` のように名前を1つ指定した場合は確認なしで消えますが、`del *.*` のように「すべてのファイル」を意味するワイルドカードを指定すると、既定では「よろしいですか (Y/N)?」のような確認が入ります（次の行のように /q を付けると省略されます）。 |
| フォルダの中のファイルをまとめて、確認なしで一気に削除したい ⚠️ | `del /s /q フォルダ名\*.*` | `del /s /q C:\work\*.*`<br>C:\work フォルダとそのサブフォルダ内のすべてのファイルが、確認なしで削除されます（フォルダ自体は残ります）。 | ⚠️ /s は「サブフォルダも含めて」、/q は "quiet（確認メッセージを出さない）"。組み合わせると大量のファイルが一瞬で消え、元に戻せません。 |
| テキストファイルの中身を画面に表示したい | `type ファイル名` | `type memo.txt`<br>memo.txt の中身がそのまま画面に表示されます。 | 短いテキストファイルの中身をサッと確認したいときに使います。画像や実行ファイルに使うと文字化けした表示になります。 |
| 長いファイルの中身を1画面ずつ見たい | `more ファイル名` | `more memo.txt`<br>1画面表示するたびに「-- More --」と表示され、キー入力を待ちます。 | more は type に「一時停止」機能を足したイメージです。長いログファイルなどの確認に便利です。 |
| フォルダの中の構造を階層（木構造）で見たい | `tree`（ファイル名も表示するなら `tree /f`） | `tree /f`<br>今いるフォルダ以下のフォルダ構造が、木の枝のような線でつながれて表示されます。/f を付けるとファイル名も一緒に表示されます。 | tree は「木」。フォルダ全体の見取り図をざっと把握したいときに便利です。フォルダ数が多いと表示が長くなります。 |
| ファイルの属性（読み取り専用・隠しファイルなど）を確認したい | `attrib ファイル名` | `attrib memo.txt`<br>該当する属性にだけ、R（読み取り専用）や H（隠しファイル）などのアルファベットが表示されます。 | 属性（ファイルの性質を表す追加情報）は R=Read-only（読み取り専用）、H=Hidden（隠しファイル）のように頭文字で表されます。 |
| ファイルを読み取り専用や隠しファイルにしたい（または解除したい） | `attrib +r/-r ファイル名`、`attrib +h/-h ファイル名` | `attrib +h memo.txt`<br>memo.txt が隠しファイルになり、通常の dir 表示や検索に出てこなくなります。<br>`attrib -h memo.txt` で元の表示に戻ります。 | + が「属性を付ける」、- が「属性を外す」の意味です。隠しファイルにしても中身が消えるわけではなく、見えなくなるだけです。読み取り専用（+r）にしたファイルを del でそのまま削除しようとすると、「アクセスが拒否されました」のようなエラーになることがあります。削除したいときは先に `attrib -r` で属性を外すか、del の /f オプション（読み取り専用ファイルも強制的に削除する）を使います。 |
| フォルダをサブフォルダごとまとめてコピーしたい | `xcopy コピー元 コピー先 /e`（概要） | `xcopy C:\work D:\backup\work /e /i`<br>C:\work フォルダの中身を、サブフォルダも含めて D:\backup\work にコピーします。 | xcopy は copy を拡張したコマンドで、フォルダ単位のコピーが得意です。/e は空フォルダも含めてコピー、/i はコピー先フォルダが無ければ自動作成する指定です。 |
| xcopy よりも高機能・高信頼にフォルダをコピーしたい（概要） | `robocopy コピー元 コピー先 /e`（概要） | `robocopy C:\work D:\backup\work /e`<br>xcopy と似た形でフォルダをコピーしますが、進み具合やエラーを詳しく記録し、途中で失敗しても自動的に再試行してくれます。 | robocopy は "robust file copy（頑丈なコピー）"の略で、xcopy の後継的な存在です。フォルダ同士を完全に一致させる機能もありますが、削除も伴うため、ここでは概要にとどめます。⚠️ 既定ではコピーに失敗すると最大100万回・30秒間隔で延々と再試行する仕様になっているため、使用中のファイルなどがあるといつまでも処理が終わらないように見えることがあります。気になる場合は `/r:3 /w:5`（3回だけ・5秒間隔で再試行）のように回数と間隔を指定すると安心です。 |

> ⚠️ 注意: `rd /s` は、フォルダの中身をサブフォルダごと一気に削除できる分、指定するフォルダを間違えると取り返しがつきません。実行前に `dir` や `tree` で対象フォルダの中身を必ず確認しましょう。
>
> ⚠️ 注意: `del /s /q` は「サブフォルダも含めて（/s）」「確認なしで（/q）」ファイルを削除するため、意図しない大量のファイルを一瞬で消してしまう危険があります。特に `*.*`（すべてのファイル）を指定するときは、対象フォルダのパスを何度も見直してから実行してください。

### 補足: 相対パスと絶対パスの違い

パス（ファイルやフォルダの場所を表す文字列）には、相対パス（今いる場所を基準にした道順）と絶対パス（`C:\Users\test\Desktop` のように、ドライブの根元からの完全な道順）の2種類があります。相対パスは今いるフォルダによって行き先が変わるのに対し、絶対パスはどこから実行しても同じ場所を指すという違いがあります。たとえるなら、相対パスは「今いる駅から2駅先」、絶対パスは「東京都〇〇区〇〇の住所」のようなものです。慣れないうちは、確実に迷わない絶対パスを使うと安心です。

### 補足: ワイルドカード（`*` と `?`）の意味

ワイルドカード（複数のファイル名をまとめて指定するための記号）を使うと、1つずつファイル名を打たなくても複数のファイルをまとめて指定できます。`*` は「0文字以上の何でもよい文字列」を表し、`?` は「ちょうど1文字分の何でもよい文字」を表します。たとえば `dir *.txt` は拡張子が `.txt` のファイルをすべて表示し、`del report?.txt` は `report1.txt` や `reportA.txt` のように report の後に1文字だけ続くファイルを対象にします。`*.*` は「すべてのファイル」を意味するため、削除やコピーで使うときは特に対象を確認してから実行しましょう。

## 2. システム情報の確認と環境変数

このセクションでは、自分のパソコンが「どんな環境で動いているか」を調べるコマンドと、コマンドの動作に影響する「環境変数（Windowsやアプリが設定値を保存しておくための、名前と値のペアの入れ物）」の扱い方を学びます。サーバー構築の現場では、まず相手のマシンのOSやユーザー権限、文字コードの設定を確認してから作業を始めることが多いため、ここで扱うコマンドは調査の基本セットになります。

| やりたいこと | コマンド（書式） | 実行例 | 覚え方・注意点 |
| --- | --- | --- | --- |
| OSの詳細情報（バージョン、インストール日、メモリ量など）をまとめて確認したい | `systeminfo` | `systeminfo`<br>OS名、ビルド番号、物理メモリ、ネットワークアダプター情報などがずらりと表示される | 情報量が多く、収集に数十秒かかることがある。「システムの健康診断」のようなイメージ。特定項目だけ見たいときは `findstr`（文字列検索コマンド）と組み合わせる |
| コンピューター名（ホスト名）を確認したい | `hostname` | `hostname`<br>`DESKTOP-ABC123` のように1行だけ表示される | 「この端末の呼び名」を返すだけのシンプルなコマンド。ネットワーク越しに相手を識別するときによく使う |
| 使っているWindowsのバージョン番号を確認したい | `ver` | `ver`<br>`Microsoft Windows [Version 10.0.19045.3803]` のように表示される | `systeminfo` より手早く、バージョン番号だけサッと見たいときに使う |
| 今ログインしているユーザー名を確認したい | `whoami` | `whoami`<br>`desktop-abc123\yamada` のように「コンピューター名\ユーザー名」の形式で表示される | 「自分は誰？」に答えてくれるコマンド。複数アカウントを切り替えて作業しているときの確認に便利 |
| ログインユーザーの所属グループや権限を詳しく確認したい | `whoami /all` | `whoami /all`<br>ユーザー情報に加えて、所属グループの一覧や割り当てられている特権（権限）の一覧が表示される | 管理者権限があるかどうかを確認したいときに使う。表示項目が多いので、必要な行だけ探すのに少し慣れが要る |
| 現在設定されている環境変数を一覧で確認したい | `set` | `set`<br>`Path=...`、`TEMP=...` のように、変数名=値の形式で一覧が表示される | 引数なしの `set` は「今この画面（コマンドプロンプト）で使える変数の全部入り」を見せてくれる。先頭の文字を指定すると絞り込める（例: `set P` と打つと `Path` や `PROMPT` など P で始まる変数だけ表示） |
| 環境変数を一時的に設定・変更したい | `set 変数名=値` | `set MYVAR=hello`<br>その画面を閉じるまでの間だけ `MYVAR` という変数に `hello` が入る | ⚠️ ここで設定した内容は今開いているウィンドウの中だけで有効。ウィンドウを閉じると消える（永続的に変更したい場合は別途システム設定が必要）。既存の変数名（特に `PATH`）を上書きしないよう注意 |
| 環境変数の中身を画面に表示したい | `echo %変数名%` | `echo %PATH%`<br>PATH変数に登録されているフォルダーの一覧が1行で表示される | `%` で変数名を挟むのがポイント。挟み忘れると `%変数名%` という文字列がそのまま表示されてしまう |
| 画面にメッセージや文字列を表示したい | `echo` | `echo Hello, World!`<br>そのまま `Hello, World!` と表示される | バッチファイル（複数のコマンドをまとめて実行するファイル）の中で処理の進行状況を表示するのによく使われる |
| 今日の日付を確認したい（変更もできる） | `date /t`（確認のみ）<br>`date`（変更もできる） | `date /t`<br>`2026/09/04` のように現在の日付だけを表示する | ⚠️ `/t` を付けずに `date` だけ実行すると、新しい日付の入力を求めるプロンプトが出る。システムの日付を変更する権限は既定では管理者だけに与えられているため、管理者権限のコマンドプロンプトではそのまま数値を入力すると日付が実際に変わってしまう（管理者権限がない場合は「アクセスが拒否されました」といったエラーになり変更されないことが多い）。いずれの場合も、確認だけしたいときは必ず `/t` を付ける習慣にする |
| 現在時刻を確認したい（変更もできる） | `time /t`（確認のみ）<br>`time`（変更もできる） | `time /t`<br>`14:05` のように現在時刻だけを表示する | ⚠️ 考え方は `date` と同じ。`/t` なしだと時刻変更モードに入ってしまう。時刻の変更にも既定では管理者権限が必要なので、管理者として実行しているコマンドプロンプトでは特に注意する |
| PATH環境変数（コマンドを探すフォルダーの一覧）を確認したい | `path` | `path`<br>現在のPATHの中身が1行で表示される（`echo %PATH%` と同じ結果になる） | 「コマンドを探しに行く場所リスト」を表示するコマンド。表示だけなら `set` や `echo %PATH%` でも代用できる。⚠️ `path` の後にフォルダーを指定して実行すると、既存のPATHに追加されるのではなく丸ごと置き換わってしまう。さらに `path ;` と実行すると検索対象がカレントフォルダーだけになり、その画面で他のコマンドが動かなくなることがある（ウィンドウを閉じれば元の設定に戻る） |
| 実行したいコマンドの実体（exeファイルなど）がどこにあるか探したい | `where コマンド名` | `where python`<br>PATHの中から `python.exe` が見つかったフォルダーのフルパスが表示される（複数見つかれば全部表示） | 「where」は「どこ？」という意味そのまま。同じ名前のコマンドが複数の場所にあって、どれが実際に使われているか確認したいときに便利 |
| ドライブのボリュームラベル（ドライブに付けられた名前のこと）とシリアル番号を確認したい | `vol` | `vol`<br>`ドライブ C のボリューム ラベルは WINDOWS です` のように表示される<br>`vol D:` のように指定すれば別ドライブも確認できる | 「このドライブの名札（ラベル）は何？」を教えてくれるコマンド。ドライブを指定しない場合はカレントドライブが対象になる |
| ドライブのボリュームラベル（名前）を設定・変更したい | `label` | `label D: BACKUP`<br>Dドライブのラベルが `BACKUP` に変更される | ⚠️ 引数なしで `label` だけ実行すると、現在のラベルを表示したうえで新しいラベルの入力を求められる。何も入力せずEnterすると、現在のラベルを削除してよいか確認された上で削除される（確認の手順はWindowsのバージョンによって多少異なる場合がある）。操作対象のドライブレター（C:やD:など）を間違えないよう、実行前に必ず確認する |
| 現在の文字コードページ（画面で使う文字の規格）を確認したい | `chcp` | `chcp`<br>`現在のコード ページ: 932` のように表示される（932はShift-JIS系、65001はUTF-8を表す番号） | 「コードページ」は文字をどのルールで表示・変換するかの設定。番号を指定すれば `chcp 65001` のように変更もできるが、フォントや実行中のツールが対応していないと日本語が文字化けすることがある |

> ⚠️ 注意: `date` と `time` は `/t` を付け忘れると「日付・時刻を変更するモード」に入ってしまいます。日付・時刻の変更には既定で管理者権限が必要なため、管理者権限のないユーザーではエラーになり変更されないことが多いのですが、管理者権限で実行しているコマンドプロンプトではうっかり数値を入力すると本当にシステムの日付や時刻が書き換わってしまいます。確認だけしたい場合は必ず `/t` オプションを付けましょう。また `set 変数名=値` や `path フォルダー...` で既存の重要な変数（特に `PATH`）を上書きすると、そのウィンドウ内で他のコマンドが「認識されません」というエラーになることがあります（`path ;` は特に、検索対象をカレントフォルダーだけに絞り込んでしまいます。ウィンドウを閉じれば元に戻りますが、作業中は混乱のもとになります）。`label` もドライブレターの指定を間違えると意図しないドライブの名前を変えてしまうため、実行前に対象ドライブを確認してください。

### 補足: 環境変数とPATHの仕組み

環境変数は、いわば「Windows全体やアプリが参照できるメモ帳」のようなものです。中でも `PATH` は特別で、「コマンドを入力したときに、実行ファイル（.exeファイルなど）をどのフォルダーの中から探すか」という検索対象フォルダーの一覧が入っています。たとえば `python` とだけ入力してPythonが起動するのは、PATHの中に `python.exe` が置かれているフォルダーが登録されているからです。`where` コマンドは、この仕組みを利用して「実際にどのフォルダーの実行ファイルが使われているか」を教えてくれます。

### 補足: 文字コードページと文字化けの関係

`chcp` で確認できる「コードページ」は、画面上の文字をどの規則で解釈・表示するかを決める設定です。日本語環境では通常 `932`（Shift-JIS系、Windowsでは「ANSI/OEM Japanese」とも呼ばれます）が使われますが、これを `65001`（UTF-8）などに切り替えると、コマンドプロンプトの表示や一部のツールの出力が正しく表示されなくなる（いわゆる文字化け）ことがあります。作業中に文字化けが起きたときは、まず `chcp` で現在の設定を確認するのが調査の第一歩になります。

## 3. プロセス・サービス・電源の操作

パソコンの中では、いま起動しているアプリや裏方の仕組み（サービス）が同時にたくさん動いています。このセクションでは、それらの状態を確認したり、フリーズしたアプリを強制終了したり、サーバー機を安全に再起動・シャットダウンしたりするコマンドを学びます。サーバー構築の現場では「動いているはずのサービスが止まっていないか」「再起動が必要なときにどう安全に行うか」を確認する場面が非常に多いため、ここで扱う内容は実務でもよく使われます。

| やりたいこと | コマンド（書式） | 実行例 | 覚え方・注意点 |
| --- | --- | --- | --- |
| 実行中のプロセス（起動中のプログラム）の一覧を見たい | `tasklist` | `tasklist`<br>プロセス名・PID（プロセスID、プロセスごとに割り振られる番号）・使用メモリ量などが一覧表示される | 一言でいうと「今動いているアプリの名簿」。タスクマネージャーの「詳細」タブをコマンドで見ているイメージ。 |
| プロセスがどのサービス（Windows が裏で動かしている機能）と結びついているか見たい | `tasklist /svc` | `tasklist /svc`<br>各プロセスに紐づくサービス名が一緒に表示される（サービスを持たないプロセスは「N/A」と表示される） | `svc` は service（サービス）の略。「このプロセス、実は裏でこんなサービスを動かしていたのか」を確認するときに使う。 |
| PID を指定してプロセスを強制終了したい | `taskkill /PID <番号> /F` | `taskkill /PID 1234 /F`<br>PID が 1234 のプロセスが終了する | ⚠️ `/F` は force（強制）の意味で、確認なしに即終了させる。保存していない作業は失われるので、PID は `tasklist` で必ず確認してから使う。子プロセス（そのプロセスから起動された別のプロセス）ごとまとめて終了したいときは `/T` も付ける。 |
| プロセス名を指定して強制終了したい | `taskkill /IM <プロセス名> /F` | `taskkill /IM notepad.exe /F`<br>実行中の notepad.exe（メモ帳）がすべて終了する | ⚠️ `/IM` は image name（実行ファイル名）の意味。同じ名前のプロセスが複数あると全部まとめて終了するため、範囲が広く危険度が高い。 |
| コマンドプロンプトから別ウィンドウでアプリを起動したい | `start <プログラム名>` | `start notepad`<br>今のコマンドプロンプトとは別に、新しいウィンドウでメモ帳が開く | `start` を付けないと今の画面のまま処理を待つことがある。「新しい窓を開いて渡す」イメージで覚えるとよい。 |
| サービスの状態（動いているか、止まっているか）を確認したい | `sc query <サービス名>` | `sc query wuauserv`<br>Windows Update サービスの状態（RUNNING や STOPPED など）が表示される | `sc` は service control（サービス制御）の略。サービス名を省略すると、既定では止まっているサービスは含まれず「動いている（アクティブな）サービス」だけが一覧表示される点に注意（止まっているものも含めた全件を見たいときは `sc query state= all` のように状態を指定する）。 |
| サービスの状態をさらに詳しく確認したい | `sc queryex <サービス名>` | `sc queryex wuauserv`<br>状態に加えてプロセス ID（PID）なども表示される | `queryex` は query extended（拡張された照会）の意味。`sc query` だけでは足りない情報（PID など）が欲しいときに使う。 |
| サービスを開始したい | `net start <サービス名>` | `net start "Print Spooler"`<br>印刷関連のサービスが起動する | サービス名にスペースが含まれる場合は `" "`（ダブルクォート）で囲む。管理者権限のコマンドプロンプトでないと失敗しやすい。 |
| サービスを停止したい | `net stop <サービス名>` | `net stop "Print Spooler"`<br>印刷関連のサービスが停止する | ⚠️ 他のサービスがこのサービスに依存している場合、「このサービスを止めると次のサービスも止まりますが続けますか？」のような確認が出て、Y（はい）と答えると道連れで止まることがある。停止前に影響範囲を確認したい。 |

| 現在のユーザーをログオフしたい | `logoff` | `logoff`<br>現在サインインしているユーザーがログオフされる（開いているアプリも終了する） | ⚠️ 保存していない作業は失われる可能性がある。シャットダウンと違い電源は切れず、サインイン画面に戻るだけという違いがある。 |

### 補足: PID とプロセス名、どちらを指定すべきか

`taskkill` には `/PID`（番号で指定）と `/IM`（名前で指定）の2つの方法があります。`/PID` はプロセスを一つずつピンポイントで狙えるため安全性が高く、`/IM` は同じ名前のプロセスをまとめて終わらせたいときに便利ですが、その分「巻き込み」が起きやすくなります。一言でいうと、`/PID` は「名指しで一人だけ」、`/IM` は「同じ名前の人を全員」というイメージです。迷ったときは、まず `tasklist` で PID を確認してから `/PID` を使うほうが安全です。なお `/F` だけでは対象プロセスから起動された子プロセスは残ることがあるため、まとめて終了させたい場合は `/T`（tree、プロセスの親子関係ごと終了する）を組み合わせます。

> ⚠️ `taskkill /F`（強制終了）は、対象のプロセスに保存確認や終了処理をする時間を与えずに即座に終了させます。編集中のファイルがあれば内容が失われる可能性があるため、本当にそのプロセスを終了してよいか、PID・プロセス名の両方をよく確認してから実行してください。また `csrss.exe` のような Windows の中核をなすシステムプロセスは、保護されていて `/F` を付けても終了できない（アクセスが拒否される）か、無理に終了させようとするとシステム全体がクラッシュ（ブルースクリーン）することがあります。`tasklist` の一覧で見覚えのないシステムプロセスは終了しないようにしてください。

### 補足: `sc` の「サービス名」と表示名は別物

`sc query` や `sc queryex`、`sc start`／`sc stop` に指定する名前は、画面上の分かりやすい「表示名」（例: Windows Update）ではなく、`wuauserv` のようなレジストリ上の内部的な「サービス名」です。一方、`net start` / `net stop` はどちらの名前を指定してもたいてい動きます。一言でいうと、`sc` は「正式な内部名」しか通じない担当者、`net` は「あだ名でも通じる」担当者、というイメージです。サービス名が分からないときは `sc query`（動いているサービスの一覧）や `services.msc`（サービス管理ツール）で確認するとよいでしょう。

### 補足: サービスの操作は管理者権限が必要になることが多い

`net start` や `net stop` でサービスを操作する場合、多くは管理者権限（Administrator 権限）でコマンドプロンプトを起動していないと「アクセスが拒否されました」というエラーになります。サーバー構築の現場では、サービスの起動・停止はシステム全体に影響するため、実行前に「このサービスを止めても他の機能に影響しないか」を確認する習慣をつけておくとよいでしょう。

### 補足: `shutdown` の `/f` オプションと未保存データ

ここで紹介した `shutdown /s /t <秒数>` や `shutdown /r /t <秒数>` は、指定した秒数が経過するとシャットダウン・再起動が始まりますが、既定では保存されていないファイルがあるアプリを無理やり閉じようとはせず、場合によっては「このアプリを終了できません」といった画面が表示されて処理が止まってしまうことがあります。強制的にすべてのアプリを閉じてから実行したいときは `/f`（force、強制）を付けます（例: `shutdown /r /t 60 /f`）。ただし `/f` は保存確認なしにアプリを閉じるため、⚠️ 未保存の作業が失われるリスクがさらに高くなる点に注意してください。

> ⚠️ `shutdown /s` や `shutdown /r` は、他の人が使っているサーバーやリモート接続中の端末に対して実行すると、作業中のセッションが強制的に切断されます。特に本番稼働中のサーバーでは、事前の周知や `shutdown /a` によるキャンセル手段があることを覚えたうえで慎重に扱ってください。

## 4. ネットワークの確認

インターネットや社内ネットワークにつながらないとき、「どこで詰まっているのか」を切り分けるための道具がこのセクションのコマンドたちです。サーバーエンジニアは障害対応のたびにこれらを使うので、今のうちに手に馴染ませておきましょう。一言でいうと、「自分のPC → 途中経路 → 相手のサーバー」の順番に確認していくイメージです。

| やりたいこと | コマンド（書式） | 実行例 | 覚え方・注意点 |
| --- | --- | --- | --- |
| 自分のPCのIPアドレスをざっくり確認したいとき | `ipconfig` | `ipconfig`<br>IPv4 アドレスやデフォルトゲートウェイ（そのPCがインターネットに出ていく際の玄関口となる機器のアドレス）などが表示される | 一言でいうと「今の自分の住所を見る」コマンド。まず最初に打つべき定番コマンド |
| IPアドレスの詳細情報（MACアドレスやDNSサーバーなど）まで確認したいとき | `ipconfig /all` | `ipconfig /all`<br>物理アドレス（MACアドレス。ネットワーク機器ごとに割り振られた固有の識別番号）、DNSサーバー（ドメイン名をIPアドレスに変換してくれるサーバー）、DHCP（IPアドレスを自動で割り当てる仕組み）の有効/無効なども表示される | `/all` は「全部見せて」の意味。トラブル報告時はこちらの情報を求められることが多い |
| DNSの古いキャッシュ（一度調べた名前と住所の対応を覚えている情報）を消したいとき | `ipconfig /flushdns` | `ipconfig /flushdns`<br>「Windows IP 構成 DNS リゾルバー キャッシュは正常にフラッシュされました。」のように表示される | サイトのURLは変わったはずなのに古いページや接続エラーが出るときに使う。パソコンの「物忘れさせる」コマンドと覚えるとよい |
| 相手（サーバーなど）まで通信が届くか確認したいとき | `ping 宛先` | `ping google.com`<br>「バイト数=32 時間=10ms TTL=118」のような応答が4回表示され、届いていれば成功、"要求がタイムアウトしました。" などが出れば失敗 | 一言でいうと「もしもし、聞こえますか？」の確認。TTL（Time To Live。データが経由できる最大のホップ数）や応答時間（ms）で回線の状態もざっくり分かる |
| 応答が止まるまで ping を打ち続けたいとき | `ping -t 宛先` | `ping -t google.com`<br>Ctrl+C キーを押すまで応答を送り続ける | ⚠️ 自動では止まらないので、確認が終わったら必ず Ctrl+C で止めること。統計だけその場で見て実行は続けたい場合は Ctrl+Break を使うと、止めずにそこまでの結果を表示できる。回線の不安定さ（たまに応答が途切れる、など）を見たいときに便利 |
| 相手までの経路（途中でどんな機器を通っているか）を調べたいとき | `tracert 宛先` | `tracert google.com`<br>1ホップ目（自宅ルーターなど）から順番に、通過した中継機器のIPアドレスや応答時間が一覧表示される | 「どこの中継地点で詰まっているか」を知りたいときの定番。ホップ（hop）とは経路上の中継地点1つ分のこと。途中の行だけ "要求がタイムアウトしました。" と表示されても、その中継機器がICMP（ping や tracert が使う確認用の通信）への応答を止めているだけのことが多く、その先の行まで届いていれば通信自体は問題ないケースが多い |
| 経路の各地点での「安定性」まで詳しく調べたいとき | `pathping 宛先` | `pathping google.com`<br>経路を洗い出したあと、各ホップに対して既定で100回・250ミリ秒間隔（1ホップあたり約25秒）パケット（データの小さな塊）を送り続け、パケットロス率（届かなかった割合）を集計して表示する | tracert より詳しいが時間がかかる。ホップ数が多い経路では全体で数分〜10分程度かかることもある。「tracert + ping をまとめてやってくれる」道具とイメージすると分かりやすい |
| ドメイン名に対応するIPアドレスを調べたいとき | `nslookup ドメイン名` | `nslookup example.com`<br>使用中のDNSサーバーの情報と、対象ドメインの名前・IPアドレスが表示される | 「name server lookup」の略。ホームページが表示されないとき、DNSの問題かどうかを切り分けるのに使う |
| 今この瞬間の通信状況（どこと接続しているか）を一覧で見たいとき | `netstat -an` | `netstat -an`<br>プロトコル（通信の約束事。TCPやUDPなど）、ローカルアドレス、外部アドレス、状態（LISTENING＝待ち受け中、ESTABLISHED＝接続確立中など）が一覧表示される | `-a` は全ての接続、`-n` は名前解決せず数字（IPアドレスやポート番号）のまま表示、の意味。どのポート（通信の窓口番号）が使われているか確認できる |
| どのアプリ（プロセス）がその通信をしているか特定したいとき | `netstat -ano` | `netstat -ano`<br>netstat -an の一覧に加え、一番右にPID（プロセスID。動作中の各プログラムに割り振られた番号）の列が表示される | `o` は owner（所有者）の意味。表示されたPIDをタスクマネージャーの「詳細」タブで探すと、どのアプリが通信しているか分かる。⚠️ PID番号だけを見て安易にタスクを強制終了すると、システムに必要なプロセスまで止めてしまうことがあるので、プロセス名までよく確認してから操作すること |
| 最近通信した同じネットワーク内の機器のMACアドレスを確認したいとき | `arp -a` | `arp -a`<br>同じネットワーク内の機器について、IPアドレスと物理アドレス（MACアドレス）の対応表が表示される | ARP（Address Resolution Protocol）は「IPアドレスからMACアドレスを調べる仕組み」のこと。社内LANでの機器特定などに使われる。ただしこの一覧は一時的なキャッシュ（通信がないと数分程度で消えていく情報）であり、ずっと残る通信履歴ではない点に注意 |

> ⚠️ `ping -t` は明示的に止めるまで実行され続けます。長時間動かしたままにすると通信や画面のログが埋もれてしまうので、確認が終わったら必ず `Ctrl+C` を押して停止してください。また `pathping` は仕組み上、経路が長いと実行に数分以上かかる場合があります。途中で操作を止めたい場合も `Ctrl+C` で中断できます。

### 補足: なぜ ping → tracert → nslookup の順で切り分けるのか

「サイトが開かない」という同じ症状でも、原因は自分のPC、途中の経路、DNS、相手サーバーなど様々な場所にあり得ます。まず `ping` で「そもそも相手まで届いているか」を確認し、届かなければ `tracert` で「どこまでは届いているか」を確認、名前解決（ドメイン名からIPアドレスを調べること）が怪しければ `nslookup` で確認する、という順番で進めると、問題の場所を一つずつ絞り込めます。この考え方は実際のサーバー障害対応でもよく使われる基本的な手順です。

## 5. ディスク・ユーザー・権限の確認

このセクションでは、パソコンのディスク（ハードディスクやSSD）に不具合がないかを調べる方法と、「今どのユーザーでログインしていて、どんな権限を持っているか」を確認する方法を扱います。サーバー構築の現場では「なぜかアクセスできない」「なぜか動かない」というトラブルの原因がディスクや権限にあることが多いため、まずは"見る"コマンドに慣れることが目標です。

| やりたいこと | コマンド（書式） | 実行例 | 覚え方・注意点 |
| --- | --- | --- | --- |
| ドライブに不具合がないか点検したい（読み取り専用） | `chkdsk [ドライブ:]` | `chkdsk C:` <br> ファイルシステムとディスクの状態をチェックし、結果のレポートを表示する（実際の修復は行わない） | 一言でいうと「健康診断だけして薬は出さない」モード。読み取り専用なので基本的に何度実行しても安全だが、ディスクの容量によっては時間がかかる |
| 見つかった問題を実際に修復したい | `chkdsk [ドライブ:] /f` | `chkdsk C: /f` <br> 問題があれば修復を試みる。対象がWindows起動中のドライブ（例: Cドライブ）だと使用中のため独占できず、「次回の再起動時に検査を予約しますか?」と聞かれることが多い | ⚠️ 注意: `/f` を付けると修復のためにドライブを独占的に使う必要があり、再起動が必要になる場合がある。引数なしのチェックとは挙動が大きく異なる点を区別して覚えること |
| 不良セクタ（ディスク上の物理的に壊れた記録領域）も含めて検査・回復したい | `chkdsk [ドライブ:] /r` | `chkdsk C: /r` <br> ファイルシステムの修復に加え、不良セクタを検出し、そこに書かれていたデータの回復を試みる | `/r` は `/f` の機能をすべて含んでいるため、`/f /r` のように両方書かなくても意味は同じ。不良セクタの検査は時間がかかりやすく、`/f` 単独より対象ドライブを長く占有しやすい点に注意 |
| ドライブの一覧・サイズ・空き容量を確認したい（新しい方法） | `Get-Volume [-DriveLetter <文字>]` | PowerShellで `Get-Volume` <br> ドライブレター・ファイルシステムの種類・サイズ・空き容量・健全性などが一覧表示される | 用語: コマンドレット（PowerShellの命令ひとつひとつのこと）。`Get-Volume` はディスク容量確認の後継コマンドレットとして案内されている |
| PowerShell上のドライブ全般を確認したい | `Get-PSDrive [<ドライブ名>]` | PowerShellで `Get-PSDrive` <br> Cドライブなどのファイルシステムに加え、レジストリ（設定情報の保管場所）など、PowerShellが「ドライブ」として扱う対象も一覧表示される | `Get-Volume` より対象が広い概念。ディスクの空き容量だけ知りたいときは `Get-Volume` の方がシンプルで読みやすい |
| （参考・旧方式）コマンドプロンプトでディスク一覧を見たい | `wmic logicaldisk get <プロパティ名>` | `wmic logicaldisk get name,size,freespace` <br> ドライブレター、サイズ、空き容量が表示される | ⚠️ `wmic` はMicrosoftが段階的に廃止を進めているコマンドで、Windows 11の新しいバージョン（24H2/25H2以降）では新規インストール時に既定で入らなくなっており、既存環境でも今後の更新で取り除かれていく方針が示されている。これから覚えるなら `Get-Volume` や `Get-PSDrive` などPowerShell側を優先するとよい |
| ドライブのボリュームラベルとシリアル番号を確認したい | `vol [ドライブ:]` | `vol C:` <br> ボリュームラベル（ドライブに付けた名前）とボリュームシリアル番号が表示される | 用語: ボリューム（ディスクの中で1つのドライブとして扱われる区画のこと）。`dir` コマンドの先頭にも同じ情報が出る |
| コンピューター上のユーザーアカウント一覧を見たい | `net user` | `net user` <br> このコンピューターに存在するローカルユーザーアカウントの一覧が表示される | 用語: ユーザーアカウント（Windowsにログインするための個人ごとの入り口）。自分のアカウント名もここで確認できる |
| 特定ユーザーの詳細（有効/無効、所属グループなど）を見たい | `net user <ユーザー名>` | `net user Taro` <br> アカウントが有効かどうか、パスワードの最終設定日、所属しているグループなどが表示される | まず `net user` で一覧を見て、正しいユーザー名を確認してから使うと迷いにくい |
| （参考）新しいユーザーを追加したい | `net user <ユーザー名> <パスワード> /add` | `net user Hanako P@ssw0rd /add` <br> 新しいローカルユーザーアカウントが作成される | ⚠️ 管理者権限が必要な変更系コマンド。パスワードをコマンドにそのまま書くと、画面表示やコマンド履歴に平文のまま残ってしまうため実運用では注意が必要。本セクションでは「こういうこともできる」程度に留め、詳しい運用は別途学ぶこと |
| 管理者権限を持つユーザーを確認したい | `net localgroup administrators` | `net localgroup administrators` <br> Administrators（管理者）グループに所属しているユーザー名の一覧が表示される | 用語: グループ（複数のユーザーをまとめて同じ権限を与えるための入れ物）。「誰が管理者か」を確認する定番コマンド |
| 自分に割り当てられている特権を確認したい | `whoami /priv` | `whoami /priv` <br> システム時刻の変更やシャットダウンなど、現在のユーザーが持つ「特権」の一覧と、それぞれが有効か無効かが表示される | 用語: 特権（Privilege。システムレベルの特別な操作を行うために個別に割り当てられる許可のこと） |
| 自分がどのグループに所属しているか確認したい | `whoami /groups` | `whoami /groups` <br> Administratorsグループなど、所属しているすべてのグループ名とSIDが一覧表示される | 用語: SID（セキュリティ識別子。ユーザーやグループを一意に区別するためのID）。実際の権限はこの所属グループによって決まることが多い |
| ファイルやフォルダーの権限（誰が何をできるか）を確認したい | `icacls <パス>` | `icacls C:\Users\Taro\Documents` <br> そのフォルダーに対して、どのユーザー・グループが読み取りや書き込みなどのどの権限を持っているかが表示される | 用語: ACL（アクセス制御リスト。「誰が」「何を」できるかを定めたルールの一覧）。表示して確認するだけなら安全に使える |
| （非常に強力・上級者向け）ディスクのパーティションを操作したい | `diskpart` | `diskpart` <br> 専用のコマンドラインモードに入り、ディスクの初期化・パーティション作成・フォーマットなどを行える | ⚠️⚠️ 非常に危険。用語: パーティション（1つのディスクを区切って作る独立した保存領域のこと）。初心者は基本的に使わない |

> ⚠️ 注意: `diskpart` は非常に強力なコマンドで、操作対象のディスク番号を間違えると、そのディスク全体のデータを一瞬で失ってしまう可能性があります。理由は、`diskpart` がハードウェアに近いレベルでディスクを直接操作するため、`chkdsk` のような読み取り専用モードが基本的になく、選んだ対象に対してすぐに変更が反映されてしまうからです。学習中のうちは無理に使わず、もし将来使う場面があっても、実行前に「今選んでいるディスク番号・パーティション番号」を`list disk` や `list partition` などで何度も確認する習慣をつけてください。同様に `chkdsk /f`（および不良セクタも検査する `/r`）も再起動を伴う修復処理になるため、何を対象にしているかを事前に確認してから実行しましょう。

### 補足: chkdskの「引数なし」「/f付き」「/r付き」の違い

`chkdsk` を引数なしで実行すると、ディスクの状態を読み取って報告するだけの"健康診断"にとどまり、ファイルやディスクの中身は変更されません。一方 `/f` を付けると、見つかったエラーの修復まで行うため、対象のドライブを一時的に独占して使う必要があります。Windowsが起動しているCドライブのように「今まさに使用中」のドライブは独占できないため、多くの場合「次回の起動時に検査を実行しますか?」と確認され、再起動後に修復が走る、という流れになります。さらに `/r` を付けると、`/f` の機能に加えてディスク上の不良セクタ（物理的に壊れて読み書きできなくなった領域）まで検査し、そこにあったデータの回復を試みます。`/r` は `/f` の機能を包含しているため、`/f` と `/r` を両方指定する必要はありません。

### 補足: wmicの廃止傾向とPowerShellへの移行

`wmic` は長年ディスクやシステム情報を確認する定番コマンドでしたが、Microsoftは近年、段階的にこのコマンドの廃止を進めています。Windows 11の新しいバージョン（24H2/25H2以降）では、新規にインストールした環境で既定では入らなくなっており、既存の環境についても今後の更新プログラムを通じて取り除かれていく方針が公表されています。背景には、`wmic` がマルウェア（悪意のあるソフトウェア）に悪用されやすい仕組みだったこともあり、セキュリティ向上を目的とした整理という側面もあるようです。今後新しく学ぶ場合は、同じような情報を得られる `Get-Volume`（ディスクの容量確認向け）や `Get-PSDrive`（PowerShellのドライブ全般の確認向け）を優先して覚えておくと、将来の環境でも通用しやすくなります。

### 補足: 権限まわりの用語の関係

`whoami /groups` で「自分がどのグループに入っているか」がわかり、`net localgroup administrators` で「そのグループに誰が入っているか」がわかります。さらに `whoami /priv` は所属グループとは別に、自分個人に割り当てられた特権（システム時刻の変更などの特別な操作の許可）を示します。そして `icacls` は、これらユーザーやグループが「特定のファイル・フォルダーに対して」どこまで読み書きできるかを表すACL（アクセス制御リスト）を確認するコマンドです。一言でいうと、「グループに入る（whoami /groups・net localgroup）→ 特権を持つ（whoami /priv）→ 個々のファイルへのアクセス権が決まる（icacls）」という流れでつながっています。

## 6. PowerShell 入門ブリッジ（コマンドプロンプトの次のステップ）

コマンドプロンプトに慣れてきたら、次のステップとして「PowerShell（パワーシェル）」という、もう一つのコマンド操作画面を知っておくと将来役立ちます。コマンドプロンプトが文字（テキスト）のやり取りを基本にしているのに対し、PowerShell は「オブジェクト（プロセスやファイルなどの情報のかたまり）」をそのままやり取りできる点が大きな違いで、サーバー管理や自動化（作業を自分の代わりに実行させること）に強い後継ツールとして、実務でもよく使われています。

### PowerShell の開き方

Windows キーを押して「PowerShell」と入力し、表示された「Windows PowerShell」（青いアイコン）をクリックすると起動できます。コマンドプロンプトの画面から呼び出したい場合は、`cmd` の中で `powershell` と入力して Enter を押しても開けます（元のコマンドプロンプトに戻りたいときは `exit` と入力します）。なお、Windows にはじめから入っているこの「Windows PowerShell」（5.1 系）とは別に、Microsoft が開発を続けている新しい「PowerShell」（7 系。黒いアイコンで、使いたい場合は別途インストールが必要）も存在しますが、この章では追加インストールなしにすぐ使える Windows PowerShell を前提に説明します。一言でいうと、コマンドプロンプトの「上位互換の画面がもう一つ増えた」とイメージすると分かりやすいです。

### コマンドレットの命名規則「動詞-名詞」

PowerShell の命令のことを「コマンドレット（cmdlet。PowerShell の命令ひとつひとつのこと）」と呼びます。コマンドレットには `動詞-名詞` という共通のルールがあり、たとえば `Get-Process`（プロセスを取得する）、`Stop-Service`（サービスを止める）のように、「何をするか（動詞）」と「何に対してか（名詞）」が必ずハイフンでつながっています。この規則のおかげで、名前をうろ覚えでも「プロセスを取得したいから Get-Process かな」と推測しやすいのが PowerShell の特徴です。

名前を思い出せないときや使い方を確認したいときは、`Get-Help` と `Get-Command` が強い味方になります。この2つに加えて、コマンドプロンプトからの移行でまず使うことになる基本的なコマンドレットを、目的別に次の表にまとめました。

| やりたいこと | コマンド（書式） | 実行例 | 覚え方・注意点 |
| --- | --- | --- | --- |
| コマンドレットの具体的な使い方（実行例）を見たい | `Get-Help <コマンドレット名> -Examples` | `Get-Help Get-Process -Examples`<br>Get-Process の使用例だけが表示される | 困ったらまず Get-Help。初回実行時はヘルプ本体のダウンロード（`Update-Help`。Windows PowerShell では管理者権限とネット接続が必要）を促されることがある |
| 名前がうろ覚えのコマンドレットを探したい | `Get-Command <検索語を含むパターン>` | `Get-Command *service*`<br>名前に service を含むコマンドレット一覧が表示される | `*`（ワイルドカード。「任意の文字列」を表す記号）で前後を挟むと部分一致検索になる |
| 動いているプロセス（起動中のプログラム）の一覧を見たい | `Get-Process` | `Get-Process`<br>実行中の全プロセスが CPU 使用率などと一緒に一覧表示される | タスクマネージャーの「プロセス」タブに相当 |
| 特定のプロセスを強制終了したい | `Stop-Process -Name <プロセス名>` または `-Id <プロセスID>` | `Stop-Process -Name notepad`<br>起動中のメモ帳がすべて強制終了する | ⚠️ 保存していない内容は失われる。名前を指定すると同名プロセスが複数ある場合すべて終了するので注意。自分以外のユーザーが起動したプロセスを終了するには管理者として実行する必要があり、確認メッセージを省略したいときは `-Force` を付ける |
| Windows サービスの状態一覧を見たい | `Get-Service` | `Get-Service`<br>Status 列に Running（実行中）／Stopped（停止中）などが表示される | 「サービス（services.msc）」画面のコマンド版というイメージ |
| サービスを開始／停止したい | `Start-Service <サービス名>` / `Stop-Service <サービス名>` | `Stop-Service -Name Spooler`<br>印刷スプーラーサービスが停止する | ⚠️ 管理者として実行する必要がある場合が多く、システムに関わるサービスを止めると他の機能が使えなくなることがある。他のサービスがそのサービスに依存していると停止に失敗することがあり、依存先も含めて止めるには `-Force` が必要になる |
| フォルダの中身一覧を見たい（dir 相当） | `Get-ChildItem` | `Get-ChildItem`<br>今いるフォルダのファイルとサブフォルダの一覧が表示される | 慣れないうちはエイリアス（別名）の `dir` や `ls` と打っても同じ結果になる |
| フォルダを移動したい（cd 相当） | `Set-Location <パス>` | `Set-Location C:\Users`<br>カレントフォルダが C:\Users に移動する | エイリアス `cd` も使える。パスにスペースがあれば " " で囲む |
| 今いる場所（カレントフォルダ）を確認したい | `Get-Location` | `Get-Location`<br>現在のパスが表示される | 引数なしの `cd` を打ったときの結果に相当 |
| ファイルをコピーしたい | `Copy-Item <コピー元> <コピー先>` | `Copy-Item report.txt D:\backup\`<br>report.txt が D:\backup フォルダにコピーされる | ⚠️ コピー先に同じ名前のファイルがあると、確認なしに上書きされる（読み取り専用ファイルを上書きするときだけ `-Force` が必要）。フォルダごとコピーするときは `-Recurse` オプションを付ける |
| ファイルを移動・名前変更したい | `Move-Item <移動元> <移動先>` | `Move-Item old.txt archive\old.txt`<br>old.txt が archive フォルダへ移動する | 移動先に別名を指定すると、リネーム（名前変更）としても使える。移動先に同名ファイルがあるとエラーになり、上書きするには `-Force` が必要 |
| ファイルやフォルダを削除したい（del 相当） | `Remove-Item <パス>` | `Remove-Item temp.txt`<br>temp.txt が削除される | ⚠️ ゴミ箱を経由せず完全に削除される。中身のあるフォルダを削除しようとすると確認を求められることがあり、`-Recurse` を付けると中身ごと一括で削除できる |
| テキストファイルの中身を画面に表示したい（type 相当） | `Get-Content <ファイル名>` | `Get-Content log.txt`<br>log.txt の内容がそのまま画面に表示される | エイリアス `type` や `cat` でも同じ結果になる |
| ファイルの中から特定の文字列を含む行を探したい（Linux の grep に近い） | `Select-String -Pattern <検索文字列> -Path <ファイル名>` | `Select-String -Pattern "Error" -Path log.txt`<br>"Error" を含む行番号と内容の一覧が表示される | `Get-Content log.txt \| Select-String "Error"` のように `\|`（パイプ。コマンドの結果を次のコマンドに渡す記号）でつなぐ書き方もよく使われる |

> ⚠️ **注意**：`Stop-Process` はプロセスの強制終了、`Stop-Service` はサービスの停止、`Remove-Item` はファイル・フォルダの削除、`Copy-Item` は同名ファイルへの上書きを、それぞれ確認なしに行うことがあるコマンドです。実行すると元に戻せない、または保存前のデータが失われる可能性があります。特にサーバーの学習では、練習用の環境（自分専用の仮想マシンなど）以外で試さないようにしましょう。不安なときは、多くのコマンドレットが対応している `-WhatIf`（実際には実行せず、何が起きるかだけを確認できるオプション）や `-Confirm`（実行前に確認メッセージを表示させるオプション）を付けて、本番前に動作を確認する習慣をつけると安全です。

### 補足: コマンドプロンプトとの対応表

これまでコマンドプロンプトで覚えたコマンドは、PowerShell では次のコマンドレットに置き換わります。両方の書き方を知っておくと、どちらの画面に出会っても迷わなくなります。

| コマンドプロンプトのコマンド | 対応する PowerShell コマンドレット | 内容 |
| --- | --- | --- |
| `dir` | `Get-ChildItem` | フォルダの中身一覧を表示 |
| `cls` | `Clear-Host` | 画面を消去する |
| `copy` | `Copy-Item` | ファイルをコピーする |
| `del` | `Remove-Item` | ファイルを削除する ⚠️ 元に戻せない |
| `type` | `Get-Content` | ファイルの中身を表示する |
| `cd` | `Set-Location` | フォルダを移動する |
| `echo` | `Write-Output` | 文字列を画面に出力する |

### 補足: なぜ PowerShell では出力を「そのまま」次のコマンドに渡せるのか

コマンドプロンプトでコマンドをつなげると、基本的には「表示された文字」がそのまま次のコマンドに渡されます。一方 PowerShell の `|`（パイプ）は、文字ではなく「プロセスの情報」「ファイルの情報」といったオブジェクトのままデータを受け渡しできるため、`Get-Process | Stop-Process` のように、取得した結果に対してそのまま操作を続けられます。これが、PowerShell が単なる「コマンドプロンプトの見た目違い」ではなく、より高度な自動化に向いていると言われる理由の一つです。

### 補足: 実行ポリシーについて（概要のみ）

PowerShell には「実行ポリシー（スクリプトファイル `.ps1` を実行してよいかどうかのルール）」という仕組みがあり、初期状態では安全のためにスクリプトの実行が制限されていることが一般的です。現在の設定は `Get-ExecutionPolicy` で確認でき、変更したい場合は `Set-ExecutionPolicy` を使いますが、この設定はセキュリティに直結するため、変更方法の詳細は本書では扱いません。実務や学習を進める中で必要になった際は、なぜ制限されているのかを理解したうえで、信頼できる情報源や管理者の指示に従って慎重に設定するようにしましょう。

## 7. リダイレクト・パイプ・キー操作の時短ワザ

ここまでの章では「1つのコマンドをどう打つか」を見てきましたが、実務では**コマンドの結果をファイルに保存したり、別のコマンドに渡して加工したりする**場面がとても多くなります。また、同じコマンドを何度も打ち直す手間を減らすキー操作や、管理者権限が必要な作業のやり方も、日々の作業スピードを大きく左右します。この章では、そうした「地味だけど効く」時短ワザをまとめて紹介します。

| やりたいこと | コマンド（書式） | 実行例 | 覚え方・注意点 |
| --- | --- | --- | --- |
| コマンドの実行結果をファイルに書き出したい（上書き） | `command > ファイル名` | `dir > filelist.txt` <br> カレントフォルダの一覧が `filelist.txt` に保存される（画面には何も表示されない） | ⚠️ 同名ファイルがすでにあると中身がすべて消えて上書きされる。大事なファイル名を指定していないか必ず確認してから実行する |
| コマンドの実行結果をファイルに追記したい | `command >> ファイル名` | `echo 作業完了 >> work.log` <br> 既存の `work.log` の末尾に「作業完了」の行が追加される | `>` は「上書き」、`>>` は「矢印2本＝追記」と覚えると区別しやすい。ファイルが存在しない場合は新規作成される |
| あるコマンドの出力を、別のコマンドの入力としてそのまま渡したい（パイプ） | `command1 \| command2` | `dir \| findstr "sample"` <br> `dir` の一覧結果のうち、「sample」という文字を含む行だけが表示される | パイプ（あるコマンドの出力を、次のコマンドの入力としてそのままつなぐ仕組みのこと）は「配管（パイプ）でデータを流し込む」イメージ。多くの日本語配列キーボードでは、Backspace キーのすぐ左にある `¥` キーを `Shift` と一緒に押すと `\|` が入力できる（このキーは `Shift` なしだと `\`（バックスラッシュ）になる） |
| 大量の出力や文章の中から、特定の文字列だけを探したい | `findstr "文字列" ファイル名` <br> または `command \| findstr "文字列"` | `findstr "エラー" app.log` <br> `app.log` の中から「エラー」を含む行だけを表示する | findstr（ファイルや入力の中から指定した文字列を含む行を検索するコマンド）。既定では大文字・小文字を区別するが、`/i` を付けると区別せずに検索できる（例: `findstr /i "error" app.log`） |
| 出力された行を並べ替えて見やすくしたい | `command \| sort` | `dir /b \| sort` <br> ファイル名の一覧をアルファベット順（五十音・数字も含めて、システムの言語設定に基づく並び順）に並べ替えて表示する | sort は既定では大文字・小文字を区別せず、行の内容を文字として比較して並べ替えるだけで、数値として大小を判断しているわけではない点に注意（"10" が "2" より前に来ることがある） |
| 長い出力を1画面ずつ確認しながら読みたい | `command \| more` | `dir /s \| more` <br> サブフォルダも含めた一覧が1画面分ずつ表示され、続きを見るにはキーを押す | 画面の下に `-- 続行するには何かキーを押してください --` のような表示が出たら、`Space` キーで次のページ、`Enter` キーで1行だけ先に進められる。`Q` キーを押すと途中で終了できる。ずらずら流れて読めない出力があったらまず `\| more` を試す |
| ファイル名やフォルダ名を最後まで打たずに入力したい | Tab キーで補完 | `cd Doc` まで入力して `Tab` キーを押す <br> → `cd Documents\` のように自動的に続きが入力される | 一言でいうと「最初の数文字＋Tab」でよい。候補が複数あるときは Tab を押すたびに候補が順番に切り替わる |
| 少し前に打ったコマンドをもう一度使いたい | 上下矢印キー（↑ / ↓） | ↑キーを1回押す <br> → 直前に実行したコマンドがそのまま表示される（さらに押すとさらに前のコマンドに戻る） | 買い物のレシートを1つずつめくり返すイメージ。表示されたコマンドは Enter を押すまで実行されないので、途中で書き換えてから実行することもできる |
| これまで打ったコマンドの一覧をまとめて見たい（コマンドプロンプト） | F7 キー | コマンドプロンプトの画面で `F7` キーを押す <br> → 画面上に過去に打ったコマンドの一覧がポップアップ表示され、上下キーで選んで Enter で再実行、Esc で閉じられる | コマンド履歴（これまでに入力したコマンドを記録しておく仕組み）をまとめて見返せる機能だが、このポップアップはコマンドプロンプト（cmd.exe）に特有のもの。PowerShell では文字入力の処理を PSReadLine というモジュール（既定で自動的に読み込まれる）が担っており、標準の設定では F7 に何も割り当てられていないため、同じようには動作しない。PowerShell で履歴をたどりたいときは、代わりに `Ctrl + R` （インクリメンタル検索）が使える |
| コマンド履歴をもっと便利に使う仕組みを知りたい | `doskey` （履歴・マクロ管理の仕組み） | `doskey /history` <br> これまでに入力したコマンドの一覧をテキストとして表示する | doskey は、コマンドプロンプトに「コマンド履歴の保存」や「よく使うコマンドに短い別名（マクロ）を付ける」機能を提供する仕組み。まずは「上下矢印キーや F7 で履歴をたどれるのは、この doskey の仕組みが裏で働いているから」と理解しておけば十分 |
| 実行中のコマンドを途中で強制的に止めたい | `Ctrl + C` | `ping -t 8.8.8.8` のように終了しないコマンドを実行中に `Ctrl + C` を押す <br> → コマンドの実行が中断され、プロンプトに戻る | ⚠️ ファイルの書き込みやダウンロードの途中で `Ctrl + C` を押すと、処理が中途半端な状態で止まり、ファイルが壊れたり不完全なまま残ったりすることがある。応答が返ってこないときの「最後の手段」として使う |
| 画面に表示された文字をコピー＆貼り付けしたい（Windows Terminal の場合） | `Ctrl + Shift + C` / `Ctrl + Shift + V` （右クリックの挙動はバージョン・設定による） | コピーしたい範囲をマウスでドラッグして選択し、`Ctrl + Shift + C` でコピー <br> `Ctrl + Shift + V` で貼り付け <br> （右クリックは、選択範囲をそのままコピーする場合や、コピー・貼り付け用のメニューが開く場合など、バージョンや設定によって挙動が異なる） | 通常のアプリで使う `Ctrl + C` / `Ctrl + V` は、コマンドプロンプトでは「強制中断」に使われているため、コピー＆貼り付け用に `Shift` を加えた別のショートカットが用意されている、と覚えると混同しにくい。確実に使えるのはこのキーボードショートカットで、右クリックの動きは環境によって変わることがあると知っておく |
| 管理者権限が必要な作業を行いたい | スタートメニューから「管理者として実行」 | スタートメニューでアプリ（例: 「コマンドプロンプト」）を検索し、アイコンを右クリックして「管理者として実行」を選ぶ <br> → タイトルバーに「管理者」と表示された状態でコマンドプロンプトが起動する | ⚠️ 管理者権限（Windows の設定変更やシステムファイルの操作など、通常より強い操作を許可する権限のこと）が必要なコマンド（ネットワーク設定の変更やサービスの操作など）を、権限なしで実行すると「アクセスが拒否されました」のようなエラーになることが多い。UAC（ユーザーアカウント制御。Windows が「本当に実行してよいか」を確認してくる仕組み）の確認画面が出たら内容を確認してから許可する |
| コマンドの実行結果を、そのままメールやメモ帳に貼り付けたい | `command \| clip` | `ipconfig \| clip` <br> `ipconfig` の実行結果が画面には表示されず、そのままクリップボード（コピーした内容を一時的に保存しておく場所のこと）にコピーされる | コピーした内容は、メモ帳やメールソフトなどで通常どおり `Ctrl + V` で貼り付けられる。長いコマンド結果を人に共有したいときや、そのままドキュメントに貼りたいときに便利 |

> ⚠️ **上書き系の操作に注意**
> `>` によるリダイレクトは、既存ファイルの中身を確認なしに消して上書きします。また、管理者として実行したコマンドプロンプトでは、通常より強い権限で操作できてしまうため、意図しないコマンドの影響範囲も大きくなります。慣れないうちは、大事なファイルやフォルダに対してこれらの操作を行う前に、バックアップを取るか、まずは影響のない場所で試すことをおすすめします。

### 補足: リダイレクトとパイプの違い

リダイレクト（コマンドの出力の行き先を変えること）は「出力を**ファイル**に流し込む」操作で、`>` や `>>` を使います。一方パイプは「出力を**次のコマンド**に流し込む」操作で、`|` を使います。どちらも「コマンドの結果をそのまま画面に表示するのではなく、別の場所に送る」という考え方は同じなので、「行き先がファイルならリダイレクト、行き先が別のコマンドならパイプ」と覚えると整理しやすいです。

### 補足: パイプを組み合わせて使う

`|` は複数回つなげて使うこともできます。たとえば `dir /s /b | findstr ".log" | sort` のように書くと、「サブフォルダも含めた一覧を取得 → `.log` を含む行だけに絞り込む → 並べ替える」という一連の処理を1行で実行できます。一言でいうと、パイプは「小さな道具（コマンド）を数珠つなぎにして、複雑な処理を組み立てる」ための仕組みです。慣れてくると、findstr・sort・more・clip を組み合わせるだけで、専用のツールを使わなくてもかなりの作業がこなせるようになります。

## 8. 安全に使うための注意と困ったときの対処

ここまで紹介してきたコマンドの中には、使い方を誤るとファイルやデータが元に戻せなくなってしまうものがあります。このセクションでは「うっかり事故」を防ぐための心構えと、エラーが出たときに慌てずに調べる方法を身につけます。一言でいうと、「怖いコマンドを知っておく」ことと「困ったときの調べ方を知っておく」ことが、安全にコマンド操作を続けるための一番の武器です。コマンドプロンプトだけでなく、PowerShell（より新しいコマンドライン環境）にも同じように注意が必要な操作があるので、あわせて見ていきましょう。

### 特に注意したい危険なコマンド一覧

| やりたいこと | コマンド（書式） | 実行例 | 覚え方・注意点 |
| --- | --- | --- | --- |
| フォルダ内のファイルを一括削除したい | `del /s /q <パス>` | `del /s /q C:\work\*.log`<br>指定フォルダとそのサブフォルダに含まれるログファイルをまとめて削除する | ⚠️ `/q`（quietの略で確認メッセージを省略する）を付けると、ワイルドカード（`*` などファイル名の一部を「何でもよい」として扱う記号）で複数ファイルを一括指定したときに出る「本当によろしいですか」という確認が省略され、即実行される。ファイル名を1つだけ指定する削除では元々確認が出ないことが多いので、`/q`が特に効いてくるのはワイルドカード使用時だと覚えておくとよい。指定を間違えると、意図しないファイルまで消える |
| フォルダごと丸ごと削除したい | `rd /s /q <フォルダ>` | `rd /s /q C:\temp\old`<br>指定フォルダとその中身をすべて削除する | ⚠️ `/s`（サブフォルダも含めてツリーごと削除する）と`/q`（確認なしで実行する。ただし`/s`と組み合わせたときに効果を持つ）の組み合わせは、フォルダ名を一文字間違えただけで大事なフォルダごと消してしまう。実行前に必ずパスを見直す |
| PowerShellでフォルダごと強制的に削除したい | `Remove-Item -Recurse -Force <パス>` | `Remove-Item -Recurse -Force C:\temp\old`<br>指定フォルダとその中身をすべて削除する | ⚠️ `-Recurse`（サブフォルダも含めてすべて処理する）と`-Force`（読み取り専用や隠しファイルも含め、確認なしで削除する）を組み合わせると、`rd /s /q`と同じくらい一瞬でフォルダが消える。実行前に`-WhatIf`（実際には実行せず、何が起きるかだけ表示してくれるオプション）を付けて`Remove-Item -Recurse -Force C:\temp\old -WhatIf`のように試し打ちすると安全 |
| ドライブを初期化したい | `format <ドライブ文字>:` | `format D:`<br>Dドライブの中身をすべて消してまっさらな状態に戻す | ⚠️ 指定したドライブの中身は原則すべて消える。Windowsが起動して使っているドライブ（多くの場合C）は、OS自身がそのドライブを使用中のため通常はロックされていてフォーマットに失敗することが多いが、これはあくまで「巻き込まれにくい」というだけの話。CドライブでないドライブやUSBメモリ、外付けHDDなどは稼働中でも普通にフォーマットできてしまうので、ドライブ文字を打ち間違えるとそちらの大事なデータが消える |
| ディスクの中身を完全に消去したい | `diskpart` の中で `clean` | `diskpart`（管理者権限で起動が必要）→ `list disk`（接続されているディスクの一覧と番号・サイズを確認）→ `select disk 1` → `clean`<br>選択したディスクのパーティション情報を消去する | ⚠️ `select disk` で番号を間違えると、システムが入っている本体のディスクを消してしまう危険があるため、`select disk`の前に必ず`list disk`でディスク番号とサイズを見比べて確認する。`clean`はパーティション情報を消すだけで元データが残っていることもあるため、より確実にデータ復元を防ぎたい場合（PCを譲渡・廃棄するときなど）は全セクタを上書きする`clean all`を使う、という違いも知っておくとよい。慣れないうちは触らないのが無難 |
| ファイルの見た目・扱いを変えたい（隠す/読み取り専用にするなど） | `attrib +h +s +r <ファイル>` | `attrib +h myfile.txt`<br>ファイルを隠しファイルにする<br>元に戻したいときは`attrib -h myfile.txt`のように`-`（マイナス）を付けて実行する | 乱用すると、自分でファイルを隠しファイルや読み取り専用にしたまま忘れてしまい、「ファイルが見つからない」「保存できない」と混乱する原因になる。`+s`（システムファイル用の属性）は本来Windows自体が使うためのものなので、普段のファイルには付けないほうが無難。また`+h`や`+s`を付けたファイルは、先にその属性を解除しないと他の属性を変更できないという制限があることも覚えておく |
| ファイルやフォルダの所有者・アクセス権を変更したい | `takeown /f <パス>`<br>`icacls <パス> /grant <ユーザー>:<権限>` | `takeown /f C:\data\report.docx`<br>ファイルの所有者を自分に変更する | ⚠️ システムフォルダ（`C:\Windows` など）に対して乱用すると、Windows自体の権限設定が崩れて正常に動かなくなることがある。個人のファイル以外では慎重に。`takeown`は「所有者」を変更するだけなので、実際に読み書きできるようにするには`icacls`で改めて権限を付与する必要がある場合が多い。どちらも管理者権限のコマンドプロンプトで実行するのが基本 |
| パソコンをシャットダウンしたい | `shutdown /s /t <秒数>` | `shutdown /s /t 0`<br>0秒後（=即座）にシャットダウンする | ⚠️ 保存していない作業がすべて失われる可能性がある。`/t`を省略すると既定で30秒の待ち時間が入るが、`/t 0`のように0を指定すると待ち時間なしで即座に実行されるため特に誤爆しやすい。誤って実行してしまっても、待ち時間が残っているうちに別のコマンドプロンプトやPowerShellのウィンドウで`shutdown /a`を実行すれば中止できる（`/t 0`の場合は間に合わない）。再起動したいときは`/s`の代わりに`/r`を使う |
| Windowsの設定情報を直接書き換えたい | `regedit` を起動してレジストリを編集 | `regedit`<br>レジストリエディタ（Windowsの設定情報を保存しているレジストリ〈大きな設定データベースのようなもの〉を直接編集する画面）を開く | ⚠️ 意味が分からないままキーや値を書き換えると、Windowsが起動しなくなることがある。編集前にバックアップ（エクスポート）を取るのが基本。コマンドラインから該当キーだけをバックアップしたい場合は`reg export <キー名> backup.reg`のような形でも取得できる |

> ⚠️ 上の表にあるコマンドは、いずれも「実行した瞬間に取り返しがつかない」可能性がある操作です。特に `del`・`rd`・`Remove-Item -Force`・`format`・`diskpart` の `clean` はファイルやディスクの中身を直接消すため、練習のときは必ず「消えても困らないテスト用のフォルダ」で試すようにしましょう。パスやドライブ文字、ディスク番号を打つ前に、もう一度見直す癖をつけると事故を大きく減らせます。

### 補足: 「ゴミ箱を経由しない削除がある」という心構え

普段エクスプローラーでファイルを削除すると、いったんゴミ箱に入るので間違えても復元できます。しかし、コマンドプロンプトの `del`・`rd` や PowerShell の `Remove-Item` は、既定（何も設定しない場合の標準の動作）ではゴミ箱を経由せず、その場でファイルを消してしまいます。つまり「あとで戻せるはず」という感覚のままコマンドで削除すると、実際には戻せないことがあるということです。大事なファイルを削除する前には、別の場所にコピーを取っておくと安心です。

### 補足: 実行前に `/?` や `Get-Help` でヘルプを確認する習慣

意味がよく分からないコマンドやオプションをそのまま実行するのは、初めて訪れる建物で案内図を見ずに進むようなものです。実行前に一度立ち止まって、そのコマンドが何をするものか確認する習慣をつけましょう。

- コマンドプロンプトでは、コマンド名の後ろに `/?` を付けると使い方が表示されます。例: `del /?`
- PowerShellでは、コマンドレット（PowerShellの命令ひとつひとつのこと）名の前に `Get-Help` を付けます。例: `Get-Help Remove-Item`
- 特に「削除」「フォーマット」「シャットダウン」など、元に戻せない可能性のある単語を含むコマンドを打つときは、実行前のヘルプ確認を必須の一手間にしておくと安全です。

### 補足: PowerShellの `-WhatIf` `-Confirm` で「試し打ち」する

PowerShellの多くのコマンドレット（ファイルを変更・削除するものなど）には、共通のオプションとして `-WhatIf` と `-Confirm` が用意されています。`-WhatIf` を付けて実行すると、実際には何も変更せず「実行した場合に何が起きるか」だけを表示してくれます。`-Confirm` を付けると、実行の直前に1件ずつ確認を求められます。危険そうなコマンドほど、いきなり本番実行するのではなく、まず `-WhatIf` で試してから本番を実行する、という手順を習慣にすると事故を防ぎやすくなります。

### よくあるエラーメッセージの意味

エラーが出ても、多くの場合は落ち込む必要はありません。エラーメッセージは「ここが原因かもしれません」というヒントです。代表的なものを知っておくと、慌てずに対処できます。

| エラーメッセージ（例） | 意味 | よくある原因・対処法 |
| --- | --- | --- |
| `'xxx' は、内部コマンドまたは外部コマンド、操作可能なプログラムまたはバッチ ファイルとして認識されていません。` | 入力したコマンド名をコマンドプロンプトが理解できなかった、という意味 | コマンド名のスペルミス、または PATH（コマンドを探しに行くフォルダの一覧のこと）にそのプログラムの場所が登録されていないことが多い。スペルを確認し、正しいフォルダから実行するか PATH の設定を見直す |
| `用語 'xxx' は、コマンドレット、関数、スクリプト ファイル、または操作可能なプログラムの名前として認識されません。` | PowerShellで、上と同じように「コマンド名を理解できなかった」ことを伝える、PowerShell側の言い回し | 原因・対処法はコマンドプロンプトの場合とほぼ同じ（スペルミス・PATHの見直し）。加えて、必要なモジュール（追加のコマンド群をまとめたもの）がまだ読み込まれていないだけ、というケースもあるので、そのコマンドが特定のモジュールに属していないか確認する |
| `アクセスが拒否されました。` | 操作する権限がない、または対象が使用中である、という意味 | 管理者権限（Administrator権限。Windowsの設定やシステムファイルを変更できる強い権限のこと）が必要な操作を一般権限で実行しようとした、ファイルが他のアプリで開かれたまま使用中、読み取り専用属性が付いている、などが考えられる。管理者としてコマンドプロンプトを開き直す、ファイルを閉じてから再実行する |
| `〜.ps1 を読み込むことができません。このシステムでは、スクリプトの実行が無効になっているため、ファイル 〜.ps1 を読み込むことができません。` | PowerShellの実行ポリシー（スクリプトファイルを実行してよいかどうかを制御する安全装置のような設定）によって、スクリプトの実行がブロックされている、という意味 | 通常のWindows（クライアント向けエディション）では既定で「Restricted」（スクリプトの実行を全面的に禁止する設定）になっていることが多く、`.ps1`ファイルを初めて実行しようとしたときに出やすい。`Get-ExecutionPolicy` で現在の設定を確認し、必要に応じて管理者の指示のもとで設定を変更する（設定変更はセキュリティに関わるため、自己判断で緩めすぎないよう注意） |

### 困ったときの調べ方

エラーが出たとき、あるいはコマンドの動きが予想と違ったときは、次の順番で調べると効率的です。

1. まずはそのコマンド名に `/?` を付けて実行し、公式の使い方を確認する（例: `xcopy /?`）
2. PowerShellのコマンドレットなら `Get-Help <コマンドレット名> -Online` を実行すると、より詳しいオンラインのドキュメントがブラウザで開かれる場合がある（例: `Get-Help Remove-Item -Online`）
3. それでも解決しない場合は、エラーメッセージやコマンド名をそのまま検索キーワードにして、Microsoft Learn（Microsoft公式のドキュメントサイト）を検索する

エラーメッセージは全文をそのままコピーして検索すると、同じ症状の情報が見つかりやすくなります。「自分だけが困っている」と思いがちですが、たいていのエラーは他の人も一度は経験しているものなので、焦らず一つずつ調べていきましょう。

## 安全に使うための共通ルール

- 練習は、消えても困らない検証用の環境（自分専用の VM やテスト用フォルダなど）で行う
- ファイルの削除・上書き・フォーマットなど、元に戻せない可能性がある操作の前には、対象のパスやドライブ文字を必ず見直す
- 使い方に自信が持てないコマンドは、まず `/?` や `Get-Help`、`-WhatIf` のような読み取り専用・確認用のオプションで挙動を先に確認する
- 管理者権限（Administrator 権限）が必要な操作は、「何が・どこまで変わるのか」を理解してから実行する
- ワイルドカード（`*` や `?`）や `/s`・`/q`・`-Recurse`・`-Force` のような「まとめて」「確認なしで」処理するオプションは、組み合わせるほど影響範囲が広がることを意識する
- エラーが出ても慌てず、まずはメッセージ全文を読み、`/?` や公式ドキュメント（Microsoft Learn）で調べる
- 大事なファイルやシステムに影響する操作の前には、バックアップやスナップショットを取っておく
