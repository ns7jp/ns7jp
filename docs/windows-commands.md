# Windows コマンド集（初心者向け）

このページは、未経験からサーバー構築・運用エンジニアを目指す人が、Windows のコマンドプロンプトと PowerShell の基本コマンドを**目的から逆引きする**ための保存版リファレンスです。[やさしい用語・見方ガイド](./beginner-guide.md)で「なぜ動くか」の役割を押さえたあと、実際に手を動かして確かめるときに、このページを開いてください。姉妹ドキュメントの[Linux コマンド集](./linux-commands.md)とあわせて使うと、両方の OS での操作の共通点・違いも把握しやすくなります。

## 使い方

全部を暗記する必要はありません。「困りごと → 打つコマンド → 何を見て判断するか」の3点セットで覚え、細かいオプションは必要になったときに `コマンド名 /?`（コマンドプロンプト）や `Get-Help コマンドレット名`（PowerShell）で調べる習慣をつけます。見出しから目的に近いセクションを探し、そこだけ読めば使える構成にしています。

## 安全に練習するための注意

- 本番環境ではなく、壊しても困らない VM や検証用の Windows 環境で練習してください
- `del`、`rd /s`、`Remove-Item`、`format`、`diskpart` などの操作は元に戻せない、またはディスクの中身やシステムの動作に影響する操作です。実行前に `dir` や `-WhatIf` などで対象を確認してから実行してください
- 各セクションには、破壊的な操作に対して同様の注意書き（⚠️）を添えています。見出しだけ拾い読みせず、実行前に必ず目を通してください

> **注記**: このドキュメントは、コマンドの仕様や一般的な既定の挙動をもとにまとめた参考資料であり、この AI 支援セッションには実際に Windows を操作できる環境が無いため、記載しているコマンドを実機で実行して確認したものではありません。Windows のバージョンや設定によって挙動・表示・既定値が異なる場合があるため、初めて実行するコマンドやシステムを変更する操作の前には、`コマンド名 /?`（コマンドプロンプト）や `Get-Help`（PowerShell）、公式ドキュメント（Microsoft Learn）で確認してください。

## 基本操作・移動・自分の状況を知る

コマンドプロンプト（キーボードで文字を入力してパソコンを操作する黒い画面のこと）を開いて最初にやるべきことは、難しい設定変更ではなく「今どこのフォルダにいるか」「自分がどのユーザーとしてログインしているか」「このマシンで何ができるか」を確認することです。このカテゴリでは、フォルダの中身の確認と移動、画面や自分の状況の確認、そして分からないことをその場で調べる方法という、この先どのカテゴリに進んでも土台になる基本コマンドをまとめます。まずは壊れても困らない練習用のフォルダで、実際に手を動かしながら覚えていきましょう。

| やりたいこと | コマンド | 例 | 確認・判断のポイント |
| --- | --- | --- | --- |
| 今いるフォルダの中身を一覧表示したい | `dir` | `dir` | `<DIR>` の表示があるかどうかでフォルダかファイルかを見分ける |
| ファイル名だけを横に並べてコンパクトに見たい | `dir /w` | `dir /w` | ファイル数が多いフォルダで全体をざっと把握できているか |
| 一覧が多いとき1画面ずつ止めて見たい | `dir /p` | `dir /p` | 「続行するには何かキーを押してください」で表示が止まるか |
| 別のフォルダへ移動したい | `cd` | `cd Documents`<br>`cd C:\Users\test\Desktop`<br>`cd ..` | 移動後に `cd`（パスなし）や `dir` で今の場所を確認する |
| 画面を整理したい | `cls` | `cls` | 消えるのは画面表示だけで、ファイル操作の結果には影響しない |
| コマンドプロンプトを終了したい | `exit` | `exit` | ウィンドウが閉じることで終了したと分かる |
| コマンドの使い方を自分で調べたい | `help` / `コマンド名 /?` | `help`<br>`dir /?` | 知りたいオプションの説明が見つかるか |
| フォルダの構造を見取り図で見たい | `tree /f` | `tree /f` | 深い階層・ファイル数が多いフォルダで出力が膨大になっていないか |
| コマンドの実体（exeファイルなど）がどこにあるか探したい | `where` | `where python` | PATHの中のどのフォルダから見つかったか、複数ヒットしていないか |
| 今使っているマシンの名前を確認したい | `hostname` | `hostname` | 想定しているコンピューター名と一致しているか |
| Windowsのバージョン番号を確認したい | `ver` | `ver` | ビルド番号が想定しているバージョンと一致しているか |
| 今ログインしているユーザーを確認したい | `whoami` | `whoami` | 表示が想定しているアカウント名かどうか |
| 今日の日付だけを確認したい | `date /t` | `date /t` | `/t` を付け忘れて変更モードに入っていないか |
| 今の時刻だけを確認したい | `time /t` | `time /t` | `/t` を付け忘れて変更モードに入っていないか |

### dir --- フォルダの中身を一覧表示する

`dir`（directory の略で、指定したフォルダの中身を一覧表示するコマンド）は、コマンドプロンプトで一番よく使うコマンドといっても過言ではありません。実行すると、今いるフォルダに含まれるファイルとフォルダの名前・サイズ・最終更新日時が表示され、フォルダには `<DIR>` という印が付きます。マウスでエクスプローラーを開かなくても、今いる場所に何があるかをすぐ確認できます。

オプションを付けると見え方を変えられます。`/w`（wide の頭文字）はファイル名だけを複数列に並べてコンパクトに表示し、`/p`（pause の略）はファイル数が多くて1画面に収まらないときに1画面ごと表示を止めてくれます。

```bat
REM 基本形: 今いるフォルダの中身を一覧表示する
dir

REM /w: ファイル名だけを横に並べてコンパクトに表示する
dir /w

REM /p: 1画面表示するたびに一時停止する（ファイルが多いフォルダ向け）
dir /p
```

出力例（`dir`）です。実際の表示は Windows のバージョンや言語設定によって多少異なりますが、次のように表示されることが多いです。

```text
 ドライブ C のボリューム ラベルは Windows です
 ボリューム シリアル番号は XXXX-XXXX です

 C:\Users\test\Documents のディレクトリ

2026/09/01  10:15    <DIR>          project
2026/09/03  09:50               220 memo.txt
               1 個のファイル                 220 バイト
               1 個のディレクトリ  xxx,xxx,xxx,xxx バイトの空き領域
```

**確認・判断のポイント**: 先頭近くに `<DIR>` と表示されている行はフォルダ、数字（バイト数）が表示されている行はファイルです。サイズが `0` のまま増えていないか、更新日時が想定通りかは、作業の確認でもよく見る箇所です。

**つまずきやすい点**: `dir` は既定では隠しファイルやシステムファイル（`+h` や `+s` の属性が付いたファイル）を一覧に表示しません。「ファイルが無い」と思っても、実際には属性で隠れているだけのことがあります（すべて表示したい場合は `dir /a` のようにオプションを追加します）。また `/w` と `/p` は `dir /w /p` のように組み合わせて使うこともできます。

### cd と cd .. --- 別の場所へ移動する

`cd`（change directory の略）は、コマンドプロンプトで今作業しているフォルダを切り替えるコマンドです。指定の仕方には、ドライブの根元（`C:\` など）からの完全な道順を書く**絶対パス**と、今いる場所を基準にした道順を書く**相対パス**の2種類があります。たとえば `cd C:\Users\test\Desktop` は絶対パスで指定した例、`cd Documents` は今いるフォルダの中の Documents フォルダへ移動する相対パスの例です。1つ上の階層（親フォルダ）へ戻りたいときは `cd ..` という特別な書き方を使います。

```bat
REM 絶対パス: ドライブの根元からの完全な道順を指定する
cd C:\Users\test\Desktop

REM 相対パス: 今いる場所を基準にした道順を指定する
cd Documents

REM 1つ上の階層(親フォルダ)へ戻る
cd ..

REM ..を\でつなぐと複数階層まとめて上がれる
cd ..\..

REM 別ドライブのフォルダへ、ドライブごと確実に切り替えて移動する
cd /d D:\work

REM 引数なしの cd は、今いる場所(パス)を表示する
cd
```

出力例（存在しないフォルダを指定した場合）です。次のようなエラーが表示されることが多いです。

```text
指定されたパスが見つかりません。
```

**確認・判断のポイント**: `cd` は移動に成功しても何も表示せず、静かに移動するだけです。移動できたかどうかは、引数なしの `cd` や `dir` で確認します。

**つまずきやすい点**: `cd` だけでは別のドライブへは移動できません。たとえば C ドライブにいる状態で `cd D:\work` と実行しても、プロンプトの表示は `C:\...` のままで変化せず、実際のドライブも C のままです。この操作は「次に D ドライブへ切り替えたときに、そのドライブ側でカレントフォルダとして扱う場所」を裏側で覚えさせているだけで、見た目には何も起きません。そのため「移動できていないのでは」と勘違いしやすい動きになります。別ドライブへ確実に移動したいときは `cd /d D:\work` のように `/d` オプションを付けるか、先に `D:` とだけ入力してドライブを切り替えてから `cd` を使います。またフォルダ名にスペースが含まれる場合は `cd "Program Files"` のように `" "`（ダブルクォート）で囲む必要があります。

### cls --- 画面を整理する

`cls`（clear screen の略）は、コマンドプロンプトの画面に表示されている文字をすべて消して、まっさらな状態に戻すコマンドです。`dir` や `tree` を何度も実行して画面が文字で埋まってきたときに、見た目をスッキリさせるために使います。

```bat
cls
```

**確認・判断のポイント**: 実行すると画面が空白になり、入力待ちの記号（プロンプト）だけが左上に残ります。それ以外の変化はありません。

**つまずきやすい点**: `cls` が消すのは画面の表示だけで、それまでに実行した操作の結果（作成・削除したファイルなど）には一切影響しません。何か操作を間違えたと思って焦って `cls` を打っても、失敗した操作が元に戻るわけではない点に注意してください。

### exit --- コマンドプロンプトを終了する

`exit` は、開いているコマンドプロンプトのウィンドウを閉じるコマンドです。ウィンドウ右上の × ボタンをクリックするのと同じ結果になりますが、キーボードだけで操作を完結できます。

```bat
exit
```

**確認・判断のポイント**: 実行するとウィンドウそのものが閉じます。閉じたことがそのまま実行結果の確認になります。

**つまずきやすい点**: バッチファイル（複数のコマンドをまとめて実行するファイル）の中で `exit` を使うと、状況によってはコマンドプロンプト自体を終了させてしまい、それ以降の行が実行されなくなります。バッチファイルの処理だけを終わらせて、コマンドプロンプトのウィンドウ自体は開いたままにしたい場合は、`exit /b` のように `/b`（batch の略）を付けます。

### help と コマンド名 /? --- コマンドの使い方を自分で調べる

すべてのコマンドとオプションを暗記する必要はありません。困ったときにその場で調べる方法を知っていれば十分です。`help` は、コマンドプロンプトに組み込まれている内部コマンドの一覧と簡単な説明を表示します。一方、`コマンド名 /?` は、その1つのコマンドについて、使えるオプションをより詳しく確認したいときに使います。

```bat
REM 使えるコマンドの一覧をざっと確認する
help

REM 特定のコマンドの詳しい使い方(オプション)を見る
dir /?

REM help経由でも、コマンド名を指定すれば同じような説明が見られることが多い
help dir
```

**確認・判断のポイント**: `help` は一覧性が高く「そもそもどんなコマンドがあるか」を眺めるのに向いています。`コマンド名 /?` はそのコマンド1つに絞った詳しい説明が表示されるため、オプションの意味を確認したいときはこちらのほうが早く目的の情報にたどり着けます。

**つまずきやすい点**: `help` の一覧に載るのは、Windows に標準で付属しているコマンドだけです。あとから自分でインストールしたツール（`git` や `python` など）は、コマンドプロンプトから実行できても `help` の一覧には出てきません。また、これは PowerShell の `Get-Help` とは別の仕組みなので、PowerShell の画面では `help` や `/?` の代わりに `Get-Help コマンドレット名` を使う必要があります（PowerShell については別カテゴリで扱います）。

### tree（/f）--- フォルダ構造をひと目で見る

`tree` は、フォルダの中身を親子関係のまま木の形で表示するコマンドです。`dir` で1つずつフォルダを覗いて回らなくても、フォルダ全体の見取り図を一度に把握できます。既定ではフォルダの構造だけが表示され、ファイル名は表示されません。ファイル名も一緒に表示したい場合は `/f` オプションを付けます。

```bat
REM 今いるフォルダ以下の構造を木構造で表示する(フォルダのみ)
tree

REM /f: ファイル名も一緒に表示する
tree /f
```

出力例（`tree /f`）です。パスを指定せずに実行した場合、一番上の行は今いるフォルダのフルパスではなく `C:.`（ドライブ名 + ピリオド、「このドライブの今の場所」という意味）の形で表示されます。それ以外の部分も含め、次のように表示されることが多いです。

```text
フォルダー パスの一覧
ボリューム シリアル番号は XXXX-XXXX です
C:.
├───docs
│       README.md
│
└───src
        main.py
```

**確認・判断のポイント**: フォルダの階層構造がひと目で把握できているか、想定していないフォルダやファイルが紛れ込んでいないかを確認します。

**つまずきやすい点**: `/f` を付けないとファイル名は表示されないため、「ファイルが無い」と勘違いしやすい点に注意してください。逆に、階層の深いフォルダや `node_modules` のようにファイル数の多いフォルダで実行すると、出力が非常に長くなり画面が埋まってしまいます。出力が多いときは `tree /f | more` のように `more` と組み合わせて1画面ずつ確認すると見やすくなります。さらに、`tree /f > list.txt` のように出力をファイルへリダイレクトしてメモ帳などのテキストエディタで開くと、罫線に使われている `├` や `│` などの記号が文字化けして見えることがあります。これはコマンドプロンプトが使っている既定の文字コードと、エディタ側が想定する文字コードが一致していないために起こる表示上の問題で、内容自体が壊れているわけではありません。

### where --- コマンドの実体がどこにあるか探す

`where` は、入力したコマンド名の実体（`.exe` ファイルなど）が、PATH（コマンドを探しに行くフォルダーの一覧が入った設定）に登録されているフォルダーの中のどこにあるかを探して、そのフルパスを表示するコマンドです。同じ名前のコマンドが複数の場所にインストールされていて、実際にどちらが使われているのか分からないときに便利です。

```bat
where python
```

出力例です。次のように表示されることが多いです。

```text
C:\Users\test\AppData\Local\Programs\Python\Python312\python.exe
```

**確認・判断のポイント**: 複数の行が表示された場合、一番上に表示されたものが実際にそのコマンド名を打ったときに使われる実体です（PATH の中で先に見つかったものが優先されるため）。想定と違うバージョンが一番上に出てきた場合、PATH の並び順を見直す手がかりになります。

**つまずきやすい点**: `where` は既定で、今いるフォルダと PATH に登録されているフォルダーの中しか探しません。ファイル自体はパソコンの中に存在していても、そのフォルダーが PATH に登録されていなければ「情報: 指定されたパターンのファイルが見つかりませんでした。」のようなメッセージになり、「ファイルが存在しない」わけではなく「PATH が通っていない」だけ、というケースがよくあります。

### hostname --- 今使っているマシンの名前を確認する

`hostname` は、今操作しているパソコンのコンピューター名（ネットワーク上でそのマシンを識別するための名前）を1行だけ表示するシンプルなコマンドです。リモートデスクトップや複数のサーバーを行き来しながら作業していると、今どのマシンを操作しているか見失いがちなので、作業を始める前に確認する習慣をつけます。

```bat
hostname
```

出力例です。次のように表示されることが多いです。

```text
DESKTOP-ABC123
```

**確認・判断のポイント**: 表示されたコンピューター名が、今から作業しようとしているマシンと一致しているかを確認します。複数のウィンドウを開いて別々のサーバーに接続しているときに特に有効です。

**つまずきやすい点**: `hostname` が表示するのはあくまで「コンピューター名」であり、IP アドレスやユーザー名は含まれません。ネットワーク上の住所（IP アドレス）まで確認したい場合は、別カテゴリで扱う `ipconfig` を使う必要があります。

### ver --- Windowsのバージョンを確認する

`ver` は、今使っている Windows のバージョン番号を1行で表示するコマンドです。手順書やインストーラーが対応しているバージョンかどうかを手早く確認したいときに使います。

```bat
ver
```

出力例です。次のように表示されることが多いです。

```text
Microsoft Windows [Version 10.0.19045.3803]
```

**確認・判断のポイント**: 表示されたバージョン番号（特に末尾のビルド番号）が、作業しようとしている手順の対象バージョンと一致しているかを確認します。バージョンが古い場合、手順通りに動かない機能がある可能性に気づけます。

**つまずきやすい点**: `ver` で分かるのは内部的なバージョン番号だけで、「Windows 10」か「Windows 11」か、「Home」か「Pro」かといったエディション名までは表示されません。エディションや詳しいシステム情報まで確認したい場合は、別カテゴリで扱う `systeminfo` を使います。

### whoami --- 自分が誰か確認する

`whoami`（who am I、「自分は誰か」の略）は、今コマンドプロンプトにログインしているユーザー名を表示するコマンドです。複数のアカウントを切り替えて作業していたり、管理者権限で開いたウィンドウと通常のウィンドウを行き来していたりすると、「今どのユーザーで操作しているか」を見失いがちなので、作業前に確認する習慣をつけます。

```bat
whoami
```

出力例です。次のように表示されることが多いです。

```text
desktop-abc123\test
```

**確認・判断のポイント**: 表示は「コンピューター名\ユーザー名」の形式になります。この部分が想定しているアカウントと一致しているかを確認します。

**つまずきやすい点**: `whoami` を実行しただけでは、そのユーザーが管理者権限を持っているかどうかまでは分かりません（管理者アカウントでも一般アカウントでも、表示される形式は同じです）。管理者権限があるかどうかを詳しく確認したい場合は `whoami /priv` や `whoami /groups` といった別のオプションを使う必要があります（詳細は別カテゴリで扱います）。

### date /t --- 今日の日付を確認する

`date` は、システムに設定されている今日の日付を確認・変更するコマンドです。確認だけしたい場合は、必ず `/t`（time の略ではなく「表示のみ」を意味するオプション）を付けて実行します。

```bat
REM 今日の日付だけを表示する(変更しない)
date /t
```

出力例です。次のように表示されることが多いです。

```text
2026/09/04
```

**確認・判断のポイント**: 表示された日付が、作業ログやファイルの更新日時と照らし合わせて想定通りかを確認します。

**つまずきやすい点**: ⚠️ `/t` を付けずに `date` だけを実行すると、確認モードではなく「新しい日付を入力してください」という**変更モード**に入ってしまいます。日付の変更には既定で管理者権限が必要なため、管理者権限のないユーザーでは「アクセスが拒否されました。」のようなエラーになり変更されずに済むことが多いのですが、管理者権限で実行しているコマンドプロンプトでは、ここでうっかり数字を入力して Enter を押すと、本当にシステムの日付が書き換わってしまいます。何も入力せずそのまま Enter だけを押せば日付は変わらずに抜けられますが、慣れないうちは焦って数字を打ち込んでしまうことがあります。確認だけしたいときは、常に `/t` を付ける習慣にしてください。

### time /t --- 今の時刻を確認する

`time` は、システムに設定されている現在の時刻を確認・変更するコマンドです。考え方は `date` と全く同じで、確認だけしたい場合は必ず `/t` を付けて実行します。

```bat
REM 今の時刻だけを表示する(変更しない)
time /t
```

出力例です。次のように表示されることが多いです。

```text
14:05
```

**確認・判断のポイント**: 表示された時刻が、作業記録やログの時刻表示とずれていないかを確認します。特に他のサーバーと時刻合わせ（時刻同期）をしている環境では、大きくずれていないかの簡易チェックに使えます。

**つまずきやすい点**: ⚠️ `date` と同じ理由で、`/t` を付けずに `time` だけを実行すると「新しい時刻を入力してください」という変更モードに入ってしまいます。時刻の変更にも既定で管理者権限が必要なので、管理者として実行しているコマンドプロンプトでは特に注意してください。一般ユーザー権限では変更が拒否されることが多い一方、管理者権限のウィンドウでは数字を入力してしまうとそのままシステムの時刻が変わってしまいます。

**⚠️ `date` と `time` は、`/t` を付け忘れると日付・時刻を変更するモードに入ってしまいます。確認だけしたいときは、必ず `/t` オプションを付けて実行してください。特に管理者権限のコマンドプロンプトでは、うっかり数値を入力して Enter を押すと、システム全体の日付・時刻が実際に書き換わってしまいます。**

## ファイル・フォルダの操作

フォルダを作ったり、ファイルをコピー・移動・削除したりする操作は、コマンドプロンプトでもっとも頻繁に使う基本動作です。このカテゴリでは、フォルダの作成・削除、ファイルのコピー・移動・名前変更・削除、中身の確認、属性（ファイルの性質を表す追加情報）の変更、そしてフォルダ単位でまとめてコピーする方法までを扱います。とくに `rd /s` や `del /s /q` のように、確認なしで大量のファイルを一気に消してしまえる操作は、サーバー構築の作業でも事故につながりやすいため、注意点とあわせてしっかり押さえていきましょう。

| やりたいこと | コマンド | 例 | 確認・判断のポイント |
| --- | --- | --- | --- |
| 新しいフォルダを作りたい | `md` / `mkdir` | `md test` | 成功時は何も表示されない。`dir` で作成されたか確認する |
| 空のフォルダを削除したい | `rd` / `rmdir` | `rd test` | 中身が残っていると失敗する（安全装置）。空かどうかは事前に `dir` で確認する |
| ⚠️ フォルダを中身ごと削除したい | `rd /s` | `rd /s /q test` | `/s` で中身ごと削除、`/q` で確認を省略。ゴミ箱を経由せず元に戻せない |
| ファイルをコピーしたい | `copy` | `copy memo.txt D:\backup\` | 「1 個のファイルをコピーしました。」のような件数表示を確認する。フォルダ自体はコピーできない |
| ファイル・フォルダを移動したい（名前変更にも使える） | `move` | `move memo.txt D:\backup\` | 移動後は元の場所から消える。移動先に新しい名前を指定すればリネームとしても使える |
| ファイル・フォルダの名前だけ変更したい | `ren` / `rename` | `ren memo.txt memo_old.txt` | 実行後は無反応なので `dir` で確認する。フォルダをまたぐ移動はできない（それは `move` の役目） |
| ファイルを削除したい | `del` / `erase` | `del memo.txt` | 名前を1つ指定した削除も、`*.log` のような一部だけのワイルドカードによる削除も、既定では確認なしに即削除される。確認が入るのは `*.*`（すべてのファイル）を指定したときだけ |
| ⚠️ 大量のファイルを確認なしで削除したい | `del /s /q` | `del /s /q C:\work\*.*` | `/s` でサブフォルダも含め、`/q` で `*.*` 指定時に出る確認を省略する。実行前にパスとワイルドカードを必ず見直す |
| ファイルの中身を画面で見たい | `type` | `type memo.txt` | 短いテキストファイル向け。バイナリファイルに使うと文字化けした表示になる |
| 長いファイルを1画面ずつ見たい | `more` | `more memo.txt` | 1画面ごとに一時停止する。`q` キーで途中終了できる |
| ファイルの属性を確認・変更したい | `attrib`（`+r`/`-r`、`+h`/`-h`） | `attrib +h memo.txt` | `R`＝読み取り専用、`H`＝隠しファイルを表す。`+` で付与、`-` で解除する |
| フォルダをサブフォルダごとコピーしたい | `xcopy /e /i` | `xcopy C:\work D:\backup\work /e /i` | `/e` で空フォルダも含める、`/i` でコピー先フォルダを自動作成する。最後に表示される件数を確認する |
| より高機能・高信頼にフォルダをコピーしたい | `robocopy /e` | `robocopy C:\work D:\backup\work /e /r:3 /w:5` | ⚠️ 既定では失敗時に最大100万回・30秒間隔で再試行し続ける。`/r` と `/w` で回数と間隔を指定すると安心 |
| 複数のファイルをまとめて指定したい | ワイルドカード `*` `?` | `dir *.txt` | `*` は0文字以上、`?` はちょうど1文字を表す。削除・コピーの前に対象を `dir` で確認する |

### md と mkdir --- 新しいフォルダを作成する

`md`（make directory の略）と `mkdir` は、今いるフォルダの中に新しいフォルダ（ディレクトリともいいます）を作るコマンドです。両者は完全に同じ働きをする別名（エイリアス）どうしで、どちらを使っても結果は変わりません。指定するパス（フォルダの場所を表す文字列）の途中の階層がまだ存在していなくても、Windows のコマンドプロンプトではまとめて作成されるのが既定の挙動です。

```bat
REM 今いるフォルダの中に test という名前のフォルダを作る
md test

REM mkdir でも全く同じ結果になる(md は mkdir の短縮形)
mkdir test

REM 存在しない中間フォルダも含めて、複数階層をまとめて作成できる
md C:\work\project\logs
```

`md` は成功しても何も表示せず、静かにフォルダを作るだけです。作成できたかどうかは `dir` で確認します。すでに同じ名前のフォルダやファイルがある場合は、次のようなエラーが表示されることが多いです。

```text
C:\Users\test>md test
サブディレクトリまたはファイル test は既に存在します。
```

**確認・判断のポイント**: 実行後に何も表示されなければ、たいてい成功しています。`dir` を打って、目的のフォルダが増えているかを確認する習慣をつけましょう。エラーメッセージが出た場合は、同名のフォルダ・ファイルがすでに存在していないか、指定したパスの綴りが正しいかを見直します。

**つまずきやすい点**: `md C:\work\project\logs` のように、途中の `work` や `project` フォルダがまだ無くても、Windows では自動的にまとめて作成されます。この挙動は覚えておくと便利ですが、逆に言えば「本当はまだ存在していないはずのフォルダ」が一度に作られてしまうこともあるため、深い階層をまとめて指定するときはパスを一度見直してから実行すると安心です。

### rd と rmdir --- フォルダを削除する（⚠️ /s の危険性に注意）

`rd`（remove directory の略）と `rmdir` は、フォルダを削除するコマンドです。オプションを何も付けない場合、対象のフォルダが空でないと削除できないという安全装置が最初から備わっています。中身ごとまとめて削除したいときは `/s`（subdirectory の意味で、サブフォルダも含めて処理する指定）を付けますが、この場合は本当に消してよいか確認するメッセージが表示されます。さらに `/q`（quiet の略で、確認メッセージを省略する指定）を組み合わせると、確認なしで即座に削除が実行されます。

```bat
REM 空のフォルダを削除する(中身が残っていると失敗する)
rd test

REM rmdir でも同じ働きをする
rmdir test

REM 中身をサブフォルダごとすべて削除する(実行前に確認が入る)
rd /s test

REM 確認なしで、中身をサブフォルダごとすべて削除する
rd /s /q test
```

`rd /s`（`/q` なし）を実行すると、次のように削除してよいかの確認が表示されることが多いです。

```text
C:\Users\test>rd /s test
test、よろしいですか (Y/N)? y
```

中身が残っている状態で `/s` を付けずに `rd` を実行すると、次のようなエラーが表示され、削除は行われないことが多いです。

```text
C:\Users\test>rd test
ディレクトリが空ではありません。
```

**確認・判断のポイント**: オプションなしの `rd` がエラーで止まるのは、誤ってフォルダごと消してしまうのを防ぐための安全装置です。「消えなかった」= 失敗ではなく、むしろ正常な防御反応だと捉えましょう。`/s` を付けたときに出る `(Y/N)?` の確認では、対象のパスをもう一度見直してから `Y` を入力する習慣をつけます。

**つまずきやすい点**: ⚠️ `/s` で削除したフォルダとその中身は、エクスプローラーのゴミ箱を経由しないため、基本的に元に戻せません。`/q` は確認メッセージを省略するだけで動作自体を変えるものではありませんが、`/s` と組み合わせると「確認なしで中身ごと一瞬で消える」状態になるため、指定するフォルダ名やパスを打ち間違えていないか、実行前に `dir` や `tree` で必ず確認してください。

**⚠️ `rd /s` はサブフォルダやファイルを含めてフォルダを丸ごと削除する、取り返しのつかない操作です。特に `/q` と組み合わせるときは、対象のパスを何度も見直してから実行してください。**

### copy --- ファイルをコピーする

`copy` は、ファイルを別の場所や別の名前で複製するコマンドです。コピー元とコピー先のパスを指定するだけのシンプルな使い方に加え、複数のファイルを1つに結合してコピーする「結合コピー」という使い方もあります。なお `copy` はファイル専用のコマンドで、フォルダそのものをまとめてコピーすることはできません（フォルダごとコピーしたいときは、この後に紹介する `xcopy` や `robocopy` を使います）。

```bat
REM ファイルを別のフォルダにコピーする
copy memo.txt D:\backup\

REM コピーと同時に別の名前を付ける
copy memo.txt memo_backup.txt

REM 複数のファイルを1つのファイルに結合してコピーする
copy part1.txt+part2.txt combined.txt
```

コピーが成功すると、次のようにコピーした件数が表示されることが多いです。

```text
C:\Users\test>copy memo.txt D:\backup\
        1 個のファイルをコピーしました。
```

**確認・判断のポイント**: 「1 個のファイルをコピーしました。」のように、末尾に表示される件数が想定どおりかを確認します。件数が `0` だったり想定より少なかったりする場合は、コピー元のパスやファイル名の指定を見直します。コピー先に同名ファイルがすでにある場合、状況によっては上書きしてよいか確認されることがあります。

**つまずきやすい点**: `copy` はファイル専用で、フォルダそのものは対象にできません。フォルダをコピーしようとすると、意図しない挙動になったりエラーになったりします。またコピー先のパスの末尾に `\`（バックスラッシュ）を付け忘れると、「フォルダへのコピー」のつもりが「その名前のファイルとして保存」される場合があるため、フォルダを指定するときは末尾の `\` を意識しましょう。

### move --- ファイル・フォルダを移動する（名前変更にも使える）

`move` は、ファイルやフォルダを別の場所へ移すコマンドです。`copy` と違って元の場所には残らず、実行後はコピー元から消えます。また `copy` と違い、`move` はフォルダそのものも移動対象にできます。移動先のパスに新しい名前を指定すると、実質的に「名前変更」としても使えます。

```bat
REM ファイルを別のフォルダへ移動する
move memo.txt D:\backup\

REM フォルダごと別の場所へ移動する
move C:\work\old_project D:\archive\

REM 移動先に新しい名前を指定すると、名前変更としても使える
move memo.txt memo_new.txt
```

移動が成功すると、次のように件数が表示されることが多いです。

```text
C:\Users\test>move memo.txt D:\backup\
        1 個のファイルを移動しました。
```

**確認・判断のポイント**: 表示される件数を確認するとともに、`dir` で元の場所からファイルが消えていること、移動先に増えていることの両方を確かめると確実です。移動先に同名のファイルがすでにある場合は、上書きしてよいか確認されることがあります。

**つまずきやすい点**: `copy` と混同して「元の場所にもファイルが残るはず」と思い込むと、意図せずファイルを移動してしまい元の場所で見つからなくなることがあります。また異なるドライブ（`C:` から `D:` など）をまたいだ移動は、内部的にはコピーしてから元を削除するという動きになるため、サイズの大きいファイルでは完了までに時間がかかることがあります。

### ren と rename --- ファイル・フォルダの名前を変更する

`ren`（rename の短縮形）と `rename` は、同じフォルダ内でファイルやフォルダの名前だけを変更するコマンドです。働きは同じで、どちらを使っても構いません。ワイルドカード（`*` や `?` を使って複数のファイル名をまとめて指定する書き方）を使うと、一括での名前変更もできます。

```bat
REM ファイルの名前を変更する
ren memo.txt memo_old.txt

REM rename でも全く同じ結果になる
rename memo.txt memo_old.txt

REM ワイルドカードを使って、拡張子だけをまとめて変更する
ren *.txt *.bak
```

`ren` も成功時には何も表示しません。指定したファイルが見つからない場合は、次のようなエラーになることが多いです。

```text
C:\Users\test>ren nofile.txt renamed.txt
指定されたファイルが見つかりません。
```

**確認・判断のポイント**: 実行後は無反応なので、`dir` で名前が変わっているかを確認します。ワイルドカードを使った一括変更のあとは、想定していないファイルまで名前が変わっていないかを `dir` で見比べておくと安心です。

**つまずきやすい点**: `ren`・`rename` は同じフォルダ内での名前変更専用で、別のフォルダへ移しながら名前も変える、ということはできません（フォルダをまたいだ移動は `move` の役目です）。またワイルドカードでの一括変更は便利な反面、対象を絞り込みすぎたり広げすぎたりすると、意図しないファイルまで巻き込んでしまうことがあるため、実行前に `dir` で対象件数を確認する癖をつけましょう。

### del と erase --- ファイルを削除する（⚠️ 確認が入るのは `*.*` のときだけ）

`del`（delete の略）と `erase` は、ファイルを削除するコマンドで、働きは同じです。`memo.txt` のようにファイル名を1つだけ指定した場合は、既定では確認メッセージなしにそのまま削除されます。ここで初心者が誤解しやすいのが、`*.log` のような拡張子だけを指定した部分的なワイルドカードの扱いです。`/q`（quiet の略で、確認メッセージを省略する指定）を付けていなくても、`*.log` や `*.txt` のような部分的なワイルドカードは既定でそのまま確認なしに削除されます。確認メッセージが入るのは、`*.*` のように「すべてのファイル」を意味するワイルドカード（Microsoft のヘルプでは「グローバル ワイルドカード」と呼ばれています）を指定したときだけです。サブフォルダも含めて対象にしたいときは `/s` を付けます。

```bat
REM ファイルを1つ削除する(既定では確認なしで即削除される)
del memo.txt

REM erase でも全く同じ結果になる
erase memo.txt

REM 拡張子だけを指定した部分的なワイルドカードも、既定では確認なしに削除される
del *.log

REM *.*(すべてのファイル)を指定すると、既定では削除前に確認が入る
del *.*

REM サブフォルダも含めて、確認なしで一括削除する
del /s /q C:\work\*.*
```

`*.*` を指定した削除では、次のような確認メッセージが表示されることが多いです。

```text
C:\Users\test>del *.*
*.*、よろしいですか (Y/N)? y
```

一方、`del *.log` のように拡張子などを指定した部分的なワイルドカードでは、この確認は表示されず、画面には何も表示されないまま該当ファイルがそのまま削除されることが多いです。

**確認・判断のポイント**: ファイル名を1つだけ指定した削除も、`*.log` のような部分的なワイルドカードを指定した削除も、既定では無反応のまま即削除されるため、「消えたかどうか」は必ず `dir` で確認します。`*.*` を指定したときだけ現れる `(Y/N)?` の確認では、対象のパスが想定どおりかを見直してから答えます。

**つまずきやすい点**: ⚠️ `del`・`erase` はゴミ箱を経由しないため、削除したファイルは基本的に元に戻せません。とくに注意したいのは、確認メッセージが表示されるのは `*.*`（すべてのファイル）を指定した場合だけで、`*.log` や `*.txt` のように一部だけを指定したワイルドカードでは `/q` を付けなくても既定で確認なしに削除される点です。「ワイルドカードを使えば安全装置が働くはず」と思い込まず、削除系のコマンドを実行する前には、必ず同じパターンを `dir` に指定して対象を目で確認する習慣をつけてください。また読み取り専用属性（`attrib +r`）が付いているファイルをそのまま `del` しようとすると、「アクセスが拒否されました。」のようなエラーになることがあります。削除したい場合は、先に `attrib -r` で属性を外すか、読み取り専用ファイルも強制的に削除する `/f` オプションを使います。さらに `del` はファイルだけを削除し、フォルダ自体は残る点も `rd` と混同しやすいので注意してください。

**⚠️ `del /s /q` はサブフォルダも含めて、確認なしで大量のファイルを一瞬で削除します。とくに `*.*`（すべてのファイル）のようなワイルドカードと組み合わせるときは、対象のパスとパターンを何度も見直してから実行してください。**

### type と more --- ファイルの中身を画面で確認する

`type` は、テキストファイルの中身をそのまま画面に表示するコマンドです。短いファイルの内容をサッと確認したいときに便利ですが、内容が長いファイルに使うと、画面の上のほうが流れて見えなくなってしまいます。そこで使うのが `more` で、`type` に「1画面ごとに一時停止する」機能を足したイメージのコマンドです。長いログファイルなどの確認に向いています。

```bat
REM テキストファイルの中身をそのまま表示する
type memo.txt

REM 長いファイルを1画面ずつ表示する
more memo.txt

REM type の出力を more に渡して、1画面ずつ確認することもできる
type biglog.txt | more
```

`type` の実行結果は、次のように表示されることが多いです。

```text
C:\Users\test>type memo.txt
本日の作業メモ
- サーバー設定を確認する
- バックアップを取得する
```

`more` を使うと、1画面表示するごとに画面下に次のような表示で入力待ちになることが多いです。

```text
-- More --
```

**確認・判断のポイント**: `type` は内容が最後まで一気に流れて表示されるため、短いファイルの中身をサッと確認する用途に向いています。ファイルが長く、上のほうが読めないと感じたら `more` に切り替えます。`more` の画面下に一時停止のメッセージが出たら、`Space` キーで次の画面、`Enter` キーで1行だけ進められます。

**つまずきやすい点**: `type` を画像ファイルや実行ファイル（`.exe` など）のようなテキスト以外のファイルに使うと、意味の無い文字化けした表示になります。テキストファイルかどうか分からないときは、拡張子やファイルの種類を先に確認してから使いましょう。また `more` は各画面の表示後にキー入力を待つ仕様のため、何も反応が無いと「コマンドプロンプトが固まった」と勘違いしやすいです。`Space` キーや `Enter` キーで先に進められるほか、最後まで表示し終える前に途中でやめたいときは `q` キーでいつでも打ち切って終了できます。

### attrib --- ファイルの属性を確認・変更する

`attrib` は、ファイルやフォルダに付いている属性（そのファイルの性質を表す追加情報）を確認したり、付けたり外したりするコマンドです。代表的な属性には `R`（Read-only、読み取り専用）と `H`（Hidden、隠しファイル）があり、属性名の前に `+` を付けるとその属性を付与、`-` を付けると解除するという意味になります。

```bat
REM ファイルの現在の属性を確認する
attrib memo.txt

REM 読み取り専用にする(誤って上書き・削除しにくくする)
attrib +r memo.txt

REM 読み取り専用を解除する
attrib -r memo.txt

REM 隠しファイルにする(通常の dir 表示や検索に出てこなくなる)
attrib +h memo.txt

REM 隠しファイルを元の表示に戻す
attrib -h memo.txt
```

属性を確認すると、該当する属性のアルファベットだけが並んで表示されることが多いです。

```text
C:\Users\test>attrib memo.txt
A          C:\Users\test\memo.txt
```

このように `A`（Archive、書き換えられたことを示す一般的な属性）だけが表示されているファイルは、読み取り専用や隠しファイルの設定が付いていない、いわば「素の状態」であることが多いです。`+r` を付けた後に確認すると、`A` に加えて `R` が並んで表示されることが多いです。

**確認・判断のポイント**: `attrib` の実行結果に並んでいるアルファベットを見て、今どの属性が付いているかを判断します。`R` が付いているファイルは上書き・削除がしにくくなっており、`H` が付いているファイルは通常の `dir` 表示に出てこなくなります。

**つまずきやすい点**: 隠しファイル（`+h`）にしても、ファイルの中身が消えるわけではなく、見えなくなるだけです。「ファイルが消えた」と慌てる前に、隠しファイルになっていないかを疑ってみましょう。また読み取り専用（`+r`）にしたファイルをそのまま `del` で削除しようとすると、「アクセスが拒否されました。」のようなエラーになることがあります。削除したいときは、先に `attrib -r` で属性を外すか、`del` の強制削除オプションを使う必要があります。

### xcopy --- フォルダをサブフォルダごとコピーする（/e /i）

`xcopy` は、`copy` を拡張したコマンドで、フォルダ単位のコピーが得意です。`/e`（サブフォルダも含めてコピーする指定で、中身が空のフォルダも対象にする）と `/i`（コピー先のフォルダが存在しない場合に、確認を求めずフォルダとして自動作成する指定）を組み合わせて使うことが多いです。

```bat
REM フォルダの中身をサブフォルダも含めてコピーする
xcopy C:\work D:\backup\work /e

REM コピー先フォルダが無ければ自動的にフォルダとして作成する
xcopy C:\work D:\backup\work /e /i
```

コピーが完了すると、コピーしたファイルの一覧とともに、最後に件数が表示されることが多いです。

```text
C:\Users\test>xcopy C:\work D:\backup\work /e /i
C:\work\report.docx
C:\work\logs\app.log
2 個のファイルをコピーしました
```

**確認・判断のポイント**: 最後に表示される「◯個のファイルをコピーしました」の件数が、想定しているファイル数と合っているかを確認します。件数が少ない場合は、コピー元に読み取れないファイルがあったか、`/e` の付け忘れで空のサブフォルダが除外されていないかを疑います。

**つまずきやすい点**: `/e` を付け忘れると、中身が空のサブフォルダはコピーされません。また `/i` を省略した状態でコピー先フォルダが存在しないと、対象はファイル名かディレクトリ名かを尋ねる質問が表示されてそこで処理が止まってしまうことがあります。バッチファイル（複数のコマンドをまとめて実行するファイル）の中で無人実行させたい場合、この質問で止まってしまうとハマりやすいため、コピー先フォルダの有無にかかわらず `/i` を付けておくと安全です。

### robocopy --- より高機能・高信頼にフォルダをコピーする（/e、既定の再試行仕様に注意）

`robocopy`（robust file copy、頑丈なコピーの意味）は、`xcopy` の後継として案内されることが多い、より高機能なコピーコマンドです。`/e` はここでも「サブフォルダを、空のものも含めてコピーする」指定で、進み具合やエラーを詳しく記録しながら、コピーに失敗したファイルを自動的に再試行してくれるのが大きな特徴です。

```bat
REM フォルダをサブフォルダごとコピーする
robocopy C:\work D:\backup\work /e

REM 再試行の回数と間隔を指定して、無限に近い再試行を防ぐ
robocopy C:\work D:\backup\work /e /r:3 /w:5
```

実行すると、コピーの進み具合や結果のサマリー（集計表）が次のように表示されることが多いです。

```text
C:\Users\test>robocopy C:\work D:\backup\work /e
-------------------------------------------------------------------------------
   ROBOCOPY     ::     Robust File Copy for Windows
-------------------------------------------------------------------------------

                  新しいファイル                report.docx
                  100%

------------------------------------------------------------------------------
                    合計       コピー     スキップ     不一致       失敗       特殊
    ディレクトリ:          2          1          1          0          0          0
        ファイル:          1          1          0          0          0          0
```

**確認・判断のポイント**: サマリーの「失敗」列が `0` であるかをまず確認します。「スキップ」件数が想定より多い場合は、すでに同じ内容のファイルがコピー先にあり処理が省略された可能性があります。`robocopy` は終了後に戻り値（終了コード）も返しますが、他の多くのコマンドと違い `0` だけが成功を意味するわけではなく、値ごとに意味が異なる点は覚えておくとよいでしょう。

**つまずきやすい点**: ⚠️ `robocopy` は既定では、コピーに失敗すると最大100万回、30秒間隔で延々と再試行し続ける仕様になっています。コピー中のファイルが他のアプリで使用中だったりすると、処理がいつまでも終わらないように見えることがあります。これが気になる場合は、`/r:3`（3回だけ再試行する）や `/w:5`（5秒間隔で再試行する）のように、回数と間隔を明示的に指定しておくと安心です。また ⚠️ `/mir` はコピー元とコピー先を完全に一致させるオプションで、コピー先にしか無い余分なファイルを自動的に削除してしまいます。削除を伴う分だけ扱いが難しく、指定を誤ると意図しないファイルまで消してしまうため、まずは削除を伴わない `/e` を使ったコピーに慣れてから触れることをおすすめします。

### ワイルドカード（`*` と `?`） --- 複数のファイルをまとめて指定する

ワイルドカード（複数のファイル名をまとめて指定するための記号）を使うと、1つずつファイル名を打たなくても、複数のファイルをまとめて操作の対象にできます。`*` は「0文字以上の何でもよい文字列」を表し、`?` は「ちょうど1文字分の何でもよい文字」を表します。ここまで紹介した `dir`・`copy`・`move`・`ren`・`del` など、多くのコマンドで共通して使える書き方です。

```bat
REM 拡張子が .txt のファイルをすべて表示する
dir *.txt

REM report に続けて1文字だけ違うファイルを対象にする(report1.txt や reportA.txt など)
dir report?.txt

REM すべてのファイルを意味する(削除・コピーで使うときはとくに注意する)
dir *.*
```

`dir *.txt` を実行すると、次のように条件に合うファイルだけが一覧表示されることが多いです。

```text
C:\Users\test>dir *.txt
2026/09/04  10:15    <DIR>          .
2026/09/04  10:15    <DIR>          ..
2026/09/04  09:50               220 memo.txt
2026/09/04  09:52               512 report.txt
               2 個のファイル                 732 バイト
```

**確認・判断のポイント**: 削除やコピーなどの操作でワイルドカードを使う前に、まず `dir` に同じパターンを指定して実行し、対象のファイルが想定どおりの一覧になっているかを確認します。件数や中身が予想と違う場合は、`*` と `?` の使い分けを見直しましょう。

**つまずきやすい点**: `*.*` は「すべてのファイル」を意味し、拡張子の無いファイルまで対象に含まれます。`del` コマンドで確認メッセージが表示されるのはこの `*.*` を指定したときだけで、`*.log` のような一部だけのワイルドカードでは確認なしに削除される点は、前の `del` のセクションで説明したとおりです。`del *.*` や `rd /s /q` のような削除系コマンドとワイルドカードを組み合わせると、対象範囲が一気に広がってしまうため、実行前に必ず `dir` で同じパターンの一覧を確認する習慣をつけてください。またワイルドカードはコマンドプロンプト自身が解釈するのではなく、それぞれのコマンド（`dir` や `del` など）が独自に解釈しています。そのため一部のコマンドや状況では、期待していたパターンと少し違う挙動になることもあるので、慣れないうちは `dir` での事前確認を省かないようにしましょう。

## 環境変数とシステム情報の確認

このカテゴリでは、自分がいま使っているパソコンが「どんなOS・ハードウェアで動いているか」「どのユーザーとしてログインしていて、どんな権限を持っているか」「コマンドを実行するときにWindowsがどんな設定値（環境変数）を参照しているか」を調べるコマンドをまとめます。サーバー構築の現場では、作業を始める前にまず相手のマシンの状態を把握してから手を動かすことが多いため、ここで扱うコマンドは調査の基本セットになります。とくにPATH環境変数（コマンドを探しに行くフォルダーの一覧）の仕組みと、操作を誤ると起きる事故は必ず押さえておきましょう。

| やりたいこと | コマンド | 例 | 確認・判断のポイント |
| --- | --- | --- | --- |
| OSやハードウェアの詳細情報をまとめて確認したい | `systeminfo` | `systeminfo` | OS名・ビルド番号・物理メモリ量などが一度に表示される。項目が多いので `findstr`（文字列検索コマンド）と組み合わせて絞り込む |
| 今設定されている環境変数を一覧表示したい | `set` | `set` | `変数名=値` の形式ですべて並ぶ。`PATH` や `TEMP` など主要な変数が想定どおり入っているか確認する |
| 環境変数を一時的に設定・変更したい ⚠️ | `set 変数名=値` | `set MYVAR=hello` | 設定が反映されるのは今開いているウィンドウの中だけ。既存の変数名（とくに`PATH`）を上書きしていないか確認する |
| 文字列やメッセージを画面に表示したい | `echo` | `echo Hello, World!` | 指定した文字列がそのまま表示される。バッチファイル（複数のコマンドをまとめて実行するファイル）の進捗表示によく使われる |

| ドライブのボリュームラベルを設定・変更したい ⚠️ | `label` | `label D: BACKUP` | 対象のドライブレター（C:やD:など）を打ち間違えていないか。ラベルに使える文字数はファイルシステムによって異なる点にも注意する |
| ログインユーザーの所属グループ・特権を詳しく確認したい | `whoami /all` | `whoami /all` | ユーザー情報・所属グループ一覧・特権一覧がまとめて表示される。管理者権限を持っているかどうかの確認に使う |

### systeminfo --- OSとハードウェアの情報をまとめて確認する

`systeminfo` は、このパソコンのOS名やバージョン、インストール日、物理メモリ（RAM）の容量、ネットワークアダプター（ネットワークに接続するための機器）の情報などを、まとめて画面に表示するコマンドです。トラブル対応や環境調査の最初の一歩として、「このマシンは一体どんな環境なのか」をざっと把握したいときに使います。表示される項目数がとても多いため、「マシンの健康診断」を一度に受けているようなイメージで捉えるとよいでしょう。

```bat
REM OSやハードウェアの情報をまとめて確認する(表示にはある程度時間がかかることがある)
systeminfo

REM 特定の項目だけを絞り込んで確認したい場合は findstr(文字列を検索するコマンド)と組み合わせる
systeminfo | findstr /i "OS 名"
systeminfo | findstr /i "メモリ"
```

出力例です。実際の項目名や値は、Windowsのバージョンや言語設定、インストールされている環境によって変わります。

```text
ホスト名:                DESKTOP-ABC123
OS 名:                   Microsoft Windows 11 Pro
OS バージョン:            10.0.22631 N/A ビルド 22631
システムの種類:            x64-based PC
物理メモリの合計:          16,384 MB
ネットワーク カード:        Realtek PCIe GbE Family Controller
```

**確認・判断のポイント**: OS名・バージョン（ビルド番号）を見れば、そのマシンにインストールできるソフトウェアの条件を満たしているかどうかが分かります。物理メモリの合計は、これから構築しようとしているサーバーソフトが要求するスペックを満たしているかの判断材料になります。項目数が多いため、探している情報が決まっているときは `findstr` で絞り込むと効率的です。`findstr` に渡すキーワードは、実際に表示される項目名（「OS 名:」のように、アルファベットの略語と日本語の間に半角スペースが入ることが多い点に注意）と一致させる必要があります。

**つまずきやすい点**: `systeminfo` は情報を収集するのに数秒から数十秒かかることがあり、実行してもすぐに結果が出ないため「固まった」と勘違いしやすいです。気長に待ちましょう。また表示される項目名は日本語Windowsと英語Windowsで異なるため、`findstr` で絞り込む際のキーワードも環境に合わせて変える必要があります。

### set --- 環境変数の一覧表示と一時的な設定

`set` は、今開いているコマンドプロンプトの画面で使える環境変数（Windowsやアプリが参照する、名前と値のペアで管理された設定値のこと）を確認・設定するコマンドです。引数を付けずに実行すると、現在有効なすべての環境変数が一覧表示されます。また `set 変数名=値` の形で実行すると、新しい変数を作ったり、既存の変数の値を書き換えたりできます。

```bat
REM 引数なし: 現在の環境変数をすべて一覧表示する
set

REM 先頭の文字を指定して絞り込む(例: Pで始まる変数だけ表示)
set P

REM 新しい環境変数を一時的に作成する
set MYVAR=hello

REM 作成した変数の中身を確認する
echo %MYVAR%
```

`set` を引数なしで実行したときの出力例です。実際には数十行にわたって表示されます。

```text
ComSpec=C:\Windows\system32\cmd.exe
NUMBER_OF_PROCESSORS=8
OS=Windows_NT
Path=C:\Windows\system32;C:\Windows;C:\Windows\System32\Wbem
PROMPT=$P$G
TEMP=C:\Users\yamada\AppData\Local\Temp
USERNAME=yamada
```

**確認・判断のポイント**: `変数名=値` の形式で一覧が表示されるので、期待している変数（`PATH`、`TEMP`、`USERNAME`など）が存在し、想定どおりの値になっているかを確認します。`set 文字` のように先頭の文字だけ指定すると、その文字で始まる変数だけに絞り込めるため、目的の変数を探しやすくなります。

**つまずきやすい点**: ⚠️ `set` で設定した内容は、今開いているそのウィンドウの中だけで有効な一時的なものです。ウィンドウを閉じると消えてしまい、次に開いたコマンドプロンプトには反映されません（パソコン全体で永続的に環境変数を変更したい場合は、システムのプロパティ画面から設定するなど別の方法が必要です）。また `set 変数名=値` は、既存の変数名を指定するとその内容を丸ごと上書きします。とくに `set PATH=...` のようにPATH変数を書き換えるコマンドを、既存の値を含めずに実行してしまうと、それまで登録されていたコマンドの検索先が消えてしまい、そのウィンドウ内で多くのコマンドが「認識されません」というエラーになることがあります。既存のPATHに追記したいだけの場合は `set PATH=%PATH%;追加したいフォルダー` のように、必ず現在の値（`%PATH%`）を含めて書く必要がある点に注意してください。

### echo と echo %変数名% --- 文字列と環境変数の中身を表示する

`echo` は、指定した文字列をそのまま画面に表示する、もっとも基本的なコマンドの一つです。バッチファイル（複数のコマンドをまとめて実行するファイル）の中で「今どの処理をしているか」を表示するのによく使われます。また `%` で変数名を挟んで `echo %変数名%` の形にすると、その環境変数に入っている値だけを取り出して表示できます。

```bat
REM 文字列をそのまま画面に表示する
echo Hello, Windows!

REM 環境変数の中身を確認する(%で変数名を挟む)
echo %PATH%
echo %USERNAME%
echo %TEMP%

REM 存在しない変数名を指定した場合の挙動を確認する
echo %NOT_EXIST_VAR%
```

出力例です。

```text
C:\Users\yamada>echo Hello, Windows!
Hello, Windows!

C:\Users\yamada>echo %USERNAME%
yamada

C:\Users\yamada>echo %NOT_EXIST_VAR%
%NOT_EXIST_VAR%
```

**確認・判断のポイント**: 文字列がそのまま表示されれば正常に動作しています。環境変数を確認する場合は、期待している値（たとえばユーザー名やフォルダーパス）がそのまま返ってきているかをチェックします。

**つまずきやすい点**: `%` で挟み忘れると、`echo %変数名%` のつもりで打った文字列がただの文字列として扱われ、期待通りに展開されません。さらに注意したいのは、存在しない変数名を指定した場合の挙動です。Linuxのシェルでは未定義の変数は空文字として扱われることが多いのに対し、コマンドプロンプトでは `%NOT_EXIST_VAR%` のように、`%記号ごとそのまま文字列として表示される` 点が大きく違います。これは「変数が見つからなかった」ことを示すエラーではなく、単に置き換えができなかった結果なので、見慣れないうちは「変数が空だった」のか「変数名を間違えた」のか区別しにくく、混乱の原因になりがちです。

### path --- PATH環境変数を確認する（置き換えの危険に注意）

`path` は、PATH環境変数（コマンドを入力したときに、実行ファイル（`.exe`ファイルなど）をどのフォルダーの中から探すかという検索対象フォルダーの一覧）の中身を確認するための専用コマンドです。引数を付けずに実行すると、`echo %PATH%` と同じ内容が1行で表示されます。たとえば `python` とだけ入力してPythonが起動するのは、PATHの中に `python.exe` が置かれているフォルダーが登録されているからです。

```bat
REM 現在のPATHの中身を確認する(表示するだけなら安全)
path

REM echo %PATH% でも同じ内容を確認できる
echo %PATH%

REM 【危険】以下のようにフォルダーを指定して実行すると、既存のPATHが丸ごと置き換わってしまう
REM path C:\tools

REM 既存のPATHを保ったまま新しいフォルダーを追加したいときは、
REM 現在の値(%PATH%)を含めて書く
path %PATH%;C:\tools
```

出力例（引数なしで実行した場合）です。

```text
C:\Users\yamada>path
PATH=C:\Windows\system32;C:\Windows;C:\Windows\System32\Wbem;C:\Program Files\Git\cmd
```

**確認・判断のポイント**: 表示された一覧の中に、これから使いたいコマンド（たとえばGitやPythonなど）の実行ファイルが置かれているフォルダーが含まれているかを確認します。含まれていなければ、そのコマンドは「認識されません」というエラーになります。実際にどのフォルダーの実行ファイルが使われているかまで特定したい場合は、`where コマンド名` を使うとより詳しく調べられます。

**つまずきやすい点**: ⚠️ `path` は「表示専用」に見えて、実は引数にフォルダーを指定すると、既存のPATHへ追加するのではなく丸ごと置き換えてしまう仕様になっています。たとえば `path C:\tools` と実行すると、それまで登録されていた `C:\Windows\system32` などの標準的な検索先がすべて消え、その画面では `dir` などの基本コマンド以外の多くのコマンドが動かなくなることがあります。さらに `path ;` のように実行すると、検索対象がカレントフォルダー（今いる場所）だけに絞り込まれてしまい、ほとんどのコマンドが使えなくなります。いずれの場合も、この変更は今開いているウィンドウの中だけの一時的なものなので、ウィンドウを閉じれば元の設定に戻りますが、作業中に「さっきまで動いていたコマンドが急に使えなくなった」と混乱する典型的な原因になります。PATHに新しいフォルダーを追加したいときは、必ず `path %PATH%;追加したいフォルダー` のように、現在の値を含めた形で書くようにしてください。

**⚠️ `path` に引数を渡すときは、必ず `%PATH%` を含めて既存の内容を残すようにしてください。既存のPATHを丸ごと消してしまうと、そのウィンドウ内の多くのコマンドが動かなくなります。**

### chcp --- 文字コードページを確認する（文字化けとの関係）

`chcp` は、コマンドプロンプトの画面が文字をどの規則で解釈・表示するかを決める「コードページ（文字コードの規格に番号を割り振ったもの）」を確認・変更するコマンドです。日本語Windowsでは通常 `932`（Shift-JIS系。Windowsでは「ANSI/OEM Japanese」とも呼ばれます）が使われますが、番号を指定すれば `65001`（UTF-8）などに切り替えることもできます。

```bat
REM 現在のコードページを確認する
chcp

REM コードページをUTF-8(65001)に切り替える
chcp 65001

REM 日本語環境の既定であるShift-JIS系(932)に戻す
chcp 932
```

出力例です。

```text
C:\Users\yamada>chcp
現在のコード ページ: 932
```

**確認・判断のポイント**: `932` と表示されていれば日本語（Shift-JIS系）、`65001` と表示されていればUTF-8として文字を扱っている状態です。ツールの出力やファイルの中身が文字化けして見えるときは、まず `chcp` で現在の設定を確認し、ファイル側の文字コードとコマンドプロンプト側のコードページが一致しているかを疑うのが調査の第一歩になります。

**つまずきやすい点**: `chcp 65001` に切り替えると、UTF-8で書かれたファイルの表示が正しくなる場合がある一方で、コマンドプロンプト自体のフォントや、実行しているツールがUTF-8に対応していないと、かえって表示が崩れる（文字化けする）ことがあります。「UTF-8にすれば必ず直る」というわけではなく、あくまで表示側の設定を合わせているだけである点を理解しておきましょう。またこの設定変更も、そのウィンドウの中だけで有効な一時的なものです。

### vol --- ドライブのボリュームラベルとシリアル番号を確認する

`vol` は、指定したドライブの「ボリュームラベル（ドライブに付けられた名前のこと）」と「ボリュームシリアル番号（そのドライブが初期化されたときに割り振られる識別番号）」を表示する、確認専用のコマンドです。ドライブを指定しなければ、今いる場所のドライブ（カレントドライブ）が対象になります。

```bat
REM カレントドライブのラベルとシリアル番号を確認する
vol

REM ドライブを指定して確認する
vol D:
```

出力例です。

```text
C:\Users\yamada>vol C:
ドライブ C のボリューム ラベルは Windows です
ボリューム シリアル番号は 1234-ABCD です
```

**確認・判断のポイント**: 表示されたラベル名が、想定しているドライブ（たとえば外付けHDDやUSBメモリに付けた分かりやすい名前）と一致しているかを確認します。同じ形のUSBメモリを複数使っているときなど、「今つないでいるのはどのドライブか」を見分ける手がかりになります。

**つまずきやすい点**: `vol` はあくまで確認のみで、表示するだけの安全なコマンドです。ラベルを変更したい場合は、次に説明する `label` コマンドを使う必要があります。混同しないようにしましょう。

### label --- ドライブのボリュームラベルを設定・変更する

`label` は、`vol` で確認できるボリュームラベル（ドライブに付けられた名前）を、実際に設定・変更するためのコマンドです。ドライブレターとラベル名を指定して実行すると、そのドライブの名前がすぐに書き換わります。ラベルに使える文字数は、ドライブのファイルシステム（ドライブを管理する方式のこと。FAT32やNTFSなど）によって異なる点に注意が必要で、FAT32でフォーマットされたドライブでは半角11文字（全角5文字）まで、NTFSでフォーマットされたドライブでは半角32文字（全角16文字）までという制限があります。

```bat
REM Dドライブのラベルを BACKUP に変更する
label D: BACKUP

REM 引数なしで実行すると、現在のラベルが表示されたうえで新しいラベルの入力を求められる
label D:
```

引数なしで `label D:` を実行したときの流れの例です（Dドライブが FAT32 でフォーマットされている場合）。

```text
C:\Users\yamada>label D:
ドライブ D のボリューム ラベルは BACKUP です
ボリューム シリアル番号は 1234-ABCD です

ボリューム ラベルを入力してください。(半角で 11 文字、全角で 5 文字以内)
```

このあと新しい名前を入力してEnterを押せばラベルが変更されます。何も入力せずにEnterだけを押すと、「現在のボリューム ラベルを削除しますか （Y/N）?」のような確認が表示され、Yと答えるとラベルが削除されます。NTFSでフォーマットされたドライブでは、文字数の案内が「（半角で 32 文字、全角で 16 文字以内）」のように変わります。またこの確認メッセージの出方はWindowsのバージョンによって多少異なる場合があります。

**確認・判断のポイント**: 実行前に `vol` で現在のラベルとドライブレターを確認し、変更したいドライブと一致しているかを必ずチェックしてから実行します。実行後は再度 `vol` を実行して、意図したとおりに変わったかを確認すると安心です。

**つまずきやすい点**: ⚠️ `label` は指定したドライブレター（`C:`や`D:`など）に対して即座に変更を反映するため、ドライブレターを打ち間違えると、意図しないドライブ（たとえばシステムが入っているCドライブ）のラベルを書き換えてしまう可能性があります。またラベルに使える文字数はファイルシステムによって異なり（FAT32は半角11文字まで、NTFSは半角32文字まで）、一律に「11文字まで」と覚えてしまうと、NTFSドライブで長いラベルが入力できたときに戸惑うことがあります。ラベル自体はデータの中身に影響しない飾りのような情報ですが、複数のドライブを扱う作業中に「どのドライブか分からなくなる」混乱のもとになるため、対象のドライブレターは実行前に必ず確認しましょう。また引数なしで実行して何も入力せずEnterを押すと、現在のラベルの削除に進んでしまう点にも注意してください。

**⚠️ `label` を実行する前には、必ず `vol` で対象のドライブレターと現在のラベルを確認してください。ドライブレターを間違えると、意図しないドライブの名前を変更してしまいます。**

### whoami /all --- ログインユーザーの権限を詳しく確認する

`whoami /all` は、`whoami` 単体（ユーザー名だけを表示するコマンド）よりもさらに詳しく、今ログインしているユーザーに関する情報をまとめて表示するコマンドです。ユーザー名やSID（セキュリティ識別子。ユーザーやグループを一意に区別するためのID）に加えて、所属しているグループの一覧と、そのユーザーに割り当てられている特権（システムレベルの特別な操作を行うための個別の許可）の一覧まで確認できます。

```bat
REM ユーザー情報・所属グループ・特権をまとめて確認する
whoami /all

REM 所属グループだけを見たい場合
whoami /groups

REM 割り当てられている特権だけを見たい場合
whoami /priv
```

出力例です。実際の項目数はもっと多く、複数のグループや特権が並びます。

```text
ユーザー情報
----------------------------------

ユーザー名             SID
====================== ==============================================
desktop-abc123\yamada  S-1-5-21-1111111111-2222222222-3333333333-1001


グループ情報
----------------------------------------------------------------------
グループ名                                種類     SID          属性
========================================= ======== ============ ===============
BUILTIN\Administrators                    エイリアス S-1-5-32-544  グループの使用不可


特権情報
----------------------------------------------------------------------
特権名                        説明                              状態
============================= ================================= ======
SeShutdownPrivilege           システムのシャットダウン           無効
SeChangeNotifyPrivilege       トラバース チェックのバイパス       有効
```

**確認・判断のポイント**: グループ情報の中に `BUILTIN\Administrators`（管理者グループ）が含まれているかどうかで、そのユーザーが管理者権限を持っているかを判断できます。ただし「グループに属している」ことと「今まさに管理者として実行している」ことは別で、実際の権限は特権情報の「状態」列（有効/無効）も合わせて確認する必要があります。何らかの操作が「アクセスが拒否されました」で失敗したときは、まず `whoami /all` で自分がどのグループ・どの特権を持っているかを確認すると、原因の切り分けに役立ちます。

**つまずきやすい点**: `whoami /all` はグループに「属している」ことを示していますが、Windowsの管理者アカウントには既定でUAC（ユーザーアカウント制御。実行内容を確認してくる仕組み）が働いており、コマンドプロンプトを普通に開いただけでは管理者権限が有効になっていないことがあります。実際、管理者グループに所属していても昇格していない状態では、グループ情報の `BUILTIN\Administrators` の属性が「使用不可」を意味する表示になり、権限が一時的に無効化されていることが読み取れます。管理者権限が必要な操作でエラーになる場合は、コマンドプロンプト自体を「管理者として実行」し直す必要があります。また表示される項目名や属性の文言はWindowsのバージョンや言語設定によって多少異なることがあります。

## プロセス・サービス・電源の操作

パソコンの中では、いま開いているアプリだけでなく、画面に見えない「サービス（Windows が裏側で常に動かしている機能のこと）」もたくさん同時に動いています。このカテゴリでは、それらの動作状況を確認する方法、反応しなくなったアプリを強制的に終了する方法、そしてサーバー機を安全に再起動・シャットダウンする方法を扱います。とくに `taskkill /F` や `shutdown`、`logoff` は、使い方を誤ると保存前のデータが失われたり、他の利用者の作業を巻き込んだりする操作なので、確認・判断のポイントとつまずきやすい点を必ず読んでから実行してください。

| やりたいこと | コマンド | 例 | 確認・判断のポイント |
| --- | --- | --- | --- |
| 実行中のプロセス（起動中のプログラム）を一覧表示したい | `tasklist` | `tasklist` | プロセス名と PID（プロセス ID、プロセスごとに割り振られる番号）が一覧に出ているか、メモリ使用量が異常に大きいプロセスがないか |
| プロセスがどのサービスと結びついているか確認したい | `tasklist /svc` | `tasklist /svc` | 目的のプロセス名の右側にサービス名が表示されているか。サービスを持たないプロセスは「N/A」と表示される |
| PID を指定してプロセスを終了したい | `taskkill /PID <PID> /F` | `taskkill /PID 1234 /F` | 実行前に `tasklist` で、その PID が本当に終了させたいプロセスのものか確認する |
| プロセス名を指定してまとめて終了したい | `taskkill /IM <プロセス名> /F` | `taskkill /IM notepad.exe /F` | 同じ名前の別ウィンドウもすべて巻き込んで終了する。対象がシステムに必要なプロセスでないか確認する |
| 子プロセスごとまとめて終了したい | `taskkill /PID <PID> /T /F` | `taskkill /PID 1234 /T /F` | `/T` を付けたときは、思わぬ関連プロセスまで一緒に終了していないか確認する |
| 別ウィンドウでアプリを起動したい | `start` | `start notepad` | 新しいウィンドウが開いたか、今のコマンドプロンプトの入力待ちがすぐ戻ってきたか |
| サービスの状態（動作中か停止中か）を確認したい | `sc query` | `sc query wuauserv` | `STATE` の欄が `RUNNING` か `STOPPED` かを確認する。サービス名を省略すると、既定では動いているサービスだけが一覧に出る点に注意 |
| サービスの状態を詳しく確認したい（PID など） | `sc queryex` | `sc queryex wuauserv` | `PID` 列が表示されているか。`0` ならまだプロセスとして起動していないことを意味する |
| サービスを開始したい | `net start` | `net start "Print Spooler"` | 「〜サービスを開始しました。」と表示されるか。管理者権限のウィンドウで実行しているか |
| サービスを停止したい | `net stop` | `net stop "Print Spooler"` | 依存関係の確認メッセージが出た場合、道連れで止まる他のサービスに影響がないか |
| 指定した秒数後にシャットダウンしたい | `shutdown /s /t <秒数>` | `shutdown /s /t 60` | タイマーが動いている間に `shutdown /a` で中止できることを確認しておく |
| 指定した秒数後に再起動したい | `shutdown /r /t <秒数>` | `shutdown /r /t 60` | 他の利用者やリモート接続への影響がないか、実行前に確認する |
| 予約したシャットダウン・再起動を取り消したい | `shutdown /a` | `shutdown /a` | 「中止されました」のようなメッセージが出るか。`/t 0` を指定していた場合は間に合わないことがある |
| 未保存のアプリも含めて強制的に閉じたい | `shutdown /r /t <秒数> /f` | `shutdown /r /t 60 /f` | 未保存のデータがあるアプリが開いていないか、実行前に確認する |
| 現在のユーザーをログオフしたい | `logoff` | `logoff` | サインイン画面に戻るか、開いていたアプリの未保存データが失われていないか |

### tasklist --- 実行中のプロセスを一覧表示する（/svc）

`tasklist`（task list の略で、今動いているプロセス〈起動中のプログラムのこと〉を一覧表示するコマンド）は、タスクマネージャーの「詳細」タブに表示されている内容を、コマンドラインから確認できるコマンドです。プロセス名、PID（プロセス ID。プロセスごとに割り振られる、重複しない番号のこと）、使用メモリ量などが一覧で表示され、あとで紹介する `taskkill` で特定のプロセスを終了する前の「確認作業」として使うことが多いコマンドです。

`/svc`（service の略）オプションを付けると、各プロセスがどのサービス（Windows が裏側で動かしている機能のこと）と結びついているかが分かります。svchost.exe のように、1つの実行ファイルが複数のサービスをまとめて動かしていることも多く、「このプロセス、見た目は地味だけど実は重要なサービスを支えていた」と気づけるのが `/svc` の役割です。

```bat
REM 実行中のプロセスを一覧表示する
tasklist

REM プロセスに紐づくサービス名も一緒に表示する
tasklist /svc

REM プロセス名で絞り込みたいときは /FI(フィルター)を使う
tasklist /FI "IMAGENAME eq notepad.exe"
```

出力例（`tasklist`）です。実行するタイミングやインストールされているソフトによって、表示されるプロセスの数・内容は変わります。

```text
イメージ名                     PID セッション名     セッション#    メモリ使用量
========================= ======== ================ =========== ============
System Idle Process              0 Services                   0          8 K
System                           4 Services                   0        132 K
notepad.exe                   4820 Console                     1      6,120 K
explorer.exe                  3140 Console                     1     45,200 K
```

**確認・判断のポイント**: 見たいプロセスの名前（イメージ名）と PID が一致しているかをまず確認します。メモリ使用量の欄が普段よりも極端に大きい場合、そのプロセスが何らかの問題（メモリリークなど）を抱えている可能性のサインになります。`tasklist /svc` を使ったときは、対象プロセスのサービス名の欄が「N/A」になっていれば、そのプロセスはサービスとは無関係な通常のアプリだと判断できます（System Idle Process や csrss.exe のような、そもそもサービスを持たない基本プロセスも「N/A」になります）。

**つまずきやすい点**: 一見すると同じ名前のプロセス（例えば `svchost.exe` や `chrome.exe`）が何行も並んでいることがありますが、これは異常ではなく、1つのアプリが複数のプロセスに分かれて動いている（あるいは複数のサービスを別々のプロセスとして動かしている）ことがよくあるためです。名前だけで判断せず、次に説明する `taskkill` で終了させる前には PID まで確認する習慣をつけましょう。

### taskkill --- プロセスを終了する（/PID, /IM, /F, /T）

`taskkill`（task kill の略で、指定したプロセスを終了させるコマンド）は、フリーズして反応しなくなったアプリや、`tasklist` で見つけた不要なプロセスを終了させるためのコマンドです。終了させたいプロセスの指定方法には、`/PID`（PID を番号でピンポイントに指定する方法）と `/IM`（image name の略で、プロセス名を指定する方法）の2種類があります。

⚠️ `/F`（force、強制の意味）を付けると、対象のプロセスに保存確認や後片付けの時間を与えず、即座に終了させます。編集中のファイルがあれば、保存されていない内容がそのまま失われる可能性があります。`/F` を付けずに終了を試みる方法もありますが、これはアプリに「閉じてください」という信号を送るだけの、いわばウィンドウの閉じるボタンを押すのに近い動作のため、フリーズしたアプリには効かないことが多く、実務ではよく `/F` とセットで使われます。だからこそ、実行前に `tasklist` で対象を確認する手間を惜しまないことが大切です。

さらに `/T`（tree、プロセスの親子関係の意味）を付けると、指定したプロセスから起動された子プロセスもまとめて終了させられます。`/F` だけでは子プロセスが生き残ってしまうことがあるため、関連プロセスごと確実に終了させたい場合に組み合わせます。

```bat
REM PID を指定してピンポイントに強制終了する(tasklistで事前にPIDを確認しておく)
taskkill /PID 1234 /F

REM プロセス名を指定して、同名のプロセスをまとめて強制終了する
taskkill /IM notepad.exe /F

REM 子プロセスも含めて、まとめて強制終了する
taskkill /PID 1234 /T /F

REM 強制ではなく、まずは通常の終了を試みる(/Fを付けない)
taskkill /PID 1234
```

出力例です。

```text
成功: PID 1234 のプロセスは強制終了されました。
```

うまくいかない場合は、次のように表示されることがあります。

```text
エラー: プロセス "csrss.exe"、PID 612 を終了できませんでした。
理由: アクセスが拒否されました。
```

**確認・判断のポイント**: 「成功」のメッセージが表示されれば、指定したプロセスが終了したと判断できます（`/F` を付けなかった場合は「終了シグナルを送信しました」のような、実際に終了したとは断言しないメッセージになることがあり、`/F` を付けたときの「強制終了されました」という文言とは意味合いが異なります）。エラーが出た場合は、対象プロセスが権限で保護されているシステムプロセスであるか、すでに終了済みであるか、指定した PID や名前が間違っている可能性があります。`/T` を使った直後は、`tasklist` をもう一度実行して、関連プロセスまで意図した範囲で終了しているかを確認すると安心です。

**つまずきやすい点**: ⚠️ `/IM` は名前が一致するプロセスをすべてまとめて終了させるため、同じ名前で別々の作業をしている複数のウィンドウ（例えばメモ帳を何枚も開いている場合）が、意図せず全部まとめて閉じられてしまうことがあります。1つだけをピンポイントで終了したいときは、`tasklist` で PID を確認したうえで `/PID` を使うほうが安全です。また `csrss.exe` のような Windows の中核を支えるシステムプロセスは、保護されていて `/F` を付けても終了できない（アクセスが拒否される）ことが多く、無理に終了させようとするとシステム全体が不安定になる場合があります。加えて Windows 10/11 では、セキュリティ対策ソフト関連の一部プロセスなどが PPL（Protected Process Light、保護されたプロセスの仕組み）で保護されており、管理者権限で `/F` を付けても終了できないことがあります。`tasklist` の一覧で見覚えのないシステムプロセスは、終了の対象にしないようにしてください。

**⚠️ `taskkill /F` は、対象プロセスに保存や後片付けの猶予を与えず即座に終了させる操作です。編集中のファイルがある場合は必ず保存してから、PID・プロセス名の両方をよく確認したうえで実行してください。**

### start --- 別ウィンドウでプログラムを起動する

`start` は、指定したプログラムやコマンドを、今のコマンドプロンプトとは別の新しいウィンドウで起動するコマンドです。`start` を付けずにプログラムをそのまま実行すると、そのプログラムが終了するまで今のコマンドプロンプトの入力待ちに戻ってこないことがありますが、`start` を使うと新しいウィンドウにその処理を任せて、元のコマンドプロンプトはすぐに次の入力を受け付けられる状態に戻ります。

```bat
REM メモ帳を新しいウィンドウで起動する
start notepad

REM ウィンドウのタイトルを指定して起動する(1つ目の引数はタイトルとして扱われる)
start "作業用メモ" notepad

REM 指定したフォルダをエクスプローラーで開く
start .

REM Webページを既定のブラウザーで開く
start https://learn.microsoft.com
```

出力例です。`start` 自体は基本的に何も表示せず、指定したアプリが新しいウィンドウとして開くだけです。

```text
C:\Users\test>start notepad
C:\Users\test>
```

**確認・判断のポイント**: 新しいウィンドウが実際に開いたかどうかで成功を判断します。元のコマンドプロンプトの入力待ち（プロンプト）がすぐに戻ってきていれば、正しく別ウィンドウとして起動できています。もし戻ってこない場合は、`start` を付け忘れていないかを確認しましょう。

**つまずきやすい点**: `start "文字列" コマンド` のように、`start` の直後にダブルクォートで囲んだ文字列を書くと、それは起動するコマンドの一部ではなく「ウィンドウのタイトル」として扱われる、という仕様に最初は戸惑いやすいです。タイトルを指定せずにパスだけを渡したい場合、パスにスペースが含まれていると意図せずタイトル扱いされてしまうことがあるため、`start "" "C:\Program Files\App\app.exe"` のように空のタイトルを明示的に指定する書き方もよく使われます。

### sc query / queryex --- サービスの状態を確認する

`sc`（service control、サービス制御の略）は、Windows のサービス（バックグラウンドで常に動き続ける機能のこと）を操作するためのコマンドです。中でも `sc query` は、指定したサービスが今「動いている（RUNNING）」のか「止まっている（STOPPED）」のかといった状態を確認するために使います。サーバー構築の現場では、「入れたはずのサービスがちゃんと起動しているか」を確認する場面が非常に多く、`sc query` はその基本の確認手段です。

`sc queryex`（query extended、拡張された照会の意味）は `sc query` の情報に加えて、そのサービスが今どの PID（プロセス ID）で動いているかまで表示してくれます。サービスの状態だけでなく、対応するプロセスまで `tasklist` で追いかけたいときに役立ちます。

```bat
REM Windows Update サービスの状態を確認する
sc query wuauserv

REM 同じサービスをPID付きで詳しく確認する
sc queryex wuauserv

REM サービス名を省略すると、既定では動いているサービスだけが一覧表示される
sc query

REM 止まっているサービスも含めて、すべてのサービスを一覧表示する
sc query state= all
```

出力例（`sc queryex wuauserv`）です。バージョンや環境によって細部の表示は変わります。

```text
SERVICE_NAME: wuauserv
        TYPE               : 20  WIN32_SHARE_PROCESS
        STATE              : 4  RUNNING
                                (STOPPABLE, NOT_PAUSABLE, ACCEPTS_SHUTDOWN)
        WIN32_EXIT_CODE    : 0  (0x0)
        SERVICE_EXIT_CODE  : 0  (0x0)
        CHECKPOINT         : 0x0
        WAIT_HINT          : 0x0
        PID                : 2364
        FLAGS              :
```

**確認・判断のポイント**: `STATE` の欄が `RUNNING`（動作中）か `STOPPED`（停止中）かをまず見ます。`RUNNING` の後ろに `(STOPPABLE, ...)` のような補足がある場合、そのサービスに対して現在どんな操作（停止できるか、一時停止できるかなど）が許可されているかを示しています。`sc queryex` で見た `PID` が `0` の場合は、サービスとしては存在していてもまだプロセスとして起動していない、という意味になります。

**つまずきやすい点**: `sc query`（サービス名を省略した場合）は、既定では動作中のサービスだけを一覧表示し、停止中のサービスは含まれません。「探しているサービスが一覧に出てこない」と思ったら、そもそも止まっているだけの可能性があるため、`sc query state= all`（`state=` の後ろの半角スペースを省略しないよう注意。スペースが無いと構文エラーになります）で全件を確認してみましょう。また `sc` に指定する名前は、画面に表示される分かりやすい「表示名」（例: Windows Update）ではなく、`wuauserv` のような内部的な「サービス名」である点にも注意が必要です。サービス名が分からないときは、`services.msc`（サービス管理ツールの画面）で対応する内部名を確認できます。

### net start / net stop --- サービスを開始・停止する

`net start` と `net stop` は、指定したサービスを実際に開始・停止させるコマンドです。`sc query` が「今の状態を見るだけ」の確認用コマンドだったのに対して、こちらは状態を実際に変更する操作用のコマンドという違いがあります。`net` コマンドに指定する名前は、`sc` とは異なり、画面に表示される分かりやすい「表示名」（スペースを含む場合は `" "` で囲む）でも動くことが多く、初心者にも扱いやすいのが特徴です。

```bat
REM 印刷関連のサービス(Print Spooler)を開始する
net start "Print Spooler"

REM 同じサービスを停止する
net stop "Print Spooler"

REM 現在動いているサービスの一覧を確認する
net start
```

出力例です。

```text
C:\WINDOWS\system32>net start "Print Spooler"
Print Spooler サービスを開始します.
Print Spooler サービスは正常に開始されました。

C:\WINDOWS\system32>net stop "Print Spooler"
次のサービスは他のサービスに依存しています。次のサービスも同時に停止されます。

   (依存している他のサービス名がここに列挙されます)

このまま続行しますか。 (Y/N) [N]:
```

**確認・判断のポイント**: 「正常に開始されました」「正常に停止されました」のようなメッセージが出れば成功です。`net stop` の実行時に、上の出力例のような依存関係の確認メッセージが表示されたら、Y（はい）と答える前に「巻き込まれて止まる別のサービスに、業務上・システム上の支障が出ないか」を必ず確認してから答えるようにします。

**つまずきやすい点**: ⚠️ `net start` / `net stop` の実行には、多くの場合、管理者権限（Administrator 権限。Windows の設定変更やシステムの操作を許可する強い権限のこと）でコマンドプロンプトを起動している必要があります。管理者権限のないウィンドウで実行すると、「システム エラー 5 が発生しました。アクセスが拒否されました。」のようなエラーになり、サービスは開始・停止されません。「エラーになったから壊れた」わけではなく、多くの場合は権限不足が原因なので、まずはスタートメニューからコマンドプロンプトを「管理者として実行」し直してみましょう。また `net stop` は、そのサービスに依存している他のサービスを道連れに停止することがあるため、サーバー構築の現場では、停止前に「このサービスを止めると何が連動して止まるか」を確認する習慣が欠かせません。

### shutdown --- シャットダウン・再起動を予約する（/s, /r, /a, /f）

`shutdown` は、パソコンをシャットダウン（電源を切ること）したり、再起動したりするためのコマンドです。`/s`（shutdown の略）でシャットダウン、`/r`（restart の略）で再起動を意味し、`/t`（time の略）に続けて秒数を指定すると、その秒数が経過してから処理が実行されます。`/t` を省略した場合は既定で 30 秒後に実行されます。

⚠️ ここで特に注意したいのが `/t 0` の指定です。`/t` に `0` を指定すると、待ち時間なしで即座にシャットダウン・再起動が始まります。通常は 30 秒などの猶予があるおかげで、コマンドを打ち間違えたことに気づいてから `shutdown /a`（abort、中止の意味）で取り消せますが、`/t 0` の場合はその猶予が無いため、一瞬で処理が実行されてしまい、あとから取り消すことができません。学習中は `/t 0` をむやみに使わず、必ず数十秒以上の待ち時間を指定する習慣をつけることをおすすめします。

また既定では、保存されていないファイルを持つアプリがあると「このアプリを終了できません」といった画面が表示され、処理が途中で止まってしまうことがあります。すべてのアプリを問答無用で閉じてから実行したい場合は `/f`（force、強制の意味）を追加しますが、これは保存確認なしにアプリを閉じるため、未保存の作業が失われるリスクがさらに高くなります。

```bat
REM 60秒後にシャットダウンする(この間にshutdown /aで中止できる)
shutdown /s /t 60

REM 60秒後に再起動する
shutdown /r /t 60

REM 予約したシャットダウン・再起動を取り消す
shutdown /a

REM 未保存のアプリも強制的に閉じたうえで、60秒後に再起動する
shutdown /r /t 60 /f

REM 危険: 待ち時間なしで即座にシャットダウンする(誤爆しやすいため学習中は避ける)
shutdown /s /t 0
```

出力例です。

```text
C:\Users\test>shutdown /s /t 60
C:\Users\test>shutdown /a
ログオフは取り消されました。スケジュールされたシャットダウンは取り消されました。
```

上の2行目のように、`/a` で中止に成功したときのメッセージには「ログオフ」という単語が含まれることがあります。これは実際にサインアウトを取り消したという意味ではなく、Windows が内部的に共有しているメッセージ文言によるもので、続く「スケジュールされたシャットダウンは取り消されました。」の部分が予約の取り消しを表しています。文言だけを見て「ログオフの話をしている、シャットダウンの取り消しには失敗したのでは」と早合点しないようにしてください。一方、そもそも予約されたシャットダウンが存在しない状態（`/t 0` で即座に実行済みの場合や、すでにタイマーが切れて処理が始まった後など）で `/a` を実行すると、「実行されていないシステム シャットダウンを中止することはできません。」のようなメッセージが表示されることがあります。

**確認・判断のポイント**: `shutdown /s` や `/r` を実行した直後は、画面右下などに「まもなくサインアウトします」といった通知（Windows のバージョンにより表示位置や文言は異なります）が出ることが多く、これで予約が受け付けられたことを確認できます。`shutdown /a` を実行して「取り消されました」というメッセージが出れば取り消し成功、「中止することはできません」というメッセージが出た場合はタイムアウトがすでに終わっている（つまり間に合わなかった）と判断できます。

**つまずきやすい点**: ⚠️ `shutdown /s` や `shutdown /r` は、リモート接続中の端末や、他の人が使っているサーバーに対して実行すると、作業中のセッションを強制的に切断してしまいます。特に本番稼働中のサーバーでは、事前の周知なしに実行しないよう注意してください。また `/t` の秒数を短く（特に `0` に）指定するほど、`shutdown /a` による取り消しが間に合わなくなる点も、初心者が特に誤りやすいポイントです。まずは長めの秒数（数分程度）で試し、慣れてから短くしていくと安全です。

**⚠️ `shutdown /s` や `/r` はシステム全体・他の利用者に影響する操作です。`/t` の秒数、特に `/t 0` の指定には十分注意し、実行前に未保存のファイルがないか、他に接続している利用者がいないかを必ず確認してください。**

### logoff --- 現在のユーザーをログオフする

`logoff` は、現在サインインしているユーザーをログオフ（サインアウト）させるコマンドです。開いているアプリはすべて終了し、画面はサインイン画面（ログイン画面）に戻ります。`shutdown` との大きな違いは、パソコン本体の電源は切れない、という点です。あくまで「今のユーザーの利用を終了して、次に使う人が別のユーザーでサインインできる状態に戻す」ための操作です。

```bat
REM 現在のユーザーをログオフする
logoff
```

`logoff` 自体は特別な出力を表示せず、実行するとそのまま画面がサインイン画面に切り替わることが多いです。

**確認・判断のポイント**: 実行後にサインイン画面（またはユーザー選択画面）が表示されれば、ログオフが完了したと判断できます。パソコンの電源は入ったままなので、`shutdown` のように電源ランプが消えたり、ファンの音が止まったりすることはありません。

**つまずきやすい点**: ⚠️ `logoff` を実行すると、開いていたアプリはすべて終了し、保存していない作業内容は失われる可能性があります。「サインアウトするだけだから大丈夫」と思い込まず、実行前に編集中のファイルを保存する習慣をつけましょう。また、リモートデスクトップ（ネットワーク越しに別のパソコンを遠隔操作する仕組み）で接続しているセッションに対して `logoff` を実行すると、その接続がそのまま切断される点にも注意してください。

**⚠️ `logoff` は開いているアプリをすべて終了させる操作です。未保存のファイルがないかを実行前に必ず確認し、リモートデスクトップ接続のセッションに対して実行すると接続そのものが切断されることも覚えておいてください。**

## ネットワークの確認

「サイトが開かない」「社内システムにつながらない」というトラブルが起きたとき、原因が自分のパソコンにあるのか、途中の経路にあるのか、それとも相手のサーバー側にあるのかを順番に切り分けていくための道具が、このセクションで扱うコマンドたちです。サーバー構築・運用の現場では障害対応のたびにこれらのコマンドで状況を確認するため、今のうちに手に馴染ませておくと、あとの学習がぐっと楽になります。まずは自分のパソコンの設定を確認する `ipconfig` から始め、相手までの通信を確認する `ping`・`tracert`・`pathping`、名前解決（ドメイン名をIPアドレスに変換すること）を確認する `nslookup`、今この瞬間の通信状態を見る `netstat`・`arp -a` という順番で見ていきます。

| やりたいこと | コマンド | 例 | 確認・判断のポイント |
| --- | --- | --- | --- |
| 自分のPCのIPアドレスをざっくり確認したい | `ipconfig` | `ipconfig` | IPv4アドレスとデフォルトゲートウェイが表示されているか |
| IPアドレスの詳細（MACアドレスやDNSサーバーなど）まで確認したい | `ipconfig /all` | `ipconfig /all` | 物理アドレス（MACアドレス）、DNSサーバー、DHCPの有効・無効 |
| DNSの古いキャッシュを消したい | `ipconfig /flushdns` | `ipconfig /flushdns` | 「正常にフラッシュされました」のようなメッセージが出るか |
| 相手まで通信が届くか確認したい | `ping` | `ping google.com` | 応答が4回返るか、"要求がタイムアウトしました。" が出ていないか |
| 応答が止まるまで ping を打ち続けたい | `ping -t` | `ping -t google.com` | 継続的に応答が返り続けるか（⚠️ 自分で止めるまで終わらない） |
| 相手までの経路を調べたい | `tracert` | `tracert google.com` | どのホップ（経路上の中継地点）まで応答が返っているか |
| 経路上の各地点の安定性まで詳しく調べたい | `pathping` | `pathping google.com` | 各ホップのパケットロス率（⚠️ 集計に数分かかることがある） |
| ドメイン名に対応するIPアドレスを調べたい | `nslookup` | `nslookup example.com` | 名前解決ができているか、返ってきたIPアドレスは何か |
| 今の通信状況を一覧で見たい | `netstat -an` | `netstat -an` | 状態列が LISTENING（待ち受け中）か ESTABLISHED（接続確立中）か |
| どのアプリが通信しているか特定したい | `netstat -ano` | `netstat -ano` | 表示されたPIDをタスクマネージャーの「詳細」タブと照合できるか |
| 同じネットワーク内の機器のMACアドレスを確認したい | `arp -a` | `arp -a` | IPアドレスと物理アドレスの対応表が表示されるか |

### ipconfig --- 自分のネットワーク設定を確認する（/all, /flushdns）

`ipconfig`（IP configuration の略で、自分のパソコンに割り当てられているネットワーク設定を表示するコマンド）は、ネットワークトラブルを調べるときに最初に打つ定番コマンドです。何もオプションを付けずに実行すると、IPv4アドレス（自分のPCに割り当てられた住所のようなもの）とデフォルトゲートウェイ（そのPCがインターネットへ出ていく際の玄関口となる機器のアドレス）などの最低限の情報だけが表示されます。もう少し詳しい情報がほしいときは `/all`、DNS（ドメイン名をIPアドレスに変換してくれる仕組み）の記憶をリセットしたいときは `/flushdns` を使います。

```bat
REM 基本形: IPv4アドレスやデフォルトゲートウェイなど、最低限の情報を表示する
ipconfig

REM /all: 物理アドレス(MACアドレス)やDNSサーバー、DHCPの有効/無効など詳細情報まで表示する
ipconfig /all

REM /flushdns: 覚えている古いDNSの記録(名前解決のキャッシュ)を消去する
ipconfig /flushdns
```

`ipconfig` を実行すると、次のような内容が表示されることが多いです。

```text
Windows IP 構成

イーサネット アダプター イーサネット:

   接続固有の DNS サフィックス . . . . .:
   IPv4 アドレス . . . . . . . . . . . .: 192.168.1.15
   サブネット マスク . . . . . . . . . .: 255.255.255.0
   デフォルト ゲートウェイ . . . . . . .: 192.168.1.1
```

`ipconfig /flushdns` を実行した場合は、次のような短いメッセージだけが表示されることが多いです。

```text
Windows IP 構成

DNS リゾルバー キャッシュは正常にフラッシュされました。
```

**確認・判断のポイント**: IPv4アドレスが `192.168.x.x` や `10.x.x.x` のような通常のプライベートアドレス（組織内など限られた範囲だけで使われるアドレス）を取得できているか確認します。もし `169.254.` から始まるアドレスになっている場合、DHCP（IPアドレスを自動で割り当てる仕組み）からアドレスをうまく受け取れなかった可能性が高い、といったサインとして知られています。デフォルトゲートウェイが表示されていない場合は、ルーターとの通信経路そのものに問題がある可能性があります。

**つまずきやすい点**: `ipconfig` だけでは情報が省略されるため、MACアドレスやDNSサーバーなど詳しい情報が必要なときに `/all` を付け忘れがちです。また `/flushdns` はあくまで「名前解決の記憶（キャッシュ）」を消すだけの操作で、IPアドレス自体を取り直す操作（DHCPからの再取得）ではありません。サイトのURLは変えたはずなのに古いページや接続エラーが出続けるときに使うコマンドである、と目的を分けて覚えておくと混同しにくくなります。

### ping --- 相手まで通信が届くか確認する（-t）

`ping` は、ネットワークの疎通確認（通信がちゃんと届くかどうかの確認）で使われる代表的なコマンドです。ICMP（通信の確認のためだけに使われる、ping や tracert が利用する仕組み）という方式でパケット（データの小さなかたまり）を相手に送り、その応答が返ってくるかどうかで「相手まで届いているか」を判断します。既定では4回だけ送信して自動的に終了しますが、`-t` を付けると自分で止めるまで送信し続けます。

```bat
REM 基本形: 既定では4回だけ送信して自動的に終了する
ping google.com

REM IPアドレスを直接指定して調べることもできる
ping 8.8.8.8

REM -t: Ctrl+C を押すまで送信し続ける
ping -t google.com
```

`ping google.com` を実行すると、次のように表示されることが多いです。

```text
google.com [142.250.207.14] に ping を送信しています 32 バイトのデータ:
142.250.207.14 からの応答: バイト数 =32 時間 =12ms TTL=118
142.250.207.14 からの応答: バイト数 =32 時間 =11ms TTL=118
142.250.207.14 からの応答: バイト数 =32 時間 =13ms TTL=118
142.250.207.14 からの応答: バイト数 =32 時間 =12ms TTL=118

142.250.207.14 の Ping 統計:
    パケット数: 送信 = 4、受信 = 4、損失 = 0 (0% の損失)、
ラウンド トリップの概算時間 (ミリ秒):
    最小 = 11ms、最大 = 13ms、平均 = 12ms
```

**確認・判断のポイント**: 末尾の統計情報にある `損失 = 0 (0% の損失)` のように、失われたパケットが0件であれば、相手までの疎通は基本的に問題ありません。`時間`（応答時間、単位はミリ秒）の値が極端に大きい、または回ごとに大きくばらつく場合は、回線が不安定な可能性があります。`TTL`（Time To Live。データが経由できる最大のホップ数を表す値）は、相手までの経路の目安として使われることもあります。ほとんどの行が "要求がタイムアウトしました。" になる場合は、届いていない可能性が高く、次は `tracert` でどこまで届いているかを確認します。

**つまずきやすい点**: ⚠️ `-t` を付けると `Ctrl+C` を押すまで自動的には終了しません。付け忘れて放置すると、画面やログがどんどん流れて埋もれてしまいます。統計だけをその場で確認しつつ実行は続けたいときは `Ctrl+Break` を使うと、止めずに途中経過を表示できます。また、一部のサーバーやファイアウォール（通信の許可・拒否を制御する仕組み）は、セキュリティ上の理由で ping への応答（ICMP）そのものをブロックしていることがあります。この場合、実際にはWebサイトが正常に見られる状態でも `ping` だけは失敗して見えることがあるため、「ping が失敗した=通信できない」と即断しないよう注意してください。

**⚠️ `ping -t` は自分で `Ctrl+C` を押すまで終了しません。確認が終わったら必ず停止し、動かしっぱなしにしないようにしてください。**

### tracert --- 相手までの経路を調べる

`tracert`（trace route の略）は、自分のパソコンから目的のサーバーまでの間に、どんな中継機器（ルーターなど）を経由しているかを1つずつ表示するコマンドです。`ping` だけでは「届くか届かないか」の結果しか分かりませんが、`tracert` を使うと「どこまでは届いていて、どこから先が詰まっているのか」という経路上の切り分けができます。

```bat
REM 目的地までの経路を1ホップ(中継地点)ずつ順番に調べる
tracert google.com
```

`tracert google.com` を実行すると、次のように表示されることが多いです。

```text
google.com [142.250.207.14] へのルートをトレースしています
経由するホップ数は最大 30 です:

  1     2 ms     1 ms     1 ms  192.168.1.1
  2     8 ms     7 ms     8 ms  10.10.0.1
  3     *        *        *     要求がタイムアウトしました。
  4    12 ms    11 ms    12 ms  142.250.207.14

トレースを完了しました。
```

**確認・判断のポイント**: 各行が1つのホップ（hop。経路上の中継地点1つ分のこと）に対応し、左から3回分の応答時間（ミリ秒）、そのホップのIPアドレス（またはホスト名）が並びます。最後の行（最終ホップ）まで応答が表示されていれば、経路全体はつながっていると判断できます。途中の行だけ "要求がタイムアウトしました。" になっていても、その先の行に応答が戻ってきていれば、その中継機器がICMPへの応答を止めているだけで、通信自体には問題がないケースが多いとされています。逆に、ある行から最後まで一貫してタイムアウトが続く場合は、その手前のどこかで詰まっている可能性が高くなります。

**つまずきやすい点**: 表示される中継地点のIPアドレスやホスト名だけを見て、それが社内ネットワークなのかプロバイダの設備なのかを判断するのは初心者には難しいことが多いです。最初のうちは「最後まで届いているか」「途中で止まっているとしたら何ホップ目か」にだけ注目すれば十分です。また `tracert` も `ping` と同様にICMPを使って経路を調べる仕組みのため、一部の中継機器では意図的にブロックされ、実際より多くの行がタイムアウトして見えることがあります。

### pathping --- 経路の安定性まで詳しく調べる

`pathping` は、`tracert` と `ping` を組み合わせたようなコマンドです。まず経路を洗い出したうえで、各ホップに対して既定で250ミリ秒間隔・100回ずつパケットを送り、パケットロス率（送ったのに届かなかった割合）を集計して表示します。`tracert` だけでは分からない「経路の途中の、特定の中継地点だけ調子が悪い」といった不安定さを切り分けたいときに向いています。

```bat
REM 経路上の各ホップの安定性(パケットロス率)まで調べる
pathping google.com
```

`pathping google.com` を実行すると、経路を洗い出したあとに、次のような集計結果が表示されることが多いです。

```text
google.com [142.250.207.14] へのルートをトレースしています
経由するホップ数は最大 30 です:
  0  DESKTOP-ABC123 [192.168.1.15]
  1  192.168.1.1
  2  10.10.0.1
  3  142.250.207.14

統計を 75 秒間計算しています...
                              ソースからここまで      このノード/リンク
ホップ  RTT    損失/送信 = %  損失/送信 = %  アドレス
  0                                           DESKTOP-ABC123 [192.168.1.15]
                                0/ 100 =  0%
  1    1ms     0/ 100 =  0%     0/ 100 =  0%  192.168.1.1
                                0/ 100 =  0%
  2    8ms     0/ 100 =  0%     0/ 100 =  0%  10.10.0.1
                                2/ 100 =  2%
  3   12ms     2/ 100 =  2%     0/ 100 =  0%  142.250.207.14
```

**確認・判断のポイント**: 「損失/送信 = %」という列（パケットロス率）が0%に近いホップは安定していると判断できます。特定のホップだけこの数値が高い場合、そこが不安定さの原因になっている可能性が高いです。特に「このノード/リンク」の列（そのホップ単体でのロス率）が高い地点は、実際に問題を抱えている中継地点である可能性が高いとされています。

**つまずきやすい点**: ⚠️ `pathping` は既定の設定のままだと、各ホップに対して100回・250ミリ秒間隔（1ホップあたり約25秒）パケットを送り続けて集計するため、ホップ数が多い経路では全体で数分〜10分程度かかることがあります。`tracert` より詳しい情報が得られる代わりに時間がかかる、という違いを理解したうえで、急いでいるときはまず `ping` と `tracert` で当たりをつけ、原因を絞り込みたいときに `pathping` を使うと効率的です。実行を途中で打ち切りたいときは `Ctrl+C` で中断できますが、その場合は集計が完了していない途中経過の結果になります。

**⚠️ `pathping` は既定の設定のままだと数分〜10分程度かかることがあります。急いで確認したいときは、先に `ping` と `tracert` で見当をつけてから使うようにしてください。**

### nslookup --- ドメイン名からIPアドレスを調べる

`nslookup`（name server lookup の略）は、`example.com` のような人が読みやすいドメイン名に対応するIPアドレスを、DNSサーバー（ドメイン名をIPアドレスに変換してくれるサーバー）に問い合わせて調べるコマンドです。「サイトが開かない」というとき、そもそもドメイン名を正しくIPアドレスに変換できているか（名前解決ができているか）を切り分けたいときに使います。

```bat
REM ドメイン名に対応するIPアドレスを調べる(既定では自分のPCに設定されているDNSサーバーが使われる)
nslookup example.com

REM 問い合わせ先のDNSサーバーを指定して調べることもできる
nslookup example.com 8.8.8.8
```

`nslookup example.com` を実行すると、次のように表示されることが多いです。

```text
サーバー:  UnKnown
Address:  192.168.1.1

権限のない回答:
名前:    example.com
Addresses:  2606:2800:21f:cb07:6820:80da:af6b:8b2c
          93.184.216.34
```

`nslookup example.com 8.8.8.8` のように問い合わせ先のDNSサーバーを明示的に指定した場合は、その指定したサーバーの情報が「サーバー」欄に表示されます。

```text
サーバー:  dns.google
Address:  8.8.8.8

権限のない回答:
名前:    example.com
Addresses:  2606:2800:21f:cb07:6820:80da:af6b:8b2c
          93.184.216.34
```

**確認・判断のポイント**: 「サーバー」欄には問い合わせ先のDNSサーバー、「名前」「Addresses」欄には対象ドメインの名前解決の結果（IPアドレス）が表示されます。ここでIPアドレスが返ってくれば名前解決自体は成功しており、開かない原因は別の場所（相手サーバー側やその後の経路など）にある可能性が高いと判断できます。逆に "DNS request timed out." のようなタイムアウトのメッセージや、"*** ~ を見つけられません: Non-existent domain" のような非存在ドメインのエラーが出る場合は、名前解決自体がうまくいっていないことになります。

**つまずきやすい点**: サーバーを指定しない場合、「サーバー」欄には自分のPCに設定されているDNSサーバー（多くは自宅やオフィスのルーター）の情報が表示されますが、そのアドレスに対する逆引き（IPアドレスからホスト名を調べること）ができないと `UnKnown` と表示されることがよくあります。これはエラーではなく、単にそのDNSサーバー自身の名前が登録されていない、というだけのことなので気にしなくて大丈夫です。また「権限のない回答」という表示も、問い合わせ先のDNSサーバーがそのドメインの正式な管理者ではなく、他のサーバーから聞いた情報をキャッシュ（一時的に覚えておく仕組み）して答えている、という意味の一般的な表示であり、こちらもエラーではありません。さらに `ping` や `tracert` が失敗していても `nslookup` だけは成功する（名前解決はできているが、その先の通信が届いていない）ということもよくあるため、「名前解決ができること」と「実際に通信できること」は別の話だと意識しておくと切り分けがスムーズになります。

### netstat --- 今の通信状況を確認する（-an, -ano）

`netstat`（network statistics の略）は、今このパソコンがどんな通信を行っているか、つまりどのポート（通信の窓口番号）を使って、どこと接続しているかを一覧表示するコマンドです。`-a` はすべての接続を、`-n` は名前解決をせず数字（IPアドレスやポート番号）のまま表示する、という意味で、この2つを組み合わせた `-an` がよく使われます。さらに `-o`（その通信の所有プロセスを表示するオプション）を加えた `-ano` を使うと、その通信を行っているプロセスのPID（プロセスID。動作中の各プログラムに割り振られる番号）まで表示されます。

```bat
REM -an: すべての接続(-a)を、名前解決せず数字のまま(-n)一覧表示する
netstat -an

REM -ano: -an の内容に加えて、通信しているプロセスのPID(プロセスID)も一緒に表示する
netstat -ano
```

`netstat -ano` を実行すると、次のように表示されることが多いです。

```text
アクティブな接続

  プロトコル  ローカル アドレス      外部アドレス        状態          PID
  TCP         0.0.0.0:135            0.0.0.0:0            LISTENING     912
  TCP         192.168.1.15:52344     142.250.207.14:443   ESTABLISHED  4820
  TCP         127.0.0.1:5432         0.0.0.0:0            LISTENING    6100
```

`netstat -an` の場合は、これと同じ内容から一番右のPID列だけが無い形で表示されることが多いです。

**確認・判断のポイント**: 「状態」列がLISTENING（そのポートで接続を待ち受けている状態）になっていれば、何らかのプログラムがそのポートで通信を受け付ける準備をしていることを示します。ESTABLISHED（接続確立中）は、実際に相手と接続が成立し通信している状態です。見覚えのないポートでLISTENINGになっているものがあれば、意図しないソフトが動いていないか調べる手がかりになります。`-ano` で表示されるPID列の番号を、`tasklist`（実行中のプロセス一覧を表示するコマンド）やタスクマネージャーの「詳細」タブと照らし合わせると、どのアプリがその通信をしているか特定できます。

**つまずきやすい点**: `-a` を付け忘れると一部の接続しか表示されないことがあるため、まず全体像をつかみたいときは `-an` を基本形として覚えておくと安心です。⚠️ 表示されたPID番号だけを見て、内容をよく確認せずに `taskkill` などで強制終了すると、システムに必要なプロセスまで止めてしまうことがあります。PIDだけでなく、必ず `tasklist` などでプロセス名まで確認してから操作するようにしてください。また `netstat` の一覧は実行した瞬間だけのスナップショット（その場限りの状態）であり、時間が経つと接続状況はどんどん変化していきます。

### arp -a --- 同じネットワーク内の機器のMACアドレスを確認する

`arp -a` は、ARP（Address Resolution Protocol。IPアドレスからMACアドレス（ネットワーク機器ごとに割り振られた固有の識別番号）を調べる仕組み）を使って、自分のパソコンが最近やり取りした、同じネットワーク内にある機器のIPアドレスとMACアドレスの対応表を表示するコマンドです。社内LAN（限られた範囲内だけで構成されたネットワーク）で「このIPアドレスの機器は物理的にどれなのか」を特定したいときなどに使われます。

```bat
REM 同じネットワーク内の機器のIPアドレスとMACアドレスの対応表を表示する
arp -a
```

`arp -a` を実行すると、次のように表示されることが多いです。

```text
インターフェイス: 192.168.1.15 --- 0xc
  インターネット アドレス  物理アドレス           種類
  192.168.1.1               aa-bb-cc-11-22-33      動的
  192.168.1.20               aa-bb-cc-44-55-66      動的
  192.168.1.255             ff-ff-ff-ff-ff-ff      静的
```

**確認・判断のポイント**: 「インターネット アドレス」列がIPアドレス、「物理アドレス」列がMACアドレスに対応します。特定のIPアドレスの機器が、同じネットワーク上のどの物理的な機器なのかを確認したいときに、この対応表を手がかりにします。「種類」列が「動的」となっているものは通信のたびに自動更新される一時的な情報で、「静的」は手動で設定された情報や、ブロードキャストアドレス（ネットワーク内の全員宛の特別なアドレス）のようにあらかじめ決まっているものを表します。

**つまずきやすい点**: `arp -a` の一覧は、あくまで自分のパソコンが最近やり取りをした機器だけが載る一時的なキャッシュ（通信がないと数分程度で情報が消えていく仕組み）であり、ネットワーク全体の機器台帳のようにずっと保持され続ける記録ではありません。見たい機器が一覧に出てこないときは、一度その機器に向けて `ping` を打ってから改めて `arp -a` を実行すると、そのタイミングの通信によって情報が記録されることが多いです。

### 補足: なぜ ping → tracert → nslookup の順で切り分けるのか

「サイトが開かない」という同じ症状でも、原因は自分のパソコンの設定、途中の経路、名前解決（DNS）、相手サーバー自体など、さまざまな場所に隠れている可能性があります。まず `ping` で「そもそも相手まで届いているか」を確認し、届かなければ `tracert`（経路のどこまでは届いているかを見たい）や `pathping`（さらに経路の安定性まで詳しく見たい）で経路上の詰まりどころを確認し、URLは合っているはずなのに開かない場合は `nslookup` で「ドメイン名が正しくIPアドレスに変換できているか」を確認する、という順番で進めると、原因のありかを一つずつ絞り込んでいくことができます。この考え方は、実際のサーバー障害対応でもよく使われる基本的な手順です。`netstat` や `arp -a` は、相手までの疎通確認そのものではなく、自分のパソコン側で「今どんな通信をしているか」「同じネットワーク上のどの機器と接続しているか」を確認したいときに使う、少し性質の違う調査コマンドとして区別して覚えておくとよいでしょう。

## ディスク・ユーザー・権限の確認

このセクションでは、ディスク（ハードディスクやSSDなどの記憶装置のこと）の状態を点検する方法と、「今どのユーザーでログインしていて、どんな権限を持っているか」を確認する方法を学びます。サーバー構築の現場では、「なぜか正しく動かない」「なぜかアクセスできない」という不具合の原因が、ディスクの不良やユーザー・フォルダーの権限設定にあることが少なくありません。ここで扱うコマンドのほとんどは「見るだけ」の安全な確認コマンドですが、中には一つ操作を間違えるとディスクの中身を丸ごと失いかねない危険なコマンド（`diskpart`）も含まれているため、安全なものと危険なものをはっきり区別しながら読み進めてください。

### chkdsk --- ディスクの状態を点検・修復する

`chkdsk`（check disk の略）は、ディスク上のファイルシステム（ディスクの中でファイルやフォルダーをどう管理するかを決めているルールの仕組みのこと）やディスクそのものに問題がないかを調べるコマンドです。実行するときの引数（コマンドに付け足す追加の指示のこと）によって、「調べるだけ」なのか「実際に直す」のかが大きく変わるため、まずはこの違いを区別して覚えることが大切です。

引数を何も付けずに実行すると、ディスクの状態を読み取って報告するだけの、いわば「健康診断」にとどまり、ディスクの中身は変更されません。`/f`（fix、修復の意味）を付けると、見つかった問題を実際に直そうとするため、対象のドライブを一時的に独占して使う必要があります。さらに `/r`（recover、回復の意味）を付けると、`/f` の機能に加えて、ディスク上の不良セクタ（物理的に壊れて読み書きできなくなった記録領域のこと）まで検査し、そこに残っていたデータの回復を試みます。`/r` は `/f` の機能を含んでいるため、両方同時に指定する必要はありません。

```bat
REM 引数なし: 読み取り専用でディスクの状態を確認する(中身は変更しない)
chkdsk C:

REM /f: 見つかった問題を実際に修復する(対象ドライブを一時的に占有する)
chkdsk C: /f

REM /r: 不良セクタの検査・データ回復まで行う(/f の機能を含む)
chkdsk C: /r
```

引数なしで実行すると、次のように表示されることが多いです（項目の一部を抜粋しています）。

```text
ファイル システムの種類は NTFS です。

Windows によってファイル システムがスキャンされました。問題は検出されませんでした。

  500,105,216 KB 合計ディスク領域
   45,203,884 KB が 182,004 個のファイルに使用されています
       98,304 KB がシステムで使用されています
  454,802,948 KB が使用可能です
```

一方、Windowsが起動中に使っているCドライブのように「今まさに使用中」のドライブに対して `/f` を実行すると、次のように表示されることが多いです。

```text
別のプロセスがこのボリュームを使用しているため、
CHKDSK は実行できません。

次回、システムを起動するときに、このボリュームを検査しますか (Y/N)?
```

**確認・判断のポイント**: 引数なしの結果で「問題は検出されませんでした」と出ていれば、今のところファイルシステム上の異常はない、という意味です。`/f` を実行してすぐに終わらず「次回の起動時に検査を予約しますか」と聞かれた場合は、そのドライブが使用中で今は修復できない、という意味です。Yを選ぶと、次回の起動時に自動で検査・修復が行われます。

**つまずきやすい点**: 引数なしと `/f` 付きでは挙動がまったく違う点（見るだけ・実際に直す）を混同しないようにします。Cドライブのような起動ディスクは大抵使用中のため、`/f` を付けても即座には実行されず、再起動が必要になることが多い点も覚えておきましょう。`/r` は不良セクタの検査を伴うため、ディスクの容量が大きいほど非常に時間がかかることがあります（数十分から数時間かかることもあります）。⚠️ `/f` や `/r` は対象ドライブを一時的に占有し、状況によっては再起動を伴う操作です。実行前に対象のドライブ文字（C:やD:など）を必ず確認してください。

### Get-Volume --- ドライブの一覧・空き容量を確認する（PowerShell）

`Get-Volume` は、PowerShell（コマンドプロンプトの後継として使われることが多い、より高度なコマンドライン画面のこと）で使う、ドライブの一覧やサイズ、空き容量、健全性の状態をまとめて確認できるコマンドレット（PowerShellの命令ひとつひとつのこと）です。ディスク容量確認の新しい方法として案内されており、コマンドプロンプトの `wmic` に代わる存在として覚えておくとよいでしょう。

```powershell
# 認識されているすべてのドライブ(ボリューム)を一覧表示する
Get-Volume

# ドライブレターを指定して、特定のドライブだけ確認する
Get-Volume -DriveLetter C
```

実行すると、次のように表示されることが多いです。

```text
DriveLetter FileSystemLabel FileSystem DriveType HealthStatus OperationalStatus SizeRemaining     Size
----------- ---------------- ---------- --------- ------------ ----------------- -------------     ----
C           Windows          NTFS       Fixed     Healthy      OK                    120.5 GB  237.5 GB
D           Data             NTFS       Fixed     Healthy      OK                    340.1 GB  465.7 GB
```

**確認・判断のポイント**: HealthStatus列がHealthy以外（Warning や Unhealthy など）になっていたら、ドライブに何らかの問題がある可能性がある、と判断します。OperationalStatus列は通常「OK」になっているかを見て、ドライブが正常に稼働しているかの参考にします。SizeRemaining（残りサイズ）とSize（全体サイズ）を見比べれば、空き容量が少なくなっていないかがすぐに分かります。

**つまずきやすい点**: `Get-Volume` はPowerShell専用のコマンドレットで、コマンドプロンプト（cmd.exe）ではそのままでは使えません。サイズはGBなど読みやすい単位に自動的に丸めて表示されることが多いですが、環境や表示設定によって桁数や単位の見え方が変わることがあります。USBメモリや光学ドライブなど、C・D以外のドライブも一覧に含まれるため、対象を絞りたいときは `-DriveLetter` を活用します。

### Get-PSDrive --- PowerShellが扱う「ドライブ」全般を確認する

`Get-PSDrive` は、PowerShellが「ドライブ」として扱うすべての対象を一覧表示するコマンドレットです。ここでいう「ドライブ」はCドライブのようなディスクだけでなく、レジストリ（Windowsの設定情報をまとめて保存している場所のこと）や環境変数なども含まれる、少し広い概念です。ディスクの空き容量だけを知りたいときは前述の `Get-Volume` のほうがシンプルで読みやすいですが、「今PowerShellから見えている全体像」を把握したいときはこちらが向いています。

```powershell
# 現在認識されているすべての PSDrive を一覧表示する
Get-PSDrive

# ファイルシステム(ディスク)のドライブだけに絞り込みたい場合
Get-PSDrive -PSProvider FileSystem
```

実行すると、次のように表示されることが多いです。

```text
Name           Used (GB)     Free (GB) Provider      Root
----           ---------     --------- --------      ----
C                   117.0         120.5 FileSystem    C:\
D                    89.4         340.1 FileSystem    D:\
Env                                     Environment
HKCU                                    Registry      HKEY_CURRENT_USER
HKLM                                    Registry      HKEY_LOCAL_MACHINE
```

**確認・判断のポイント**: Provider列を見ると、その項目が「FileSystem（ディスク）」なのか「Registry（レジストリ）」なのかなど、種類を区別できます。ディスクの空き容量だけ確認したい場合は、Provider が FileSystem の行だけに注目します。

**つまずきやすい点**: HKLMやHKCUのような見慣れない名前もドライブとして一覧に混ざって出てくるため、初めて見ると戸惑うかもしれません。あくまで「PowerShellがドライブ的に扱えるようにした対象」という理解で構いません。Used/Freeの表示単位はPowerShellのバージョンや表示設定によって、バイトの生数値になっている場合とGB単位になっている場合があります。

### wmic logicaldisk get --- （参考・旧方式）コマンドプロンプトでディスク一覧を見る

`wmic`（Windows Management Instrumentation Command-line の略で、Windowsの内部情報を問い合わせるための、昔からあるコマンドプロンプト用のコマンドのこと）を使うと、`logicaldisk get` に続けてプロパティ名（知りたい項目の名前のこと）を指定するだけで、ドライブの一覧やサイズ、空き容量をコマンドプロンプトから確認できます。長らくディスク確認の定番として使われてきましたが、後述するとおりMicrosoftはこのコマンドの廃止を進めているため、これから新しく覚える場合は前述の `Get-Volume` や `Get-PSDrive` を優先することをおすすめします。

```bat
REM ドライブレター・サイズ・空き容量を確認する
wmic logicaldisk get name,size,freespace

REM ファイルシステムの種類も一緒に確認したい場合
wmic logicaldisk get name,filesystem,freespace,size
```

実行すると、次のように表示されることが多いです。

```text
FreeSpace     Name  Size
129394024448  C:    255083843584
365467664384  D:    500105383936
```

**確認・判断のポイント**: Name列がドライブレター、Sizeが総容量、FreeSpaceが空き容量で、いずれもバイト単位の数値のまま表示されます。GBに換算したい場合は自分で計算するか、`Get-Volume` など単位付きで表示してくれるコマンドを使うほうが手間がかかりません。なお `wmic ... get` は、指定したプロパティの順番（この例では name, size, freespace）どおりではなく、列名のアルファベット順（FreeSpace → Name → Size）で表示される点にも注意してください。

**つまずきやすい点**: ⚠️ `wmic` はMicrosoftが段階的に廃止を進めているコマンドです。Windows 11 22H2で「オンデマンド機能（Feature on Demand、既定では入っていないが必要なら追加できる部品）」という扱いに変わり、23H2・24H2ではその機能自体が既定で無効化されました。24H2以降に新規インストールした環境ではこの機能が最初から含まれていないことが多く、既存の環境についても、今後の更新プログラムを通じて完全に取り除かれていく方針が示されています。これから学習する場合は、`Get-Volume` や `Get-PSDrive` などPowerShell側のコマンドを優先して覚えておくと、将来の環境でも通用しやすくなります。

### net user --- コンピューター上のユーザーアカウントを確認する

`net user` は、そのコンピューターに存在するローカルユーザーアカウント（Windowsにサインインするための個人ごとの入り口のこと）の一覧や詳細を確認できるコマンドです。引数なしで実行すると一覧が、ユーザー名を指定すると、そのアカウントが有効かどうか、パスワードを最後に設定した日付、所属しているグループなど、より詳しい情報が表示されます。

```bat
REM このコンピューターのローカルユーザーアカウント一覧を表示する
net user

REM 特定ユーザーの詳細情報を表示する
net user Taro
```

`net user` を実行すると、次のように表示されることが多いです。

```text
\\DESKTOP-ABC123 のユーザー アカウント

-------------------------------------------------------------------------------
Administrator            DefaultAccount           Guest
Taro                     WDAGUtilityAccount
コマンドは正常に終了しました。
```

ユーザー名を指定した場合は、次のように表示されることが多いです（実際にはこれ以外にも、フルネームやログオン時間帯などの項目がさらに続きます）。

```text
ユーザー名                   Taro
フル ネーム
アカウント有効                Yes
アカウント満了日               なし
パスワードの最終設定日           2026/08/01
ローカル グループ  メンバーシップ      *Users
グローバル グループ メンバーシップ    *None
```

**確認・判断のポイント**: 一覧に見覚えのないアカウントが増えていないかを確認します。共有PCやサーバーでは、意図しないアカウントが後から追加されていないかのチェックに使えます。詳細表示では「アカウント有効」がYesかNoかで、そのアカウントが今サインインに使えるかどうかが分かります。

**つまずきやすい点**: `net user <ユーザー名> <パスワード> /add` のように実行すると、新しいユーザーアカウントを作成できてしまいます。⚠️ これは変更を伴う操作で、実行には管理者権限が必要です。またコマンドにパスワードをそのまま書くと、画面表示やコマンド履歴に平文（暗号化されていない、そのままの文字列のこと）で残ってしまうため、実際の運用では注意が必要です。本ドキュメントでは「一覧・詳細の確認」の使い方にとどめ、ユーザー作成の詳しい運用方法は扱いません。

### net localgroup administrators --- 管理者権限を持つユーザーを確認する

`net localgroup administrators` は、Administrators（管理者）グループ（複数のユーザーをまとめて同じ権限を与えるための入れ物のこと）に所属しているユーザーの一覧を表示するコマンドです。「このコンピューターで誰が管理者権限を持っているか」を確認する、セキュリティ確認の定番コマンドといえます。

```bat
REM Administrators グループのメンバー一覧を表示する
net localgroup administrators
```

実行すると、次のように表示されることが多いです。

```text
エイリアス名     administrators
コメント     コンピューター/ドメインに対する完全で制限のないアクセス権を持っています。

メンバー
-------------------------------------------------------------------------------
Administrator
Taro
コマンドは正常に終了しました。
```

**確認・判断のポイント**: 一覧に見覚えのないアカウントが含まれていないかを確認します。管理者グループに入っているアカウントは、システム設定の変更やソフトウェアのインストールなど強い権限を持っているため、意図しないアカウントが混ざっていた場合は速やかに調査・対応が必要です。

**つまずきやすい点**: 表示される「エイリアス名」はグループの内部的な名前で、日本語環境でも英語表記の `administrators` のまま扱われることが一般的です。似た名前の `net group` というコマンドもありますが、こちらはドメイン（会社などの組織内で複数のパソコンをまとめて管理する仕組みのこと）環境のグループを扱うコマンドで、`net localgroup` とは対象が異なる点に注意してください。

### whoami /priv と whoami /groups --- 自分の特権・所属グループを確認する

この2つは、「今サインインしているユーザーに何が許可されているか」を確認するためのコマンドで、セットで使われることが多いです。`whoami /priv` は自分に割り当てられている特権（Privilege。システム時刻の変更やシャットダウンなど、システムレベルの特別な操作を行うために個別に割り当てられる許可のこと）の一覧を、`whoami /groups` は自分が所属しているグループの一覧を表示します。

```bat
REM 自分に割り当てられている特権の一覧を確認する
whoami /priv

REM 自分が所属しているグループの一覧を確認する
whoami /groups
```

`whoami /priv` を実行すると、次のように表示されることが多いです（項目の一部を抜粋しています）。

```text
特権情報
----------------------------------------------
特権名                        説明                                  状態
============================= ===================================== ========
SeShutdownPrivilege           システムをシャットダウンします           無効
SeChangeNotifyPrivilege       トラバース チェックをバイパスします      有効
SeIncreaseWorkingSetPrivilege プロセスのワーキング セットを増加します   無効
```

`whoami /groups` を実行すると、次のように表示されることが多いです（抜粋）。

```text
グループ名                               種類      SID
======================================= ========= ==============================================
BUILTIN\Administrators                   エイリアス S-1-5-32-544
BUILTIN\Users                            エイリアス S-1-5-32-545
```

**確認・判断のポイント**: `/priv` の「状態」列がEnabled（有効）かDisabled（無効）かを見ます。一覧に載っていても「無効」であれば、その特権は今は使われていない状態です。`/groups` の一覧に `BUILTIN\Administrators` が含まれていれば、そのユーザーは管理者グループに所属していることが分かります。SID（セキュリティ識別子。ユーザーやグループを一意に区別するためのIDのこと）は、名前が変わっても変化しない内部的な識別番号です。

**つまずきやすい点**: 管理者グループに所属していても、コマンドプロンプトやアプリを「通常のまま」起動している場合、UAC（ユーザーアカウント制御。本当に管理者権限で実行してよいか確認してくる仕組みのこと）の働きにより、一部の特権が実際には制限された状態（「昇格」されていない状態）で動いていることがあります。管理者権限が必要な操作でエラーになる場合は、グループの所属だけでなく、「管理者として実行」しているかどうかも確認しましょう。

### icacls --- ファイル・フォルダーの権限（ACL）を確認する

`icacls` は、指定したファイルやフォルダーに対して、どのユーザーやグループが、どのような操作（読み取り・書き込みなど）を許可されているかを確認できるコマンドです。この「誰が」「何を」できるかをまとめたルールの一覧のことをACL（アクセス制御リストの略）と呼び、`icacls` はそのACLを画面に表示したり、変更したりするためのコマンドです。パスだけを指定して実行する分には表示だけなので、安全に使えます。

```bat
REM 指定したフォルダーの権限一覧を表示する
icacls C:\Users\Taro\Documents
```

実行すると、次のように表示されることが多いです。

```text
C:\Users\Taro\Documents NT AUTHORITY\SYSTEM:(OI)(CI)(F)
                         BUILTIN\Administrators:(OI)(CI)(F)
                         DESKTOP-ABC123\Taro:(OI)(CI)(F)
正常に処理されたファイルは 1 個です。処理に失敗したファイルは 0 個です
```

**確認・判断のポイント**: 各行の末尾にあるアルファベットが権限の内容を表します。代表的なものは F（フルコントロール、すべての操作が可能）、M（変更）、RX（読み取りと実行）、R（読み取りのみ）、W（書き込みのみ）です。想定していないユーザーやグループにF（フルコントロール）が付いていないか、という視点で確認します。

**つまずきやすい点**: `(OI)`（Object Inherit、ファイルへの継承）や `(CI)`（Container Inherit、サブフォルダーへの継承）といった括弧内の記号は、その権限が下位のファイル・フォルダーにも自動的に引き継がれる設定かどうかを示しており、慣れるまでは読み取りにくく感じます。また `icacls` は表示専用のコマンドではなく、`/grant` や `/remove` といったオプションを付けると権限そのものを変更できてしまうため、確認のつもりでオプションを付けずに実行するよう気をつけてください。

### diskpart --- （非常に危険・上級者向け）ディスクのパーティションを操作する ⚠️⚠️

`diskpart` は、ディスクの初期化やパーティション（1つのディスクを区切って作る、独立した保存領域のこと）の作成・削除・フォーマットなど、ディスクをかなり根本的なレベルで操作できる専用のコマンドラインツールです。実行すると、コマンドプロンプトとは別の `DISKPART>` という専用の対話型モード（コマンドを1つずつ入力して進める、専用の操作画面のこと）に入ります。

```bat
REM diskpart を起動する(専用の対話型コマンドラインに入る)
diskpart

REM 誤って起動してしまった場合、何も操作せずに抜けるには
exit
```

実行すると、次のように表示されることが多いです。

```text
Microsoft DiskPart バージョン 10.0.xxxx

コンピューター: DESKTOP-ABC123

DISKPART>
```

**確認・判断のポイント**: プロンプトが `DISKPART>` に変わっていたら、この専用モードに入っている合図です。`list disk` や `list volume`、`list partition` のように一覧・詳細を表示するだけのコマンドを入力しているうちは、まだ何も変更されていません。意図せず起動してしまった場合は、落ち着いて `exit` と入力すればコマンドプロンプトに戻れます。

**つまずきやすい点**: ⚠️⚠️ `diskpart` の対話モードには、`list disk` のように見るだけの安全なコマンドと、`clean` や `create partition`、`format` のようにディスクの中身を変更してしまうコマンドが同じ画面に混在しています。`chkdsk` の引数なし実行のような「常に読み取り専用」という決まった既定動作は存在せず、しかも変更を伴うコマンドを実行しても、多くの場合「よろしいですか （Y/N）?」のような確認は挟まれないまま、選択中のディスク・パーティションへ即座に反映されます。操作対象のディスク番号を一つ間違えるだけで、システムが入っている本体のディスクを含め、データを丸ごと失う可能性があります。本ドキュメントでは、この危険性を理解してもらうことを目的とし、あえて具体的な操作コマンド（ディスクの選択やパーティションの作成・削除など）の使い方までは解説しません。

**⚠️⚠️ 初心者のうちは `diskpart` を使わないでください。学習中に誤って `DISKPART>` の画面が表示された場合は、`list disk` などの一覧表示以外のコマンドは入力せず、`exit` と入力してコマンドプロンプトに戻り、必要であれば知識のある人に相談してください。**

### 補足: wmicの廃止傾向とPowerShellへの移行

`wmic` は長年、ディスクやシステム情報を確認する定番コマンドとして使われてきましたが、Microsoftは近年、このコマンドの廃止を段階的に進めています。Windows 11 22H2で「オンデマンド機能（Feature on Demand）」という、既定では入っておらず必要なときだけ追加できる扱いに変わり、23H2・24H2ではその機能自体が既定で無効化されました。24H2以降に新規インストールした環境ではこの機能が最初から含まれていないことも多く、既存の環境についても、今後の更新プログラムを通じて完全に取り除かれていく方針が公表されています。背景には、`wmic` がマルウェア（悪意のあるソフトウェアのこと）に悪用されやすい仕組みだったこともあり、セキュリティ向上を目的とした整理という側面もあるようです。これから新しく学ぶ場合は、同じような情報を得られる `Get-Volume`（ディスクの容量確認向け）や `Get-PSDrive`（PowerShellのドライブ全般の確認向け）を優先して覚えておくと、将来の環境でも通用しやすくなります。

### 補足: 権限まわりの用語のつながり

`whoami /groups` で「自分がどのグループに入っているか」がわかり、`net localgroup administrators` で「そのグループに誰が入っているか」がわかります。さらに `whoami /priv` は所属グループとは別に、自分個人に割り当てられた特権（システム時刻の変更などの特別な操作の許可）を示します。そして `icacls` は、これらユーザーやグループが「特定のファイル・フォルダーに対して」どこまで読み書きできるかを表すACL（アクセス制御リスト）を確認するコマンドです。一言でいうと、「グループに入る（whoami /groups・net localgroup）→ 特権を持つ（whoami /priv）→ 個々のファイルへのアクセス権が決まる（icacls）」という流れでつながっています。トラブルの原因が「権限不足」にありそうなときは、この順番で確認していくと切り分けやすくなります。

## PowerShell 入門ブリッジ

コマンドプロンプトの操作に少し慣れてきたら、次のステップとして「PowerShell（パワーシェル）」というもう一つのコマンド操作画面を使えるようになりましょう。PowerShell はコマンドプロンプトと同じように文字を入力して操作しますが、内部の仕組みがより新しく、サーバー管理や作業の自動化（自動化とは、人が毎回手作業で行わなくても同じ処理を機械に繰り返し実行させられるようにすること）に強い後継ツールとして、実務でもよく使われています。このセクションでは、PowerShell の開き方や命令の名前の付け方のルールといった基礎から、プロセス・サービスの確認や操作、ファイル操作、文字列検索まで、コマンドプロンプトでできていたことを PowerShell でも行えるようになる一通りの操作をまとめます。あわせて、コマンドプロンプトとの対応表や、実行前に安全確認できる `-WhatIf` のような仕組み、スクリプト実行の安全装置である実行ポリシーの概要も紹介し、これから PowerShell に触れていくための土台を作ります。

| やりたいこと | コマンド | 例 | 確認・判断のポイント |
| --- | --- | --- | --- |
| PowerShell を開きたい | （スタートメニューまたは `powershell`） | `powershell` | プロンプトの表示が `PS C:\...>` に変わったか |
| コマンドレット名を推測したい | 「動詞-名詞」の命名規則 | `Get-Process` / `Stop-Service` | 動詞（Get・Stop など）と名詞（対象）の組み合わせで機能を言い当てられるか |
| コマンドレットの使用例を見たい | `Get-Help` | `Get-Help Get-Process -Examples` | EXAMPLE 欄の書式が今やりたいことに近いか |
| コマンドレットを名前で探したい | `Get-Command` | `Get-Command *service*` | CommandType 列が Cmdlet か Alias か |
| 実行中のプロセスを確認したい | `Get-Process` | `Get-Process` | CPU や WS（メモリ）列で重いプロセスを判断できるか |
| プロセスを強制終了したい ⚠️ | `Stop-Process` | `Stop-Process -Name notepad` | 終了対象の Name や Id を `Get-Process` で事前確認したか |
| サービスの状態を確認したい | `Get-Service` | `Get-Service` | Status 列が Running か Stopped か |

### PowerShell の開き方 --- コマンドプロンプトのもう一つ先の画面

Windows キーを押して「PowerShell」と入力し、表示された「Windows PowerShell」（多くの場合、青いアイコンで表示されます）をクリックすると起動できます。すでにコマンドプロンプトを開いている場合は、その中で `powershell` と入力して Enter を押すだけでも、その場で PowerShell に切り替わります。PowerShell から元のコマンドプロンプトの画面に戻りたいときは `exit` と入力します。

なお、Windows に最初から入っている「Windows PowerShell」（5.1 系。通常は青いアイコン）とは別に、Microsoft が開発を続けている新しい「PowerShell」（7 系。通常は黒いアイコンで、使うには別途インストールが必要）も存在します。このセクションでは、追加インストールなしにそのまま使える Windows PowerShell を前提に説明します。

```bat
REM コマンドプロンプトの中から PowerShell を呼び出す
powershell

REM PowerShell を終了して元のコマンドプロンプトに戻る
exit
```

PowerShell が起動すると、次のように表示されることが多いです（更新プログラムの適用状況によっては、コピーライト表示の後に PowerShell 7 の案内メッセージが1行追加で表示されることもあります）。

```text
Windows PowerShell
Copyright (C) Microsoft Corporation. All rights reserved.

Install the latest PowerShell for new features and improvements! https://aka.ms/PSWindows

PS C:\Users\test>
```

**確認・判断のポイント**: プロンプトの先頭に `PS` が付いているかどうかで、今コマンドプロンプトと PowerShell のどちらの画面にいるかを見分けられます。`PS` が無ければコマンドプロンプト、あれば PowerShell です。

**つまずきやすい点**: スタートメニューの検索結果に「Windows PowerShell」と「PowerShell」の2つが表示されることがあり、後者（7 系）は別途インストールされていない環境では検索しても出てこない、または起動できないことがあります。まずは最初から入っている「Windows PowerShell」を使えば十分です。実行ファイル名も 5.1 系は `powershell.exe`、7 系は `pwsh.exe` と異なる点も覚えておくと混同しにくくなります。また上の出力例にある「Install the latest PowerShell...」という案内メッセージは、Windows PowerShell 5.1 が古くなっているという意味ではなく、単に新しい PowerShell 7 系の存在を知らせているだけなので、消えなくても心配する必要はありません。

### コマンドレットの命名規則「動詞-名詞」 --- 迷ったときの推測のコツ

PowerShell の命令のことを「コマンドレット（cmdlet。PowerShell の命令ひとつひとつのこと）」と呼びます。コマンドレットには「動詞-名詞」という共通の命名規則があり、たとえば `Get-Process`（プロセスを取得する）、`Stop-Service`（サービスを止める）のように、「何をするか（動詞）」と「何に対してか（名詞）」が必ずハイフンでつながっています。この規則のおかげで、名前をうろ覚えでも「プロセスを取得したいから Get-Process かな」と推測しやすいのが PowerShell の大きな特徴です。

```powershell
# 「取得する」を意味する Get と「プロセス」を組み合わせた例
Get-Process

# 「止める」を意味する Stop と「サービス」を組み合わせた例
Stop-Service -Name Spooler

# 動詞として使われている単語(承認されている動詞)の一覧を確認する
Get-Verb
```

`Get-Verb` を実行すると、次のように Verb（動詞）・AliasPrefix（エイリアスの接頭辞）・Group（用途の分類）・Description（説明）の一覧が表示されることが多いです。

```text
Verb    AliasPrefix Group        Description
----    ----------- -----        -----------
Add     a           Common       Adds a resource to a container...
Get     g           Common       Specifies an action that retrieves a resource...
Set     s           Common       Replaces data on an existing resource...
Stop    sp          Lifecycle    Discontinues an activity...
```

**確認・判断のポイント**: 使いたい動詞（Get・Stop・Start・Set・Remove など）と、対象を表す名詞（Process・Service・Item など）を組み合わせて名前を予想できるかどうかを、まず自分で考えてみる習慣をつけると覚えが早くなります。

**つまずきやすい点**: コマンドレット名は大文字・小文字を区別しないため `get-process` と打っても動きますが、読みやすさのため一般的には各単語の先頭を大文字にする書き方（`Get-Process`）が使われます。また `dir` や `ls`、`cd` のような、コマンドプロンプトや Linux 由来の短い名前で入力しても動くことがありますが、これは「エイリアス（コマンドレットに付けられた別名のこと）」として正式なコマンドレットに割り当てられているためで、正式名はあくまで「動詞-名詞」の形になります。

### Get-Help -Examples と Get-Command --- 使い方を調べる・名前を探す

すべてのコマンドレットとオプションを暗記する必要はありません。困ったときにその場で調べる方法を知っていれば十分です。`Get-Help`（コマンドレットのヘルプ、つまり説明書を表示する）に `-Examples` を付けると実行例だけを、`Get-Command`（条件に合うコマンドレットを検索する）を使うと名前がうろ覚えのコマンドレットを探せます。

```powershell
# Get-Process の使用例だけを表示する
Get-Help Get-Process -Examples

# 名前に service を含むコマンドレットを検索する(*はワイルドカード。任意の文字列を表す記号)
Get-Command *service*

# より詳しいオンラインのドキュメントをブラウザで開く
Get-Help Remove-Item -Online
```

`Get-Help Get-Process -Examples` を実行すると、次のように番号付きの実行例が並んで表示されることが多いです。

```text
NAME
    Get-Process

    --------- Example 1: Get all processes running on the local computer ---------
    Get-Process

    --------- Example 2: Get a list of processes on the local computer ---------
    Get-Process -Name "s*"
```

**確認・判断のポイント**: `Get-Help -Examples` で表示された EXAMPLE の書式が、自分が今やりたいことに近いかどうかを見比べます。`Get-Command` の結果は CommandType 列で、正式なコマンドレット（Cmdlet）なのか、別名（Alias）なのかを見分けられます。

**つまずきやすい点**: Windows PowerShell では初回に `Get-Help` を実行すると、ヘルプ本体がまだインストールされていないため簡易的な情報しか表示されず、`Update-Help`（ヘルプ本体をダウンロードするコマンドレットで、Windows PowerShell 5.1 では既定で管理者権限とインターネット接続が必要）の実行を促されることがあります。社内ネットワークなど接続が制限された環境では `Update-Help` に失敗することもあるため、その場合は `-Examples` の代わりに `-Online` や公式ドキュメント（Microsoft Learn）で調べます。なお、この管理者権限の制約は主に Windows PowerShell 5.1 に当てはまるもので、PowerShell 7 系では既定でユーザーごとの場所にヘルプを保存するため、多くの場合管理者権限なしで `Update-Help` を実行できます。

### Get-Process と Stop-Process --- 実行中のプロセスを確認・強制終了する

`Get-Process` は、今起動しているプロセス（動作中のプログラムのこと）の一覧を表示します。タスクマネージャーの「プロセス」タブに相当する情報を、コマンドで確認できます。フリーズしたアプリなどを強制的に終わらせたいときは `Stop-Process` を使いますが、保存されていない作業内容が失われる可能性があるため、対象をよく確認してから実行します。

```powershell
# 実行中の全プロセスを一覧表示する
Get-Process

# 名前を指定して1つ、または同名の複数のプロセスを強制終了する
Stop-Process -Name notepad

# PID(プロセスID。プロセスごとに割り振られる番号のこと)を指定して1つだけ終了する
Stop-Process -Id 1234

# 確認メッセージ(自分以外が起動したプロセスなどで表示される)を省略して終了する
Stop-Process -Name notepad -Force
```

`Get-Process` を実行すると、次のように CPU 使用率やメモリ使用量などとあわせてプロセスの一覧が表示されることが多いです。

```text
 NPM(K)    PM(K)      WS(K)     CPU(s)     Id  ProcessName
 ------    -----      -----     ------     --  -----------
     12    18564      34212       0.31   4820  notepad
      9    45210      68120       2.14   1220  explorer
```

**確認・判断のポイント**: CPU 列や WS（メモリ使用量）列の数値が極端に大きいプロセスがないかを確認します。強制終了する前には、Id 列（コマンドプロンプトの `tasklist` の PID に相当）と ProcessName 列を見て、本当に終了してよいプロセスかを確かめます。

**つまずきやすい点**: `-Name` で指定すると、同じ名前のプロセスが複数起動している場合すべて終了します。ピンポイントで1つだけ終わらせたいときは `-Id` を使うほうが安全です。自分が起動したプロセス（`notepad` など）を終了する場合、既定では確認メッセージは表示されずにそのまま終了します。一方、管理者として実行しているときに自分以外のユーザーが起動したプロセスを終了しようとすると確認を求められることがあり、それを省略したいときに `-Force` を使います。ただし `-Force` を付けても、Windows の中核をなす保護されたシステムプロセスなどは終了できない（アクセスが拒否される）ことがあります。

**⚠️ `Stop-Process` は保存確認や終了処理の時間を与えずにプロセスを終了させることがあります。編集中のファイルがある可能性を考え、`Get-Process` の結果で Name と Id をよく確認してから実行してください。**

### Get-Service と Start-Service / Stop-Service --- サービスの状態確認と起動・停止

`Get-Service` は、Windows サービス（Windows が裏側で常に動かしている機能のこと）の状態を一覧表示します。「サービス（services.msc）」画面のコマンド版というイメージです。サービスを開始・停止したいときは `Start-Service` / `Stop-Service` を使います。

```powershell
# サービスの一覧と状態(Running/Stopped)を確認する
Get-Service

# 名前を指定して1つだけ状態を確認する
Get-Service -Name Spooler

# サービスを開始する
Start-Service -Name Spooler

# サービスを停止する
Stop-Service -Name Spooler

# 依存している他のサービスも巻き込んで停止する
Stop-Service -Name Spooler -Force
```

次のように、Status・Name・DisplayName の列で状態が一覧表示されることが多いです。

```text
Status   Name               DisplayName
------   ----               -----------
Running  Spooler            Print Spooler
Stopped  wuauserv           Windows Update
```

**確認・判断のポイント**: Status 列が Running（実行中）か Stopped（停止中）かを確認します。停止しているはずのないサービスが Stopped になっていれば、トラブルの手がかりになります。

**つまずきやすい点**: サービスの操作は多くの場合、管理者として PowerShell を実行していないと「アクセスが拒否されました」というエラーになります。また、他のサービスが対象のサービスに依存していると、実行中の依存サービスがある状態での `Stop-Service` は失敗し、依存先も含めてまとめて止めるには `-Force` が必要になることがあるため、影響範囲を事前に確認します。

**⚠️ `Stop-Service` は他のサービスやアプリの動作に影響することがあります。止めてよいサービスかどうかを事前によく確認してから実行してください。**

### Get-ChildItem --- フォルダの中身を確認する（dir 相当）

`Get-ChildItem` は、指定したフォルダの中にあるファイルやフォルダを一覧表示するコマンドレットです。コマンドプロンプトの `dir` に相当します。

```powershell
# 今いるフォルダの中身を表示する(dir 相当)
Get-ChildItem

# サブフォルダの中身までまとめて表示する
Get-ChildItem -Recurse

# 拡張子で絞り込んで表示する
Get-ChildItem -Filter *.log
```

次のように、Mode（属性）・LastWriteTime（更新日時）・Length（サイズ）・Name（名前）の列で表示されることが多いです。

```text
    Directory: C:\Users\test\Documents

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
d-----         2026/09/04     10:15               Documents
-a----         2026/09/04      9:50            220 memo.txt
```

**確認・判断のポイント**: Mode 列の先頭が `d` ならフォルダ、`a`（アーカイブ属性）などならファイルです。Length 列が `0` のままのファイルがないかも、`dir` を見るときと同じ視点で確認します。

**つまずきやすい点**: `dir` や `ls` と打っても、エイリアス（別名）として `Get-ChildItem` が実行されるため同じ結果になりますが、正式名は `Get-ChildItem` です。`-Recurse` はサブフォルダが多いフォルダに対して実行すると、表示に時間がかかったり出力が大量になったりすることがあります。

### Set-Location と Get-Location --- フォルダの移動といまの場所の確認（cd・pwd 相当）

`Set-Location` はフォルダを移動するコマンドレットで、コマンドプロンプトの `cd` に相当します。`Get-Location` は今いる場所（カレントフォルダ）を確認するコマンドレットで、`cd` を引数なしで打ったときの動作に相当します。

```powershell
# 指定したフォルダへ移動する(cd 相当)
Set-Location C:\Users

# 今いる場所を確認する(pwd 相当)
Get-Location

# エイリアス cd でも同じ結果になる
cd C:\Windows

# 1つ上の階層へ戻る
Set-Location ..
```

`Get-Location` を実行すると、次のように Path 列に現在のフォルダが表示されることが多いです。

```text
Path
----
C:\Windows
```

**確認・判断のポイント**: `Set-Location` は成功しても基本的に何も表示しないので、移動できたかどうかは `Get-Location` で確認します。存在しないフォルダを指定すると、パスが見つからない旨のエラーが表示されます。

**つまずきやすい点**: パスにスペースが含まれる場合は `Set-Location "Program Files"` のように `" "` で囲む必要があります。相対パス（今いる場所を基準にした道順）と絶対パス（`C:\Users\test` のようにドライブの根元からの道順）の違いは、コマンドプロンプトの `cd` と同じ考え方です。

### Copy-Item・Move-Item・Remove-Item --- ファイル・フォルダのコピー・移動・削除

`Copy-Item` はファイルやフォルダをコピー、`Move-Item` は移動（名前変更にも使えます）、`Remove-Item` は削除するコマンドレットで、それぞれコマンドプロンプトの `copy`・`move`・`del` に相当します。コマンドプロンプトの `copy` と違い、`Copy-Item` はフォルダそのものもコピーできる点が特徴です。

```powershell
# ファイルをコピーする(copy 相当)
Copy-Item report.txt D:\backup\

# 読み取り専用ファイルにも上書きコピーする
Copy-Item report.txt D:\backup\ -Force

# フォルダを中身ごとコピーする
Copy-Item C:\work D:\backup\work -Recurse

# ファイルを移動する、または名前を変える(move / ren 相当)
Move-Item old.txt archive\old.txt

# ファイルを削除する(del 相当)
Remove-Item temp.txt

# フォルダを中身ごと確認なしで削除する
Remove-Item C:\temp\old -Recurse -Force
```

削除や移動が成功すると、多くの場合は画面に何も表示されず、静かに処理が終わります。対象が見つからない場合は次のようなエラーが表示されることが多いです。

```text
Remove-Item : このパスにアイテムが見つかりません: 'C:\temp\old'。
```

**確認・判断のポイント**: 何も表示されなければ成功したものとみなし、`Get-ChildItem` で結果（コピーできているか、消えているか）を確認します。エラーが出た場合は、パスのスペルやフォルダの存在を見直します。

**つまずきやすい点**: `Copy-Item` は、コピー先に同じ名前の（読み取り専用ではない）ファイルがすでにあっても、既定では確認なしにそのまま上書きします。上書きされて困るファイルがないか、実行前に確認しておくと安心です。宛先ファイルが読み取り専用の場合は上書きに失敗し、上書きするには `-Force` が必要です。また、コピー元にフォルダを指定したのに `-Recurse` を付け忘れると、エラーにはならず「中身が空の同名フォルダ」だけが作られてしまう（中身はコピーされない）ことがあるため、コピー後は `Get-ChildItem` で中身まで確認する習慣をつけると安心です。なお `Move-Item` でフォルダを移動する場合は `-Recurse` を付ける必要はありません（移動は名前の付け替えに近い処理のため、中身ごとそのまま移動します）。一方 `Remove-Item` で中身のあるフォルダを `-Recurse` なしで削除しようとすると、「このフォルダには子アイテムがあります。続行しますか」といった趣旨の確認を求められる（設定や環境によってはエラーになる）ため、中身ごとまとめて消したいときは `-Recurse` を付けます。

**⚠️ `Remove-Item` はゴミ箱を経由せず、その場でファイルやフォルダを削除します。特に `-Recurse -Force` を組み合わせると確認なしに中身ごと一瞬で消えるため、実行前に対象パスを見直すか、後述の `-WhatIf` で試し打ちしてから実行してください。`Copy-Item` や `Move-Item` も、上書き先に指定した既存ファイルの中身をやはり確認なしに置き換えてしまう点では同じです。宛先のパスを打ち間違えると、大事なファイルを気づかないまま上書きしてしまうことがあります。**

### Get-Content --- ファイルの中身を表示する（type 相当）

`Get-Content` は、テキストファイルの中身を画面に表示するコマンドレットです。コマンドプロンプトの `type` に相当します。

```powershell
# ファイルの中身を表示する(type 相当)
Get-Content log.txt

# 末尾の10行だけを表示する
Get-Content log.txt -Tail 10

# ファイルへの追記をリアルタイムに追いかける(ログの監視などに使う)
Get-Content log.txt -Tail 10 -Wait
```

短いテキストファイルであれば、次のように中身がそのまま画面に表示されます。

```text
2026-09-04 09:50:01 INFO  Server started
2026-09-04 09:50:03 INFO  Listening on port 8080
2026-09-04 10:02:17 ERROR Connection timeout
```

**確認・判断のポイント**: 表示された内容が、想定していたファイル・行数と一致しているかを確認します。ログファイルなどでは `-Tail` を使い、直近の行に異常なメッセージが出ていないかを見るのが基本の使い方です。

**つまずきやすい点**: 大きなファイルに `-Tail` を付けずに実行すると、画面に大量の行が一気に流れて読みにくくなります。`Get-Content` は `type` や `cat` と打ってもエイリアスとして同じ結果になります。

### Select-String --- 文字列を検索する（grep に近い）

`Select-String` は、ファイルや入力の中から指定した文字列を含む行を検索するコマンドレットです。コマンドプロンプトの `findstr` や、Linux の `grep` に近い働きをします。

```powershell
# ファイルの中から"Error"を含む行を探す
Select-String -Pattern "Error" -Path log.txt

# 大文字・小文字を区別して検索する
Select-String -Pattern "Error" -Path log.txt -CaseSensitive

# Get-Content の結果をパイプ(あるコマンドの出力を次のコマンドの入力としてそのまま渡す記号)でつないで絞り込む
Get-Content log.txt | Select-String "Error"
```

次のように、ファイル名・行番号・該当行の内容がセットで表示されることが多いです。

```text
log.txt:3:2026-09-04 10:02:17 ERROR Connection timeout
```

**確認・判断のポイント**: 表示された行番号と内容が、調べたい事象（エラーの発生時刻など）と一致するかを確認します。ヒット件数が多すぎる場合は、検索したい文字列をより具体的にします。

**つまずきやすい点**: `Select-String` は既定では大文字・小文字を区別せずに検索します。コマンドプロンプトの `findstr` は既定で大文字・小文字を区別する（`/i` を付けると区別しなくなる）ため、動きが逆になっている点に注意してください。区別して検索したいときは `-CaseSensitive` を付けます。もう一つ注意したいのは、`-Pattern` に指定した文字列は既定で正規表現（文字列のパターンをルールとして表す特別な記法のこと）として解釈されることです。たとえば `.`（ピリオド）は正規表現では「任意の1文字」を意味するため、`3.14` という数値の小数点をそのまま検索したいつもりでも、`3x14` や `3-14` のようにピリオド以外の1文字が入った行までヒットしてしまうことがあります。記号を含む文字列を正規表現としてではなく、そのまま検索したいときは `-SimpleMatch` を付けます。

### コマンドプロンプトとの対応表 --- 覚えた知識を PowerShell に持ち越す

これまでコマンドプロンプトで覚えたコマンドの多くは、PowerShell では別の名前のコマンドレットに置き換わりますが、`dir` や `cd` のようにエイリアス（別名）としてそのまま入力しても動くように用意されているものもあります。両方の書き方を知っておくと、どちらの画面に出会っても迷わなくなります。

| コマンドプロンプトのコマンド | 対応する PowerShell コマンドレット | 内容 |
| --- | --- | --- |
| `dir` | `Get-ChildItem` | フォルダの中身一覧を表示する |
| `cls` | `Clear-Host` | 画面を消去する |
| `copy` | `Copy-Item` | ファイルをコピーする |
| `del` | `Remove-Item` | ファイルを削除する ⚠️ 元に戻せない |
| `type` | `Get-Content` | ファイルの中身を表示する |
| `cd` | `Set-Location` | フォルダを移動する |
| `echo` | `Write-Output` | 文字列を画面に出力する |

```powershell
# コマンドプロンプトで使っていた dir はエイリアス(別名)としてそのまま入力しても動く
dir

# 正式なコマンドレット名を使っても同じ結果になる
Get-ChildItem
```

**確認・判断のポイント**: 対応表の右側の正式なコマンドレット名を実行して、左側のコマンドプロンプトのコマンドと同じ目的の結果が得られるかを確認します。エイリアスと正式名のどちらを打っても、内部的には同じコマンドレットが実行されています。

**つまずきやすい点**: エイリアスはあくまで「短く打てる別名」であり、PowerShell 独自のオプション（`-Recurse` や `-Force` など）はコマンドプロンプト時代の書き方（`/s` や `/q` など）とは書式が異なります。名前が同じだからといってオプションの書き方まで同じとは限らない点に注意してください。

### -WhatIf と -Confirm --- 実行前に安全確認する

多くのコマンドレット（ファイルを変更・削除するものなど）には、共通のオプションとして `-WhatIf` と `-Confirm` が用意されています。`-WhatIf`（「もし実行したら」の意味）を付けて実行すると、実際には何も変更せず「実行した場合に何が起きるか」だけを表示してくれます。`-Confirm` を付けると、実行の直前に1件ずつ確認を求められます。

```powershell
# 実際には削除せず、何が起きるかだけを確認する
Remove-Item C:\temp\old.txt -WhatIf

# 実行前に1件ずつ確認を求める
Remove-Item C:\temp\old.txt -Confirm
```

`-WhatIf` を付けて実行すると、次のように「What if:」で始まる行が表示され、実際の削除は行われません。

```text
What if: C:\temp\old.txt を削除しようとしています。
```

**確認・判断のポイント**: 「What if:」の後に表示された対象パスや操作内容が、自分が意図しているものと一致しているかを確認します。一致していれば `-WhatIf` を外して本番実行する、という流れで使います。

**つまずきやすい点**: `-WhatIf` と `-Confirm` は、内部でその仕組み（`SupportsShouldProcess` という機能）に対応しているコマンドレットにしか付けられません。対応していないコマンドレットに付けると、実行されずに「そのようなパラメーターは存在しません」といった趣旨のエラーになります。あるコマンドレットが対応しているかどうかは、`Get-Help <コマンドレット名> -Full` を実行し、パラメーターの一覧に `-WhatIf` や `-Confirm` が載っているかで確認できます。危険そうな操作ほど、まず `-WhatIf` で試してから本番実行する、という手順を習慣にすると安心です。

### 実行ポリシーの概要 --- スクリプト実行の安全装置

PowerShell には「実行ポリシー（スクリプトファイル `.ps1` を実行してよいかどうかを制御するルールのこと）」という仕組みがあり、初期状態では安全のためにスクリプトの実行が制限されていることが一般的です。現在の設定は `Get-ExecutionPolicy` で確認できます。

```powershell
# 現在の実行ポリシーを確認する(確認のみで、何も変更しない)
Get-ExecutionPolicy
```

次のように、設定されているポリシー名が1行で表示されることが多いです。

```text
Restricted
```

**確認・判断のポイント**: 表示された値が `Restricted`（スクリプトの実行を全面的に禁止する設定）になっている場合、`.ps1` ファイルを実行しようとするとエラーになります。一般的な Windows（クライアント向けエディション）では既定で `Restricted` になっていることが多い一方、Windows Server では既定で `RemoteSigned`（自分がそのマシン上で作成したスクリプトはそのまま実行でき、インターネットなど外部からダウンロードしたスクリプトには発行元の署名が必要、という設定）になっていることが多く、動作しているマシンの種類によって既定値が異なります。まずは今の設定を確認することが第一歩です。

**つまずきやすい点**: 実行ポリシーを変更する `Set-ExecutionPolicy` というコマンドレットも存在しますが、この設定はセキュリティに直結するため、変更方法の詳細は本書では扱いません。実務や学習を進める中で必要になった際は、なぜ制限されているのかを理解したうえで、信頼できる情報源や管理者の指示に従って慎重に設定してください。なお、制限によってスクリプトが実行できないときは、「このシステムでは、スクリプトの実行が無効になっているため」といった趣旨のエラーメッセージが表示されることが多く、これは PowerShell が正常に安全装置として働いている状態です。

## リダイレクト・パイプ・キー操作の時短ワザ

ここまでの章では「1つのコマンドをどう打つか」を中心に見てきましたが、実務ではコマンドの実行結果をファイルに保存したり、別のコマンドに渡してさらに絞り込んだりする場面がとても多くなります。また、同じコマンドを何度も打ち直す手間を減らすキー操作や、管理者権限が必要な作業への入り方を知っているかどうかも、日々の作業スピードを大きく左右します。この章では、そうした「地味だけれど効果の大きい」時短ワザをまとめて紹介します。コマンドそのものだけでなく、キーボード操作もいくつか含まれますが、いずれも覚えると毎日の作業が確実に速くなるものばかりです。

| やりたいこと | コマンド | 例 | 確認・判断のポイント |
| --- | --- | --- | --- |
| コマンドの実行結果をファイルに保存したい（上書き） | `command > ファイル名` | `dir > filelist.txt` | 画面に何も表示されなければ成功。`type filelist.txt` で中身を確認する |
| コマンドの実行結果をファイルに追記したい | `command >> ファイル名` | `echo 作業完了 >> work.log` | ファイルの末尾に行が増えているかを確認する。既存の内容が消えていないかも見る |
| コマンドの出力を別のコマンドにそのまま渡したい（パイプ） | `command1 \| command2` | `dir \| findstr "sample"` | 左のコマンドの出力が、右のコマンドへの入力として絞り込まれているかを見る |
| 出力や文章から特定の文字列を探したい | `findstr "文字列" ファイル名`<br>`command \| findstr "文字列"` | `findstr /i "error" app.log` | 該当する行だけが表示されているか。ヒット件数が想定より多い・少ない場合はオプションを見直す |
| 出力された行を並べ替えたい | `command \| sort` | `dir /b \| sort` | 五十音・アルファベット順に並んでいるか。数値の大小順にはならない点に注意する |
| 長い出力を1画面ずつ確認したい | `command \| more` | `dir /s \| more` | 画面下部の「続行するには何かキーを押してください」の表示が出ているかで、続きがあると分かる |
| ファイル名・フォルダ名を最後まで打たずに入力したい | Tab キー | `cd Doc` と入力して Tab | 補完された内容が意図した名前になっているかを確認してから Enter を押す |
| 過去に打ったコマンドを呼び出したい | ↑ / ↓ キー、F7 キー、`doskey` | `doskey /history` | 表示されたコマンドが本当に実行したい内容かを確認してから Enter を押す |
| 実行中のコマンドを途中で強制的に止めたい | `Ctrl + C` | `ping -t 8.8.8.8` の実行中に押す | プロンプト（入力待ちの記号）が戻ってくれば中断できている |
| 画面の文字をコピー＆貼り付けしたい（Windows Terminal） | `Ctrl + Shift + C` / `Ctrl + Shift + V` | ドラッグで選択 → `Ctrl + Shift + C` | 貼り付け先で意図した文字列（改行の位置なども含む）になっているかを確認する |
| 管理者権限が必要な作業をしたい | 「管理者として実行」 | スタートメニューで検索 → 右クリック | タイトルバーに「管理者:」と表示されているかで判断する |
| 実行結果をそのままメモ帳やメールに貼り付けたい | `command \| clip` | `ipconfig \| clip` | 別のアプリで `Ctrl + V` を押し、意図した内容が貼り付けられるかを確認する |

### `>` と `>>` --- コマンドの結果をファイルに保存する

リダイレクト（コマンドの出力先を、画面から別の場所〈主にファイル〉に切り替える仕組みのこと）を使うと、`dir` や `ipconfig` のように本来なら画面に表示される結果を、そのままファイルへ書き出せます。`>` は「新しくファイルを作る、または既存ファイルの中身をまるごと置き換える（上書きする）」動作、`>>` は「既存ファイルの末尾に追記する」動作という違いがあります。ログを日々書き足していきたいのか、最新の状態だけを保存したいのかによって使い分けます。

```bat
REM dir の結果を新しいファイルに保存する(同名ファイルがあれば中身は上書きされる)
dir > filelist.txt

REM echo で出した文字列を、既存ファイルの末尾に追記する
echo 作業完了 >> work.log

REM ファイルが存在しない場合、>> でも自動的に新規作成される
echo 1行目 >> newlog.txt
```

`dir > filelist.txt` を実行すると、通常なら画面に出るはずの一覧表示が画面には一切表示されず、代わりに `filelist.txt` の中に保存されるように動作します。保存された内容を確認するには、次のように `type` コマンドで開きます。

```text
> type filelist.txt
 ドライブ C のボリューム ラベルは WINDOWS です
 ボリューム シリアル番号は XXXX-XXXX です

 C:\Users\test\work のディレクトリ

2026/09/04  10:15    <DIR>          .
2026/09/04  10:15    <DIR>          ..
2026/09/04  10:15    <DIR>          Documents
2026/09/04  09:50               220 memo.txt
               1 個のファイル                 220 バイト
               3 個のディレクトリ  XXX,XXX,XXX バイトの空き領域
```

**確認・判断のポイント**: リダイレクトが成功すると、画面には基本的に何も表示されません（何か表示されたら、それはエラーメッセージである可能性が高いです）。保存されたはずのファイルを `type` や `dir` で確認し、想定した内容が入っているかを見ます。`>>` を使ったときは、実行のたびに行数が増えているかどうかで、正しく追記できているかを判断できます。

**つまずきやすい点**: ⚠️ `>` は既存ファイルの中身を確認なしにすべて置き換えます。保存先のファイル名を大事なファイルの名前と間違えると、元の内容は失われ、元に戻せません。実行前にファイル名を必ず見直しましょう。また、`>` や `>>` が対象にするのは標準出力（通常の実行結果）だけで、エラーメッセージ（標準エラー出力）は既定では対象になりません。そのため、コマンドが失敗してエラーになっていても、そのエラー内容はリダイレクト先のファイルには保存されず、画面にそのまま表示されることがある点も覚えておくと混乱を防げます。標準出力とエラー出力の両方をまとめて1つのファイルに保存したいときは、`dir > filelist.txt 2>&1` のように `2>&1` を `>` の後ろに続けて書きます。

### `|`（パイプ）--- コマンドの出力を別のコマンドに渡す

パイプ（あるコマンドの出力を、そのまま次のコマンドの入力としてつなぐ仕組みのこと）を使うと、`dir` のような一覧表示コマンドの結果を、`findstr` や `sort` のような別のコマンドにその場で渡して加工できます。リダイレクトの行き先が「ファイル」だったのに対し、パイプの行き先は「次のコマンド」という違いがあります（両者の違いは後述の補足で詳しく説明します）。`|` は複数回つなげることもでき、小さなコマンドを数珠つなぎにして複雑な処理を組み立てられます。

```bat
REM dir の結果から「sample」という文字を含む行だけを表示する
dir | findstr "sample"

REM さらに、絞り込んだ結果を並べ替えてから表示する
dir /b | findstr ".log" | sort
```

```text
> dir | findstr "sample"
2026/09/04  11:02               512 sample_data.csv
2026/09/04  11:05               128 sample_note.txt
```

**確認・判断のポイント**: パイプでつないだ処理は、必ず左から右へ順番に実行されます。`command1 | command2` であれば、まず `command1` の結果全体が確定してから、それが `command2` の入力として渡される、という流れをイメージすると理解しやすいです。想定より結果が少ない・多いときは、間に挟んでいるコマンド（`findstr` の検索語など）を1つずつ外して、どの段階で意図と違う絞り込みになっているかを確認します。

**つまずきやすい点**: 多くの日本語配列キーボードでは、`|`（パイプ記号）を単独のキーで入力できず、Backspace キーのすぐ左にある `¥` キーを `Shift` キーと一緒に押して入力します（このキーは `Shift` なしだと `\`〈バックスラッシュ〉になります）。キー配列によっては別の位置にあることもあるため、見つからない場合はキーボードの配列設定を確認してください。また、コマンドプロンプトのパイプは基本的に「文字（テキスト）」をやり取りする仕組みで、PowerShell のパイプ（オブジェクトという情報のかたまりをやり取りできる仕組み。詳しくは前章を参照）とは性質が異なります。同じ `|` という記号でも、画面のどちらで使っているかによって挙動が変わることがある点を覚えておきましょう。

### findstr --- 出力やファイルの中から文字列を検索する

`findstr`（find string の略で、ファイルや入力の中から指定した文字列を含む行を検索するコマンド）は、大量のログや一覧の中から必要な行だけを取り出したいときに使います。ファイル名を直接指定する使い方と、パイプ経由で別のコマンドの結果を検索対象にする使い方の、どちらもよく使われます。

```bat
REM ファイルの中から「エラー」を含む行を表示する
findstr "エラー" app.log

REM 大文字・小文字を区別せずに検索する
findstr /i "error" app.log

REM ヒットした行の行番号も一緒に表示する
findstr /n "エラー" app.log

REM dir の結果をそのまま検索対象にする
dir | findstr "sample"
```

```text
> findstr /n "エラー" app.log
15:2026-09-04 10:02:11 エラー: 接続がタイムアウトしました
48:2026-09-04 10:15:33 エラー: ファイルが見つかりません
```

**確認・判断のポイント**: 表示された行に、探していたキーワードが本当に含まれているかを確認します。`/n` を付けておくと、元のファイルの何行目だったかが分かるので、あとで `more` や `type` でその周辺の文脈を見返すときに役立ちます。ヒット件数が0件のときは、キーワードのスペルミスや、大文字・小文字の違い（既定では区別される）を疑います。

**つまずきやすい点**: `findstr` は既定で大文字・小文字を区別します。区別せずに探したいときは `/i` を付け忘れないようにしましょう。また、`findstr "cat dog"` のようにスペースで区切って複数の単語を指定すると、既定では「cat という文字列を含む行」または「dog という文字列を含む行」のどちらかにヒットする、いわゆる OR 検索として扱われます。「cat dog」という連続した文字列そのものを検索したい場合は `findstr /c:"cat dog"` のように `/c:` を使う必要がある点に注意してください。

### sort --- 出力された行を並べ替える

`sort` は、コマンドの出力やファイルの中身を行単位で並べ替えるコマンドです。単体で使うことは少なく、`dir` や `findstr` の結果をパイプで渡して、見やすい順番に整えるために使われることがほとんどです。

```bat
REM ファイル名の一覧を並べ替えて表示する
dir /b | sort

REM 逆順(降順)に並べ替える
dir /b | sort /r

REM 並べ替えた結果をファイルに保存する(リダイレクトと組み合わせる)
dir /b | sort > sorted_list.txt
```

```text
> dir /b | sort
Documents
access.log
error.log
memo.txt
```

**確認・判断のポイント**: 表示された順番が、アルファベット順・五十音順のような文字としての並び順になっているかを確認します。`/r` を付けたときは、その逆順になっているかを見ます。

**つまずきやすい点**: `sort` は行の中身を文字として比較するだけで、数値の大小として判断しているわけではありません。また既定では大文字・小文字を区別せずに比較します（`Apple` と `apple` は同じ扱いになります）。数値の並びについては、`report2.txt` と `report10.txt` を並べ替えると、数値としては 2 より 10 が大きいはずなのに、文字としては `"1"` が `"2"` より前に来るため `report10.txt` が `report2.txt` より前に表示されることがあります。数値としての順番が必要な場合は、この点を踏まえて結果を見るか、別の方法を検討する必要があります。また、並べ替えの基準（照合順序）はシステムの言語設定に依存するため、日本語のファイル名を含む一覧では、環境によって並び順の細部が変わることがあります。

### more（パイプで使う）--- 長い出力を1画面ずつ確認する

`more` は、画面に収まりきらない長い出力を1画面ずつ止めながら表示するコマンドです。第1章では `type` コマンドと組み合わせる使い方に触れましたが、この章で紹介したいのは、`dir` などの出力をパイプで `more` に渡す使い方です。ずらずらと大量に流れてしまう出力があったら、まず `| more` を挟んでみる、という習慣をつけると読みやすくなります。

```bat
REM サブフォルダも含めた一覧を1画面ずつ表示する
dir /s | more

REM findstr で絞り込んでから、それでも長い場合は more も挟む
dir /s | findstr ".log" | more
```

画面の下に「-- 続行するには何かキーを押してください --」のような表示が出て、そこで入力待ちの状態になることが多いです。

**確認・判断のポイント**: この一時停止の表示が出ている間は、`Space` キーで次の1画面分、`Enter` キーで1行だけ先に進めます。`Q` キーを押すと、そこで表示を打ち切って通常のプロンプトに戻ります。最後まで進んで一時停止の表示が出なくなれば、それが出力の末尾ということです。

**つまずきやすい点**: `more` はあくまで「画面での見やすさ」を確保するための機能であり、`Q` キーで途中終了すると、それ以降の内容はどこにも保存されません。あとから見返したい場合は、`| more` だけでなく `> ファイル名` で先に保存しておき、保存したファイルを `more ファイル名` で確認する、という順序にすると安心です。

### Tab補完 --- ファイル名・フォルダ名を最後まで打たずに入力する

Tab補完（ファイルやフォルダの名前を、最初の数文字だけ入力して `Tab` キーを押すと、コマンドプロンプトが残りを自動的に補って入力してくれる機能のこと）を使うと、長いファイル名やフォルダ名を最後まで正確にタイプする必要がなくなり、入力ミスによるエラーも減らせます。

```bat
REM "Doc" まで入力してから Tab キーを押す
cd Doc

REM Tab を押すと、候補があれば自動的に続きが補われる
cd Documents\

REM 候補が複数あるときは、Tab を押すたびに次の候補へ切り替わる
REM (Documents\ → Downloads\ のように順番に表示される)
```

**確認・判断のポイント**: Tab を押した直後に表示された内容が、意図しているファイル・フォルダ名になっているかを確認してから Enter を押します。候補が複数ある場合は同じ場所で何度も Tab を押すと候補が順番に切り替わっていくので、目的の名前が出たところで止めます。

**つまずきやすい点**: Tab補完は、その時点で入力済みの文字列と一致する候補が現在のフォルダの中に存在しなければ何も起こりません。フォルダを移動しないまま存在しない場所を指定していると、いつまでも候補が出てこないため、まず `dir` で現在の場所と中身を確認するとよいでしょう。また、複数候補があるときに確認せずそのまま Enter を押すと、意図と違うファイルやフォルダを対象にコマンドを実行してしまうことがあるため、特に削除・上書き系のコマンドと組み合わせるときは補完結果を必ず目で確認する習慣をつけてください。

### 上下矢印キー・F7・doskey --- コマンド履歴を活用する

この3つは、いずれも「一度打ったコマンドをもう一度探して打ち直す手間を省く」ための仕組みで、実は裏側でつながっています。上下矢印キー（↑ / ↓）は直前に実行したコマンドを1つずつ呼び出す、F7キーはコマンドプロンプト（cmd.exe）の画面上に過去のコマンド一覧をポップアップ表示する、そして `doskey`（コマンド履歴の保存や、コマンドに短い別名〈マクロ〉を付ける機能を提供する仕組み）は、これら履歴機能そのものを裏側で支えているプログラムです。

```bat
REM 直前に実行したコマンドをそのまま呼び出す
REM (↑ キーを1回押す。さらに押すとさらに前のコマンドに戻る)

REM 過去のコマンド一覧をポップアップで表示する(cmd.exe の機能)
REM (F7 キーを押す。上下キーで選び、Enter で再実行、Esc で閉じる)

REM これまで入力したコマンドをテキストの一覧として表示する
doskey /history

REM 履歴の一覧をファイルに保存する(リダイレクトと組み合わせる)
doskey /history > history_log.txt
```

```text
> doskey /history
dir
cd Documents
findstr "エラー" app.log
doskey /history
```

**確認・判断のポイント**: 上下矢印キーで呼び出したコマンドは、Enter を押すまでは実行されずプロンプト上に表示されるだけなので、内容を確認してから、必要であれば書き換えてから実行できます。F7 のポップアップでは、選んだ行が画面下部やハイライト表示で分かるようになっているので、それが目的のコマンドかを確認してから Enter を押します。

**つまずきやすい点**: F7 のポップアップ表示は cmd.exe（コマンドプロンプト）に特有の機能です。さらに、Windows 11 で既定のターミナルアプリとなっている Windows Terminal 上で cmd.exe を使っている場合、画面表示の内部方式（ConPTY）の仕様上、このF7のポップアップ自体がうまく表示されない、または反応しないことがある点も知っておくとよいでしょう（Windows Terminal 側の既知の制限として報告されており、今後の更新で扱いが変わる可能性もあります）。従来型のコンソール画面（conhost.exe）で cmd.exe を直接開いた場合は今までどおり動作しますが、Windows Terminal で反応しないと感じたときは、代わりに `doskey /history` や上下矢印キーを使うと確実です。PowerShell では文字入力の処理を PSReadLine というモジュール（既定で自動的に読み込まれる）が担っており、標準の設定では F7 に何も割り当てられていないため、同じようには動作しません。PowerShell で履歴をたどりたいときは、代わりに `Ctrl + R`（インクリメンタル検索）が使えます。また、この履歴はコマンドプロンプトのウィンドウを閉じると既定では失われる一時的なものです。次に開いたウィンドウでは空の状態から始まるため、「昨日打ったコマンドを今日も呼び出したい」という場合には使えない点も覚えておきましょう。

### Ctrl+C --- 実行中のコマンドを強制的に中断する

`Ctrl + C` は、実行中のコマンドに対して中断の指示を送るキー操作です。`ping -t` のように、明示的に止めるまで終了しないコマンドを実行しているときの「止め方」として欠かせません。

```bat
REM 自動では終了しないコマンドの例
ping -t 8.8.8.8

REM 実行中に Ctrl + C を押すと、実行が中断されてプロンプトに戻る
```

```text
8.8.8.8 からの応答: バイト数=32 時間=12ms TTL=118
8.8.8.8 からの応答: バイト数=32 時間=11ms TTL=118
^C
>
```

**確認・判断のポイント**: `Ctrl + C` を押した直後に、実行中だった出力がそこで止まり、プロンプト（入力待ちの記号）が戻ってくれば、正しく中断できたということです。戻ってこない場合は、そのコマンドが `Ctrl + C` による中断に対応していない可能性があるため、ウィンドウを閉じるなど別の方法を検討します。

**つまずきやすい点**: ⚠️ ファイルの書き込みやダウンロードなど、データを書き換えている最中のコマンドを `Ctrl + C` で中断すると、処理が中途半端な状態のまま止まり、ファイルが壊れたり不完全な内容のまま残ったりすることがあります。あくまで「応答が返ってこないときの最後の手段」として使い、通常はコマンドが自然に終わるのを待つほうが安全です。なお `ping` のように、コマンドによっては `Ctrl + C` とは別のキー操作（`ping -t` に対する `Ctrl + Break` など、途中経過の統計だけを表示して実行自体は続ける操作）が用意されていることもあるため、そのコマンド特有の挙動を知りたいときは `コマンド名 /?` で確認するとよいでしょう。

### コピー＆貼り付け（Windows Terminal）--- 画面の文字をコピー・貼り付けする

通常のアプリでは `Ctrl + C` / `Ctrl + V` がコピー・貼り付けの定番ですが、コマンドプロンプトでは `Ctrl + C` がすでに「実行中のコマンドを中断する」操作として使われています。そこで Windows Terminal（複数のコマンドプロンプトや PowerShell のタブをまとめて開ける、比較的新しいターミナルアプリ）では、`Shift` キーを加えた別のショートカットがコピー・貼り付け専用に用意されています。

```bat
REM 1. コピーしたい範囲をマウスでドラッグして選択する
REM 2. Ctrl + Shift + C を押してコピーする
REM 3. 貼り付けたい場所にカーソルを合わせ、Ctrl + Shift + V を押して貼り付ける
```

**確認・判断のポイント**: 貼り付けた先の内容が、選択した範囲と一致しているか（余分な空白や改行が入っていないか）を確認します。長いコマンドの結果をコピーしたときは、途中で見切れていないかも合わせて確認するとよいでしょう。

**つまずきやすい点**: `Ctrl + C` はコマンドプロンプトでは中断の操作に使われているため、コピーのつもりで `Ctrl + C` だけを押すと、実行中のコマンドを中断してしまうことがあります（何も実行していない状態であれば実害はありませんが、癖をつけておくと安心です）。また、右クリックの挙動は、選択範囲をそのままコピーする場合や、コピー・貼り付け用のメニューが開く場合など、Windows Terminal のバージョンや設定によって異なることがあります。確実に使えるのは `Ctrl + Shift + C` / `Ctrl + Shift + V` のキーボードショートカットなので、まずはこちらを基本として覚えておくとよいでしょう。

### 「管理者として実行」--- 管理者権限でコマンドプロンプトを起動する

ネットワーク設定の変更やサービスの操作など、Windows の設定やシステムファイルに関わる操作の多くは、通常の権限のままでは「アクセスが拒否されました」というエラーになります。これは、意図しない変更からシステムを守るための安全装置で、こうした操作を行うには管理者権限（Administrator 権限。通常より強い操作を許可する権限のこと）でコマンドプロンプトを起動し直す必要があります。

```bat
REM スタートメニューで「コマンド プロンプト」と検索し、
REM アイコンを右クリックして「管理者として実行」を選ぶ

REM 検索結果を選んだ状態で Ctrl + Shift + Enter を押すと、
REM 右クリックせずに直接、管理者として起動できる(時短ワザ)

REM 管理者権限があるかどうかを、起動後にコマンドで確認する
net session
```

管理者権限で起動できていれば、ウィンドウのタイトルバーに「管理者: コマンド プロンプト」のように表示されることが多いです。管理者権限がない状態で `net session` を実行すると、次のようなエラーが表示されることが多いです。

```text
システム エラー 5 が発生しました。

アクセスが拒否されました。
```

**確認・判断のポイント**: タイトルバーの表示に加えて、`net session` のような「管理者権限がないとエラーになる」コマンドを実行してみると、確実に確認できます。エラーにならず何らかの結果（何も表示されない、または一覧が表示される）が返ってくれば、管理者権限で動作していると判断できます。UAC（ユーザーアカウント制御。Windows が「本当に実行してよいか」を確認してくる仕組み）の確認画面が表示されたら、内容をよく確認してから「はい」を選びます。

**つまずきやすい点**: ⚠️ 管理者権限のコマンドプロンプトでは、通常より強い権限でコマンドが実行されるため、他の章で紹介した削除やフォーマットのような操作を誤って実行したときの影響範囲も大きくなります。「なんとなく管理者として実行しておく」のではなく、必要な作業が終わったら管理者権限のウィンドウは閉じ、普段の作業は通常権限のウィンドウで行う習慣をつけると安心です。また `net session` のような確認コマンド自体は情報を表示するだけの安全な操作ですが、管理者権限が必要な他のコマンド（`net start` / `net stop` など）と組み合わせるときは、実行前に何が起きるかを必ず確認してください。

### `| clip` --- 実行結果をクリップボードにコピーする

`clip`（Windows に標準で組み込まれているクリップボードコピー用のコマンド）は、パイプで受け取った内容を、そのままクリップボード（コピーした内容を一時的に保存しておく場所のこと）に送り込みます。長いコマンドの実行結果を、メモ帳やメールにそのまま貼り付けたいときに便利です。

```bat
REM ipconfig の実行結果を、画面に表示せずクリップボードにコピーする
ipconfig | clip

REM ファイルの中身をクリップボードにコピーする
type report.txt | clip
```

`ipconfig | clip` を実行すると、通常なら画面に表示される `ipconfig` の結果が画面には一切表示されず、その代わりにクリップボードへ格納されるように動作します。

**確認・判断のポイント**: 画面には何も表示されないため、成功したかどうかはメモ帳やメールソフトなどで `Ctrl + V` を押して貼り付けてみることで確認します。意図した内容がそのまま貼り付けられれば成功です。

**つまずきやすい点**: `clip` を実行すると、それまでクリップボードに入っていた内容（コピーしていた別の文字列や画像など）は確認なしに置き換わります。何かをコピーし直したいときは、貼り付けが必要な作業を先に済ませてから `clip` を使うとよいでしょう（Windows のクリップボード履歴〈`Win + V` キーで開ける機能で、既定では無効になっていることが多く、事前に有効化しておく必要があります〉を使っている場合は、上書きされた後でも過去にコピーした内容を呼び戻せることがあります）。また、クリップボードにコピーされる文字の見え方は、画面の文字コードページ（`chcp` で確認できる設定）の影響を受けることがあり、環境によっては日本語を含む出力を貼り付けたときに文字化けして見えることがあります。文字化けが起きた場合は、`chcp` の設定を確認するとよいでしょう。

### 補足: リダイレクトとパイプの違い

リダイレクト（`>` や `>>`）とパイプ（`|`）は、どちらも「コマンドの結果を、そのまま画面に表示するのではなく別の場所に送る」という考え方は共通していますが、送り先が異なります。リダイレクトは出力を**ファイル**に流し込む操作、パイプは出力を**次のコマンド**に流し込む操作です。たとえるなら、リダイレクトは「川の水を貯水池（ファイル）に貯める」イメージ、パイプは「川の水を、次の水車（別のコマンド）にそのまま流し込む」イメージです。「行き先がファイルならリダイレクト、行き先が別のコマンドならパイプ」と覚えておくと、`dir > filelist.txt`（ファイルへ保存）と `dir | findstr "sample"`（次のコマンドへ渡す）を混同しにくくなります。

### 補足: パイプを組み合わせて使う

`|` は複数回つなげて使うこともできます。たとえば `dir /s /b | findstr ".log" | sort` のように書くと、「サブフォルダも含めた一覧を取得する → `.log` を含む行だけに絞り込む → 並べ替える」という一連の処理を1行で実行できます。最後に `> ファイル名` を付け足せば、絞り込んで並べ替えた結果をそのままファイルに保存することもできます。慣れてくると、`findstr` ・`sort` ・`more` ・`clip` を組み合わせるだけで、専用のツールを使わなくてもかなりの作業がこなせるようになります。

**⚠️ `>` によるリダイレクトは、既存ファイルの中身を確認なしに上書きします。大事なログや設定ファイルに向けて `>` を使う前は、保存先のファイル名を必ず見直し、上書きではなく追記したいだけであれば `>>` を使ってください。また「管理者として実行」した状態のウィンドウでは、通常より強い権限でコマンドが実行されるため、この章や他の章で紹介した削除・フォーマットなどの操作と組み合わせるときは、対象のパスやファイル名を実行前に必ず確認してください。**

## 安全に使うための注意と困ったときの対処

ここまでの章では、日々の作業に役立つコマンドを数多く紹介してきました。しかしその中には、使い方を一歩間違えると、ファイルやディスクの中身が二度と元に戻らなくなってしまうコマンドがいくつも含まれています。この章では、そうした危険なコマンドをあらかじめ知っておくこと、実行前に立ち止まって確認する習慣を持つこと、そしてエラーが出たときに慌てず自分で調べられるようになることを目標にします。コマンドプロンプトだけでなく、PowerShell（より新しいコマンドライン環境）にも同じように注意が必要な操作があるので、あわせて見ていきましょう。

| やりたいこと | コマンド | 例 | 確認・判断のポイント |
| --- | --- | --- | --- |
| フォルダ内のファイルをまとめて確認なしで削除したい ⚠️ | `del /s /q <パス>` | `del /s /q C:\work\*.log` | 対象パスとワイルドカードの範囲を実行前に必ず見直す。ゴミ箱を経由しないため元に戻せない |
| フォルダを中身ごと丸ごと削除したい ⚠️ | `rd /s /q <フォルダ>` | `rd /s /q C:\temp\old` | `dir` や `tree` で対象フォルダの中身を先に確認してから実行する |
| PowerShellでフォルダを強制的に削除したい ⚠️ | `Remove-Item -Recurse -Force <パス>` | `Remove-Item -Recurse -Force C:\temp\old -WhatIf` | まず `-WhatIf` で「何が削除されるか」を確認してから本番実行する |
| ドライブを初期化したい ⚠️ | `format <ドライブ文字>:` | `format D:` | ドライブ文字を実行前に指差し確認する。Cドライブ以外は稼働中でも消せてしまう |
| ディスクを完全に消去したい ⚠️⚠️ | `diskpart` の `clean` | `list disk` → `select disk 1` → `clean` | `list disk` でディスク番号とサイズを本当に対象としたいディスクと突き合わせる |
| ファイルを隠す・読み取り専用にしたい ⚠️ | `attrib +h` / `attrib +r` など | `attrib +h myfile.txt` | 乱用すると「ファイルが消えた」と勘違いする原因になる。`attrib` だけで現在の属性を確認できる |
| 所有者・アクセス権を変更したい ⚠️ | `takeown /f`、`icacls /grant` | `takeown /f C:\data\report.docx` | システムフォルダに対して行わない。実行後は `icacls` で権限が意図通り付いたか確認する |
| 待ち時間なしで即座にシャットダウンしたい ⚠️ | `shutdown /s /t 0` | `shutdown /s /t 0` | `/t` の秒数を確認する。`0` だと `shutdown /a` によるキャンセルが間に合わない |
| レジストリを直接編集したい ⚠️⚠️ | `regedit` | `regedit` | 編集前に該当キーを `reg export` でバックアップできたか確認する |
| コマンドの使い方を実行前に確認したい | `/?`、`Get-Help` | `del /?` / `Get-Help Remove-Item` | 特に削除・フォーマット系のコマンドでは、実行前の確認を必須の一手間にする |
| 実際には実行せず影響だけ試したい | `-WhatIf`、`-Confirm` | `Remove-Item C:\temp\old -Recurse -WhatIf` | 表示された対象パスが想定通りか確認してから `-WhatIf` を外して実行する |
| エラーメッセージの意味を調べたい | エラーメッセージの確認 | `アクセスが拒否されました。` | メッセージ全文を読み、下表や Microsoft Learn（Microsoft公式のドキュメントサイト）で調べる |

### del /s /q と rd /s /q ⚠️ --- ファイルとフォルダをまとめて確認なしで削除する

`del`（ファイルを削除するコマンド）と `rd`（フォルダを削除するコマンド）は、それぞれ `/s`（サブフォルダも含める）と `/q`（quietの略で、確認メッセージを省略する）というオプションを組み合わせることで、大量のファイル・フォルダを一瞬で、しかも確認なしに削除できてしまいます。`/q` は主に、ワイルドカード（`*` などで複数ファイルを一括指定する記号）を使ったときに出る「よろしいですか （Y/N）?」という確認を省略する意味を持ちます。

`del /s /q` はファイルだけを削除してフォルダ自体は残しますが、`rd /s /q` はフォルダそのものごと削除してしまうという違いがあるため、どちらを使うべきかを目的に応じて区別する必要があります。

```bat
REM 指定フォルダとサブフォルダ内の .log ファイルをまとめて、確認なしで削除する
del /s /q C:\work\*.log

REM 指定フォルダを中身ごと丸ごと削除する(フォルダ自体も消える)
rd /s /q C:\temp\old
```

`/q` を付けない場合と付けた場合の違いは、次のように表示されることが多いです。

```text
C:\>rd /s C:\temp\old
C:\temp\old、よろしいですか (Y/N)? y

C:\>rd /s /q C:\temp\old

C:\>
```

**確認・判断のポイント**: 成功しても画面には基本的に何も表示されないため、削除できたかどうかは `dir` で対象フォルダを見て確認します。存在しないパスを指定した場合は「指定されたファイルが見つかりません。」のようなエラーが出て、打ち間違いに気づけます。

**つまずきやすい点**: ファイル名を1つだけ指定する `del` では元々確認が出ないことが多く、`/q` の効果を実感しにくいですが、`*.*` のようなワイルドカードを使った途端に大量のファイルが対象になります。⚠️ `del` はファイル名やワイルドカードの代わりにフォルダ名だけを指定すると、そのフォルダ内の全ファイルを対象にします（フォルダ自体は残ります）。`/q` を付けているとこの場合の確認も省略されるため、`del /s /q C:\work` のようにファイル名を書き忘れると、`C:\work` 以下の全ファイルが確認なしで一気に消えてしまいます。どちらのコマンドもゴミ箱を経由せず、その場でファイル・フォルダが消えるため、実行後に「やっぱりやめたい」と思っても元に戻せません。

**⚠️ del /s /q と rd /s /q は、対象のパスを一文字間違えただけで、意図しない大量のファイルやフォルダを一瞬で失う危険があります。実行前に `dir` や `tree` で対象を必ず確認し、可能であれば別の場所にバックアップを取ってから使ってください。**

### Remove-Item -Recurse -Force ⚠️ --- PowerShellでフォルダを丸ごと削除する

`Remove-Item` は PowerShell における `del`・`rd` に相当するコマンドレット（PowerShellの命令ひとつひとつのこと）です。`-Recurse`（サブフォルダも含めてすべて処理する）と `-Force`（読み取り専用や隠しファイルも含め、確認なしで削除する）を組み合わせると、`rd /s /q` と同じくらいの速さでフォルダごと消えてしまいます。

PowerShell の多くのコマンドレットには共通して `-WhatIf`（実際には実行せず、何が起きるかだけを表示するオプション）が用意されているため、削除系のコマンドではまずこれで「試し打ち」してから本番を実行するのが安全な手順です。

```powershell
# 実際には削除せず、何が削除される予定かだけを確認する
Remove-Item -Path C:\temp\old -Recurse -Force -WhatIf

# 確認して問題なければ、実際に削除する
Remove-Item -Path C:\temp\old -Recurse -Force
```

`-WhatIf` を付けたときは、次のように表示されることが多いです。

```text
What If: 対象 "C:\temp\old" に対して "項目の削除" を実行します。
```

**確認・判断のポイント**: `-WhatIf` の出力に表示されたパスが、本当に削除したい対象と一致しているかを確認してから、`-WhatIf` を外して実行します。実行後は `Get-ChildItem`（`dir` に相当）で対象が消えたことを確かめます。

**つまずきやすい点**: `-Force` を付けると読み取り専用・隠しファイルも問答無用で削除対象になります。⚠️ `Remove-Item` もゴミ箱を経由しないため元に戻せません。中身のあるフォルダを `-Recurse` を付けずに削除しようとすると、「対象には子項目があり、`-Recurse` パラメーターが指定されていません」といった確認を求められることがあります。この確認を避けるのは `-Force` ではなく `-Recurse` の役割なので、「`-Recurse` は再帰の指定、`-Force` は読み取り専用・隠しファイルも対象に含める指定」と役割を混同しないようにしてください。

**⚠️ Remove-Item -Recurse -Force は、指定したパス以下をすべて確認なしで削除する、PowerShell の中でも特に強力なコマンドです。実行前に必ず -WhatIf を付けて対象を確認し、本番実行は落ち着いてから行ってください。**

### format ⚠️ --- ドライブの中身を消してまっさらな状態に戻す

`format`（ドライブを初期化するコマンド）は、指定したドライブ文字のファイルシステム（ファイルの保存方法を管理する仕組み）を作り直し、そのドライブに入っているデータを原則としてすべて消し去ります。Windowsが起動して使っているドライブ（多くの場合Cドライブ）は、OS自身が使用中のため通常はロックされていてフォーマットに失敗することが多いのですが、これはあくまで「巻き込まれにくい」というだけの話です。Cドライブ以外の内蔵ドライブや、USBメモリ・外付けHDDなどは、稼働中でも普通にフォーマットできてしまいます。

```bat
REM Dドライブをフォーマットする(実行すると確認が求められる)
format D:

REM ボリュームラベル(ドライブに付ける名前)を指定してフォーマットする例
format D: /V:BACKUP
```

実行すると、次のように表示されることが多いです。

```text
新しいボリューム ラベルを入力してください (32 文字までです)? BACKUP
警告: ドライブ D のすべてのデータが失われます。
続行しますか (Y/N)? y
```

**確認・判断のポイント**: 確認プロンプトに表示されるドライブ文字とボリュームラベルが、本当にフォーマットしたい対象と一致しているかを見比べます。エクスプローラーで対象ドライブの中身をあらかじめ確認しておくと、より安心です。

**つまずきやすい点**: ⚠️ 「Cドライブは失敗しやすい」という話を、他のドライブにも当てはまると勘違いしないでください。ドライブ文字の打ち間違いによる事故は、USBメモリや外付けドライブでこそ起こりやすくなります。

**⚠️ format は指定したドライブの中身を原則すべて消し去る、取り返しのつかない操作です。実行前にドライブ文字を必ず指差し確認し、対象ドライブに大事なデータが残っていないかをエクスプローラーなどで確かめてから実行してください。**

### diskpart の clean ⚠️⚠️ --- ディスクそのものを消去する非常に強力なコマンド

`diskpart` は、ディスクの初期化・パーティション（1つのディスクを区切って作る独立した保存領域のこと）の作成・フォーマットなどを行う、専用のコマンドライン環境（`diskpart` と入力すると `DISKPART>` というプロンプトに切り替わる、専用の操作モード）です。その中の `clean` コマンドは、選択したディスクのパーティション情報を消去します。

`diskpart` が特に危険なのは、`chkdsk` のような「読み取り専用で確認だけする」モードが基本的に存在せず、`select disk` で選んだ対象に対してコマンドの効果がすぐに反映されてしまう点です。操作はディスク単位（パーティションより一段階上、物理的なディスクそのもの）に及ぶため、番号を一つ間違えるだけで、システムが入っている本体のディスクを対象にしてしまう危険があります。

```bat
REM diskpart を管理者権限のコマンドプロンプトから起動する
diskpart
```

`diskpart` のプロンプトに入った後は、次のように操作・表示されることが多いです。

```text
DISKPART> list disk

  ディスク ###  状態          サイズ    空き    Dyn  Gpt
  ------------  -------------  -------  -------  ---  ---
  ディスク 0    オンライン        238 GB      0 B
  ディスク 1    オンライン         14 GB      0 B

DISKPART> select disk 1

ディスク 1 が選択されました。

DISKPART> clean

DiskPart は正常にディスクをクリーンしました。
```

**確認・判断のポイント**: `select disk` の前に必ず `list disk` を実行し、ディスク番号とサイズを見比べて、本当に対象としたいディスク（多くの場合、Windowsが入っていない小さめのディスクやUSBメモリなど）かどうかを確認します。`select disk` を実行した直後にも、選択されたディスクの表示を見て再確認する習慣をつけます。

**つまずきやすい点**: ⚠️⚠️ `clean` はパーティション情報を消すだけで、元データ自体は残っていることもあります。より確実にデータの復元を防ぎたい場合（PCを譲渡・廃棄するときなど）は、全セクタを上書きする `clean all` を使うという違いがありますが、いずれにしても取り扱いには十分な知識が必要です。初心者のうちは、学習目的であっても無理に使わないのが無難です。

**⚠️⚠️ diskpart の clean は、ディスク番号を一つ間違えるだけで、システムが入っている本体のディスクを含め、選んだディスクのデータを一瞬で失う可能性がある、この章の中でも特に危険なコマンドです。学習中は使わず、もし将来使う場面があっても、list disk による確認を何度も行ってから実行してください。**

### attrib の乱用 ⚠️ --- ファイルを隠す・読み取り専用にする属性操作の落とし穴

`attrib`（ファイルの属性を確認・変更するコマンド）は、`+r`（読み取り専用にする）、`+h`（隠しファイルにする）、`+s`（システムファイル用の属性を付ける）のように、ファイルの性質を表す「属性」を付けたり外したりします。ファイルそのものを破壊するコマンドではありませんが、乱用すると自分でつけた属性を忘れてしまい、「ファイルが見当たらない」「保存できない」といった混乱を招きやすいという意味で、注意が必要なコマンドです。

```bat
REM ファイルを隠しファイルにする
attrib +h myfile.txt

REM ファイルを読み取り専用にする
attrib +r myfile.txt

REM 付けた属性を解除して元に戻す
attrib -h -r myfile.txt
```

属性だけを確認したいときは、次のように表示されることが多いです。

```text
C:\work>attrib myfile.txt
A  R  H       C:\work\myfile.txt
```

**確認・判断のポイント**: 引数なしで `attrib ファイル名` を実行すると、該当する属性のアルファベット（R=読み取り専用、H=隠しファイルなど）だけが表示されます。「ファイルが見当たらない」ときは、まずこれで隠し属性（H）が付いていないかを疑います。

**つまずきやすい点**: `+s`（システムファイル用の属性）は本来Windows自体が使うためのものなので、普段のファイルには付けないほうが無難です。⚠️ また、読み取り専用にしたファイルを `del` でそのまま削除しようとすると「アクセスが拒否されました」のようなエラーになることがあり、削除したいときは先に `attrib -r` で属性を外すか、`del` の `/f` オプション（読み取り専用ファイルも強制的に削除する）を使う必要があります。隠し属性（H）とシステム属性（S）を両方付けたファイルは、`attrib -h -s ファイル名` のように2つを同時に解除しないと属性が外れないことがあり、`-h` だけ・`-s` だけを個別に外そうとしても効果がないように見える場合がある点にも注意してください。

**⚠️ attrib の乱用は、ファイルそのものを壊すわけではありませんが、自分でつけた属性を忘れて「ファイルが消えた」「保存できない」と混乱する事故につながります。属性を変更したときは、必要がなくなった時点で元に戻す作業もセットで習慣にしてください。**

### takeown と icacls の乱用 ⚠️ --- 所有者とアクセス権を書き換える

`takeown`（take ownershipの略で、ファイル・フォルダの所有者を変更するコマンド）と `icacls`（アクセス制御リスト〈ACL。「誰が」「何を」できるかを定めたルールの一覧〉を確認・変更するコマンド）は、セットで使われることが多いコマンドです。他のユーザーが所有していてアクセスできないファイルに対して、まず `takeown` で自分を所有者にし、続けて `icacls` で読み書きの権限を付与する、という流れになります。

```bat
REM ファイルの所有者を自分に変更する
takeown /f C:\data\report.docx

REM 所有者を変更した自分のアカウントに、フルコントロール権限を付与する
icacls C:\data\report.docx /grant %USERNAME%:F
```

`takeown` を実行すると、次のように表示されることが多いです。

```text
成功: ファイル (またはフォルダー): "C:\data\report.docx" の所有者が
現在実行中のユーザーへ正しく変更されました。
```

**確認・判断のポイント**: `takeown` を実行しただけでは、実際に読み書きできるようになるとは限りません。`icacls <パス>` で権限一覧を再確認し、意図した権限が付いているかどうかを見ます。

**つまずきやすい点**: `takeown` は「所有者」を変更するだけのコマンドで、権限そのものを付与するわけではないため、実際に読み書きできるようにするには別途 `icacls` での権限付与が必要になる場合が多くあります。`icacls` の `/grant` は既定では権限を**追加**するだけで、既存の権限を置き換えるわけではない点にも注意してください（既存の権限をすべて置き換えたいときは `/grant:r` を使います）。⚠️ システムフォルダ（`C:\Windows` など）に対して乱用すると、Windows自体の権限設定が崩れて正常に動かなくなることがあるため、個人のファイル以外では慎重に扱ってください。どちらも管理者権限のコマンドプロンプトで実行するのが基本です。

**⚠️ takeown と icacls の乱用は、意図せずシステムファイルの権限を書き換えてしまうと、Windows自体が正常に動作しなくなる原因になります。操作対象が本当に自分の個人ファイルかどうかを、実行前に必ず確認してください。**

### shutdown /s /t 0 ⚠️ --- 待ち時間なしの即時シャットダウン

`shutdown` の `/s`（shutdownの意味）は電源を切る操作、`/t`（timeの意味）はシャットダウンが始まるまでの待ち時間を秒数で指定するオプションです。`/t` を省略すると既定で30秒後になりますが、`/t 0` のように0を指定すると待ち時間なしで即座に実行されます。誤って `shutdown /a`（abortの意味で、予約をキャンセルするコマンド）を打とうとしても、待ち時間がまったくないため間に合いません。

```bat
REM 0秒後(=即座)にシャットダウンする
shutdown /s /t 0

REM 通常は余裕を持たせて数十秒後にしておくと、間違えてもキャンセルできる
shutdown /s /t 30

REM カウントダウン中に、予約したシャットダウンを取り消したいとき
shutdown /a
```

`/t 30` のように余裕を持たせた場合は、指定した秒数のカウントダウンのあと、次のようなメッセージとともにサインアウト・シャットダウンの準備が進むことが多いです。

```text
Windows をシャットダウンします。
この操作は システム によって開始されました。
```

**確認・判断のポイント**: 実行するコマンドの `/t` に続く秒数を必ず確認します。動作を確認したいだけであれば `/t 0` ではなく、余裕を持った秒数（例: 60）を指定し、必要ならその間に `shutdown /a` でキャンセルできるようにしておきます。

**つまずきやすい点**: ⚠️ `/t 0` はキャンセルの猶予が全くないため、誤って実行すると保存していない作業がすべて失われる可能性があります。リモート接続中の端末や、他の人が使っている共有サーバーに対して実行すると、作業中のセッションが強制的に切断される点にも注意してください。再起動したいときは `/s` の代わりに `/r`（restartの意味）を使います。

**⚠️ shutdown /s /t 0 は、実行した瞬間にキャンセルの猶予なく電源が落ちます。保存していない作業は失われ、他の人が使っているサーバーであれば強制的に接続を切断します。動作を確認したいだけのときは、必ず /t に余裕を持った秒数を指定してください。**

### regedit ⚠️⚠️ --- レジストリを直接編集する

`regedit` を実行すると、レジストリエディタ（Windowsやアプリの設定情報を保存している、レジストリ〈大きな設定データベースのようなもの〉を直接編集するGUI〈グラフィカルな画面〉のツール）が開きます。レジストリはWindowsの動作そのものに関わる設定を大量に含んでいるため、意味が分からないままキーや値を書き換えると、特定のアプリが起動しなくなるだけでなく、Windows自体が起動しなくなることもあります。

```bat
REM レジストリエディタを起動する(GUIツールが開く)
regedit

REM 編集前に、対象のキーをファイルへバックアップとして書き出す
reg export "HKCU\Software\SampleApp" C:\backup\SampleApp.reg

REM コマンドラインからレジストリの値を確認したいだけのとき(変更は行わない)
reg query "HKCU\Software\SampleApp"
```

`reg export` を実行すると、次のように表示されることが多いです。

```text
C:\>reg export "HKCU\Software\SampleApp" C:\backup\SampleApp.reg
操作は正常に終了しました。
```

**確認・判断のポイント**: レジストリを編集する前に、`reg export` で該当キーのバックアップを取れたかを確認します。変更後は、対象のアプリやWindowsの機能が正常に動作するかどうかを実際に確かめます。

**つまずきやすい点**: `regedit` はGUIのツールですが、`reg` コマンドを使えばコマンドラインからも同様にレジストリの参照・バックアップ・書き換えができます。⚠️ 誤って重要なキーを削除・変更してしまうと、事前にバックアップを取っていなければ復元が難しく、最悪の場合Windowsの再インストールが必要になることもあります。

**⚠️⚠️ regedit でのレジストリ編集は、意味を理解しないまま行うとWindows自体が起動しなくなるなど、影響範囲がシステム全体に及ぶことがあります。編集前には必ず reg export でバックアップを取り、不安なときは触らないという判断も大切です。**

### 「ゴミ箱を経由しない削除がある」という心構え

普段エクスプローラー（ファイルやフォルダをマウスで操作する画面）でファイルを削除すると、いったんゴミ箱に入るため、間違えてもたいてい復元できます。しかし、コマンドプロンプトの `del`・`rd` や PowerShell の `Remove-Item` は、既定（何も設定しない場合の標準の動作）ではゴミ箱を経由せず、その場でファイルを消してしまいます。つまり「あとで戻せるはず」という、エクスプローラー操作の感覚のままコマンドで削除すると、実際には戻せないことがあるという点を、まず心構えとして持っておく必要があります。

```bat
REM コマンドプロンプトでの削除は、既定ではゴミ箱を経由しない
del memo.txt
```

```powershell
# PowerShellの Remove-Item も、既定ではゴミ箱を経由しない
Remove-Item memo.txt
```

**確認・判断のポイント**: 削除するコマンドを打つ前に、「これはゴミ箱を経由する操作か、経由しない操作か」を一瞬だけ意識します。コマンドで削除したファイルは、基本的にエクスプローラーのゴミ箱には出てきません。

**つまずきやすい点**: ⚠️ 「間違えてもゴミ箱から戻せるだろう」という思い込みのまま、練習のつもりで `del` や `Remove-Item` を打ってしまうと、実際には元に戻せない削除になっていることがあります。本当に大事なファイルを削除する前には、別のフォルダやドライブにコピーを取っておくと安心です。

### /? と Get-Help --- 実行前にコマンドの使い方を確認する習慣

意味がよく分からないコマンドやオプションを、確認せずにそのまま実行するのは、初めて訪れる建物で案内図を見ずに奥へ進むようなものです。コマンドプロンプトでは、コマンド名の後ろに `/?` を付けると使い方が表示されます。PowerShellでは、コマンドレット名の前に `Get-Help` を付けます。特に「削除」「フォーマット」「シャットダウン」など、元に戻せない可能性のある単語を含むコマンドを打つときは、実行前のヘルプ確認を必須の一手間にしておくと安全です。

```bat
REM コマンドプロンプトで、コマンドの使い方(オプション一覧)を確認する
del /?
rd /?
```

```powershell
# PowerShellで、コマンドレットの説明を確認する
Get-Help Remove-Item

# 使用例だけを見たいとき
Get-Help Remove-Item -Examples

# より詳しいオンラインのドキュメントをブラウザで開きたいとき
Get-Help Remove-Item -Online
```

`del /?` を実行すると、次のように表示されることが多いです。

```text
指定したファイルを削除します。

DEL [/P] [/F] [/S] [/Q] [/A[[:]属性]] 名前 [...]
ERASE [/P] [/F] [/S] [/Q] [/A[[:]属性]] 名前 [...]

  名前          削除するファイルの一覧を指定します。ワイルドカードを使って、
                複数のファイルを指定できます。
  /P            各ファイルを削除する前に確認します。
  /F            読み取り専用ファイルを強制的に削除します。
  /S            すべてのサブディレクトリからも指定したファイルを削除します。
  /Q            ワイルドカードを使った削除で、確認メッセージを表示しません。
```

**確認・判断のポイント**: 気になるオプション（特に `/s` `/q` `-Recurse` `-Force` など、範囲を広げたり確認を省略したりするもの）の意味を確認してから実行します。`Get-Help` は初回実行時に、ヘルプ本体のダウンロード（`Update-Help`。Windows PowerShellでは管理者権限とネット接続が必要）を促されることがあります。

**つまずきやすい点**: `cd` のように、シェル自体に組み込まれたコマンド（内部コマンド）でも `cd /?` のように `/?` がそのまま使え、`help cd` と同じ内容が表示されます。一方、Windows標準ではない外部のコマンドラインツール（`git` や各種パッケージ管理ツールなど）の中には `/?` を認識せず、代わりに `--help` や `-h` を使うものもあるため、`/?` を付けても反応がないときはこちらも試してみてください。`Get-Help -Online` はインターネット接続が必要で、接続がない環境では開けません。

### -WhatIf と -Confirm --- PowerShellでの「試し打ち」

PowerShellの多くのコマンドレット（ファイルを変更・削除するものなど）には、共通のオプションとして `-WhatIf` と `-Confirm` が用意されています。`-WhatIf` を付けて実行すると、実際には何も変更せず、「実行した場合に何が起きるか」だけを表示してくれます。`-Confirm` を付けると、実行の直前に1件ずつ確認を求められます。危険そうなコマンドほど、いきなり本番実行するのではなく、まず `-WhatIf` で試してから本番を実行する、という手順を習慣にすると事故を防ぎやすくなります。

```powershell
# 実際には削除せず、何が起きるかだけを確認する
Remove-Item -Path C:\temp\old -Recurse -Force -WhatIf

# 1件ずつ確認しながら実行したいとき
Remove-Item -Path C:\temp\old -Recurse -Force -Confirm
```

`-Confirm` を付けた場合は、次のように表示されることが多いです。

```text
確認
対象 "C:\temp\old" に対して "項目の削除" を実行しますか?
[Y] はい(Y)  [A] すべて続行(A)  [N] いいえ(N)  [L] すべて続行しない(L)  [S] 中断(S)  [?] ヘルプ (既定値は "Y"):
```

**確認・判断のポイント**: `-WhatIf` の出力に表示された対象パスが、想定通りの範囲かどうかを確認してから、`-WhatIf` を外して本番を実行します。`-Confirm` は1件ごとに立ち止まるため、対象が多いときは確認だけで時間がかかる場合があります。

**つまずきやすい点**: すべてのコマンドレットが `-WhatIf` に対応しているわけではなく、対応にはコマンドレット側の実装（`SupportsShouldProcess` という仕組み）が必要です。また `-WhatIf` を付けて安心したまま、後で本番実行するのを忘れてしまう、という逆のつまずきもあるため、「確認 → 本番実行」の2段階を意識しておくとよいでしょう。

### よくあるエラーメッセージの意味

エラーが出ても、多くの場合は落ち込む必要はありません。エラーメッセージは「ここが原因かもしれません」というヒントです。代表的なものを知っておくと、慌てずに対処できます。

| エラーメッセージ（例） | 意味 | よくある原因・対処法 |
| --- | --- | --- |
| `'xxx' は、内部コマンドまたは外部コマンド、操作可能なプログラムまたはバッチ ファイルとして認識されていません。` | 入力したコマンド名を、コマンドプロンプトが理解できなかった、という意味 | コマンド名のスペルミス、または PATH（コマンドを探しに行くフォルダーの一覧のこと）にそのプログラムの場所が登録されていないことが多い。スペルを確認し、正しいフォルダーから実行するか PATH の設定を見直す |
| `用語 'xxx' は、コマンドレット、関数、スクリプト ファイル、または操作可能なプログラムの名前として認識されません。` | PowerShellで、上と同じく「コマンド名を理解できなかった」ことを伝える言い回し | 原因・対処法はコマンドプロンプトの場合とほぼ同じ（スペルミス・PATHの見直し）。加えて、必要なモジュール（追加のコマンド群をまとめたもの）がまだ読み込まれていないだけ、というケースもある |
| `アクセスが拒否されました。` | 操作する権限がない、または対象が使用中である、という意味 | 管理者権限が必要な操作を一般権限で実行しようとした、ファイルが他のアプリで開かれたまま使用中、読み取り専用属性が付いている、などが考えられる。管理者としてコマンドプロンプトを開き直す、対象のファイルを閉じてから再実行する |
| `指定されたパスが見つかりません。` | 指定したフォルダーやファイルの場所が存在しない、という意味 | パスのスペルミスや、相対パス（今いる場所を基準にした道順）と絶対パスの取り違えが多い。`pwd` に相当する `cd`（引数なし）や `dir` で、今いる場所と対象の実在を確認する |
| `〜.ps1 を読み込むことができません。このシステムでは、スクリプトの実行が無効になっているため、ファイル 〜.ps1 を読み込むことができません。` | PowerShellの実行ポリシー（スクリプトファイルを実行してよいかどうかを制御する安全装置のような設定）によって、スクリプトの実行がブロックされている、という意味 | 通常のWindows（クライアント向けエディション）では既定で「Restricted」（実行を全面的に禁止する設定）になっていることが多い。`Get-ExecutionPolicy` で現在の設定を確認し、必要に応じて管理者の指示のもとで設定を変更する |
| `プロセスはファイルにアクセスできません。別のプロセスが使用中です。` | 削除やリネームなどの対象ファイルを、他のアプリ（プロセス）が開いたまま使用中である、という意味 | 対象のファイルを開いているアプリ（エディタやExcelなど）を閉じてから再実行する。`タスクマネージャー` や `tasklist` で、関連しそうなプロセスが動いていないか確認する |

**確認・判断のポイント**: エラーメッセージが出たら、まず全文を読み、「コマンドが見つからない系」「権限がない系」「対象が存在しない・使用中系」のどれに近いかを見分けます。上の表に近い言い回しがあれば、それが原因の手がかりになります。

**つまずきやすい点**: コマンドプロンプトとPowerShellでは、同じ状況でも表示されるエラーメッセージの言い回しが異なる場合があります。今どちらの画面で作業しているかを見失わないようにすると、原因の絞り込みがしやすくなります。

### 困ったときの調べ方

エラーが出たとき、あるいはコマンドの動きが予想と違ったときは、次の順番で調べると効率的です。

```bat
REM 1. まずはそのコマンド名に /? を付けて実行し、公式の使い方を確認する
xcopy /?
```

```powershell
# 2. PowerShellのコマンドレットなら、より詳しいオンラインドキュメントを開く
Get-Help Remove-Item -Online
```

1. まずはそのコマンド名に `/?` を付けて実行し、公式の使い方を確認する（例: `xcopy /?`）
2. PowerShellのコマンドレットなら `Get-Help <コマンドレット名> -Online` を実行すると、より詳しいオンラインのドキュメントがブラウザで開かれる場合がある
3. それでも解決しない場合は、エラーメッセージやコマンド名をそのまま検索キーワードにして、Microsoft Learn（Microsoft公式のドキュメントサイト）を検索する

**確認・判断のポイント**: エラーメッセージは、要約したり自分の言葉に置き換えたりせず、全文をそのままコピーして検索すると、同じ症状の情報が見つかりやすくなります。検索結果が複数あるときは、Microsoft公式のドキュメント（`learn.microsoft.com` のページ）を優先して読むと、記載内容の信頼性が高く安心です。

**つまずきやすい点**: 「自分だけが困っている」と思いがちですが、たいていのエラーは他の人も一度は経験しているものです。焦って手当たり次第にオプションを付け足すのではなく、`/?` や `Get-Help` で仕様を確認しながら一つずつ調べていく方が、結果的に早く解決できます。
