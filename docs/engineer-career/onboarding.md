# 入社後に相談しながら担当を広げる

この文書は、就職活動で示した能力と職場で任される仕事をつなぎます。
30・60・90日の学習内容は [職場の担当へつなぐ計画](../server-engineer/workplace.md)を正本とし、ここでは面談、支援依頼、担当拡張の判断を扱います。
日数は話し合いの節目です。経過日数やラボの成功だけで権限、単独担当、習得済みを確定しません。

## 入社前に引き継ぐ

[応募・条件確認](job-search.md)の記録から、合意した初期担当、未確認の条件、説明した実施範囲を本人が確認します。
入社先の情報を公開GitHubへ追加せず、職場の記録先と利用できるツールを入社先へ確認します。

| 確認すること | 残す内容 |
| --- | --- |
| 期待される初期業務 | 自分が理解した担当範囲と、責任者の説明との差 |
| 指導・相談の窓口 | 技術、優先順位、権限、勤務の相談先と不在時の代理 |
| 仕事の正本 | 社内チケット、手順、承認、証跡をどこに記録するか |
| 個人ラボとの違い | 製品、規模、利用者影響、権限、データ、変更手順 |
| 利用できる支援 | 見学、ペア作業、検証環境、レビューの依頼方法 |

分からない項目は `未確認` とします。本人の同意や上司の承認を、説明文の生成で補いません。
本人の週10時間は就職前の学習・作品改善・就職活動の総枠です。入社後に業務時間へ上乗せする義務として使いません。
業務、通勤、休息、社内研修を確認して業務外の配分を本人が見直し、既存の週次運用へ反映します。

## 30・60・90日の面談で決める

各節目で [既存の到達計画](../server-engineer/workplace.md)を開き、実施機会と記録を見ます。
達成を急いで本番作業を増やさず、見学・検証・指導付き実施を担当者と選びます。

| 節目 | 本人が準備する事実 | 相談して決めること | 次へ進む条件 |
| --- | --- | --- | --- |
| 30日 | 用語、対象、連絡経路の理解と不明点。見学・検証の記録 | 小さく担当できる作業、確認者、停止条件 | 対象と手順を確認し、実施前後に相談できる |
| 60日 | 指導付き作業の結果、差異、質問と指摘、手戻り | 継続支援が必要な条件、次の一作業 | 対象作業に必要な試験と報告を確認者が確認する |
| 90日 | 合意範囲での遂行記録、未経験条件、残課題 | 次の期間の範囲、支援、レビュー間隔 | 担当範囲と例外時の判断者を実際に合意する |

機会、権限、環境がない場合は `NOT RUN` と理由を残します。書類を埋めるための架空の担当経験は作りません。
確認者の予定がつかない場合は確認待ちです。独力で進めたと宣言せず、代理や日程を相談します。
正式な評価方法と期限は所属組織の運用を確認し、この文書の目安と区別します。

## 毎日の短い確認

日々の案件管理は [既存の案件運営](../server-projects/operations.md)を使います。この文書のために社内の正本と同じ報告を二重作成しません。
始業時には今日の約束、対象と権限、不明点、確認者の予定を確認します。
終業前には実施内容、結果、未完了、次の一手、相談が必要な点を職場で決めた方法で残します。

| 仕事を受けたときの確認 | 記入する内容 |
| --- | --- |
| 何を終わらせるか | 依頼の目的、対象、成果物、期待値 |
| どこまで任されるか | 自分で判断できる範囲、指導・承認が必要な操作 |
| いつまでか | 希望期限と合意期限、途中の確認時点 |
| 異常時はどうするか | 中止条件、戻し方、連絡先、不在時の代理 |
| 終了を誰が確認するか | 試験結果、報告方法、確認者、残課題の渡し先 |

実際の案件は [受付から終結までの8工程](../server-projects/README.md)へつなぎます。
このキャリア記録に「できた」と記入しても、案件の変更承認や検収を満たしたことにはなりません。

## 質問と相談を早くする

相談は分からないことを列挙するだけでなく、相手が判断できる事実と期限を添えます。
詳細な報告の順番と役割は [役割・判断・報告](../server-projects/roles-and-communication.md)を使います。

```text
相談メモ（下書き。作成しただけでは連絡済みにならない）
対象 / 目的 / 合意した担当範囲: 未記入
現状: 未着手 / 予定内 / 遅延のおそれ / 停止 / 判断待ち
確認できた事実と記録先: 未記入
分からない点 / 想定との差: 未記入
実施済み操作と利用者影響: 未記入
自分で考えた選択肢 / それぞれの影響: 未記入
判断をお願いしたい人 / 内容 / 期限: 未記入
次の更新予定: 未記入
実際の連絡日時 / 返答 / 合意の記録先: 未連絡 / 未回答 / 未合意
```

AIは公開可能な架空例や許可された情報で下書きを支援します。職場データの入力可否は組織の規則に従います。
AIから本人や関係者への送信・約束を自動実行せず、送信案と実際の連絡を分けます。
相手が回答していないことを、了承や問題なしの証拠にしません。

## 担当範囲を一つずつ広げる

| 検討する変更 | 提示する根拠 | 責任者と確認すること |
| --- | --- | --- |
| 同じ手順を別日に実施 | 再実施した対象、結果、相談内容 | 次回も同じ前提か。支援を減らせる範囲はどこか |
| 別の対象へ適用 | 環境差、追加試験、影響、戻し方 | 新しい対象に必要な権限・レビュー・作業承認 |
| 小さな設計・改善を担当 | 課題、案の比較、試験方法、工数 | 優先順位、採否、担当、確認者 |
| 引継ぎを担当 | 手順、注意点、残事項、説明記録 | 受領者の確認範囲、未解決事項の担当 |

根拠は「説明できた」「支援付きで実施」「本人が再実施」「他者確認済み」を分けます。
進め方の独自分類であり、IPAの正式レベル認定や職場からの権限付与を意味しません。
職場の作業承認、本人の実施、確認者の確認は、それぞれの原記録に対応させます。

## うまく進まないとき

| 状況 | 最初の対応 | 再開・見直しの条件 |
| --- | --- | --- |
| 対象、権限、戻し方が不明 | 変更操作を始めず、確認者へ相談 | 前提と判断経路が明確になる |
| 作業が期待と違う・利用者影響がある | 決めた中止条件に従い、事実を報告 | 責任者の対応判断と必要な再試験 |
| 同じ指摘・手戻りが続く | 原因を手順、理解、前提、確認方法に分ける | 次の作業1件で変更した方法を試す |
| 教わる機会や案件がない | 未実施と必要な機会を記録し、見学・検証を相談 | 実施機会と支援が決まる |
| 複数の依頼で時間が足りない | 作業と期限、見込み時間を責任者へ提示 | 優先順位、範囲、期限、支援の合意 |
| 業務外の活動を続ける負担が大きい | 個人の追加課題を減らし、配分を本人が見直す | 続けられる時間と対象が決まる |

対応を急ぐ必要がある場面では、完全な報告書の完成を待たずに職場の連絡手順に従います。
自分の調査を延長して連絡期限や切戻し期限を越えないよう、依頼時に相談の時点を決めます。

## 次の期間に残す面談メモ

```text
面談日 / 対象期間 / 参加者: 未記入
本人が実施した範囲と根拠: NOT RUN
説明・判断で確認できた範囲: 未確認
指導やレビューを受けた範囲と原記録: 未確認
まだ経験していない条件 / 支援が必要な点: 未記入
次に希望する担当1件と理由: 未記入
責任者が合意した担当 / 支援 / 期限 / 確認方法: 未合意
業務外の活動時間と次回見直し日: 本人確認待ち
```

実業務の詳細と評価原本は許可された社内の場所へ置きます。顧客名、構成、ログを個人GitHubへ持ち出しません。
公開学習へ戻す場合は独立した個人ラボの課題として作り、職場の実績と混同しません。
設計根拠は [一次資料](sources.md)、技術の次の課題は [既存の職場接続](../server-engineer/workplace.md)へ戻します。
